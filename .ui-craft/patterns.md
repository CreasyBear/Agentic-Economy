# Validated Patterns

Reusable UI patterns that have passed the finish bar and may be copied, not reinvented.

## Public Shell

- Astryx `AppShell` + `TopNav` own header, footer, and max-width container behavior.
- Header: AE identity left, primary action right, secondary links as text.
- Footer: one-line boundary note left, secondary actions right.

## Trust Bar

- 3 items max on desktop, stacked on mobile.
- Use Astryx `Badge`, `StatusDot`, `Banner`, or card primitives rather than custom icon treatments.
- Labels are concise; descriptions state the boundary plainly.

## Primary CTA

- Use the Astryx primary action treatment.
- Secondary action is a plain text/link treatment, visually subordinate.
- One primary action per public viewport.

## Routing Object

- Dominant public object: a real provider evidence frame, query composer, generated answer artifact, citation card, or next action when it clarifies the flow.
- Do not add evidence rails unless they show real provider evidence that is not already said by the headline, lede, or query panel.

## Hero

- Fits in one viewport: headline ≤2 lines, lede ≤20 words, CTA visible.
- Prefer structured content and real local provider evidence over decorative imagery, stock AI art, or fake UI.
