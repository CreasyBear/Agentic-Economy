# Architecture

**Analysis Date:** 2026-08-09

## Pattern Overview

Agentic Economy is a full-stack TypeScript application with a TanStack Start request/runtime shell, React/TanStack Router presentation, domain modules, and Convex as the durable source. The runtime is assembled by `src/start.ts`, the browser router is created in `src/router.tsx`, and Vite/Nitro/TanStack Start are composed in `vite.config.ts`. The root package is ESM and declares Node 22 in `package.json`.

The conceptual dependency direction is:

```text
browser components/routes
        ↓ public module seams + server functions
HTTP/server adapters and CLI
        ↓ source ports, action contracts, validated commands
AE domain modules (deterministic policy, projections, evidence)
        ↓ typed Convex source references
Convex queries/mutations/actions/workflows
        ↓
external model, provider, payment, notification, and agent protocols
```

Routes are adapters rather than database owners: the route-boundary contract rejects route-owned Convex transport/schema imports (`tests/imports/route-boundary.test.ts`). Domain packages expose stable `public.ts` contracts and keep implementation in `internal/`; the action registry is explicit rather than side-effect-discovered (`src/modules/actions/index.ts`).

Convex and the deterministic domain/kernel own identity, authority, admission, validation, effects, payment, and completion evidence. Models emit typed answer prose or customer-request proposals; they do not select providers, invent operation references, authorize effects, or become the public source of provider facts (`src/modules/common/action.ts`, `src/modules/customer-request/compiler.ts`, `src/modules/answer/internal/answer-tool-use-agent.ts`). Detailed prompt/model/tool and information-architecture traces remain in `.planning/codebase/PROMPT-DATA-FLOW.md` and `.planning/codebase/IA-DATA-FLOW.md`.

## Layers

### Presentation and route composition

- `src/routes/__root.tsx` establishes the document, Clerk provider selection, global CSS, observability boot, and error boundary around the TanStack route tree.
- `src/components/ae/layout/AePublicShell.tsx` and `src/components/ae/layout/AeOperatorShell.tsx` provide the public and operator shells. `src/routes/_operator.tsx` is a pathless layout that keeps operator chrome mounted while child routes load.
- `src/components/ae/chat/AeChat.tsx` owns chat composition state, route/session projection selection, optimistic turns, navigation, and browser-side convergence. Presentation components render typed projections rather than raw Convex rows (`src/components/ae/chat/AeThreadTurnStreamSection.tsx`, `src/components/ae/artifacts/AeGenerativeAnswer.tsx`).

### Server and HTTP adapters

- TanStack file routes in `src/routes/` expose pages and server handlers. Representative adapters include `src/routes/api.answer.turn.ts`, `src/routes/api.v1.services.ts`, `src/routes/api.v1.requests.ts`, `src/routes/mcp.ts`, and `src/routes/api.stripe.webhook.ts`.
- Shared request concerns live in `src/lib/server/`: bounded JSON/text readers (`bounded-request-body.ts`), HTTP rate admission (`rate-limit.ts`), method guards (`method-guard.ts`), RFC 9457 response construction (`problem.ts`), Convex source clients (`convex-source.ts`), and source-write admission (`source-write-admission.ts`).
- Server functions in domain packages are thin ports. For example, `src/modules/registry/registry.functions.ts` turns public registry reads into typed Convex queries, while `src/modules/catalog/owner-claim.functions.ts` validates owner commands and calls authenticated source mutations.
- `tools/ae/cli.ts` is a separate external-agent/human port. It exercises HTTP surfaces or the in-process action registry, and projects shared problem details through `tools/ae/lib/output.ts`.

### Domain modules and deterministic kernel seams

- `src/modules/common/` contains shared deterministic primitives such as canonical digests, stable hashes, bounded JSON, IDs, normalization, and the central `Action` contract (`src/modules/common/action.ts`).
- Capability contracts are parsed and validated by `src/modules/capability-contract/public.ts`; provider imports and admission are isolated in `src/modules/capability-supply/internal/publication-importers.ts`, `internal/publication/`, and `internal/admit-provider-schema.ts`. Publication state, binding eligibility, readiness, and operation identity are domain decisions, not model decisions.
- Registry/catalog modules project source-owned business and offering supply into public DTOs (`src/modules/registry/public.ts`, `src/modules/registry/internal/services-api-projection.ts`, `src/modules/catalog/internal/offering-supply.ts`). `ServiceDto.endpoints[]` and opaque `operation:v1:<digest>` references are the agent-facing representation (`src/modules/registry/internal/service-projection.ts`, `src/modules/capability-supply/public.ts`).
- Answer turns are split between typed answer contracts (`src/modules/answer/`) and durable turn orchestration (`src/modules/answer-thread/`). The orchestrator owns intent/route selection, retrieval-first behavior, model entry, grounding gates, event assembly, persistence, and finalization (`src/modules/answer-thread/internal/turn-orchestrator.ts`).
- Customer Request is a proposal-to-authority boundary: semantic interpretation and the route compiler produce `authority: 'proposal_only'` plans (`src/modules/customer-request/compiler.ts`), while route mandates, approval modes, prepared actions, and execution ports enforce authority (`src/modules/customer-request/route-mandate.ts`, `src/modules/customer-request/action-preparation.ts`, `src/modules/action-invocation/`). The old routing authority is retired except for explicit history/readback guards (`src/modules/routing-kernel/retirement.ts`, `tests/imports/routing-authority-retirement.test.ts`).
- `src/modules/work-tree/` is the project/decision domain. Its root server functions dynamically load the graph-backed loop and delegate identity, fencing, idempotency, and durable state to Convex (`src/modules/work-tree/human-root.functions.ts`).
- Money, inquiry, discovery, study, demand, notification, security, harness, and external-run modules follow the same public-contract/internal-policy pattern (`src/modules/money/public.ts`, `src/modules/inquiries/public.ts`, `src/modules/discovery/public.ts`, `src/modules/harness/`, `src/modules/security/`).

### Durable Convex backend

- `convex/schema.ts` composes the current table bundles for action invocation, answer threads, business/catalog, capability supply/contracts, Customer Request, registry, routing history, demand, discovery, harness, inquiries, notifications, observability, security, money, settings, Project Spine, work trees, studies, and external runs.
- `convex/*.ts` files are function adapters and durable transactions. They use Convex validators and generated references; domain shapes and projections are imported from `src/modules/**`, while request-side ports call them through `src/lib/server/convex-source.ts`.
- Durable answer identity is allocated before model work by `convex/answerThreads.ts`: a reservation binds session, request digest, thread, turn, and sequence; persistence inserts answer/tool rows; finalization patches the harness state; Stop transitions the reservation and turn to `stopped`. Owner queries and share-token queries return projections, not raw documents.
- Capability operation readers in `convex/capabilitySupplyOperations.ts` re-check current publication, business, offering, binding, contract, readiness, credential, adapter, and method conditions before returning a keyless descriptor. Customer Request actions in `convex/customerRequestApplication.ts` and route transport workers in `convex/customerRequestRouteExecution.ts` keep compilation, authorization, dispatch, recovery, and cancellation behind durable source code.
- Convex scheduled work is declared in `convex/crons.ts`; readiness probes, cleanup, Project Spine workflow state, work-tree state, money ledger state, and notification outbox are durable backend concerns rather than browser state.

### External execution and protocol adapters

- `src/modules/model-gateway/public.ts` is the single OpenRouter model factory. The answer agent uses AI SDK 7 in `src/modules/answer/internal/answer-tool-use-agent.ts`; the SDK owns provider encoding and loop mechanics, while AE owns tool admission, budgets, evidence, grounding, and answer gates.
- Keyless operation execution is DB-described and fail-closed. A selected per-operation tool closes over one canonical operation reference, `src/modules/capability-execution/operation-execute.functions.ts` validates its schema and public HTTPS target, and `operation-execute.server.ts` supplies guarded network fetches. Keyed, x402, non-GET, and non-JSON execution is refused by this seam.
- Registered action contracts are exposed to HTTP, UI, CLI, answer, agent JSON, and MCP surfaces according to `src/modules/common/action.ts` metadata. `src/lib/server/mcp-api.ts` exposes only explicitly surfaced actions, keeps anonymous access read-only, and asks the Customer Request agent-auth seam for stronger authority modes.
- Route transport and paid operations are separate from keyless execution. `src/modules/capability-supply/route-transport-runtime.ts` handles bounded HTTP/MCP/x402 observations, while `src/modules/action-invocation/` owns attempts, release fences, standing mandates, reconciliation, and durable/in-memory development adapters.

## Data Flow

### Buyer answer turn: reserve, execute, project

1. `/t/new` mounts `AeChat` with no thread and may carry a bounded `q` query (`src/routes/t.new.tsx`). `AeChat` derives the initial idempotency key from a page scope and query, and creates random keys for subsequent turns (`src/components/ae/chat/AeChat.tsx`). Existing `/t/$threadId` loads an owner projection through `src/modules/answer-thread/thread-route.ts`.
2. The browser posts `{ query, threadId?, searchContext? }` to `/api/answer/turn` with `X-AE-Turn-Key` (`src/components/ae/chat/answer-stream.ts`). `src/routes/api.answer.turn.ts` requires JSON, enforces the 16 KiB body bound and 128-character key bound, parses `answerTurnRequestSchema`, applies rate admission, resolves the pseudonymous `ae_session` cookie, and computes request/reservation digests.
3. `reserveAnswerTurn` in `src/modules/answer-thread/answer-thread.functions.ts` calls `convex/answerThreads.ts` before model/provider work. Convex enforces session ownership, thread existence, turn limits, request-digest replay/conflict, and monotonic sequence allocation. A replay returns durable state instead of launching a second run.
4. The route opens an AI SDK UI stream containing transient typed `AnswerTurnFrame` data (`src/modules/answer/answer-ui-stream.ts`). `streamAnswerTurn` in `src/modules/answer-thread/internal/turn-orchestrator.ts` runs the harness phases `context → intent → route → retrieval → model → gate → assemble → persist → report` and emits public work events while retaining private evidence/model observations.
5. Retrieval-first reads the registry and operation surfaces through typed action/source ports (`src/modules/answer-thread/internal/turns/retrieval-first.ts`, `src/modules/registry/registry.actions.ts`). Boundary, frozen, inquiry, clarification, and insufficient-frozen routes are deterministic; unresolved searches enter the AI SDK agent (`src/modules/answer-thread/internal/turns/agent.ts`). The agent's fixed discovery actions and at most one descriptor-derived capability tool are assembled in `answer-tool-use-agent.ts`.
6. A selected operation tool closes over the descriptor's canonical `operationRef`; `executeKeylessOperation` validates caller input, re-reads the source descriptor, checks keyless HTTP-JSON GET eligibility, validates the endpoint/target, fetches under the 512 KiB upstream bound, validates output, and returns a digest-bearing result (`src/modules/capability-execution/operation-execute.functions.ts`). The answer layer applies the separate 64 KiB model/evidence bound and records one `operation.execute` tool call (`src/modules/answer/internal/answer-tool-use-agent.ts`).
7. The gate sanitizes prose, grounds provider slugs and published facts, checks epistemic/injection/provider-claim rules, and produces a typed failure or accepted snapshot (`src/modules/answer/internal/answer-gate.ts`, `src/modules/answer-thread/internal/answer-turn-safety.ts`). Assembly emits artifacts/work/summary deltas from the accepted snapshot (`src/modules/answer/internal/emit-snapshot-events.ts`).
8. Persistence is reservation-bound: answer/tool rows are written by `convex/answerThreads.ts`, then harness finalization is recorded through `convex/harnessSessions.ts`. Only after durable persistence/finalization does the stream emit `complete` or a terminal typed error (`src/modules/answer-thread/internal/turn-orchestrator.ts`).
9. `AeThreadTurnStreamSection` reduces frames, requests owner readback, and lets the durable projection replace optimistic/transient state (`src/components/ae/chat/AeThreadTurnStreamSection.tsx`, `src/components/ae/chat/answer-turn-state.ts`, `src/components/ae/chat/projection-merge.ts`). Stop is a durable POST to `src/routes/api.answer.turn.stop.ts`; share and revoke are explicit owner mutations, and `/s/$shareToken` reads an HMAC-verified read-only projection (`src/modules/answer-thread/internal/share-token.ts`, `src/routes/s.$shareToken.tsx`).

### Public catalog and capability flow

- `/api/businesses`, `/api/businesses/search`, `/$slug`, and `/api/v1/services*` parse route inputs and dispatch the registry action contracts (`src/routes/api.businesses.ts`, `src/routes/api.businesses.search.ts`, `src/routes/api.v1.services.ts`, `src/modules/registry/registry.actions.ts`). The registry source reads published, unsuppressed supply projections from Convex (`src/modules/registry/registry.functions.ts`, `convex/registry.ts`) and projects public business DTOs or canonical `ServiceDto` endpoints; raw rows and owner data do not cross the public seam.
- Provider onboarding imports AE envelopes, OpenAPI HTTP, MCP, or x402 descriptions, bounds source size/depth, normalizes schemas and transport, then admits/publishes only a valid contract/offering/binding (`src/modules/capability-supply/internal/publication-importers.ts`, `src/modules/capability-supply/internal/publication/admit.ts`, `src/modules/capability-contract/public.ts`). Readiness and lifecycle determine whether Convex operation readers expose an executable descriptor.
- The answer agent can discover an operation via registry operation actions, select one strict descriptor, and execute it through the keyless seam. The same operation identity powers public endpoint projection, execution evidence, and later readback (`src/modules/capability-supply/operation-projection.ts`, `convex/capabilitySupplyOperations.ts`).

### Owner, agent, inquiry, and project flows

- `/claim` and `/claim/form` validate owner facts in server functions, resolve the Clerk actor, and call `convex/business.ts` plus `convex/catalog.ts`; published catalog projection is then read through the owner/public catalog ports (`src/modules/catalog/owner-claim.functions.ts`).
- `/_operator/*` routes share the Clerk session gate in `src/lib/server/require-operator-session.ts`, load readbacks through module server functions, and render owner/admin/developer shells. Convex admin functions check active membership/action authority (`convex/authz.ts`, `convex/security.ts`); route membership does not itself grant admin mutation authority.
- `/$slug/inquiry` resolves current target admission and submits a public inquiry through `src/modules/inquiries/route-readbacks.ts` and `src/modules/inquiries/inquiry.functions.ts`. Owner/admin inquiry views consume redacted readbacks and delivery state rather than raw customer records.
- `/api/v1/requests` and its nested request routes pass through `src/lib/server/customer-request-agent-api.ts`: bearer/OAuth agent authentication selects `inspect_only`, `approve_each`, or `bounded_mandate` modes, deterministic compile/projection produces proposal-only plans, and Convex Customer Request actions perform confirmation, run, cancellation, recovery, and repeat-permission mutations (`src/modules/customer-request/agent-contract.ts`, `convex/customerRequestApplication.ts`).
- `/` remains a static buyer entry unless a project reference is supplied. Project reads/decisions go through the server functions in `src/modules/work-tree/human-root.functions.ts`, which resolve authenticated or signed guest identity and delegate fencing/idempotency to Convex; the UI renders `RootWorkTreeLoop` (`src/routes/index.tsx`, `src/components/ae/home/RootWorkTreeLoop.tsx`).

## Key Abstractions

- **Public module seam:** `public.ts` files export domain contracts and projections; `internal/` owns policy/implementation. This is the primary replacement boundary for route, server, and Convex adapters (`src/modules/answer/public.ts`, `src/modules/registry/public.ts`, `src/modules/capability-supply/public.ts`).
- **Action contract and registry:** `defineAction`, `ActionContext`, invocation/effect/authority metadata, and `listActions`/`listMcpActions` provide one explicit machine-operation catalog (`src/modules/common/action.ts`, `src/modules/actions/index.ts`).
- **Source transport:** `ConvexSourceTransport`, typed `sourceQuery`/`sourceMutation`/`sourceAction`, and `call*Source*` functions keep authenticated/public Convex calls behind one server adapter (`src/lib/server/convex-source.ts`).
- **Capability identity and contracts:** `defineCapabilityContract` validates bounded JSON Schema contracts; `createPublicOperationRef` creates digest-based operation identity; operation projections carry execution, provenance, pricing, and evidence metadata (`src/modules/capability-contract/public.ts`, `src/modules/capability-supply/public.ts`, `src/modules/capability-supply/operation-projection.ts`).
- **Answer evidence/projection:** `AnswerSnapshot`, `AnswerEvent`, `AnswerTurnFrame`, `FrozenTurnEvidence`, and `PublicThreadProjection` separate transient stream frames, private durable evidence, and public redacted artifacts (`src/modules/answer/answer-synthesizer.ts`, `src/modules/answer/answer-ui-stream.ts`, `src/modules/answer-thread/answer-thread.schema.ts`).
- **Customer Request authority:** `CustomerRequestV2Aggregate`/route plan is a proposal; `RouteMandate`, preparation/approval types, action invocation views, and route execution journals are the authority/effect/evidence seams (`src/modules/customer-request/compiler.ts`, `src/modules/customer-request/route-mandate.ts`, `src/modules/action-invocation/contracts.ts`, `convex/customerRequestRouteExecution.ts`).
- **Projection-first public API:** catalog, services, inquiries, discovery, answer, admin, and work-tree routes use dedicated readbacks/projections so public surfaces do not expose internal documents (`src/modules/registry/internal/services-api-projection.ts`, `src/modules/answer-thread/internal/public-projection.ts`, `src/modules/security/admin-readback.functions.ts`).

## Entry Points

- **Application runtime:** `src/start.ts` creates request middleware; `src/router.tsx` creates the TanStack Router; `src/routes/__root.tsx` mounts the document/root outlet. Middleware order includes method guards, observability, security headers, agent content negotiation, CSRF for server functions, source-write context, and optional Clerk middleware (`src/start.ts`).
- **Public browser routes:** `/`, `/$slug`, `/$slug/inquiry`, claim pages, static help/legal/marketing pages, `/t/new`, `/t/$threadId`, `/i/$threadId`, and `/s/$shareToken` are implemented by the corresponding files in `src/routes/` and wired into generated `src/routeTree.gen.ts`.
- **Operator routes:** `src/routes/_operator.tsx` parents `/owner/*`, `/admin/*`, `/developers/discovery`, and agent-access routes. Operator leaf pages use `operatorRouteOptions` and module-specific server readbacks (`src/lib/operator/route-options.ts`).
- **HTTP/API routes:** answer turn/thread/share/Stop endpoints, business/registry/services APIs, inquiry and Customer Request APIs, sandbox/provider routes, storefront/import routes, notification/webhook routes, Stripe webhook, OAuth endpoints, discovery files, MCP, and well-known manifests are all file routes under `src/routes/` (the generated route graph is `src/routeTree.gen.ts`).
- **Agent/discovery surfaces:** `/mcp`, `/SKILL.md`, `/llms.txt`, `/robots.txt`, `/sitemap.xml`, `/.well-known/ucp`, `/.well-known/oauth-*`, `/.well-known/http-message-signatures-directory`, and `/$slug/ucp` are built by `src/modules/actions`, `src/modules/discovery`, and route handlers such as `src/routes/SKILL[.]md.ts` and `src/routes/[.]well-known/ucp.ts`.
- **Convex runtime:** `convex/schema.ts` is the durable schema root; `convex/http.ts` registers Convex HTTP actions (sandbox providers and retired V1 routing responses); `convex/_generated/` supplies generated API/server/data-model references. Function modules such as `convex/answerThreads.ts`, `convex/registry.ts`, `convex/customerRequestApplication.ts`, and `convex/capabilitySupplyOperations.ts` are deployed entry points.
- **CLI/evaluation:** `tools/ae/cli.ts` is the command-line entry, `eval/` contains tool-call/answer/engine/quality/parity harnesses, and `tests/` contains source, integration, browser, deploy-smoke, import-boundary, and contract suites.

## Error Handling

- The canonical error model is `ProblemDetails` with RFC 9457 fields plus canonical `kind` and stable `code` (`src/lib/errors.ts`). `src/lib/server/problem.ts` always emits `application/problem+json` with `Cache-Control: no-store`; route adapters map validation, method, auth, rate, source, and execution failures to this helper.
- Request boundaries fail closed before side effects: method guards cover unsupported verbs, `readBoundedRequestJson` caps bodies, Zod schemas validate route/action inputs, and rate admission runs before answer reservation (`src/lib/server/method-guard.ts`, `src/lib/server/bounded-request-body.ts`, `src/routes/api.answer.turn.ts`).
- Answer failures use an allowlisted/redacted `AnswerTurnProblem` vocabulary. The server emits typed stream errors and persists terminal problem JSON; browser transport distinguishes problem responses, malformed SSE, missing streams, network errors, and aborts (`src/modules/answer/answer-ui-stream.ts`, `src/components/ae/chat/answer-stream.ts`). Durable readback remains terminal truth.
- Convex source failures are typed as `ConvexSourceError` and mapped to safe HTTP or CLI failures without exposing arbitrary backend payloads (`src/lib/server/convex-source.ts`, `src/routes/api.answer.turn.ts`, `tools/ae/lib/output.ts`). Convex functions use `convex/values` validators and return discriminated outcomes for expected refusal/conflict states (`convex/answerThreads.ts`, `convex/customerRequestRouteExecution.ts`).
- Capability and transport failures are results, not model-success exceptions: `operation-execute.functions.ts` returns `ok`, `refused`, or `error`; route transport preserves partial/unknown/payment/reconciliation observations; gates reject unsupported or ungrounded answer content (`src/modules/capability-execution/operation-execute.functions.ts`, `src/modules/capability-supply/route-transport-runtime.ts`, `src/modules/answer/internal/answer-gate.ts`).
- React route errors use dedicated pending/error shells and the root observability boundary (`src/components/ae/layout/AeOperatorRouteStates.tsx`, `src/components/ae/feedback/AeObservabilityErrorBoundary.tsx`). Private route failures conceal existence and redact customer/provider details (`src/modules/answer-thread/internal/public-projection.ts`, `src/lib/observability/private-route-safety.ts`).

## Cross-Cutting Concerns

- **Identity and authorization:** Clerk middleware and server-session gates protect sign-in/claim/operator paths (`src/start.ts`, `src/lib/server/require-clerk-server-session.ts`). Anonymous answer ownership is a long-lived, HTTP-only `ae_session` cookie (`src/modules/answer-thread/internal/session-cookie.ts`); Convex re-checks session/actor identity (`convex/authz.ts`, `convex/answerThreads.ts`). Admin membership, Customer Request bearer scopes, MCP tier/mode, share HMAC tokens, and signed browser guest assertions are separate authority mechanisms (`convex/security.ts`, `src/lib/server/customer-request-agent-auth.ts`, `src/lib/server/mcp-api.ts`, `src/modules/answer-thread/internal/share-token.ts`, `src/lib/server/browser-guest-session.ts`).
- **Write admission and idempotency:** source-write middleware captures method/origin/path/body digest for server functions, `src/modules/security/source-write-admission.ts` signs/validates operation scope, and `convex/sourceWriteAdmission.ts` consumes nonces. Answer reservations, catalog revisions, Customer Request revisions, work-tree generations, and action invocation attempts all fence writes with digests/expected versions (`src/modules/answer-thread/internal/turn-digests.ts`, `src/modules/work-tree/internal/`, `src/modules/action-invocation/`).
- **Bounds and network safety:** bounded request/body parsers, answer/tool caps, exact JSON-schema depth/node limits, operation endpoint validation, DNS/private-target checks, timeout/redirect policies, and upstream response limits are distributed across `src/lib/server/bounded-request-body.ts`, `src/modules/capability-contract/public.ts`, `src/modules/network-guard/public.ts`, and `src/modules/capability-execution/operation-execute.functions.ts`.
- **Integrity and evidence:** canonical digests, source hashes, contract refs, operation refs, result hashes, audit events, harness journals, and payment/reconciliation evidence prevent a model/provider response from silently becoming authority (`src/modules/common/canonical-digest.ts`, `src/modules/observability/public.ts`, `src/modules/harness/`, `src/modules/action-invocation/`). Public projections deliberately omit credentials, raw prompts, private hashes, and unverified claims (`src/modules/answer-thread/internal/public-projection.ts`, `src/modules/discovery/public.ts`).
- **Observability:** request middleware isolates Sentry and flushes PostHog server events (`src/start.ts`, `src/lib/observability/sentry.server.ts`, `src/lib/observability/posthog.server.ts`); client boot/error boundaries and funnel/event modules instrument browser journeys (`src/lib/observability/boot-client-observability.ts`, `src/lib/observability/capture-client-events.ts`, `src/lib/observability/funnel-client.ts`). Observability is additive and cannot become domain evidence.
- **Scheduling and recovery:** Convex crons schedule readiness and cleanup (`convex/crons.ts`); Convex Workflow/Workpool/worker modules own waits, dispatch, retry, cancellation, and durable recovery (`convex/projectSpine.ts`, `convex/customerRequestRouteWorkpool.ts`, `convex/customerRequestRouteTransportWorker.ts`). Domain journals, release fences, reconciliation, and readbacks remain authoritative over scheduler status (`convex/customerRequestRouteExecution.ts`, `src/modules/action-invocation/`).
- **Bundle and deployment isolation:** server-only Convex/Clerk/Graphology paths are dynamically imported from browser-reachable server functions such as `src/modules/work-tree/human-root.functions.ts`; the route bundle safety contract prevents those imports from leaking into client code (`tests/unit/routes/route-client-bundle-safety.test.ts`). Vite/Nitro/Sentry settings are centralized in `vite.config.ts`, while runtime output is deployment-specific.
