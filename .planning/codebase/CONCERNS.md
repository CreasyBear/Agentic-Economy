# Codebase Concerns

**Analysis Date:** 2026-07-06

## Executive Risk Summary

The fresh Agentic Economy repo is much cleaner than the old source-mine, but it still carries launch-critical proof gates and a few high-leverage engineering risks:

1. The active 14-day bootstrap gate is still open; public shipment remains blocked by real evidence, not source-local code completion.
2. CI currently references a missing `test:ui-contract` script, so the eval gate cannot be trusted until the workflow/package drift is fixed.
3. Several Convex runtime paths still use broad `.collect()` loaders despite generated Convex guidance warning that unbounded collections become performance and transaction-limit risks.
4. Route/API surfaces for future or later-phase capabilities are present in the active route tree; copy/tests must continue to prevent public readiness, payment, booking, autonomous-action, and provider-proof overclaims.
5. Astryx is the current UI authority, but legacy `Ae*` presentation components and retiring CSS still exist, so UI work can accidentally extend the old system.

## Active Product / Launch Blockers

### 14-day bootstrap gate remains open

**Evidence**
- `.planning/STATE.md` marks `status: active_gate_with_open_blockers` and names the active gate as `.planning/scopes/scope-14day-bootstrap-gate/`.
- `.planning/STATE.md` requires 30-50 source-backed profiles, 10 recruited providers, 100 attributable sessions, at least 10 qualified inquiries, at least 5 voluntary provider corrections/listing requests, and zero boundary overclaim before public shipment of later platform rungs.

**Risk**
- Source/local tests can pass while the product still lacks deployed/provider/customer evidence.
- Marketing, assistant answers, route copy, or documentation can drift into claims the evidence gate has not earned.

**Safe handling**
- Treat source-local proof as necessary but insufficient.
- Keep deployed smoke, provider smoke, outside-in assistant audit, and evidence-ledger requirements explicit in closeouts.
- Do not claim production marketplace, payment, booking, autonomous fulfillment, or broad agent runtime readiness from local tests.

### Phase 6 remains source/local proof unless deployed provider evidence exists

**Evidence**
- `.planning/STATE.md` records Phase 6 as closed as source/local proof only and says production/deployed claims need real provider-smoke evidence.
- `package.json` has fail-loud provider smoke commands: `test:provider-smoke:business-action-stripe`, `test:provider-smoke:autumn-stripe`, `test:provider-smoke:resend`, `test:provider-smoke:novu`, and `test:provider-smoke:capability-check`.
- Deploy smoke tests live under `tests/deploy-smoke/*.spec.ts` and use `playwright.deploy-smoke.config.ts`, which does not start a local server.

**Risk**
- A local/test-mode Stripe or notification result can be mistaken for production money/provider proof.
- Public copy can imply paid activation, settlement, autonomous business action, or provider delivery before deployed readbacks exist.

**Safe handling**
- Keep Phase 6/public payment/business-action language proposal-only unless a real deployed provider readback is attached.
- Keep provider smoke tests failing loudly when required env/operation/provider inputs are absent.

## Build and CI Concerns

### CI eval workflow references a missing script

**Evidence**
- `.github/workflows/eval-gate.yml` runs `npm run test:ui-contract` in the "Copy + SEO + UI contract + import/source scans" step.
- `package.json` does not declare `test:ui-contract`.
- `tests/ui-contract/` is absent in this checkout.

**Impact**
- The GitHub eval gate will fail or be bypassed depending on CI behavior; either outcome makes the CI signal misleading.

**Fix approach**
- Either restore a `test:ui-contract` script and matching tests, or remove that command from `.github/workflows/eval-gate.yml` and move the intended checks into existing copy/SEO/import/TS guardrails.
- Update `.planning/codebase/TESTING.md` and release instructions after fixing the drift.

### Fast-moving runtime stack needs pinned upgrade discipline

**Evidence**
- Runtime dependencies include `@tanstack/react-start` `1.168.26`, `@tanstack/react-router` `1.170.16`, React `19.2.7`, Vite `8.1.0`, TypeScript `6.0.3`, Convex `1.42.0`, and Nitro nightly via `nitro: npm:nitro-nightly@^3.0.1-20260628-090458-3df69609` in `package.json`.
- `src/routeTree.gen.ts` is generated by TanStack Router and is large enough to hide unrelated churn.

**Impact**
- Upgrades can break SSR, route generation, server functions, generated Convex contracts, and Playwright dev-server behavior together.

**Safe handling**
- Keep runtime upgrades in dedicated maintenance changes.
- Run route generation, focused route tests, `npm run typecheck`, `npm run check:convex-codegen`, and browser smoke before merging runtime upgrades.

## Performance / Scale Concerns

### Broad Convex loaders remain in hot paths

**Evidence**
- Convex generated guidance in `convex/_generated/ai/guidelines.md` warns against unbounded `.collect()` and recommends `.take()`, pagination, indexes, or async iteration.
- Current `.collect()` usage exists in `convex/source_state.ts`, `convex/inquiries.ts`, `convex/notificationOutbox.ts`, `convex/billingStore.ts`, `convex/registry.ts`, `convex/discovery.ts`, `convex/catalog.ts`, `convex/businessActionStore.ts`, `convex/protectedActionStore.ts`, and `convex/observability.ts`.
- Examples include whole-table helper patterns such as `collect(db, tableName)` in `convex/source_state.ts`, `convex/inquiries.ts`, `convex/notificationOutbox.ts`, and `convex/billingStore.ts`.

**Impact**
- Read sets, transaction time, memory, and write-conflict surface grow with catalog size, inquiry history, notification rows, billing operations, and audit/projection rows.
- Unit tests can stay green until production data crosses Convex transaction or response limits.

**Fix approach**
- Replace whole-domain loaders with indexed slice readers by business id, owner id, thread id, operation id, dispatch id, or projection key.
- Use `.take(n)` plus scheduled continuation for cleanup/bulk work.
- Materialize public registry/discovery read models and keep admin diagnostics paginated.
- Add scale-shape tests or budget assertions for owner inbox, registry search/detail, discovery generation, notification outbox, and billing lookups.

### Public discovery and registry paths still need projection-first discipline

**Evidence**
- Registry/discovery code uses indexed reads in places, but `convex/registry.ts`, `convex/catalog.ts`, and `convex/discovery.ts` still perform per-business hydration and some full-status collection.
- `.planning/STATE.md` keeps public discovery/search/API in the active product slice.

**Impact**
- Public routes can become slow or hit Convex limits as source-backed profiles and services increase.
- Assistant and SEO surfaces rely on the same public truth, so projection drift affects both humans and agents.

**Fix approach**
- Make `registryProjectionItems` / `registrySearchDocuments` style projection tables the primary public read path.
- Treat direct hydration as admin/repair-only where possible.
- Add freshness/read-budget tests around projection rebuild and public route reads.

## Security and Reliability Concerns

### Storefront import SSRF surface must stay centralized

**Evidence**
- `POST /api/storefront/import-draft` in `src/routes/api.storefront.import-draft.ts` reads a bounded request body and calls `storefrontImportDraftAction`.
- `src/modules/storefront/internal/network-guard.ts` normalizes hostnames, blocks localhost/local, rejects private/special IPv4 and IPv6 ranges, vets DNS lookup results, and provides a guarded lookup function.
- `.planning/SECURITY-SPEC.md` now documents the storefront import fetch surface and SSRF quarantine.

**Impact**
- The implementation is guarded, but future owner-supplied URL fetches can bypass the shared guard if contributors copy only the import action shape.

**Safe handling**
- Keep every owner/user-supplied fetch behind `network-guard.ts`.
- Add drift tests that fail when a new server-side fetch route lacks SSRF documentation and guard usage.
- Log denied reasons without leaking target internals.

### Agent tools write boundary is high leverage

**Evidence**
- `src/routes/api.agent.tools.ts` lists and invokes quiet agent tools.
- The POST handler now enforces content length and `readBoundedRequestText` before JSON parse, validates strict schemas, verifies Web Bot Auth identity, records identity for audit, and requires source-owned write admission before write-tier tools run.
- Write tool scopes are declared in `WRITE_TOOL_SCOPES` for `inquiry.submit` and `businessAction.requestCapability`.

**Impact**
- A small allowlist or admission mistake can expose a write-capable action to the agent surface.

**Safe handling**
- Add direct allowlist tests for every `agentTools` surface entry: read-only tools stay read-only, write tools require signature plus source-write admission, and unknown write tools are refused.
- Keep body caps and schema max lengths near route/action boundaries.

### Local E2E auth bypass is centralized but still client-named

**Evidence**
- Server-side checks use `src/lib/server/local-e2e-bypass.ts`, which throws if `VITE_AE_DISABLE_CLERK_FOR_LOCAL_E2E` is enabled in production.
- `playwright.config.ts` sets `VITE_AE_DISABLE_CLERK_FOR_LOCAL_E2E=true` for local E2E runs.
- The helper explains that `src/routes/__root.tsx` must mirror the semantics client-side instead of importing the server helper.

**Impact**
- The helper fixes the old duplicated server reads, but the `VITE_` prefix still suggests a browser-exposed variable and can confuse future server code.

**Fix approach**
- Consider splitting server and client names when the next auth/test harness maintenance pass happens.
- Keep tests that prove production refuses the bypass independently of app startup order.

## Architecture / Maintainability Concerns

### Later-phase routes are present in the active route tree

**Evidence**
- `src/routeTree.gen.ts` includes owner/admin/action/billing/business-action routes such as `_operator/owner.actions`, `_operator/owner.billing`, `_operator/admin.monetization`, `_operator/owner.business-actions`, and business-action/billing API routes.
- `.planning/STATE.md` says active public shipment is blocked by the 14-day bootstrap gate and warns against future platform overclaims.

**Impact**
- Route existence can be mistaken for public readiness or production proof.
- Generated route churn can hide accidental exposure changes.

**Safe handling**
- Keep route-level copy precise: owner/admin/source-local/test-mode when that is the real state.
- Keep public sitemap/navigation exposing only surfaces that have earned the active gate.
- Add generated route freshness and route-exposure guardrails if route churn continues.

### Astryx migration still coexists with legacy UI

**Evidence**
- `DESIGN.md` states Astryx is the visual/UI authority and the previous `Ae*` component system plus handwritten CSS are retired.
- Existing docs/source still reference `src/components/ae/**`, `src/styles/legacy.css`, `src/styles/tokens.css`, and `src/styles/base.css` as migration/legacy areas.
- `src/routes/__root.tsx` wires Astryx providers; `src/components/astryx/RouterLink.tsx` is the TanStack/Astryx navigation adapter.

**Impact**
- New UI work can extend the retired Daylight-era component/token system.
- Legacy CSS can mask Astryx regressions and make visual bugs hard to attribute.

**Fix approach**
- Route new UI through Astryx primitives or `src/components/astryx/*` adapters.
- Treat `src/components/ae/*` as behavior/project adapters only while migrating surfaces away from bespoke presentation.
- Shrink legacy CSS opportunistically with route migrations; do not add new CSS files.

### Action registration is manual and sensitive

**Evidence**
- Actions are registered in `src/modules/actions/index.ts` and exposed through contracts consumed by `src/routes/api.agent.tools.ts`.
- The agent endpoint filters quiet agent tool contracts before listing or invoking tools.

**Impact**
- A new action with the wrong `surfaces`, `tier`, schema, or boundary copy can become agent-visible or write-capable unintentionally.

**Fix approach**
- Require tests for action registry changes that assert visibility, tier, strict input/output schemas, and copy boundaries.
- Keep action summaries and boundaries free of unsupported booking/payment/autonomy claims.

## Test Coverage Gaps

### Missing UI contract gate

**What's missing**
- The workflow expects a UI contract suite, but the script/directory are not present.

**Risk**
- Visual/token/copy guardrails may be assumed by CI without actually running.

**Priority**
- High, because it affects the reliability of every PR gate.

### Scale-shape tests for Convex loaders

**What's missing**
- Tests that exercise owner inbox, public registry, discovery, notification outbox, billing, and business-action paths with large table counts and assert bounded reads/pagination/projection usage.

**Risk**
- Convex limit failures surface late, under real data.

**Priority**
- High before increasing profile/inquiry volume during the 14-day gate.

### Agent tool allowlist/admission matrix

**What's missing**
- A direct matrix asserting each quiet agent tool's surface, tier, write-scope requirement, unsigned behavior, refused behavior, and successful admitted path.

**Risk**
- A registry/action change can quietly expose a write or overclaiming descriptor.

**Priority**
- High for agent-facing surfaces.

### Deployed/provider smoke artifact discipline

**What's missing**
- A single easy-to-audit evidence index tying each provider smoke command to its latest successful deployed artifact and source-owned readback.

**Risk**
- Source/local green checks get mistaken for production proof.

**Priority**
- Medium-high while bootstrap gate blockers remain open.

## Recently Resolved / Do Not Reopen as Open Concerns

- **Agent tools request body cap:** `src/routes/api.agent.tools.ts` now checks `content-length` and uses `readBoundedRequestText` with `MAX_AGENT_TOOL_BODY_BYTES` before JSON parse/digest.
- **Source-write nonce cleanup:** `convex/sourceWriteAdmission.ts` defines `cleanupExpiredSourceWriteNonces`, and `convex/crons.ts` schedules it hourly.
- **Server-side local E2E bypass centralization:** `src/lib/server/local-e2e-bypass.ts` is the canonical server helper and refuses production.
- **Storefront SSRF documentation drift:** `.planning/SECURITY-SPEC.md` now documents the live storefront import fetch surface and quarantine controls.
