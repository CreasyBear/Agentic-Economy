# Codebase Concerns
**Analysis Date:** 2026-08-11

## Tech Debt
- **P1 — Owner-supply projection is a second registry read model (risk).** `convex/capabilitySupplyOwnerFunnel.ts:247-458` independently joins offerings, revisions, access paths, publications, bindings, provider connections, call events, pricing, lifecycle, readiness, and routeability. Its comments explicitly preserve a separate selection rule from the catalog path. Any change to publication/currentness or lifecycle semantics must be kept in sync across owner and public projections. The current mitigation is bounded reads plus revision, source-hash, digest, and routeability checks. Replace the parallel assembly with one internal canonical projection/read model and derive the owner view from it without weakening owner authorization.
- **P2 — Answer discovery and execution are coupled across multiple dynamic seams (debt).** `src/modules/answer/internal/keyless-data-ask.ts:236-396` rebinds registry refs and filters executable descriptors, while `src/modules/answer/internal/answer-tool-use-agent.ts:399-435` and `:840-1025` separately compose, execute, and record those descriptors. A descriptor/schema change therefore crosses discovery, tool construction, execution, and prose evidence code. The current mitigation is fail-closed descriptor validation. Keep one typed descriptor-to-tool boundary and make rejected-descriptor reasons observable rather than duplicating compatibility rules.

## Known Bugs
- **P1 — A curated operation can be discoverable but not executable (verified source defect).** `src/modules/capability-supply/curated-cluster-a-publications.ts:440-454` describes the Wikipedia summary operation as a URL path-segment request and declares redirect behavior. `src/modules/capability-execution/operation-execute.functions.ts:80-123` only admits the generic keyless HTTP-JSON GET shape and refuses unsupported transport/input shapes. The observable failure is an `operation_not_executable` refusal after discovery, so an answer can identify the operation without returning the requested page result. The refusal is the current safety mitigation. Either implement bounded path-template/redirect handling in the executor and its admission contract, or mark this publication non-executable and exclude it from answer tool candidates.

## Security Considerations
- **P1 — Convex source-write verification does not bind the envelope to an HTTP request (risk, not reproduced).** `convex/sourceWriteAdmission.ts:46-86` calls `verifySourceWriteAdmission` with scope, operation key, and correlation ID but no `request`; `src/modules/security/source-write-admission.ts:192-245` makes request binding optional. A trusted server caller that forwards a valid signed envelope to the wrong method/path/body could therefore pass the Convex boundary unless its operation key prevents the replay. Current callers such as `src/lib/server/operation-invoke-api.ts:66-76` construct the signature from the actual request and body. Thread the expected request binding through the internal mutation or enforce a route-specific operation-key derivation at the receiving boundary, then cover replay/mismatch cases.
- **P2 — Unauthenticated rate-limit buckets can trust spoofable forwarding headers (risk).** `src/lib/server/rate-limit.ts:94-108` falls back to `cf-connecting-ip`, `x-real-ip`, and the first `x-forwarded-for` value when no principal/session exists. If the edge does not overwrite these headers, a caller can rotate the apparent IP and evade the bucket. Principal and session identifiers are preferred, and operation invocation also has a Convex grant-level rate gate in `convex/capabilityOperationInvocations.ts:458-470`. Make the edge-trusted client address explicit (or ignore forwarding headers outside a trusted adapter) and retain a conservative shared fallback bucket.
- **P2 — Local E2E bypass short-circuits every HTTP rate admission (configuration risk).** `src/lib/server/rate-limit.ts:49-53` returns `{ ok: true }` whenever `isLocalE2EAuthBypassEnabled()` is enabled. `.env.example:86-90` exposes local-smoke bypass controls. The helper is intended for local use, but an accidental production configuration removes this abuse-control layer. Keep the production guard fail-closed and add startup/deployment validation that rejects bypass settings outside an explicitly local environment.

## Performance Bottlenecks
- **P1 — Owner funnel read fan-out grows with publication count (risk).** `convex/capabilitySupplyOwnerFunnel.ts:247-275` performs six bounded base queries, then issues one provider-connection query and one binding query per publication. The subsequent `:276-458` mapping repeatedly scans revisions, paths, publications, and events for each offering. The caps (`50`, `100`, `50`) prevent unbounded reads but do not prevent high latency or a large query count near those caps. Replace the per-publication lookups with indexed batch reads or a maintained owner projection, and measure query count/latency at the caps.
- **P2 — Dynamic answer turns repeat descriptor work (risk).** `src/modules/answer/internal/keyless-data-ask.ts:336-396` resolves descriptors and filters up to `MAX_CANDIDATES = 5`; `src/modules/answer/internal/answer-tool-use-agent.ts:399-435` then reuses that data to build dynamic tools for the model loop. Repeated turns can re-read the same registry data and rebuild equivalent closures. The candidate bound is the current mitigation. Memoize one descriptor snapshot per turn (and batch reads by operation ref) while preserving current publication/revision checks.

## Fragile Areas
- **P1 — Strict-schema filtering can silently remove an otherwise admitted capability (risk).** `src/modules/answer/internal/keyless-data-ask.ts:381-386` drops a descriptor when `findStrictToolSchemaViolation` or `isKeylessCapabilityCompatible` fails; `:389-395` only sets `selected` when exactly one candidate remains. A schema or input-shape change can turn a previously routable query into the generic unavailable prose in `src/modules/answer/internal/answer-tool-use-agent.ts:679-695`. Fail-closed behavior is correct for safety, but emit a bounded rejection reason/metric and add a seed-time schema compatibility gate so this degrades visibly rather than silently.
- **P2 — Invocation correctness depends on serialized operation snapshots and repeated digest comparisons (risk).** `convex/capabilityOperationInvocations.ts:1144-1165` parses a stored `operationJson` and maps parse/materialization failures to unsupported or unavailable states; `src/modules/capability-execution/operation-invoke.ts:592-617` then compares publication, revision, contract, transport, and input validity before reservation/dispatch. Publication refreshes are intentionally refused, but malformed or stale snapshots can strand work in pending/reconciliation paths. Existing digest checks and explicit reconciliation states are the mitigation. Keep the snapshot immutable and add bounded cleanup/alerting for rows that remain unreconciled past grant expiry.

## Scaling Limits
- **P1 — Source-write nonce cleanup is batch-chained maintenance.** `convex/sourceWriteAdmission.ts:201-231` deletes at most `SOURCE_WRITE_NONCE_CLEANUP_MAX_BATCH_SIZE = 500` rows per mutation and schedules another mutation whenever the batch is full. A sustained source-write volume above cleanup throughput creates a growing maintenance backlog and extra scheduler work. The current bounded batch and indexed `by_expiresAt` query protect transaction size. Add backlog age/count telemetry and tune cadence or partition cleanup before increasing write volume.
- **P2 — Candidate selection is capped at five operations.** `src/modules/answer/internal/keyless-data-ask.ts:333-386` hard-limits `MAX_CANDIDATES` to 5 and does not select automatically when multiple compatible candidates remain. As the registry grows, common queries can lose the intended operation or force a model choice among a truncated set. The cap is a prompt/tool-size safeguard. Add deterministic ranking plus an explicit disambiguation path, or document and enforce a stable operation-class limit at admission.

## Dependencies at Risk
- **P1 — Production bundling depends on a nightly Nitro package.** `package.json` includes `npm:nitro-nightly@^3.0.1-20260628-090458-3df69609`, while `vite.config.ts:11` imports `nitro/vite` and `:82-94` selects the Vercel preset with Node 22 functions. A nightly transitive change can alter route generation or deployment output without a stable-release compatibility promise. The current mitigation is a checked-in Vite configuration and explicit `nodejs22.x` runtime. Replace the nightly package with a supported stable release, or pin the exact nightly and maintain a narrow deployment smoke gate.
- **P2 — Several fast-moving toolchain majors are coupled in one build graph.** `package.json` pins Vite 8, TypeScript 6, Vitest 4, Tailwind 4, and TanStack/Nitro/Sentry plugins together, and also carries Shiki override entries. Changes in compiler/module-resolution or plugin contracts can fail outside the package that changed. Keep the lockfile authoritative and upgrade one integration family at a time with the existing type/build gates.

## Missing Critical Features
- **P1 — Owner “test” cannot execute x402 operations.** `convex/capabilitySupplyOwnerSupply.ts:177-180` explicitly returns `operation_not_executable` for `sourceKind === 'x402'`; the surrounding action only probes the challenge and records a successful test event for non-x402 sources at `:181-228`. An owner can admit and assess readiness for a paid provider operation but cannot complete the same fresh-operation test workflow. The explicit refusal avoids pretending a payment occurred. Add a payer-authorized x402 test/settlement path with durable evidence, or expose x402 as readiness-only with a distinct lifecycle step instead of presenting a universal test step.
- **P2 — Ambiguous natural-language capability requests have no typed clarification contract.** `src/modules/answer/internal/keyless-data-ask.ts:389-395` leaves `selected` undefined when more than one candidate survives, and `src/modules/answer/internal/answer-tool-use-agent.ts:679-695` falls back to unavailable prose when recovery still has no candidates. The current model tool loop can choose among the bounded candidates, but there is no deterministic user-facing question when candidates are equivalent. Add a bounded clarification result carrying the candidate operation refs and required disambiguating field.

## Test Coverage Gaps
- **P1 — Source-write request-binding coverage stops short of the Convex boundary.** The pure verifier contract is in `src/modules/security/source-write-admission.ts:192-245`, while the Convex adapter in `convex/sourceWriteAdmission.ts:46-86` omits `expected.request`. Add an integration test that submits a validly signed admission with a mismatched route/body to each protected mutation, and assert the intended operation-key/request-binding invariant rather than only testing HMAC/signature outcomes.
- **P1 — Curated transport incompatibility needs an end-to-end regression.** The Wikipedia path-segment/redirect declaration in `src/modules/capability-supply/curated-cluster-a-publications.ts:440-454` and the generic executor refusal in `src/modules/capability-execution/operation-execute.functions.ts:80-123` are separately typed seams. Add a test from curated publication through descriptor listing and execution that either proves supported path/redirect behavior or asserts the operation is filtered as non-executable; this must prevent discoverable-but-unrunnable operations from entering the answer toolset.
- **P2 — Live-registry answer coverage is narrower than fixture coverage.** Answer tests such as `tests/eval/answer-pipeline.test.ts:612-616` inject `seedKeylessExecutableSource`, while the production path uses `convexKeylessExecutableSource` in `src/modules/answer/internal/answer-tool-use-agent.ts:399-404`. Add a deployment-independent contract test for the production source adapter's bounded list/read/search behavior, including zero, one, and multiple candidates, without asserting catalog text as an execution result.
