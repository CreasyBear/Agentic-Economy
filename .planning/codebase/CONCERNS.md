# Codebase Concerns
**Analysis Date:** 2026-08-12

The source tree is currently reported as source-complete and locally verified, but it is not hosted-certified: `.planning/PROJECT.md:116-135` and `.planning/STATE.md:231-238` both keep that proof ceiling, and `output/release/` contains no strict hosted gateway receipt. The concerns below do not turn local fixtures or source checks into hosted, provider, customer, or live-money evidence.

## Tech Debt

- **Planning/status authority has drifted from the current operation API.** Evidence: `.planning/ROADMAP.md:181-187` still says there is no inspect-only comparison action or agent comparison route, while `src/modules/registry/operations.actions.ts:62-70` registers `registry.operations.compare` and `src/routes/api.v1.market-operations.compare.ts:18-65` implements the bounded namespaced HTTP route. Impact: maintainers can re-open completed work or build against the retired `/api/compare` wording. Remediation: reconcile the roadmap/state requirements with the current namespaced contract, explicitly label superseded requirements, and retain one current status authority.

- **Several runtime authorities remain very large orchestration modules.** Evidence from the current tree: `convex/moneyLedger.ts` is 6,793 lines, `src/modules/answer/internal/answer-tool-use-agent.ts` is 2,546, `convex/capabilityOperationInvocationWorker.ts` is 2,146, and `convex/capabilitySupplyOwnerFunnel.ts` is 2,105. Impact: [INFERENCE] changes to money, answer recovery, invocation workers, or owner supply have unusually large review and regression surfaces. Remediation: extract only bounded policy/read/write seams with the existing canonical state owners, then add contract tests at each seam; do not introduce a second ledger, queue, or state machine.

## Known Bugs

- **Readiness refresh can enqueue duplicate probes.** Evidence: the cron in `convex/crons.ts:7-11` runs every minute; `convex/capabilitySupply.ts:1078-1079,1244-1261` selects up to 20 due publications and immediately calls `ctx.scheduler.runAfter(0, ...)` without claiming a row; `convex/capabilitySupplyReadiness.ts:82-151` has no durable pending/in-flight lease. This conflicts with the one-pending/one-in-flight requirement in `.planning/adr/ADR-029-capability-publication-provenance-readiness.md:126-129`. Impact: [INFERENCE] a slow or repeatedly failing probe remains due and can be scheduled again on each tick, multiplying outbound requests and scheduler work. Remediation: atomically claim a publication by revision/target digest before scheduling, persist bounded pending/in-flight state, clear it on every terminal probe result, and test overlapping cron ticks and missing/failed work.

## Security Considerations

- **Production security and custody controls have source gates but no deployment proof.** Evidence: `src/lib/deployment/manifest.ts:52-85` requires canonical/Convex auth, Clerk, OpenRouter, seven source-write families, x402 custody, Stripe, and a separate live-gateway smoke configuration; `.planning/STATE.md:94-109,231-238` says the local/source gates passed but no strict hosted receipt or live-money block exists. Impact: source review demonstrates intended fail-closed behavior, not that the deployed revision used the expected secret custody, revocation, source-write authority, provider call, or money readback. Remediation: run the exact configured hosted receipt against a revision-bound deployment, independently parse its digest/readback, and keep certification blocked when any authority or custody prerequisite is absent; do not add a production bypass.

## Performance Bottlenecks

- **Dynamic keyless catalog construction is read-amplifying.** Evidence: `convex/capabilitySupplyOperations.ts:771-817` reads up to 512 publications, then performs per-publication offering, binding, business, contract, and qualification reads; `src/modules/capability-execution/operation-execute.actions.ts:124-134` consumes the complete returned array for every source listing. Impact: [INFERENCE] catalog growth can push answer/CLI discovery latency and Convex read/transaction limits before the current small curated catalog makes the cost visible. Remediation: materialize or incrementally maintain an eligible keyless descriptor projection using the existing qualification authority, or paginate bounded listing and make overflow explicit.

- **Owner provider-connection readback fans out many bounded queries in parallel.** Evidence: `convex/capabilityProviderConnections.ts:1104-1124` reads up to 50 businesses and runs five lifecycle-index queries per business, each taking up to 100 rows. Impact: [INFERENCE] an owner with many businesses/connections can approach Convex read and latency limits and make the operator console slow even though every individual query is capped. Remediation: paginate the owner surface and query a single owner-scoped/indexed connection feed (or a maintained owner projection) rather than issuing 250 lifecycle queries per refresh.

## Fragile Areas

- **Hosted runtime versions are inconsistent.** Evidence: `.nvmrc:1`, `package.json:169-172`, `vite.config.ts:77-94`, and `src/lib/deployment/manifest.ts:21,183-185,217-218` require Node 22/`nodejs22.x`, but `.vercel/project.json:5-15` configures Vercel `nodeVersion: "24.x"`. Impact: [INFERENCE] hosted build/runtime behavior and manifest validation can diverge from local and CI assumptions, blocking or invalidating exact-revision proof. Remediation: align the Vercel project setting with Node 22 before hosted certification, then verify the deployed readback reports the same runtime.

- **Hosted smoke configuration is split between the manifest, template, and workflow.** Evidence: `src/lib/deployment/manifest.ts:63-85` requires `AE_GATEWAY_SMOKE_RELEASE_API_KEY` and owner OpenAPI document/path/method variables; `.env.example:63-86` does not list them, while `.github/workflows/kernel-release-gate.yml:324-339` injects them only in CI. Impact: [INFERENCE] an operator following the repository template cannot reproduce or audit the production smoke inputs, making missing configuration look like an unavailable provider rather than a setup error. Remediation: make `.env.example`, manifest names, workflow inputs, and the hosted runbook one exact table, without placing secret values in the template.

## Scaling Limits

- **The dynamic keyless descriptor list silently truncates at 512 publications.** Evidence: `convex/capabilitySupplyOperations.ts:751-773` returns a bare array and `.take(512)` with no overflow marker; `src/modules/capability-execution/operation-execute.actions.ts:124-134` treats the array as complete. Impact: [INFERENCE] once current publications exceed 512, eligible operations after the cap disappear from the Answer/CLI tool catalog without a `hasMore` or capacity refusal. Remediation: use a cursor/paginated source or fetch `MAX+1` and return a typed capacity result; preserve deterministic qualification and never present an incomplete catalog as complete.

- **Owner connection listing has hard caps with no continuation surface.** Evidence: `convex/capabilityProviderConnections.ts:1113-1124` caps businesses at 50 and each lifecycle at 100, then returns one flattened array; `listOwner` has no pagination argument or `hasMore` result. Impact: [INFERENCE] larger owners can receive incomplete connection state and miss revocation/cleanup attention. Remediation: expose bounded cursor pagination or a server-owned owner summary with explicit overflow/attention counts before treating the list as exhaustive.

## Dependencies at Risk

- **Production build depends on a prerelease Nitro nightly.** Evidence: `package.json:149-157` aliases `nitro` to `nitro-nightly@^3.0.1-20260628-090458-3df69609`, and `package-lock.json:20263-20268` locks that nightly build. Impact: [INFERENCE] framework/runtime changes outside normal stable-release guarantees can affect the Vercel adapter or hosted proof, especially alongside the Node 22/24 mismatch. Remediation: pin a supported stable Nitro release, or record and verify the exact nightly against the aligned Node 22 hosted runtime before certification.

## Missing Critical Features

- **There is no exact-revision hosted gateway/live-money evidence packet yet.** Evidence: `src/lib/deployment/manifest.ts:63-85` defines the required smoke identity and spend inputs, but `output/release/` has no strict operation-gateway receipt; `.planning/STATE.md:231-238` and `.planning/research/2026-08-11-goblin-source-remediation-plan.md:626-639` explicitly keep hosted certification blocked. Impact: the product cannot claim hosted provider fulfilment, exact usage/metering, Stripe top-up/charge/payout conservation, or revocation replay. Remediation: provision the production authorities and approved fixtures, run the hard-capped exact-revision gateway plus live-money block, independently validate the immutable receipt, and retain the source-complete/hosted-uncertified distinction until it passes.

- **The public human URL-shortlist/dedicated accessible comparison loop is still incomplete.** Evidence: `.planning/ROADMAP.md:160-168,181-187` records the remaining URL-shortlist and dedicated comparison requirement; current source has the Answer shortlist (`src/components/ae/chat/AeShortlistTerminal.tsx`) and the namespaced API compare route (`src/routes/api.v1.market-operations.compare.ts`), but no separate human comparison route in `src/routes/`. Impact: [INFERENCE] visitors who do not use the Answer thread or API lack a durable, linkable comparison destination. Remediation: add a route only if this remains in the current product authority, reusing the existing comparison projection and validators; otherwise retire the stale requirement instead of leaving contradictory roadmap text.

- **Observed external x402 listings are catalog-only, not fulfillable supply.** Evidence: `src/modules/capability-supply/curated-cluster-c-publications.ts:6-13,89-112` explicitly marks the Cluster C listings `not_available_yet`, says AE does not execute/pay them, and keeps them out of keyless execution. Impact: [INFERENCE] discovery can show more supply than AE can currently deliver, and no paid external x402 value exchange is available for those listings. Remediation: establish a real provider connection and payment-custody contract, readiness/conformance evidence, and hosted execution/readback before enabling any listing; otherwise keep the unavailable posture and copy explicit.

## Test Coverage Gaps

- **The release-source gate does not run the full answer/eval contract suite.** Evidence: `package.json:26-27` runs `test:eval:report` but omits `test:eval:coverage`, Promptfoo validation, and `vitest run tests/eval`; the broader path is present only in `package.json:47-50`, with shared-case parity assertions in `tests/eval/answer-pipeline.test.ts:75-91`. Impact: [INFERENCE] a release can have a green generated report while prompt/config coverage or shared-case parity has drifted. Remediation: add deterministic coverage and `tests/eval` checks to the release gate (keeping network-dependent evaluation separate when required).

- **The market CLI has a separate TypeScript project that the release gate never typechecks.** Evidence: root `tsconfig.json:33-43` excludes `tools/**`; `tools/tsconfig.json:1-8` includes only `ae/**/*.ts`; no `package.json` script invokes `tsc -p tools/tsconfig.json`, and CLI behavior is exercised by spawned tests such as `tests/unit/market-terminal/cli-errors.test.ts:88-116`. Impact: [INFERENCE] CLI source/import errors can ship while the main `npm run typecheck` and behavior tests remain green. Remediation: add a scoped `tools/ae` typecheck to the release gate or fold the supported tool project into the explicit release compilation set.

- **Readiness scheduler overlap is not covered by a regression test.** Evidence: `tests/imports/capability-supply-boundaries.test.ts:59-67` checks one-shot action wiring, and `tests/integration/capability-publication.test.ts:768-839` covers publication/readiness behavior, but no current test exercises two `scheduleDueCapabilityProbes` ticks before a probe records its result. Impact: [INFERENCE] the duplicate-probe bug can recur without a test failing. Remediation: add a deterministic delayed-probe/overlapping-cron test after introducing the claim/lease, including stale revision and retry cleanup.

- **Current Answer evaluation is fixture/contract-server proof with incomplete cost metadata.** Evidence: `output/eval/answer-suite-report.json:1-31` reports 13 cases/15 turns, one capability tool, and `price_table_missing`/`provider_metadata_missing`; `eval/answer/lib/cases.ts:1-8,605-647` labels the capability operation seed-only, and `eval/answer/lib/evaluators.ts:55-116` supplies a fixed response/contract-server path. Impact: [INFERENCE] a green report does not measure live supplier latency/cost or prove external execution, settlement, or provider resilience. Remediation: keep the fixture report labelled local/source evidence, populate price/provider metadata where cost is claimed, and add the exact hosted provider/money receipt as a separate proof class rather than upgrading this eval.

- **No hosted browser/provider/customer proof is present in the current release artifacts.** Evidence: `.planning/PROJECT.md:116-135` explicitly limits current evidence to source plus focused local tests and says no hosted autonomous execution, independently operated fulfilment, customer value, or production-safety claim follows; `output/release/` contains local test/build artifacts but no strict hosted gateway receipt. Impact: [INFERENCE] end-to-end deployment, provider, and demand failures can remain invisible despite green local gates. Remediation: run the approved exact-revision hosted lane with disposable run-owned fixtures, parse/read back the receipt independently, and treat provider/customer evidence as a separate gate from source completeness.
