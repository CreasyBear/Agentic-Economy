# Coding Conventions

**Analysis Date:** 2026-07-01

## Naming Patterns

**Files:**
- Use TanStack route file names under `src/routes/` that mirror route paths: `src/routes/$slug.tsx`, `src/routes/api.agent.tools.ts`, `src/routes/owner.inquiries.$threadId.tsx`, and `src/routes/robots[.]txt.ts`.
- Use PascalCase `Ae*` component files for product-owned UI under `src/components/ae/`, such as `src/components/ae/status/AeStatusBadge.tsx` and `src/components/ae/layout/AePublicShell.tsx`.
- Keep shadcn/radix primitive wrappers in lowercase files under `src/components/ui/`, such as `src/components/ui/button.tsx`.
- Use module seams under `src/modules/<module>/`: `public.ts` exports stable contracts, `internal/` owns private implementation, `<module>.functions.ts` owns TanStack server/source adapters, and `<module>.actions.ts` owns action declarations. Examples: `src/modules/inquiries/public.ts`, `src/modules/inquiries/internal/commands.ts`, `src/modules/inquiries/inquiry.functions.ts`, and `src/modules/inquiries/inquiry.actions.ts`.
- Keep Convex entry files at `convex/*.ts`, with storage helpers named by domain: `convex/inquiries.ts`, `convex/businessActionStore.ts`, and `convex/sourceWriteAdmission.ts`.
- Do not edit generated files directly. `src/routeTree.gen.ts` is generated by TanStack Router and says it is overwritten.

**Functions:**
- Use camelCase verb phrases for functions: `brandNonEmpty` in `src/modules/common/ids.ts`, `handleInvokeAgentTool` in `src/routes/api.agent.tools.ts`, and `submitPublicInquiryThroughSource` in `src/modules/inquiries/inquiry.functions.ts`.
- Use PascalCase for React components: `AeStatusBadge` in `src/components/ae/status/AeStatusBadge.tsx`, `AePublicShell` in `src/components/ae/layout/AePublicShell.tsx`, and `Button` in `src/components/ui/button.tsx`.
- Use `handle*Request` for route-testable HTTP handlers: `handleListAgentTools` and `handleInvokeAgentTool` in `src/routes/api.agent.tools.ts`, plus discovery handlers tested from `tests/integration/developer-discovery.test.ts`.
- Use `set*ForTests` and `reset*ForTests` for test seams that mutate module-level ports: `setPublicRegistrySourcePortForTests` in `src/modules/registry/registry.functions.ts`, `setAnswerToolUseAgentForTests` in `src/modules/answer/internal/answer-tool-use-agent.ts`, and `resetAnswerTurnGuardForTests` in `src/modules/answer-thread/internal/turn-guard.ts`.

**Variables:**
- Use camelCase for constants and local variables: `publicNavActiveProps` in `src/components/ae/layout/AePublicShell.tsx`, `sentryPluginEnabled` in `vite.config.ts`, and `submitPublicInquiryMutation` in `src/modules/inquiries/inquiry.functions.ts`.
- Use exact literal arrays with `Values` suffix for domain unions: `InquiryThreadStatusValues` from `src/modules/inquiries/public.ts`, `ClaimStatusValues` from `src/modules/business/public.ts`, and `AuditEventTypeValues` from `src/modules/observability/public.ts`.
- Use branded IDs for source-owned identifiers through `brandNonEmpty` in `src/modules/common/ids.ts`; tests should build IDs with helpers like `operationKey()` and `correlationId()` as in `tests/unit/inquiries/inquiry-flow.test.ts`.
- Use `localE2e*` prefixes for deterministic local E2E fixtures in runtime seams: `localE2eOwnerId`, `localE2eBusinessId`, and `createLocalE2eInquirySourceState` in `src/modules/inquiries/inquiry.functions.ts`.

**Types:**
- Use PascalCase types and `*Result`, `*Command`, `*Record`, `*Readback`, and `*SourceState` suffixes: `SubmitInquiryCommand`, `OwnerInboxReadback`, and `InquirySourceState` in `src/modules/inquiries/public.ts`.
- Use discriminated unions keyed by `kind` for result contracts. Examples appear in `src/modules/inquiries/inquiry.functions.ts`, `src/routes/api.agent.tools.ts`, and `src/modules/common/action.ts`.
- Keep result contracts exact and avoid broad string state. `tests/imports/ts-standards.test.ts` and `src/lib/ui/contract-scans.ts` reject broad `status: string`, explicit `any`, non-null assertions, and `v.any()`.
- Use `z.infer<typeof Schema>` for server adapter data and route validation, as in `src/modules/inquiries/inquiry.functions.ts`.

## Code Style

**Formatting:**
- Formatter config: Not detected. There is no `.prettierrc*`, `prettier.config.*`, `eslint.config.*`, `.eslintrc*`, or `biome.json` in the project root.
- Authored TypeScript predominantly uses 2-space indentation, single quotes, trailing commas where multiline call sites benefit, and no semicolons. Examples: `src/routes/api.agent.tools.ts`, `src/modules/common/action.ts`, and `vitest.config.ts`.
- shadcn-generated UI files use their own style with double quotes, as in `src/components/ui/button.tsx` and `src/lib/utils.ts`. Preserve that style when editing those files.
- Generated TanStack router output in `src/routeTree.gen.ts` includes `/* eslint-disable */`, `@ts-nocheck`, and generated `as any` casts. Do not copy that style into authored files.
- TypeScript strictness is the main formatting-adjacent quality gate: `tsconfig.json` enables `strict`, `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`, `useUnknownInCatchVariables`, and `noImplicitOverride`.

**Linting:**
- ESLint/Prettier/Biome linting: Not detected in `package.json` or root config files.
- Use `npm run typecheck` from `package.json` as the baseline static check.
- Use custom Vitest guardrail scans instead of lint rules for architecture and trust contracts. The scanner implementation is `src/lib/ui/contract-scans.ts`; tests live in `tests/imports/`, `tests/copy/`, and `tests/ui-contract/`.
- Runtime code must pass the TypeScript standards scan in `tests/imports/ts-standards.test.ts`; it rejects explicit `any`, double casts through `unknown`, non-null assertions, `v.any()`, broad status strings, inexact Convex returns, hard-coded CSRF literals, and client-exposed source-write secrets.
- Route and module boundaries are enforced by `tests/imports/private-imports.test.ts`, `tests/imports/route-boundary.test.ts`, and `tests/imports/backup-imports.test.ts`.

## Import Organization

**Order:**
1. Framework, platform, and package imports first, as in `src/routes/api.agent.tools.ts`, `src/routes/__root.tsx`, and `src/modules/inquiries/inquiry.functions.ts`.
2. Blank line, then project imports through `@/` aliases, as in `src/modules/actions/index.ts`.
3. Relative imports for same-package files or Convex-to-source bridges, as in `convex/inquiries.ts` and `convex/schema.ts`.
4. Type imports are either inline with value imports or separate `import type` lines. Examples: `src/modules/common/action.ts`, `tests/unit/convex/inquiries-runtime.test.ts`, and `src/components/ae/status/AeStatusBadge.tsx`.

**Path Aliases:**
- `@/*` and `~/*` both resolve to `./src/*` in `tsconfig.json`.
- Prefer `@/` for application source imports, as in `src/routes/$slug.tsx` and `tests/integration/agent-tools-api.test.ts`.
- Routes must import public module seams and adapters, not `src/modules/*/internal/*`; this is enforced by `tests/imports/route-boundary.test.ts`.
- Sibling modules must depend on `src/modules/<module>/public.ts`, not internal implementation files; this is enforced by `tests/imports/private-imports.test.ts`.
- Convex files in `convex/` import source domain contracts by relative path, such as `../src/modules/inquiries/public` in `convex/inquiries.ts`. Keep Convex validators local to Convex entry files and shared table composition in `convex/schema.ts`.

## Error Handling

**Patterns:**
- Return discriminated result objects for expected domain and transport failures. Examples: `PublicInquirySubmitServerResult` and `OwnerInquiryMutationServerResult` in `src/modules/inquiries/inquiry.functions.ts`.
- Parse external input at boundaries with `zod` in server functions and actions: `publicInquirySubmitSchema`, `ownerReplySchema`, and `ownerVersionedSchema` in `src/modules/inquiries/inquiry.functions.ts`; `action.schema.parse` in `src/routes/api.agent.tools.ts`.
- Map source transport and admission failures into stable public error shapes. `inquirySourceError` and `ownerSourceError` in `src/modules/inquiries/inquiry.functions.ts` convert `SourceWriteAdmissionError` and `ConvexSourceError` into `{ kind: 'error', code, retryable, reason }`.
- Use `throw new Error(...)` for impossible invariants, configuration errors, and test fixture failures. Examples: `brandNonEmpty` in `src/modules/common/ids.ts`, `usesClerkBypass` in `src/routes/__root.tsx`, and fixture assertions in `tests/seo/discovery-files.test.ts`.
- Use HTTP status plus JSON error result for API handlers. `jsonError` in `src/routes/api.agent.tools.ts` returns stable codes such as `agent_tools_invalid_content_type`, `agent_tools_unknown_tool`, and `agent_tools_invalid_input`.
- Use `try/finally` around mutable test seams and source ports. Examples: `withRegistrySourcePortForTest` in `tests/helpers/source-ports.ts` and `setAnswerToolUseAgentForTests` reset blocks in `tests/eval/answer-pipeline.test.ts`.

## Logging

**Framework:** console, Sentry, PostHog-style funnel events, and source-owned audit records.

**Patterns:**
- Use source-owned audit/funnel records for business events rather than ad hoc console logging. Examples appear in `convex/inquiries.ts`, `convex/security.ts`, and `src/modules/observability/internal/funnel.ts`.
- Use client funnel emission through `emitFunnelEvent` in `src/components/ae/layout/AePublicShell.tsx` for UI actions.
- Use Sentry wrappers for frontend error capture through `src/components/ae/feedback/AeObservabilityErrorBoundary.tsx` and boot code in `src/components/ae/layout/AeObservabilityBoot.tsx`.
- Avoid logging private contact data, raw provider payloads, source hashes, or secret values. Tests assert redaction in `tests/unit/inquiries/inquiry-flow.test.ts`, `tests/seo/discovery-files.test.ts`, and `tests/deploy-smoke/phase1-deploy-smoke.spec.ts`.
- Console usage is acceptable in tests for spies or framework noise suppression, such as `tests/unit/observability/error-boundary-client.test.tsx`. Runtime code should prefer domain observability records.

## Comments

**When to Comment:**
- Comment trust boundaries and cross-surface contracts where future edits can break product promises. Examples: `src/modules/actions/index.ts`, `src/modules/common/action.ts`, and `src/routes/api.agent.tools.ts`.
- Comment generated or special-runtime files. Examples: `src/routeTree.gen.ts` and `src/routes/__root.tsx`.
- Comment design token intent in `src/styles/tokens.css`; it references `DESIGN.md` and records palette/font constraints.
- Keep comments sparse inside domain command code. Let exact types, `kind` unions, and command object names carry routine behavior.

**JSDoc/TSDoc:**
- Use TSDoc for exported contracts with trust implications, such as `ActionContext` and `AgentToolDescriptor` in `src/modules/common/action.ts`.
- Use doc comments for public action declarations, such as `submitInquiryAction` in `src/modules/inquiries/inquiry.actions.ts`.
- Do not add internal architecture vocabulary to public human surfaces. `AGENTS.md`, `src/lib/ui/contract-scans.ts`, and `tests/integration/agent-tools-api.test.ts` enforce this boundary.

## Function Design

**Size:** Domain functions can be large when they model source-owned workflows, but keep route handlers and UI adapters thin. `src/routes/$slug.tsx` delegates catalog, inquiry affordance, and SEO work; `src/modules/inquiries/internal/commands.ts` owns workflow logic.

**Parameters:** Prefer typed command objects for multi-field operations. Examples: `submitInquiry(state, command)` in `src/modules/inquiries/public.ts`, `publishBusinessCatalog(state, command)` in `tests/seo/discovery-files.test.ts`, and `sourceWriteAdmissionFromContext({...})` in `tests/unit/server/server-seams.test.ts`.

**Return Values:** Prefer exact discriminated unions with stable codes. Avoid throwing for normal user or source-state outcomes. Examples: `kind: 'ok' | 'error'` in `src/modules/inquiries/inquiry.functions.ts`, `kind: 'found' | 'not_found'` tested in `tests/integration/agent-tools-api.test.ts`, and `kind: 'allowed' | 'denied'` in Convex owner inbox results in `convex/inquiries.ts`.

## Module Design

**Exports:** 
- Export stable domain APIs from `src/modules/<module>/public.ts`. Example: `src/modules/inquiries/public.ts` re-exports command functions, types, and literal value arrays from `src/modules/inquiries/internal/*`.
- Keep module internals under `src/modules/<module>/internal/` and access them only from the same module or approved schema composition. The import guardrails in `tests/imports/private-imports.test.ts` and `src/lib/ui/contract-scans.ts` define the allowed exceptions.
- Add assistant-callable or UI/API operations as actions in `<module>/<module>.actions.ts` and register them in `src/modules/actions/index.ts`; examples are `src/modules/inquiries/inquiry.actions.ts` and `src/modules/registry/registry.actions.ts`.
- Use Convex schema composition in `convex/schema.ts` by spreading table maps exported from module internals, such as `src/modules/inquiries/internal/convex-schema` and `src/modules/catalog/internal/schema`.
- Read `convex/_generated/ai/guidelines.md` before editing Convex files under `convex/`. It requires validators for all Convex functions, careful public/internal function registration, and indexed/bounded queries.

**Barrel Files:** 
- Use `public.ts` as the module barrel for domain contracts. Examples are `src/modules/catalog/public.ts`, `src/modules/registry/public.ts`, and `src/modules/answer-thread/public.ts`.
- Use `src/modules/actions/index.ts` as the explicit action registry barrel. It imports action consts and asserts unique IDs; do not rely on side-effect registration.
- Avoid broad root-level barrels that hide module ownership. Import directly from `@/modules/<module>/public`, `@/modules/<module>/<module>.functions`, or `@/components/...`.
