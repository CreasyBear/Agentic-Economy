# External Integrations
**Analysis Date:** 2026-08-11

## APIs & External Services
- **OpenRouter (production model gateway):** `src/modules/model-gateway/public.ts` creates the only OpenRouter provider through `ai`/`@openrouter/ai-sdk-provider`; the SDK sends the server-side `OPENROUTER_API_KEY`, optional `AE_OPENROUTER_API_BASE_URL` and `SITE_URL`, and selects `AE_LLM_MODEL` (default `deepseek/deepseek-v4-flash`). Tests route the same seam to a local contract server (`tests/helpers/openrouter-contract-server.ts`), which is not a production dependency.
- **Supplier and curated HTTP APIs:** `src/modules/capability-supply/route-transport-runtime.ts` performs bounded HTTPS HTTP/JSON calls for keyless or provider-connection authorities and supports query/fixed-query mappings. Current curated source contracts include Open-Meteo forecast/geocoding, Wikipedia summaries, The Cat API, CoinGecko simple price, ipify, Exa, and Frankfurter (`src/modules/capability-supply/curated-cluster-a-publications.ts`, `curated-provider-publications.ts`). Cluster B definitions (OpenWeather, Tavily, SerpAPI, and a credentialed CoinGecko variant) require provider connections rather than platform-keyless access (`curated-cluster-b-publications.ts`).
- **MCP:** `@modelcontextprotocol/sdk` 1.30.0 and `src/modules/capability-supply/internal/transport-adapters.ts` support external streamable HTTP/JSON-RPC MCP initialize, tools-list, and tools-call flows. The public MCP surface is `src/routes/mcp.ts`; external server URLs and credentials come from admitted provider connection records, not hard-coded client secrets.
- **x402/EVM paid operations:** `@x402/core`, `@x402/evm`, and `@x402/extensions` 2.18.0 are used by `src/modules/capability-supply/internal/x402-payment-signer.ts` and the operation invocation worker to decode payment challenges and sign provider requests. Payer configuration is server-only (`AE_X402_PAYMENT_CREDENTIAL_REF`, `AE_X402_PAYMENT_PRIVATE_KEY`). The observed Agentic Market x402 publications in `curated-cluster-c-publications.ts` are explicitly discovery-only and marked as not executed or paid by AE.
- **Google Maps Embed API (optional browser integration):** `src/components/ae/artifacts/AeGenerativeMap.tsx` renders `https://www.google.com/maps/embed/v1/place` in a sandboxed iframe when `VITE_GOOGLE_MAPS_API_KEY` is present. It is client-only and the component returns no map when that variable is absent.
- **Notifications:** Resend calls `https://api.resend.com` by default from `src/lib/server/notification-provider.ts`, using `RESEND_API_KEY`, `RESEND_FROM`, optional `RESEND_API_BASE_URL`, and `AE_NOTIFICATION_OUTBOX_SECRET`. Novu calls `https://api.novu.co` by default with `NOVU_SECRET_KEY`, optional `NOVU_API_BASE_URL`, and `NOVU_WORKFLOW_INQUIRY_OWNER`/`NOVU_WORKFLOW_INQUIRY_CUSTOMER`. Both are server-side inquiry delivery paths and persist provider identifiers/readback state in the notification outbox.
- **Braintrust (evaluation-only external service):** `eval/braintrust/answer.eval.ts` uses the Braintrust SDK for an explicit `--remote` evaluation, requiring `BRAINTRUST_API_KEY` and an immutable `AE_BRAINTRUST_DATASET_VERSION`; project/dataset may be selected with `AE_BRAINTRUST_PROJECT` and `AE_BRAINTRUST_DATASET`. The default/local mode uses inline cases and `noSendLogs`, so it does not contact Braintrust.
- **Promptfoo (local evaluation runner):** `promptfoo` is a development dependency invoked by `package.json` against `eval/answer/promptfooconfig.yaml`. Its provider contract is local repository code; it is not an application runtime service or a production integration.

## Data Storage
- Convex is the sole application persistence service. `convex/schema.ts` composes the application tables, and `src/lib/server/convex-source.ts` uses `ConvexHttpClient` queries, mutations, and actions against `CONVEX_URL` or `VITE_CONVEX_URL`.
- Authenticated server Convex calls obtain a Clerk token using the `convex` template. Local self-hosted/E2E operation is an explicit development path using `CONVEX_SELF_HOSTED_ADMIN_KEY` and the local bypass; it is not the production authority.
- No external SQL, object-storage, or cache service is wired in the current source. Convex file storage is only used where a Convex table/function owns that contract; no separate storage SDK is configured.

## Authentication & Identity
- Clerk is the application identity provider. `@clerk/tanstack-react-start` is wired in `src/start.ts`, `convex/auth.config.ts` accepts Clerk JWTs with `applicationID: convex`, and server-side owner lookups call `https://api.clerk.com/v1` in `src/lib/server/notification-provider.ts`.
- The configured names are `VITE_CLERK_PUBLISHABLE_KEY`, `CLERK_SECRET_KEY`, and `CLERK_JWT_ISSUER_DOMAIN`; `src/lib/deployment/manifest.ts` requires the three together for a normal deployment. The publishable key is browser configuration; the secret and issuer settings remain server/deployment configuration.
- Local browser tests explicitly set `VITE_AE_DISABLE_CLERK_FOR_LOCAL_E2E=true`; `src/lib/server/convex-source.ts` then uses the local self-hosted admin-key path. This bypass is guarded as non-production in `src/lib/server/local-e2e-bypass.ts`.

## Monitoring & Observability
- Sentry receives sanitized client and server errors through `@sentry/react`/`@sentry/node` (`src/lib/observability/sentry.client.ts`, `sentry.server.ts`). Client/server DSNs are `VITE_SENTRY_DSN`/`SENTRY_DSN`; environment and release use `VITE_SENTRY_ENVIRONMENT`, `SENTRY_ENVIRONMENT`, `SENTRY_RELEASE`, or CI/Vercel revision variables. Build-time source maps additionally require `SENTRY_AUTH_TOKEN`, `SENTRY_ORG`, and `SENTRY_PROJECT` (`vite.config.ts`).
- PostHog receives optional funnel/product/pageview telemetry through `posthog-js` and `posthog-node` (`src/lib/observability/posthog.client.ts`, `posthog.server.ts`). Client/server keys are `VITE_POSTHOG_KEY`/`POSTHOG_KEY`; hosts default to `https://us.i.posthog.com` and can be overridden with `VITE_POSTHOG_HOST`/`POSTHOG_HOST`; app URLs use `VITE_POSTHOG_APP_URL`/`POSTHOG_APP_URL`.
- `AE_DISABLE_OBSERVABILITY` and `VITE_AE_DISABLE_OBSERVABILITY` disable telemetry. Telemetry is sanitized before sending; the application’s durable owner-activation data remains in Convex rather than PostHog (`.env.example`).

## CI/CD & Deployment
- GitHub Actions runs the source and hosted gates in `.github/workflows/kernel-release-gate.yml`: `actions/setup-node@v4` reads `.nvmrc`, npm 11.5.1 is installed, dependencies use `npm ci`, and sanitized evidence is uploaded with `actions/upload-artifact@v4`.
- The hosted gate deploys the exact GitHub revision to Vercel with `tools/release/deploy-customer-request-git-source.ts` and deploys Convex with `npx convex deploy`. It passes Vercel/Convex credentials through GitHub secret names such as `VERCEL_TOKEN`, `VERCEL_ORG_ID`, `VERCEL_PROJECT_ID`, `CONVEX_DEPLOY_KEY`, and `DEPLOY_CONVEX_URL` without storing values in the repository.
- Vite/Nitro’s production target is Vercel Node serverless (`vite.config.ts`, `nodejs22.x`, `preset: vercel`). `.vercel/project.json` currently declares `nodeVersion: 24.x`, so the checked-in deployment metadata is inconsistent with the repository’s Node 22 requirement.

## Environment Configuration
- `.env.example` is the source-visible inventory of environment names; values are intentionally absent. `src/lib/deployment/manifest.ts` classifies required groups for canonical origin, Convex, Clerk, model gateway, source-write, x402, notifications, and observability.
- Browser-exposed variables use the `VITE_` prefix. Server-only credentials include `CLERK_SECRET_KEY`, `OPENROUTER_API_KEY`, provider keys, source-write keys, `AE_CONVEX_SERVER_FUNCTION_TOKEN`, and x402 payer material; these are expected from deployment/Convex/GitHub secret stores, not committed files.
- `SITE_URL`/`AE_SITE_URL`, `AE_CANONICAL_BASE_URL`, `AE_CANONICAL_HOST_ALLOWLIST`, and `AE_ROUTING_PUBLIC_BASE_URL` control generated links, canonical routing, and provider/sandbox origin checks. `CONVEX_SELF_HOSTED_URL` and `CONVEX_SELF_HOSTED_ADMIN_KEY` are local self-hosted tooling inputs; the public app uses `CONVEX_URL`/`VITE_CONVEX_URL`.
- Names for Autumn and Stripe billing appear in `.env.example` and deployment validation helpers, but no Autumn client is imported and the current Stripe route uses a default verifier that refuses `stripe_setup_required`; they are not treated here as configured active provider integrations.

## Webhooks & Callbacks
- `POST /api/notification/resend-webhook` (`src/routes/api.notification.resend-webhook.ts`) verifies Resend/Svix signature headers with `RESEND_WEBHOOK_SECRET`, bounds the raw body, and records a sanitized provider event/readback. Other methods return method-not-allowed.
- `POST /api/notification/novu-dispatch` (`src/routes/api.notification.novu-dispatch.ts`) is an authenticated server dispatch/readback callback into Novu. It triggers the configured workflow and records transaction/workflow/message identifiers in the Convex notification outbox.
- `POST /api/stripe/webhook` (`src/routes/api.stripe.webhook.ts`) is a route contract for Stripe webhook handling, but its default verifier is an explicit `stripe_setup_required` refusal and no Stripe SDK/provider implementation is present in `package.json`; it is therefore not a working external payment callback in the current tree.
- Convex and the operation gateway also expose HTTP/MCP routes for clients and providers, but those are AE-owned entry points rather than third-party webhook callbacks (`convex/http.ts`, `src/routes/api.v1.operations.execute.ts`, `src/routes/mcp.ts`).
