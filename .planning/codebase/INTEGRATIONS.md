# External Integrations

**Analysis Date:** 2026-08-09

## APIs & External Services

- **Language models:** AE's single model-provider seam is OpenRouter through the Vercel AI SDK. `src/modules/model-gateway/public.ts` reads `OPENROUTER_API_KEY`, `AE_LLM_MODEL`, optional `AE_OPENROUTER_API_BASE_URL`, and `SITE_URL`, builds the OpenRouter provider, requests usage metadata, and supports strict structured output and bounded web-plugin options; answer modules consume this seam rather than opening their own model HTTP client (`src/modules/model-gateway/public.ts`, `src/modules/answer/`).
- **Curated keyless HTTP capabilities:** The admitted public catalog includes Open-Meteo forecast/geocoding, Wikipedia page summaries, The Cat API image search, CoinGecko simple price, and ipify public IP. Their official URLs, request/response schemas, `credentialRef: 'none'`, prices, and timeouts are curated in `src/modules/capability-supply/curated-cluster-a-publications.ts` and `src/modules/capability-supply/curated-provider-publications.ts`.
- **Curated credentialed HTTP capabilities:** Cluster B declares OpenWeatherMap, Tavily, SerpAPI, and CoinGecko Demo operations. The binding stores environment references `OPENWEATHER_API_KEY`, `TAVILY_API_KEY`, `SERPAPI_API_KEY`, and `COINGECKO_DEMO_API_KEY`; readiness resolves those references and records health only after a bounded probe succeeds (`src/modules/capability-supply/curated-cluster-b-publications.ts`, `convex/capabilitySupplyReadiness.ts`).
- **Exa and Frankfurter:** The curated provider set also contains executable Exa search/contents contracts using `EXA_API_KEY` and a keyless Frankfurter ECB single-rate contract. Both contracts carry source evidence and schemas used for catalog admission and operation selection (`src/modules/capability-supply/curated-provider-publications.ts`).
- **Observed x402 catalogue entries:** Cluster C records external Agentic Market x402 listings such as Exa search, timezone conversion, WolframAlpha, CoinMarketCap, FlightAware, Bizintel forex, and Tavily. They are explicitly discovery-only, have no AE credential, and AE does not execute or pay them; that boundary is part of the curated source rather than an implied integration (`src/modules/capability-supply/curated-cluster-c-publications.ts`).
- **Outbound transport safety:** Keyless operation execution resolves a DB/seed descriptor, validates the public HTTPS target, and uses Undici with a guarded DNS lookup; readiness probes use the same public-target and bounded-response controls. Generic provider route transport can also inject credentials from `env:NAME` references (`src/modules/capability-execution/operation-execute.server.ts`, `convex/capabilitySupplyReadiness.ts`, `src/modules/capability-supply/route-transport-runtime.ts`, `src/modules/network-guard/public.ts`).
- **x402 payment-required transport:** External `402 Payment Required` challenges are validated and signed only in the quarantined x402 adapter using `@x402/core`, `@x402/evm`, `@x402/extensions`, and `viem`. The Convex route worker records challenge/payment state and keeps provider payment separate from AE's internal money-ledger release (`src/modules/capability-supply/internal/x402-payment-signer.ts`, `convex/customerRequestRouteTransportWorker.ts`).
- **MCP server:** External agents can connect to `/mcp` using the Model Context Protocol Streamable HTTP transport. Anonymous access exposes read-only actions; non-read-only calls require an admitted customer-request agent principal and the action's declared authority mode, with bearer challenges for refusal (`src/routes/mcp.ts`, `src/lib/server/mcp-api.ts`, `src/modules/actions/`).
- **Shipping provider adapters:** The source contains injectable Shippo and EasyPost quote clients, with provider-specific base URLs, API headers, carrier/service identifiers, freshness windows, bounded response handling, and HMAC signing inputs. They are adapter seams rather than evidence of a configured production account (`src/modules/provider-integrations/shipping/server.ts`, `src/modules/provider-integrations/shipping/`).
- **Website import:** Owner-facing storefront import accepts an HTTPS website, follows a bounded redirect count, caps the response body, applies the public-target DNS guard, and extracts a draft. The route is a POST-only server callback (`src/modules/storefront/server.ts`, `src/routes/api.storefront.import-draft.ts`).

## Data Storage

- Convex is the durable application store and function boundary. The root schema composes module-owned tables for actions, answer threads, businesses/catalog, capability supply and contracts, customer requests, inquiries, notifications, observability, money, routing, security, projects, work trees, studies, and external runs (`convex/schema.ts`).
- Convex component state includes workflow, workpool, rate limiting, and an owner-activation aggregate; component registration is centralized in `convex/convex.config.ts`.
- Server-side source calls use `ConvexHttpClient`. Authenticated calls obtain a Clerk token using the `convex` template, while local E2E mode uses the self-hosted admin key; public projections use an unauthenticated Convex client. The URL is read from `CONVEX_URL` or `VITE_CONVEX_URL` (`src/lib/server/convex-source.ts`).
- Local development selects Convex's local deployment and supervises `convex dev`; local Convex metadata/state is generated under `.convex/` and is ignored rather than treated as committed application data (`tools/dev/local-dev.mjs`, `.gitignore`).
- Notification dispatch state, provider response hashes, webhook receipts, idempotency keys, and readback status are persisted in Convex notification-outbox tables rather than trusted solely to provider responses (`convex/schema.ts`, `src/routes/api.notification.novu-dispatch.ts`, `src/routes/api.notification.resend-webhook.ts`).

## Authentication & Identity

- Clerk is the user identity provider for TanStack Start. The browser wraps protected route families in `ClerkProvider`, server middleware installs `clerkMiddleware`, and Convex accepts Clerk JWTs with application ID `convex` (`src/routes/__root.tsx`, `src/start.ts`, `convex/auth.config.ts`).
- Owner/server Convex calls require an authenticated Clerk session and the `convex` token template. Local E2E bypass is explicit and requires `CONVEX_SELF_HOSTED_ADMIN_KEY`; it is not the production authentication path (`src/lib/server/convex-source.ts`, `src/lib/server/local-e2e-bypass.ts`, `tools/dev/local-dev.mjs`).
- Customer-request agents can authenticate with issued Clerk API keys and scoped principals. The OAuth surface supports dynamic client registration, device grants, authorization-code exchange, consent, and token issuance; owner approval and scope-to-authority mapping are persisted through the customer-request module (`src/lib/server/customer-request-agent-auth.ts`, `src/lib/server/customer-request-agent-oauth-api.ts`, `src/modules/customer-request/agent-access.ts`, `src/modules/customer-request/oauth-state/`).
- MCP protected actions reuse customer-request agent admission and return `WWW-Authenticate` bearer/mode challenges when credentials or scopes are insufficient (`src/lib/server/mcp-api.ts`, `src/lib/http/oauth-challenge.ts`).
- AE-owned Web Bot Auth exposes a public HTTP-message-signature JWK directory from `AE_WBA_DIRECTORY_PUBLIC_JWK_JSON`; signature-agent allowlisting and admitted public-inquiry principals are configured by `AE_WBA_SIGNATURE_AGENT_ALLOWLIST` and `AE_AGENT_PUBLIC_INQUIRY_ADMISSION_PRINCIPALS` (`src/routes/[.]well-known/http-message-signatures-directory.ts`, `.env.example`).
- Server-to-server source writes and route calls use scoped HMAC/key-family or route-signing credentials. The source-write middleware rejects missing/invalid scoped credentials, while route transport signs canonical invocation fields with `AE_ROUTE_CALL_SIGNING_SECRET` and `AE_ROUTE_CALL_SIGNING_KEY_ID` (`src/lib/server/source-write-admission.ts`, `convex/customerRequestRouteTransportWorker.ts`, `.env.example`).

## Monitoring & Observability

- Sentry captures server exceptions and browser errors; PostHog owns client/server funnel analytics. Config reads client and server DSN/key/host/app-url names, resolves release from `SENTRY_RELEASE`, `VERCEL_GIT_COMMIT_SHA`, or `GITHUB_SHA`, and can be disabled for local E2E using `VITE_AE_DISABLE_OBSERVABILITY` or `AE_DISABLE_OBSERVABILITY` (`src/lib/observability/config.ts`, `src/lib/observability/sentry.server.ts`, `src/lib/observability/posthog.server.ts`).
- TanStack Start request middleware lazily initializes Sentry/PostHog, tags Sentry scopes with the request path, captures thrown server errors, and flushes PostHog after the request; the browser boot and error boundary are mounted from the root route (`src/start.ts`, `src/routes/__root.tsx`, `src/components/ae/feedback/AeObservabilityErrorBoundary.tsx`).
- Vite enables the Sentry plugin only when `SENTRY_AUTH_TOKEN`, `SENTRY_ORG`, and `SENTRY_PROJECT` are present, and enables source maps only in that case (`vite.config.ts`).

## CI/CD & Deployment

- GitHub Actions runs the source-release gate on pushes, pull requests, merge groups, and manual dispatch. It checks out the repository, installs Node from `.nvmrc`, globally pins npm 11.5.1, runs frozen `npm ci`, verifies Convex generated source, and uploads sanitized release evidence (`.github/workflows/kernel-release-gate.yml`).
- On a main-branch push, the hosted job deploys the exact revision to Vercel through `tools/release/deploy-customer-request-git-source.ts`, deploys the Convex schema/functions with `npx convex deploy`, checks required production route-signing/site settings, seeds and probes Frankfurter, then runs hosted customer-request and WorkTree readback smoke tests (`.github/workflows/kernel-release-gate.yml`, `tools/release/deploy-customer-request-git-source.ts`).
- Nitro's Vercel preset emits Node serverless functions, and the checked-in Vercel metadata identifies the project as a Nitro project. The metadata currently reports Node 24 while the repository and Vite function config target Node 22; this is an active deployment-setting mismatch to resolve rather than an assumed compatibility guarantee (`vite.config.ts`, `.vercel/project.json`, `package.json`).
- Local/staging-like execution is intentionally separate from hosted deployment: `npm run dev:local` selects the local Convex deployment, starts Convex with typecheck disabled, and launches a local Vite child with generated local source-write/admin settings (`tools/dev/local-dev.mjs`).

- **Capability providers:** `EXA_API_KEY`, `OPENWEATHER_API_KEY`, `TAVILY_API_KEY`, `SERPAPI_API_KEY`, and `COINGECKO_DEMO_API_KEY` are referenced by curated publication bindings; readiness resolves the names dynamically from `env:NAME` references (`src/modules/capability-supply/curated-provider-publications.ts`, `src/modules/capability-supply/curated-cluster-b-publications.ts`, `convex/capabilitySupplyReadiness.ts`).
- **Billing and notifications:** The template names `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `AUTUMN_SECRET_KEY`, `AUTUMN_WEBHOOK_SECRET`, `RESEND_API_KEY`, `RESEND_FROM`, `RESEND_API_BASE_URL`, `RESEND_WEBHOOK_SECRET`, `NOVU_SECRET_KEY`, `NOVU_API_BASE_URL`, `NOVU_WORKFLOW_INQUIRY_OWNER`, `NOVU_WORKFLOW_INQUIRY_CUSTOMER`, and `AE_NOTIFICATION_OUTBOX_SECRET`. ## Webhooks & Callbacks

- **Stripe:** `POST /api/stripe/webhook` accepts the raw body and `stripe-signature`, applies a bounded-body limit, and delegates verification/application to injectable money adapters. The route's default adapters return `stripe_setup_required`, so the callback contract exists without claiming an active Stripe account (`src/routes/api.stripe.webhook.ts`, `src/modules/money/internal/stripe-webhook.ts`).
- **Resend:** `POST /api/notification/resend-webhook` caps the raw payload, verifies Resend signature/timestamp headers with `RESEND_WEBHOOK_SECRET`, and ingests a verified event into Convex with an idempotent operation/correlation key (`src/routes/api.notification.resend-webhook.ts`, `src/lib/server/notification-provider.ts`).
- **Novu:** `POST /api/notification/novu-dispatch` is an internally authorized outbound-dispatch callback. It reads a Convex outbox record, triggers/readbacks the Novu transaction, and records sent/held/error state; it requires the notification outbox system key and Novu workflow configuration (`src/routes/api.notification.novu-dispatch.ts`, `src/lib/server/notification-provider.ts`).
- **Agent OAuth:** OAuth metadata is exposed at `/.well-known/oauth-authorization-server` and `/.well-known/oauth-protected-resource`; device authorization, client registration, consent, and token exchange are served by the customer-request agent OAuth API and use no-store responses plus rate limits (`src/routes/[.]well-known/oauth-authorization-server.ts`, `src/routes/[.]well-known/oauth-protected-resource.ts`, `src/routes/oauth.device_authorization.ts`, `src/routes/oauth.token.ts`, `src/routes/oauth.register.ts`, `src/lib/server/customer-request-agent-oauth-api.ts`).
- **Web Bot Auth directory:** `GET /.well-known/http-message-signatures-directory` publishes only validated public JWK material and returns a problem response when `AE_WBA_DIRECTORY_PUBLIC_JWK_JSON` is absent or invalid (`src/routes/[.]well-known/http-message-signatures-directory.ts`).
- All callback routes explicitly reject unsupported methods through `methodNotAllowed`, and global middleware rejects non-standard methods before route handling (`src/start.ts`, `src/routes/api.stripe.webhook.ts`, `src/routes/api.notification.resend-webhook.ts`, `src/routes/api.notification.novu-dispatch.ts`).
