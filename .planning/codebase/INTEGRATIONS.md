# External Integrations
**Analysis Date:** 2026-09-01

<!-- refreshed: 2026-09-01 -->

- **APIs & External Services**:
  - **Model gateway**: `src/modules/model-gateway/public.ts` is the application model seam over OpenRouter through `@openrouter/ai-sdk-provider` and the Vercel AI SDK. It selects the configured model, supports strict structured output/reasoning options, records provider usage/cost metadata when supplied, and can enable OpenRouter web-search plugins. Durable and anonymous chat use it through `convex/chatGenerate.ts` and `convex/chatAnonymous.ts`; storefront discovery uses the same seam from `src/modules/storefront/internal/web-discovery.ts`.
  - **Admitted supplier operations**: OpenAPI/HTTP JSON sources are imported by `src/modules/capability-supply/internal/publication-importer-openapi.ts` and bound/executed by `src/modules/capability-supply/internal/route-transport-http-json.ts`. The transport uses `openapi-fetch` serializers but keeps outbound fetch, redirects, credentials, response bounds, and network policy inside AE's guarded adapters. Remote Streamable HTTP MCP sources are handled by `publication-importer-mcp.ts` and `route-transport-mcp.ts` using the official `@modelcontextprotocol/sdk`.
  - **x402 payments and paid routes**: `src/modules/capability-supply/internal/route-transport-x402.ts` handles payment challenges and settlement responses. `x402-payment-signer.ts` uses the official x402 client/encoders, while `cdp-x402-payment-signer.ts` uses `@coinbase/cdp-sdk` for managed custody and replay/idempotency policy. `x402-settlement-verifier.ts` and `x402-evm-receipt-reader.ts` verify EVM settlement through `viem` and configured HTTPS JSON-RPC endpoints. The code carries Base Sepolia sandbox and Base mainnet USDC profiles; the exact production enablement is controlled by the deployment manifest and environment configuration.
  - **Facilitator discovery**: `src/modules/capability-supply/internal/facilitator-discovery-ingest.ts` and `facilitator-discovery-client.ts` pull bounded Bazaar/discovery resources from Coinbase CDP (`https://api.cdp.coinbase.com/platform/v2/x402/discovery/resources`) and PayAI (`https://facilitator.payai.network/discovery/resources`). `convex/facilitatorDiscoveryAction.ts` fetches pages on schedule and `convex/facilitatorDiscovery.ts` reconciles them into admitted/withdrawn external capability records. This is a scheduled pull, not a provider webhook.
  - **Keyless public upstreams**: the generic admission and execution path can represent public HTTP JSON operations without customer API keys. CoinGecko, Frankfurter FX, Open-Meteo geocoding/weather, ipify, and Wikipedia occur in the current evaluation/domain vocabulary, but they are not hard-coded static catalog guarantees. The current development fixture module, `src/modules/dev/internal/dev-seed-business-fixtures.ts`, intentionally has no static businesses/operations; currently admitted resources come from real source/facilitator ingestion.
  - **External catalog snapshots**: `src/modules/market/registry-source-adapters.ts` reads bounded read-only snapshots from Agentic Market (`https://api.agentic.market/v1/services`) and TREG (`https://treg.to/catalog/platforms`). `convex/marketExternalRegistryRefresh.ts` persists these as external registry observations; they inform discovery/reference data and are not substitutes for AE's Convex-authoritative admission or execution records.
  - **Secret providers**: `src/modules/secrets/infisical-cloud.ts` integrates with Infisical's OIDC login and v4 secret endpoints over guarded HTTPS. `src/modules/secrets/vercel-oidc.ts` obtains and validates a Vercel OIDC token through `@vercel/oidc`; `src/modules/secrets/runtime.ts` and `src/modules/secrets/public.ts` keep platform and customer secret planes separate. The internal provider-consequence and secret-lifecycle routes are the callers.
  - **Billing and payouts**: Stripe Checkout/Payment Element and Stripe Connect are implemented in `src/components/ae/console/AeCreditTopUpPanel.tsx`, `src/modules/money/`, and `src/lib/server/stripe-money-provider*.ts`. Stripe is used for buyer credit top-ups, supplier Connect onboarding, and transfers; x402 remains the provider-payment rail. Autumn variable names are declared in `.env.example` and checked by `src/lib/deployment/manifest.ts`, but no current Autumn runtime adapter/import was found in `src/`, `convex/`, `tools/`, or `tests/`.
  - **Protocol surfaces**: the public MCP server in `src/lib/server/mcp-api.ts` exposes admitted read/action surfaces through the official MCP SDK at the `/mcp` route. The operation gateway is served by `src/routes/api.v1.operations.call.ts` and `src/lib/server/operation-invoke-api.ts`; `tools/ae/` and `packages/cli/` consume the HTTP/MCP contracts. AgentMux is a host/tooling concern, not an application dependency imported by this repository; the in-repo available-money integration is the x402/CDP path above.
- **Data Storage**: Convex is the authoritative application database and reactive server platform. Table composition is in `convex/schema.ts`; component mounts for workpool, rate limiting, durable agent chat, and aggregate projections are in `convex/convex.config.ts`. Backend readers, mutations, actions, scheduled jobs, money ledgers, capability records, operation invocations, recovery state, and agent-access state live under `convex/`. Local development uses a local Convex deployment launched by `tools/dev/local-dev.mjs`; production uses the configured Convex deployment. No separate SQL database or external object-storage client is configured in `package.json`; Convex storage remains a platform capability rather than a distinct third-party integration in the reviewed application paths.
- **Authentication & Identity**: Clerk is wired into the TanStack Start request pipeline in `src/start.ts` and the browser/provider tree in `src/routes/__root.tsx`; JWT verification configuration is in `convex/auth.config.ts`. `src/lib/server/agent-access-auth.ts` accepts Clerk bearer API keys, requires the expected subject/scopes, live-validates the key with Clerk, and resolves it to AE platform principal/account records. `src/lib/server/agent-access-oauth-api.ts` and `src/routes/oauth.authorize.ts` implement the owner-consent/OAuth device flow and Clerk API-key lifecycle; related route files include OAuth token, registration, and device-authorization endpoints. AE's canonical principals, accounts, grants, and authority are persisted in Convex rather than reconstructed from Clerk identifiers. x402 payer/payment identity is separately checked by the payment signer and settlement verifier. The local E2E Clerk bypass is guarded by `VITE_AE_DISABLE_CLERK_FOR_LOCAL_E2E` and is not a production authentication mode. `CLERK_WEBHOOK_SIGNING_SECRET` is declared for configuration, but no current Clerk webhook handler route was found.
- **Monitoring & Observability**: Browser and server Sentry adapters are `src/lib/observability/sentry.client.ts` and `src/lib/observability/sentry.server.ts`; the UI boundary is `src/components/ae/feedback/AeObservabilityErrorBoundary.tsx`. Browser and server PostHog adapters are `src/lib/observability/posthog.client.ts` and `src/lib/observability/posthog.server.ts`. `src/start.ts` wraps requests with correlation, sanitized error capture, and PostHog flushing while excluding health/readiness probes. `src/routes/api.health.ts`, `src/routes/api.ready.ts`, and the deployment manifest provide liveness/readiness checks; Convex supplies backend logs and scheduled-function telemetry. `AE_DISABLE_OBSERVABILITY` and `VITE_AE_DISABLE_OBSERVABILITY` are explicit brakes. No separate hosted metrics/trace SDK or custom Convex Insights client is imported by the reviewed runtime.
- **CI/CD & Deployment**: `.github/workflows/kernel-release-gate.yml` runs the Node/npm install, source-proof/conformance, Convex generated-code verification, release-integrity, unit/integration/browser, and optional staging/authenticated/paid smoke gates; `.github/workflows/react-doctor.yml` supplies an advisory React diagnostics job. `vite.config.ts` builds the TanStack/Nitro web server with the Vercel preset and Node 22 function runtime; Convex code generation/deployment and seed/release commands are defined in `package.json`, `convex.json`, and `scripts/`. `tools/dev/local-dev.mjs` supervises local Convex plus Vite startup. `scripts/build-cli.mjs` bundles the external-agent CLI into `packages/cli/dist/`, and `pack:cli:public` publishes its package download. `.vercel/project.json` currently records a Nitro project with Node `24.x`, while application/deployment manifest declarations target Node 22; this is a current metadata mismatch to resolve at deployment configuration time.

- **Webhooks & Callbacks**: `src/routes/api.stripe.webhook.ts` accepts only `POST /api/stripe/webhook`; `src/modules/money/server.ts` verifies the raw request body and `stripe-signature` with Stripe's webhook secret before projecting checkout/account events into Convex money state. Convex HTTP routes in `convex/http.ts` expose the chat bridge at `/chat/anonymous` and guarded internal callback paths `/internal/provider-consequence/journal/begin`, `/internal/provider-consequence/journal/attest`, `/internal/provider-consequence/journal/complete`, `/internal/provider-consequence/journal/abort`, `/internal/provider-consequence/x402`, and `/internal/secret-lifecycle`. The public `src/routes/api.chat.anonymous.ts` accepts JSON `POST`, rate-limits the edge request, forwards to the Convex chat endpoint with an admission secret, and projects only safe streaming headers. OAuth browser/API callbacks are implemented by `src/routes/oauth.authorize.ts` and the companion OAuth token, registration, and device-authorization route files. Facilitator discovery and external catalog refresh use scheduled outbound pulls from `convex/crons.ts`, not inbound callbacks; x402 settlement is returned in provider responses and verified by the route transport.
