# Treg External-Reference Surfaces

## Scope/source pin

- Scope: fixed external-reference inventory for Treg user and machine surfaces; this records current behavior and routes, not a redesign or comparison.
- Source repository: [`superdesigndev/treg`](https://github.com/superdesigndev/treg).
- Pinned source commit: [`superdesigndev/treg@603540f`](https://github.com/superdesigndev/treg/tree/603540f653994080d4f507a9a3564e1017c28eef) (commit timestamp `2026-08-22T10:01:05+10:00`).
- Live target: `https://treg.to`; live observations made `2026-08-23` (Australia/Perth).
- Live evidence: `https://treg.to/meta` returned 200 with `public_url=https://treg.to` and `treg_version=0.12.0`; `https://treg.to/catalog/platforms` and `https://treg.to/catalog/search?q=backlinks` are public 200 routes; `/tools`, `/billing`, `/auth/me`, and `/mcp/` without credentials return 401.
- The API is the shared backend for the dashboard, CLI, skills, and MCP: `src/treg/api.py`; the repository's `AGENTS.md` describes it as the only brain.

## Web surfaces

- Landing and anonymous entry: `GET https://treg.to/` serves the marketing landing and anonymous sandbox UI from `src/treg/api.py` and `src/treg/web/index.html`; the landing offers catalog browsing, sign-in, agent setup, and no-login try-it.
- Public catalog: `https://treg.to/catalog`, `https://treg.to/catalog/{slug}`, `https://treg.to/use-cases`, `https://treg.to/use-cases/{slug}`, `https://treg.to/use-cases/{category}/{job}`, and `https://treg.to/agents/{agent}` are server-rendered/SPA SEO surfaces implemented in `src/treg/api.py`, `src/treg/web/index.html`, and `src/treg/catalog_store.py`.
- Catalog behavior: platform shelves, provider comparisons, capability rows, price/verification facts, request parameters, examples, and access/credential status are read from `GET /catalog/platforms`, `/catalog/platforms/{slug}`, `/catalog/search`, `/catalog/endpoints/{endpoint_id}`, `/catalog/endpoints/{endpoint_id}/access`, and `/catalog/examples/{endpoint_id}` in `src/treg/api.py`.
- Public supporting pages: `https://treg.to/docs`, `/resources`, `/support`, `/contact`, `/help`, `/terms`, `/privacy`, `/robots.txt`, and `/sitemap.xml`; route handlers are in `src/treg/api.py`, with markup/assets in `src/treg/web/`.
- Dashboard shell: `https://treg.to/app` serves the same single-file Vue application, `src/treg/web/index.html`; signed-in views include Getting started, Tools, Secrets, Marketplace, Activity, Usage, Team, and conditional Admin.
- Dashboard deep links: `/app/marketplace/{service}`, `/app/skills/{name}`, and `/app/tools/{name}` are handled by `dashboard_marketplace`, `dashboard_skill_page`, and `dashboard_tool_page` in `src/treg/api.py`; client routing and views remain in `src/treg/web/index.html`.
- OAuth connect UI: Marketplace provider rows, token/key entry, capability selection, consent popup polling, resource selection, extra credentials, reconnect, and disconnect are implemented in `src/treg/web/index.html` against `/oauth/providers`, `/connections*`, and `/oauth/*` handlers in `src/treg/api.py`.
- Tutorial surfaces: `https://treg.to/tutorial` uses `src/treg/web/tutorial.html` and shared data from `src/treg/web/tutorial.js`; dashboard Help uses the same source. Markdown variants are `/tutorial.md`, `/tutorial-import-shell.md`, and `/tutorial-access.md` from `src/treg/web/`.
- Anonymous sandbox: `POST /demo/sandbox` mints a login-free demo org/token; `GET /demo/sandbox/live`, `GET /demo/sandbox/skill`, `POST /secrets`, `POST /tools`, and `/call/*` let the browser build and exercise a capped throwaway registry. Logic is in `src/treg/sandbox.py`, `src/treg/pubfeed.py`, and `src/treg/api.py`.
- Sandbox live wire/feed: an optional exact Stripe test path is controlled server-side by `src/treg/sandbox.py`; the public payment stream is `GET /landing/stripe-feed` and its signed webhook is `POST /stripe/webhook`, both in `src/treg/api.py` and `src/treg/pubfeed.py`.

## CLI surfaces

- CLI entry and dispatch: `src/treg/__main__.py` calls `src/treg/cli.py`; the client stores endpoint/token/org state in `~/.treg/config.json` (or `TREG_CONFIG`) and sends `X-Treg-Token` plus optional `X-Treg-Org`.
- Setup/config identity family: `treg config`, `treg login`, `treg logout`, `treg onboard`, `treg update`, and `treg version`; login supports browser pairing, email OTP, and `--token` for agents/CI. Implementation: `src/treg/cli.py` and `src/treg/session.py`.
- Catalog/spend family: `treg catalog`, `treg catalog search`, `treg catalog get`, `treg catalog request`, `treg call`, `treg balance`, and `treg topup`; catalog reads are unauthenticated, calls use `/call/*`, and balances/top-ups are org scoped. Implementation: `src/treg/cli.py`.
- Team family: `treg org create|ls|use|invite|invites|revoke|members|access|set-role|join|leave|delete`, plus project, provider-pin, deny-rule, agent, budget, and usage subcommands in `src/treg/cli.py`.
- Resource/vault family: `treg secret add|ls|update|rm`, `treg tool add|ls|update|rm`, `treg skill init|add|scaffold|push|ls|rm|install`, `treg connections` (including providers/resources/connect/use/rm), and `treg health [--run]`; implementation also uses `src/treg/convert.py`, `src/treg/skills.py`, and `src/treg/oauth.py`.
- Import/distribution family: `treg scan`, `treg upload` (with hidden `treg import` compatibility), `treg skill bootstrap`, and `treg mcp install`; scanners use `src/treg/providers.py`, `src/treg/agents.py`, `src/treg/mcp_install.py`, and `src/treg/web/install.sh`.
- Execution family: `treg cli run|runs|shell|setup`, with hidden/backward-compatible `treg run`, `treg runs`, `treg shell`, and `treg setup-local-run`; server/local run enforcement is in `src/treg/runner.py`, `src/treg/localrun.py`, `src/treg/shell.py`, and `src/treg/cli.py`.
- Transparent interception: `treg <program>`, `treg with -- <program>`, `treg cli shell start --proxy`, and `treg serve start|stop|status|env` use `src/treg/localproxy.py` and `src/treg/shell.py`; only registered hosts are intercepted, while unknown hosts tunnel.
- Audit/admin family: `treg audit [--calls|--runs]`, `treg calls`, `treg runs`, and `treg admin login|stats|orgs|org|users|tools|calls|health|grant|revoke|suspend-user|rm-user|suspend-org|rm-org`; API handlers are in `src/treg/api.py`.
- Compatibility aliases: hidden `treg add` maps to `tool add`, `treg oauth connect|providers` maps to `connections`, and `treg import` maps to `upload`; parser/help definitions are in `src/treg/cli.py`.

## HTTP API surfaces

- Public read API: `GET /meta`, `/providers.json`, `/catalog/platforms`, `/catalog/platforms/{slug}`, `/catalog/search`, `/catalog/endpoints/{endpoint_id}`, `/catalog/examples/{endpoint_id}`, and `/catalog/endpoints/{endpoint_id}/access` in `src/treg/api.py`; catalog reads do not require a session.
- Public write/request API: `POST /tool-requests` accepts a capability request with optional attribution; `src/treg/api.py` applies caps/rate limits, and `src/treg/mcp.py` routes MCP `catalog_request` through the same endpoint.
- Auth/browser API: `/auth/github`, `/auth/github/callback`, `/auth/google`, `/auth/google/callback`, `/auth/email/start`, `/auth/email/verify`, `/auth/me`, `/auth/logout`, `/auth/cli/start`, `/auth/cli/poll`, `/auth/cli/orgs`, `/auth/cli/approve`, `/auth/cli-token`, `/auth/revoke-tokens`, and invite-signin GET/POST are implemented in `src/treg/api.py` and `src/treg/session.py`.
- Identity/org API: `POST /users` is the open legacy registration door; `POST /orgs`, `GET /orgs`, `GET/POST /invites*`, `GET/DELETE /orgs/{id}/invites*`, `GET /orgs/{id}/members`, member role/access/cap PATCHes, `DELETE /orgs/{id}/members/{user_id}`, `POST /orgs/{id}/leave`, and `DELETE /orgs/{id}?confirm={slug}` are in `src/treg/api.py`.
- Onboarding API: `POST /onboard/demo`, `/onboard/skip`, `/onboard/reset`, `/onboard/seed-tool`, and `/onboard/accept-teammate`; the current first-run dashboard flow is in `src/treg/web/index.html`, while CLI path behavior is in `src/treg/demo.py` and `src/treg/cli.py`.
- Team/access API: agent mint/list/revoke (`/orgs/{id}/agents*`, `/agents/checkin`), projects (`/orgs/{id}/projects*`), provider pins (`/orgs/{id}/pins`), deny rules and CLI policy (`/orgs/{id}/deny*`, `/orgs/{id}/policy/cli-deny`), public tokens, and `/auth/me` machine identity details are in `src/treg/api.py`.
- Vault/resource API: `/secrets*`, `/tools*`, `/tools/by-name/{name}`, `/skills`, `/skills/analyze`, `/skills/import`, `/bundles*`, `/bundles/by-name/{name}`, `/calls*`, and `/runs` are member/org scoped and implemented in `src/treg/api.py`; secret values are never returned.
- Proxy API: `* /call/{rest:path}` in `src/treg/api.py` resolves a named tool, a full upstream URL, or a dotted catalog endpoint; `src/treg/proxy.py` preserves the upstream request/response while injecting server-held credentials.
- CLI execution API: `POST /tools/{name}/grant`, `POST /tools/{name}/run-report`, and `POST /run` support local proof-gated or server-side CLI execution; `GET /runs` merges execution audit records.
- OAuth/provider connection API: `/oauth/providers`, `POST /oauth/start`, `GET /oauth/callback`, `/oauth/status/{state}`, `/connections`, `/connections/{id}/resources`, `POST /connections/{id}/resource`, `POST /connections/token`, `POST /connections/{id}/extra-credential`, and `DELETE /connections/{id}` are in `src/treg/api.py`; provider definitions and token/key probes are in `src/treg/oauth_providers.py`.
- Health API: `POST /health/run` and `GET /health` use `src/treg/health.py`; refresh failures mark credentials invalid/needs-reconnect and health runs continue per tool.

## MCP surfaces

- Transport: `https://treg.to/mcp/` is mounted by `src/treg/api.py` and implemented in `src/treg/mcp.py`; tool calls execute through the API's auth, ACL, catalog ladder, billing, proxy, and audit paths.
- Stable MCP tools (implemented in `src/treg/mcp.py`): `catalog_search`, `catalog_get`, `call`, `balance`, `my_tools`, and `catalog_request`.
- `call` accepts catalog endpoint ids or team tool paths and supports query/body/headers plus `idempotency_key`; the response carries upstream data or an actionable refusal, with `replayed=true` on idempotent replay.
- MCP discovery and OAuth metadata: `GET https://treg.to/.well-known/oauth-protected-resource` advertises resource `https://treg.to/mcp/`, `GET /.well-known/oauth-authorization-server` advertises S256, and `GET /.well-known/skills/index.json` advertises the Treg skill.
- Authorization-server routes: `POST /oauth/register` (DCR), `GET/POST /oauth/authorize` (consent/approval), `POST /oauth/token`, `POST /oauth/revoke`, `GET /oauth/grants`, and `POST /oauth/grants/{family_id}/team`; implementation is split between `src/treg/mcp_oauth.py` and `src/treg/api.py`.
- Headless MCP auth: a team-pinned token in `Authorization: Bearer ...` is accepted without a second org header; `src/treg/mcp_install.py` writes Claude/Cursor/opencode configs and reports manual Codex/Hermes/OpenClaw setup.
- Browser flow test surface: `https://treg.to/connect-demo` and `/connect-demo/callback` exercise registration, consent, token exchange, and MCP calls using `src/treg/web/connect-demo.html`.

## Auth/team/admin surfaces

- Human auth has GitHub, Google, email OTP, and invitation sign-in; dashboard sessions use `treg_session`, while CLI/agent calls use hashed bearer tokens. Session/token resolution is in `src/treg/session.py` and `src/treg/api.py`.
- First human login creates a user but no automatic team; dashboard team creation is `POST /orgs`, then setup continues in `src/treg/web/index.html`. An invitee can accept code-free `/invites/{invite_id}/accept` or open `/invites/accept` with an invite code.
- Roles are owner/admin/member/viewer; admin/owner gates cover tools, secrets, invites, projects, policies, billing, and member access. Tool ACL, project scope, deny rules, daily caps, and agent tokens are enforced centrally in `src/treg/api.py` and `src/treg/models.py`.
- Machine identities: `POST /orgs/{id}/agents` mints/rotates an org-scoped token with role, tool/project access, tag pins, and caps; the token is returned once, hashed at rest, and revocation is `DELETE /orgs/{id}/agents/{user_id}`.
- Super-admin surfaces are `/admin/stats`, `/admin/orgs`, `/admin/orgs/{id}`, `/admin/users`, `/admin/tools`, `/admin/calls`, `/admin/errors`, `/admin/health`, reconciliation routes, referral listing, and user/org grant/suspend/delete mutations; all require `require_superadmin` in `src/treg/api.py`.

## Money/audit surfaces

- Credential ladder for a catalog call: an org's provider tool first, an org provider secret/virtual tool second, then Treg's eligible platform key; own org credentials are unmetered except registry OAuth providers explicitly marked upstream-metered (currently modeled by `src/treg/oauth_providers.py`).
- Platform-key calls reserve estimated integer micro-USD in `src/treg/ledger.py`, relay through `src/treg/api.py`/`src/treg/proxy.py`, settle to observed provider cost or release on non-billable failure; `src/treg/models.py` stores blocks, holds, and ledger entries.
- Insufficient prepaid balance is HTTP 402 with `balance_micro`, `estimated_cost_micro`, and `topup_url`; recovery is `treg balance`, dashboard Team → Billing, or connecting the provider's own key. A priced-but-unavailable endpoint is refused rather than silently free.
- Billing surfaces: `GET /orgs/{id}/balance`, `GET /billing`, `POST /billing/topup`, `POST /billing/autotopup`, `GET /billing/history`, `POST /billing/portal`, and signed `POST /billing/stripe/webhook`; implementation is `src/treg/billing.py`, `src/treg/ledger.py`, and `src/treg/api.py`.
- Stripe credits the ledger only from the webhook; manual payments can expose invoice links, auto-top-up exposes receipts, and portal availability depends on a Stripe customer. No payment/credential values are documented here.
- Audit surfaces: `GET /calls`, `/calls/{call_ref}`, and `/runs`; dashboard Activity merges them, while `src/treg/audit.py` records status, timing, tier, cost, refusal source, and redacted failure evidence.
- Idempotent retry: callers send `Idempotency-Key` on `/call/` or `idempotency_key` to MCP `call`; a stored metered success replays with `X-Treg-Idempotent-Replay: true` and the original `X-Treg-Cost-Micro`, while a different request reusing the key is 422 and an in-flight duplicate is 409.
- Builder resale surfaces: `X-Treg-Meta` tags up to five customer/workspace pairs; `/orgs/{id}/usage/by-tag`, `/orgs/{id}/budgets*`, and `/orgs/{id}/settings` report/enforce declared dimensions. `src/treg/ledger.py` is the invoice source; caps are advisory while balance is hard.
