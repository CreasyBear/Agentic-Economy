# Agentic Economy Roast — 2026-07-04
**Status:** internal vision/strategy artifact. Not public copy.
**Current product boundary:** AE today publishes business-supplied pages, assistant-readable discovery, and a qualified inquiry path for owner review. AE does not yet book, charge, dispatch, auto-fulfil, operate a live marketplace, custody funds, or run generic autonomous actions (`local://ae-orientation.md:3-15`; `local://roast-investor.md:5-6`).
**Evidence base:** `local://ae-orientation.md`, `local://roast-investor.md`, `local://roast-marketplace.md`, `local://roast-technical.md`, `local://research-landscape.md`, `local://research-demand.md`, and `local://bones-audit.md`.

## 1. Executive kill-summary
AE is not dying because the premise is stupid.
AE is dying because the premise is good in the exact way that invites everyone larger to absorb the valuable part and leave AE holding the chore list.
The current artifact is an honest, boundary-disciplined registry experiment. The dream is a domestic router / registry / directory for agent-native business interaction. The gap between those two is not a roadmap; it is a quarry (`local://roast-investor.md:354-373`; `local://roast-marketplace.md:542-546`).
### Fatal pattern 1 — Three-sided cold start with zero distribution
AE needs businesses to maintain profiles, assistants to query AE, and humans to produce qualified intent. All three sides are waiting for the other two to make the first move (`local://roast-marketplace.md:461-468`).

Businesses ask how many leads AE sends. Assistants ask why they should query AE instead of search/maps/web. Users ask why they should start at AE when Google, ChatGPT, Gemini, Perplexity, Yelp, Thumbtack, and direct business sites already exist (`local://roast-marketplace.md:94-108`).

This is not a chicken-and-egg problem. This is a chicken-and-egg-and-incubator-and-grocery-store-and-health-inspector problem.

The current launch evidence does not solve it: PM-01 owner pull and PM-02 assistant distribution remain open / unproven, and Phase 1 five-owner activation evidence is still reported as 0/5 (`local://roast-investor.md:65-80`; `.planning/STATE.md:163-170`; `.planning/scopes/PREMORTEM-VALIDATION-GATES.md:27-35`).

A generated catalog is not liquidity. Marketplace supply is responsive counterparties under current conditions, not rows with nice JSON breath mints (`local://roast-marketplace.md:80-110`; `src/modules/dev/internal/dev-seed-fixture.ts:43-82`).

### Fatal pattern 2 — Platform kill zones surround every valuable verb

If AE stays read/compare/inquire, it is too small. If AE later moves toward booking, payment, dispatch, autonomous action, receipts, or commerce execution, it walks into OpenAI/Stripe ACP, Google AP2/Search/Gemini/Maps, Shopify UCP, PayPal/Perplexity, Visa Intelligent Commerce, Mastercard Agent Pay, x402, and Cloudflare bot/payment primitives (`local://research-landscape.md:18-23`; `local://research-landscape.md:180-204`).

Google owns local intent capture, Maps, Business Profile, reviews, calls, directions, ads, and Gemini/AI Search local affordances (`https://blog.google/products-and-platforms/products/search/search-io-2026/`; `https://blog.google/innovation-and-ai/products/gemini-app/gemini-features-for-businesses/`).

OpenAI and Stripe own a plausible ChatGPT-native commerce path through Instant Checkout / ACP, with merchants retaining fulfillment and support (`https://openai.com/index/buy-it-in-chatgpt/`; `https://stripe.com/newsroom/news/stripe-openai-instant-checkout`).

Google AP2, Visa, Mastercard, PayPal, Coinbase x402, and Cloudflare are racing payment authorization, tokenization, settlement, bot identity, and paid machine access (`https://cloud.google.com/blog/products/ai-machine-learning/announcing-agents-to-payments-ap2-protocol`; `https://usa.visa.com/about-visa/newsroom/press-releases.releaseId.22276.html`; `https://www.coinbase.com/en-au/developer-platform/discover/launches/x402`; `https://blog.cloudflare.com/monetization-gateway/`).

AE’s future transaction story is therefore speculative twice: not implemented today, and already inside kill zones where incumbents have distribution, compliance, wallets, merchant bases, and fraud teams (`local://roast-investor.md:100-111`; `local://research-landscape.md:188-198`).

### Fatal pattern 3 — Commodity data with an expensive trust costume

Business-supplied pages, service claims, public facts, schema, `/llms.txt`, action descriptors, and JSON endpoints are formats. Formats are not moats (`local://roast-marketplace.md:260-282`).

If AE only republishes supplied facts, assistants can scrape or retrieve similar facts from websites, Google Business Profile, Yelp, Facebook, vertical directories, schema markup, and ordinary search results (`local://roast-marketplace.md:118-129`).

If AE meaningfully verifies facts, AE inherits manual review, source reconciliation, disputes, stale-data refresh, standards, and owner correction before it has traffic revenue (`local://roast-marketplace.md:114-132`).

If AE uses trust labels without named standards, it recreates the fake-verification theater its own product rules forbid (`PRODUCT.md:42-58`; `local://bones-audit.md:21-24`).

So the trust layer is simultaneously the differentiator and the tax. Lovely. The moat is a toll booth on a road nobody uses yet.

### Fatal pattern 4 — Feature, not company; and the dark `allowWrites:false` write path

Today’s company-shaped thing is mostly a safer directory plus qualified inquiry. The assistant-exposed write path is the funniest possible product-contract gap: `GET /api/agent/tools` lists `inquiry.submit`, the action is `readOnly:false`, but `POST /api/agent/tools` still invokes the harness with `allowWrites:false`, so signed `inquiry.submit` is refused (`src/routes/api.agent.tools.ts:87-115`; `src/modules/inquiries/inquiry.actions.ts:112-130`; `tests/integration/agent-tools-api.test.ts:273-287`).

That means the machine door advertises the first owned conversion and then slams the door on it. It is a haunted contact form.

The human inquiry domain loop has value, but the public agent-facing API is not yet read/compare/send inquiry end-to-end. It is read/compare/discover-the-wall (`local://roast-technical.md:95-110`; `local://bones-audit.md:29-31`).

The product may eventually support a deliberate, signed, admitted, qualified-write path, but that capability is not implemented through the quiet agent door today (`local://ae-orientation.md:48-52`; `local://roast-technical.md:330-346`).

### Fatal pattern 5 — Solo-founder governance apparatus: 311 planning files vs 4 actions

The artifact has 311 `.planning` files and 876,635 planning LOC against 4 registered actions: `inquiry.submit`, `registry.list`, `registry.search`, and `registry.detail` (`local://roast-technical.md:17-49`; `src/modules/actions/index.ts:22-27`).

The planning system is not useless. It prevents public overclaim, keeps proof labels separate, and preserves boundary honesty (`local://bones-audit.md:21-25`; `local://bones-audit.md:78-94`).

But the ratio is deranged: ADR machinery, scopes, gates, summaries, evidence templates, audits, and future rails are piled on top of a product whose live market proof is still owner pull unproven, assistant distribution unproven, deployed smokes blocked, and monetization absent (`local://roast-investor.md:166-181`; `local://roast-technical.md:180-193`).

This is the enterprise architecture for a lemonade stand that has not sold lemonade (`local://roast-investor.md:166-181`).

## 2. The investor case for death

### The zero-thesis

AE wants the valuation story of a protocol, the product surface of a directory, the operational burden of a marketplace, the trust burden of an escrow rail, and the distribution of Google, while currently owning a qualified inquiry path whose assistant write route is not visibly successful through the quiet door (`local://roast-investor.md:8-15`; `.planning/codebase/CONCERNS.md:31-37`).

That is not a company. That is a very carefully labelled hallway (`local://roast-investor.md:8-12`).

The founder has correctly avoided public overclaim. The kill case is that the honest product is too small and the exciting product is not there (`local://roast-investor.md:14-15`).

### Why-now is why-too-late

The internal story says services are still weird and not yet standardized, so AE can become the trust/discovery layer before platforms catch up (`local://roast-investor.md:18-31`).

The market says platforms do not need to solve all services to kill AE. They only need to absorb the monetizable verbs: identity, merchant capability descriptors, authorization, payment, checkout, user intent, and default assistant distribution (`local://research-landscape.md:18-23`; `local://roast-investor.md:18-31`).

OpenAI’s ACP and Stripe’s SPT story already say AI agents and businesses can work together to complete purchases, with merchant-controlled fulfillment and support (`https://openai.com/index/buy-it-in-chatgpt/`; `https://stripe.com/newsroom/news/stripe-openai-instant-checkout`).

Google AP2 frames agent authenticity, user authorization, mandates, and accountability as protocol terrain (`https://cloud.google.com/blog/products/ai-machine-learning/announcing-agents-to-payments-ap2-protocol`).

Shopify / UCP aims at merchant capability discovery and transaction interaction, especially commerce and checkout (`https://ucp.dev/`; `https://shopify.engineering/UCP`).

AE is standing in front of a platform bulldozer saying, “They have not paved this exact driveway yet.” Correct. They own the road (`local://roast-investor.md:18-31`).

### TAM expansion as buzzword inflation

The expanded vision says domestic router / registry / directory across services, goods, software, and tech. The internal product discipline says many broad categories are not admitted or are out of scope because platform-owned retail, SKU procurement, broad agent action catalogs, request markets, developer-platform surfaces, live money, payment, booking, dispatch, and autonomous fulfilment remain out or future-gated (`local://roast-investor.md:35-44`; `local://ae-orientation.md:9-15`).

Once goods, enterprise procurement, platform-owned retail, software/API procurement, institutional commodity flows, and broad transaction rails are excluded or future-gated, the near-term TAM collapses back toward fragmented local SMB services (`local://roast-investor.md:35-44`).

That is a real market. It is not the “ASIC + Stripe + DNS of agentic commerce” fantasy. It is tradies who may or may not answer a free inquiry (`local://roast-investor.md:35-44`).

### The first owned conversion is a contact form with incense

The first owned conversion is qualified inquiry for owner review, not booking, payment, dispatch, or auto-fulfilment (`PRODUCT.md:28-40`; `AGENTS.md:9-49`).

That is ethically correct and commercially weak. It competes with calling, emailing, Google Maps, website forms, marketplace quote flows, and the business’s own booking/contact surfaces (`local://roast-marketplace.md:234-257`).

The machine path then makes it worse by advertising `inquiry.submit` while refusing it through `allowWrites:false` (`src/routes/api.agent.tools.ts:109-115`; `tests/integration/agent-tools-api.test.ts:273-287`).

A company whose primary agentic conversion is a write path the concern file says is not visibly successful is not early. It is pre-sentient (`local://roast-investor.md:47-61`).

### Monetization is future fan fiction until owners pay for outcomes

AE cannot charge consumers for search when Google Maps, Yelp, bundled AI assistants, and review sites are free (`local://roast-investor.md:130-143`).

AE’s wedge pitch is closer to free qualified inquiry / readable by customers’ AI than to a proven paid lead marketplace. That may help supply acquisition, but it postpones revenue into a later owner-pull workflow that is not implemented as a live paid product today (`.planning/scopes/PM-03-launch-wedge-lock.md:32-35`; `.planning/archive/scopes/scope-05-transactions-receipts/SCOPE-05-INDEX.md:8-18`).

Phase 5 / Scope 5 remains source/local or test-mode-gated; live money and production transaction claims remain future-gated (`local://ae-orientation.md:9-15`; `local://roast-investor.md:130-143`).

Thumbtack, hipages, Airtasker, Oneflare, and Angi show lead/connection economics can monetize, but they monetize through the exact take-rate / lead-fee / subscription mechanics that generate provider complaints (`local://research-demand.md:71-93`; `local://research-demand.md:95-103`).

AE wants to avoid the poison. Unfortunately the poison is also the revenue (`local://roast-investor.md:140-145`).

### One founder, six costumes, no oxygen

The system spans TanStack Start, Convex, Clerk, Astryx, OpenRouter, Web Bot Auth, optional Meilisearch, Autumn/Stripe, Resend/Novu, Sentry/PostHog, deploy smokes, agent-experience harnesses, copy scans, SEO scans, eval harnesses, and future action/receipt rails (`local://ae-orientation.md:18-23`; `local://roast-investor.md:185-200`).

The codebase concerns name large high-blast-radius modules: `convex/inquiries.ts`, `turn-orchestrator.ts`, protected-action/contact-follow-up code, inquiry commands, `convex/registry.ts`, and `convex/discovery.ts` (`.planning/codebase/CONCERNS.md:13-18`; `local://roast-technical.md:262-272`).

One founder can build a sharp wedge. One founder cannot simultaneously be Google Business Profile, Stripe risk, Yelp SEO, Thumbtack ops, Convex platform engineer, trust-and-safety, and the sales team (`local://roast-investor.md:185-200`).

Pick one costume. AE is currently wearing the closet.

### The investor kill sentence

AE is not killed by a bad idea. It is killed by a good idea arriving with the wrong company shape (`local://roast-investor.md:354-373`).

There is real pain: fragmented local services have trust failures. There is a real future: agents may need safer ways to interact with businesses. AE’s mistake is trying to turn those truths into a horizontal registry before proving anyone will use the first narrow loop twice (`local://roast-investor.md:354-373`).

The product is currently a trustworthy directory with a qualified-inquiry button. The vision is a domestic agentic-commerce operating system. The distance between those two is where startups go to become well-structured PDFs (`local://roast-investor.md:360-373`).

## 3. The marketplace-economics case for death

### Mechanism: three-sided liquidity deadlock

AE’s loop needs suppliers, assistants, and humans to compound: businesses maintain listings; AE has fresher supply; assistants query AE; humans receive better recommendations; inquiries happen; owners see value; owners update more (`local://roast-marketplace.md:49-74`).

Every arrow is weak. Publishing `/llms.txt` is not distribution. A tool list is not a channel. A generated seed catalog is not live supply. A qualified inquiry is not guaranteed response (`local://roast-marketplace.md:64-74`).

The loop lacks forced motion: no captive demand, no captive supply, no mandated standard, and no narrow transaction loop where AE controls an outcome incumbents cannot (`local://roast-marketplace.md:80-110`).

### Mechanism: verification-cost moat inversion

AE’s trust promise is source, freshness, boundary, refusal discipline, and no fake verification (`PRODUCT.md:42-58`; `local://roast-marketplace.md:114-132`).

That promise becomes more expensive as it becomes more real. Hours decay. service areas decay. licenses expire. phone numbers change. response times lie. owners churn. staff changes. prices move. availability is a weather system with a phone number (`local://roast-marketplace.md:118-129`).

Unverified supplied facts are commodity. Verified facts require labor. Semi-verified language creates reputational risk (`local://roast-marketplace.md:469-473`).

AE’s trust moat therefore starts as a trust tax. The bill arrives before the customers.

### Mechanism: demand-side aggregation power

Under Aggregation Theory, the winner owns demand, then modularizes suppliers. AE starts as supplier-side infrastructure without demand ownership (`https://stratechery.com/2015/aggregation-theory/`; `local://roast-marketplace.md:136-164`).

ChatGPT, Gemini, Perplexity, Google Search/Maps, Amazon, Yelp, Thumbtack, and vertical marketplaces already sit closer to the recommendation moment (`local://research-landscape.md:108-130`).

Google Maps Grounding exposes up-to-date Google Maps information from 250M+ businesses and places to generative AI apps, which is exactly incumbent local-data gravity with an API helmet (`https://developers.googleblog.com/en/your-ai-is-now-a-local-expert-grounding-with-google-maps-is-now-ga/`; `local://roast-marketplace.md:24-25`).

If demand aggregators need structured facts, AE is a feed. Feeds get cached, scraped, priced down, swapped out, and ignored (`local://roast-marketplace.md:155-164`).

### Mechanism: incumbent registry gravity

For local/domestic services, Google Business Profile is the practical default registry because it is tied to Search, Maps, reviews, calls, directions, ads, analytics, and now AI grounding (`local://roast-marketplace.md:167-188`; `https://developers.google.com/my-business/content/faq`).

Yellow Pages did not lose because directories are impossible. It lost because local intent moved into search/maps (`local://roast-marketplace.md:442-457`; `https://ueni.com/blog/yellow-pages-are-dead/`).

DMOZ did not close because humans forgot categories. It closed because humans organizing the web could not compete with search-scale update velocity (`https://searchengineland.com/dmoz-has-officially-closed-271530`; `local://roast-marketplace.md:442-457`).

AE starts inside the incumbent fortress and calls it a wedge. A plumber does not need an agent-native philosophical layer. The plumber needs the phone to ring (`local://roast-marketplace.md:167-188`).

### Mechanism: empty-switchboard circularity

A router is an equilibrium, not a starting label. It needs endpoints, originators, resolution rules, reliability, endpoint freshness, and repeated use (`local://roast-marketplace.md:191-230`).

AE’s router sequence currently says: seed listings, publish machine-readable files, persuade assistants, generate inquiries, persuade businesses, improve ranking, grow demand, become default (`local://roast-marketplace.md:206-224`).

That is not a bootstrap plan. That is drawing the trophy and calling it training.

Routers with no traffic are registries. Registries with no privileged demand are databases. Databases with commodity data are lead lists (`local://roast-marketplace.md:226-230`).

### Mechanism: marketplace leakage

Qualified inquiry introduces the parties but does not own booking, payment, fulfillment, dispute, review, repeat purchase, or the relationship (`local://roast-marketplace.md:234-257`).

If AE works once, the user and business can bypass AE next time. If AE does not work, they do not return either (`local://roast-marketplace.md:250-257`).

Marketplaces fight leakage with payments, escrow, insurance, booking workflow, reputation, support, repeat demand, or workflow lock-in. AE intentionally does not yet claim those capabilities (`AGENTS.md:14-28`; `local://ae-orientation.md:3-15`).

That makes the current conversion safe enough to ship and too weak to anchor market power (`local://roast-marketplace.md:376-393`).

### Mechanism: data network effect threshold

AE’s future defensible data would be interaction histories, receipts, corrections, response outcomes, trust events, and ranking signals (`local://roast-marketplace.md:260-282`).

Those become valuable only after AE owns enough flow. AE needs differentiated demand to get proprietary interactions, and it needs proprietary interactions to become differentiated (`local://roast-marketplace.md:278-282`).

This is the data moat arriving after the moat was needed. Extremely punctual for a ghost.

### Mechanism: adverse selection / lemons market

High-quality providers often already have demand: word of mouth, Google reviews, repeat customers, SEO, paid ads, vertical marketplaces, and local reputation (`local://roast-marketplace.md:286-308`).

Early participants in a low-traffic new registry may skew toward weak demand, SEO directory-chasers, low-quality operators, lead brokers, or novelty scammers (`local://roast-marketplace.md:290-304`).

Preventing that requires review, verification, dispute handling, ranking discipline, and sometimes saying no. That adds trust cost before revenue (`local://roast-marketplace.md:302-308`).

The early supply most willing to participate may damage the trust brand before good supply arrives (`local://roast-marketplace.md:306-308`).

### Mechanism: tool-discovery bottleneck

Agent-readable formatting is necessary for agents. It is not sufficient for discovery, trust, ranking, repeat calls, or default use (`local://roast-marketplace.md:312-324`).

Assistants compress choices and hide intermediate sources. They have latency budgets, tool catalogs, platform incentives, source-ranking heuristics, and safety policies (`local://roast-marketplace.md:316-324`).

AE may become perfectly readable and still absent from assistant behavior (`local://roast-marketplace.md:322-324`).

### Mechanism: category heterogeneity tax

A cross-category domestic router must handle incompatible trust units: service area / licenses / insurance for local services; SKU / stock / returns for goods; auth / uptime / data processing for software; certifications / SLAs / deliverables for tech services (`local://roast-marketplace.md:328-345`).

The more horizontal AE becomes, the shallower the trust layer gets. The more vertical the trust layer gets, the more unrelated cold starts AE must run (`local://roast-marketplace.md:341-345`).

“Domestic router” risks being a strategy-shaped abstraction over many different markets that all have their own incumbent gravity (`local://roast-marketplace.md:343-345`).

### Mechanism: supplier ROI ranking

Owners maintain channels by visible lead flow: Google/Maps, website, phone/SMS/social, vertical marketplaces, ads, reputation tools, and finally niche directories/backlinks (`local://roast-marketplace.md:349-372`).

AE asks for stricter listing work before it can prove stricter demand. Expected AE leads times close rate times margin must beat maintenance time, trust friction, compliance overhead, and support burden (`local://roast-marketplace.md:362-370`).

Until expected AE leads are visible, rational owners under-maintain. Under-maintenance damages freshness. Damaged freshness damages trust. Damaged trust damages assistant/user reasons to use AE (`local://roast-marketplace.md:364-372`).

Congratulations: the maintenance flywheel is a paper shredder.

## 4. The technical case for death

### 4.2 The flagship assistant write is listed and refused

Action registry includes `submitInquiryAction`, `registryListAction`, `registrySearchAction`, and `registryDetailAction` (`src/modules/actions/index.ts:22-27`).

The quiet tool filter returns actions whose surfaces include `agentTools` (`src/modules/actions/index.ts:35-37`).

`inquiry.submit` is `readOnly:false` with `surfaces: ['agentJson', 'agentTools']` (`src/modules/inquiries/inquiry.actions.ts:127-130`).

`POST /api/agent/tools` verifies Web Bot Auth identity and records it if present, then still invokes `runHarnessTool` with `allowWrites:false` (`src/routes/api.agent.tools.ts:87-115`).

The harness maps `allowWrites !== true` to public-read mode (`src/modules/harness/tool-policy.ts:39-47`).

Approval policy permits `inquiry.submit` only in `public-qualified-write` mode and otherwise refuses with source-write policy errors (`src/modules/harness/approval-policy.ts:60-64`; `src/modules/harness/approval-policy.ts:121-128`).

The integration test asserts signed `inquiry.submit` returns `403 agent_tools_refused`, and the suite passed: 17 tests passed (`tests/integration/agent-tools-api.test.ts:273-287`; `local://roast-technical.md:52-63`).

Demolition read: the first assistant-exposed write is not end-to-end implemented at the quiet door. That is not a missing polish item. That is a product-contract pothole with lights.

Demolition read: the planning corpus has value, but the planning-to-market-proof ratio screams process drag before traction (`local://roast-technical.md:180-193`).

### 4.8 Stack and bus-factor risk arrived before live demand

Critical path includes Convex as source of truth, TanStack Start/Router, Astryx 0.1.x, Nitro nightly for Vercel output, and TypeScript/Vite future versions (`package.json:54-100`; `vite.config.ts:50-70`; `convex/schema.ts:1-33`).

Vite bundles Astryx for SSR because Astryx dist uses extensionless relative imports (`vite.config.ts:50-54`).

Design policy is Astryx-first while retired AE presentation remains active as legacy surface (`DESIGN.md:8-43`; `.planning/codebase/CONCERNS.md:5-12`).

Demolition read: these may be valid technical bets, but they are non-boring bets before PM-01/PM-02 are proven (`local://roast-technical.md:196-211`).

### 4.9 Discovery generation has a known scale cliff

`/llms.txt` calls `readPublicLlmsTxt`, which calls Convex `discovery:readLlmsTxt` (`src/routes/llms[.]txt.ts:18-23`; `src/modules/discovery/discovery.functions.ts:20-58`).

Convex `readLlmsTxt` builds from all published businesses; `publicCatalogsForDiscovery` queries all `businesses` with publicStatus `published` and maps each through context/services/capabilities/status lookups (`convex/discovery.ts:355-365`; `convex/discovery.ts:606-667`).

Existing concerns document the same catalog-wide rebuild per request as a performance bottleneck (`.planning/codebase/CONCERNS.md:65-72`; `.planning/codebase/CONCERNS.md:111-117`).

Demolition read: okay for seed/demo; not obviously okay for domestic-router scale without persisted artifacts or bounded digest reads (`local://roast-technical.md:214-228`).

### 4.10 Copy-scan compliance is carrying product-risk luggage

ADR-006 says copy/SEO/parity tests prove AE says the right thing, not that assistants behave accordingly (`.planning/adr/ADR-006-agent-experience-audit-gate.md:7-29`; `.planning/adr/ADR-006-agent-experience-audit-gate.md:48-61`).

CI heavily gates copy/SEO/UI/import/source scans, while deployed outside-in agent audit remains blocked (`.github/workflows/eval-gate.yml:41-53`; `.planning/scopes/scope-01-production-landing/01-05-agent-experience-audit-gate-PLAN.md:97-106`).

Demolition read: scans are necessary guardrails. They are not cold-assistant market behavior (`local://roast-technical.md:231-244`).

### 4.11 Public-prefixed local fixture bypass is a footgun

Server code branches on `VITE_AE_DISABLE_CLERK_FOR_LOCAL_E2E` to use fixture discovery/registry/inquiry paths (`src/modules/discovery/discovery.functions.ts:44-63`; `src/modules/inquiries/inquiry.functions.ts:826-903`).

Production guards exist, but the variable is public-prefixed and broad enough to touch auth/source-write/fixture behavior (`.planning/codebase/CONCERNS.md:53-57`).

Demolition read: not a demonstrated production bypass; absolutely an operational smell (`local://roast-technical.md:247-259`).

### 4.12 Large modules hide multiple jobs in one room

`convex/inquiries.ts` is 2627 lines; `turn-orchestrator.ts` 1819; `contact-follow-up.ts` 1801; `commands.ts` 1603; `convex/registry.ts` 1590; `convex/discovery.ts` 1502 (`.planning/codebase/CONCERNS.md:13-18`).

`convex/discovery.ts` alone contains validators, owner mutations, auth checks, table reads, catalog readers, DTOs, health/readback, and file builders (`convex/discovery.ts:1-263`; `convex/discovery.ts:355-779`).

Demolition read: manageable while one author holds the map; brittle when the product keeps shapeshifting from local directory to cross-category domestic router (`local://roast-technical.md:262-272`).

## 5. The market's verdict

### Verdict: AI discovery is real; AE demand is not yet proven

Adobe says generative-AI referral traffic to U.S. retail sites grew 4,700% YoY in July 2025, and later reported holiday 2025 AI-driven retail traffic up 693.4% YoY with AI referrals converting 31% more than other traffic sources (`https://business.adobe.com/blog/generative-ai-powered-shopping-rises-with-traffic-to-retail-sites`; `https://business.adobe.com/blog/ai-driven-traffic-surges-across-industries`).

BrightLocal says AI tools became the third most used source for local business recommendations, with AI use for local recommendations rising from 6% in 2025 to 45% in 2026 (`https://www.brightlocal.com/research/local-consumer-review-survey/`; `local://research-demand.md:23-27`).

That supports AI-assisted discovery. It does not prove AE as the registry. Consumers can already ask ChatGPT, Gemini, Perplexity, Google, Reddit, review platforms, and vertical marketplaces for summaries (`local://research-demand.md:133-140`).

The market’s verdict is: the behavior exists, but AE does not own it.

### Verdict: consumers fact-check agents, which helps the thesis and kneecaps autonomy

BrightLocal found 88% of local-AI users check review legitimacy/source and 97% sometimes double-check against real reviews (`local://research-demand.md:23-27`; `https://www.brightlocal.com/research/local-consumer-review-survey/`).

Bain / ROI Rocket found 72% had used AI tools, but only 10% had bought something using AI in any form, and only 24% felt comfortable using AI to complete purchases (`https://www.bain.com/insights/agentic-ai-commerce-hinges-on-consumer-trust/`).

Forrester independently reports only 24% of U.S. online adults trust AI agents to act on their behalf for routine purchases (`https://www.forrester.com/report/many-us-consumers-believe-in-agentic-commerce-but-few-trust-it-to-make-purchases/RES188737`).

This supports AE’s source-backed inquiry boundary and destroys any near-term story that autonomous local hiring is ready for broad claims (`local://research-demand.md:107-119`).

AE’s honest boundary is strategically sane. It is also why the product is commercially small today.

### Verdict: SMB supply will not maintain agent-readable surfaces for vibes

Casey Burridge’s 2026 `llms.txt` analysis reports 5.61% of top 10,000 sites and 5.07% of top 1,000,000 had valid `llms.txt`, with top-10k adoption rising from 1.04% in July 2025 to 5.61% in June 2026 (`https://caseyrb.com/blog/state-of-llms-txt-adoption/`).

The same analysis says Shopify had 78.1% adoption because Shopify pushed `llms.txt`, `llms-full.txt`, `agents.md`, and related endpoints by default (`https://caseyrb.com/blog/state-of-llms-txt-adoption/`).

That is platform-pushed adoption, not SMB enlightenment.

OpenAI and Perplexity merchant programs show supply appetite for structured feeds where AI platforms aggregate demand (`https://chatgpt.com/merchants/`; `https://www.perplexity.ai/hub/blog/shop-like-a-pro`).

Australian SME evidence is harsher: National AI Centre data says 43% of Australian SMEs report some AI adoption, but among non-adopters about 65% cite distrust / preference for human control, 54% say AI is not relevant, and 19% do not know how to use it (`https://www.ai.gov.au/news-and-insights/blog/ai-adoption-insights-december-2025-february-2026`).

Local SMBs will maintain AE profiles if AE sends work or a platform abstracts the maintenance. They will not maintain schemas because the file format has nice posture (`local://research-demand.md:55-68`).

### Verdict: AU local-services economics are real, but incumbents already monetize the pain

hipages FY25 reports A$83.1m total revenue, A$80.8m recurring revenue, A$7.4m MRR, 36.6k subscription tradies, 1.382m jobs, and 2.8m tradie-homeowner connections (`https://announcements.asx.com.au/asxpdf/20250822/pdf/06n5s3y9lqpx9j.pdf`).

Airtasker FY25 reports A$45.0m marketplace revenue, A$208.7m GMV, 835,647 booked tasks, average task price A$250, and 21.6% monetisation rate (`https://announcements.asx.com.au/asxpdf/20250828/pdf/06nhm6dp7f5rfz.pdf`).

Oneflare’s quoting-credit model confirms pay-to-contact is an accepted unit in local services (`local://research-demand.md:85-93`).

CHOICE warns consumers that tradie platforms vary on trust, insurance, reviews, guarantees, and independent credential checking (`https://www.choice.com.au/home-improvement/building-and-renovating/design-and-trades/articles/find-a-tradie-websites`).

ProductReview complaints around hipages, Airtasker, and ServiceSeeking mention speed as a pro but lead quality, fees, transparency, vetting, support, no-shows, and trust problems as recurring pain (`https://www.productreview.com.au/listings/home-improvement-pages`; `https://www.productreview.com.au/listings/airtasker`; `https://www.productreview.com.au/listings/serviceseeking-com-au`).

So the pain is real. The market’s verdict is not “no market.” It is “the market already punishes amateurs here.”

### Verdict: platform-owned commerce is advancing faster than neutral registry proof

OpenAI’s product-discovery and merchant pages name live shopping discovery, product feeds, merchant-owned checkout, Shopify/Etsy catalogs, and a planned self-serve merchant platform (`https://openai.com/index/powering-product-discovery-in-chatgpt/`; `https://chatgpt.com/merchants/`).

Perplexity’s shopping release describes product cards, Snap to Shop, Shopify-powered product info, Buy with Pro, and merchant programs (`https://www.perplexity.ai/hub/blog/shop-like-a-pro`).

Google Search I/O 2026 says Search agents can help with local experiences/services, retrieve pricing/availability, link out for booking, and in select categories call businesses on the user’s behalf (`https://blog.google/products-and-platforms/products/search/search-io-2026/`).

Yelp, Thumbtack, Angi, and hipages are adding AI to existing local-marketplace loops rather than waiting for a neutral directory (`https://blog.yelp.com/news/spring-product-release-2026/`; `https://press.thumbtack.com/announcements/thumbtack-launches-as-home-services-collaborator-for-openais-new-operator/`; `https://ir.angi.com/news-releases/news-release-details/angi-launches-new-ai-helper-it-celebrates-30-years-innovation`; `https://www.salesforce.com/au/customer-stories/hipages/`).

The market’s verdict: AI-commerce demand is being captured at the front door, not donated to clean registries.

### Verdict: white space exists, but it is narrow and mean

No surveyed source credibly owns a wedge-agnostic, cross-sector registry that tells agents what a business is, what it may safely do, what it cannot do, what evidence backs its claims, and what receipt proves what happened (`local://research-landscape.md:152-176`).

That is the real white space.

It is not “be ChatGPT checkout.”

It is not “be Google local.”

It is not “be Visa for agents.”

It is not “be Cloudflare for bot access.”

It is a small, hard, trust/discovery/receipt seam for boundary-explicit business profiles that assistants outside dominant platforms might read (`local://research-landscape.md:208-213`).

That could survive. But as of today, it is speculative beyond read/compare/qualified-inquiry, and it has not proven owner pull, assistant distribution, deployed agent-experience, or monetization (`local://ae-orientation.md:167-178`; `local://research-demand.md:143-166`).

## 6. What survives the fire

A roast that pretends nothing survives is dishonest. The bones audit found real assets. Keep these eight; burn the fantasy around them.

1. **Boundary-honest trust contract plus scans.** AE’s differentiated asset is not “has listings”; it is the discipline of telling humans and agents exactly what is known, unknown, unavailable, and not allowed, backed by copy scans (`local://bones-audit.md:78-81`; `PRODUCT.md:7-14`; `AGENTS.md:7-28`; `tests/copy/phase1-banned-copy.test.ts`).

2. **Action contracts as the single machine-operation source.** `defineAction` plus central `src/modules/actions/index.ts` is the correct seam for HTTP, agent JSON, quiet tools, UI affordances, harness tools, tests, and future surfaces (`local://bones-audit.md:82-83`; `src/modules/common/action.ts:27-128`; `src/modules/actions/index.ts:1-37`).

3. **Public catalog/search/detail read model and DTO discipline.** `registry.search`, `registry.detail`, `/api/businesses*`, published-only filtering, suppression awareness, and private-field bans are the actual directory substrate (`local://bones-audit.md:84-85`; `src/modules/registry/registry.actions.ts:230-280`; `tests/integration/registry-api.test.ts:176-349`).

4. **Assistant discovery door.** `/llms.txt`, `/api/agent/tools`, UCP fallback, robots, sitemap, and discovery schema parity are the agent-native front door; keep it, but fix or remove the listed-but-blocked write (`local://bones-audit.md:86-87`; `src/routes/llms[.]txt.ts:18-24`; `src/routes/api.agent.tools.ts:39-115`).

5. **Source-owned Convex/module seam and readback model.** Module-owned schema fragments, source-state reconstruction, source-write admission, and readback/repair are reusable platform infrastructure; cut the tables/features ahead of proof (`local://bones-audit.md:88-89`; `convex/schema.ts:1-33`; `convex/source_state.ts`).

6. **Answer thread + harness evidence spine.** Thread-first `/t/$threadId`, tool-call persistence, public projection redaction, harness run summaries, and eval gates are more valuable than the current presentation layer (`local://bones-audit.md:90-91`; `.planning/ANSWER-AI-CONTRACT.md:77-136`; `src/modules/harness/public.ts:1-198`).

7. **Qualified inquiry domain loop.** Submit → owner inbox → owner reply/close → audit/funnel redaction is a real first action pattern in pure domain code; it just must not be counted as deployed/agent-completable until the quiet-door write path and provider/deploy smokes pass (`local://bones-audit.md:92-93`; `src/modules/inquiries/internal/commands.ts`; `.planning/archive/phases/02-human-inquiry-owner-inbox/02-DEPLOY-SMOKE-BLOCKERS.md:96-129`).

8. **Outside-in agent-experience audit harness.** This is rare and valuable because it measures whether unbriefed agents can discover AE, respect boundaries, and recover from write walls; keep it as a release gate, not as a one-off trophy (`local://bones-audit.md:94-94`; `examples/agent-experience/README.md:1-69`; `examples/agent-experience/score.ts:1-60`).

## Final demolition

AE’s strongest surviving company is not the domestic agentic-commerce operating system. It is a narrow, honest, source-backed, assistant-readable business trust registry with qualified-inquiry receipts.

That phrase is less sexy because it is less fraudulent.

The platform world will own front doors, payments, bot access, and many transaction verbs. The marketplaces will own category-specific demand and provider monetization. The local incumbents will own review gravity. The standards bodies and platform alliances will commoditize the generic agent-readable surfaces.

What AE may still own is a disciplined proof seam: business-supplied but boundary-labelled facts, action-scoped machine operations, source-backed readbacks, and receipts that say what happened without pretending AE did more than it did.

That is a smaller company than the vision deck wants.

It might be the only honest one left.
