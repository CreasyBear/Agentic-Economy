## Numbered T33 cutover security gate checklist

The cutover plan is a widen–migrate–narrow migration from a short-lived engine plan to project-lifetime trees, with expiry fences, bounded journal reads, and thread-scoped reads (`.planning/wayfinder/tickets/T33-cutover-migration.md:7-11`; `.planning/wayfinder/MAP-framework.md:96-104`). The following gates are required before `/` swaps to the framework:

1. **Canonical identity and authorization.** T36's account/anonymous/shared-access decision is recorded; every project row is bound to the canonical Customer Request/thread and authenticated person; agent identity never substitutes for person authority; cross-project reads/writes and workflow-ID reads are refused (`.planning/wayfinder/tickets/T36-identity-and-continuity.md:7-11`; `convex/projectSpine.ts:104-126`; `src/modules/project-spine/internal/convex-schema.ts:6-27`).
2. **Generation/revision CAS.** Every mutation carries and checks expected generation/revision plus a canonical command/proposal digest. Stale and future generations refuse; duplicate commands are idempotent; replay/concurrent `advanceGeneration` cannot cancel a newer workflow or create an unbounded generation chain (`convex/projectSpine.ts:131-195`; `convex/projectSpine.ts:421-434`; `.planning/wayfinder/MAP-framework.md:118-126`).
3. **Event authenticity and injection resistance.** Decisions are accepted only through an authenticated, authority-bound command; the event payload is bound to project, generation, charter/plan digest, and actor; operation-key reuse with a different payload is refused; one decision is consumed once; all outcomes are journaled (`convex/projectSpine.ts:50-59`; `convex/projectSpine.ts:219-259`; `convex/projectSpine.ts:436-449`).
4. **Migration data and cursor proof.** A fixture migrates old engine plans/events to the new tree and proves append-only history, quote revision links, bounded reads, and thread-scoped access. Existing durable data is retained; old cursors are either explicitly translated or rejected with a deterministic restart cursor—never silently interpreted against a different table/order. Rollback cancels only newly started workflows and restores the prior definition/read model without deleting old events (`convex/projectSpine.ts:334-361`; `convex/projectSpine.ts:388-413`; `.planning/wayfinder/MAP-framework.md:96-104`).
5. **Web evidence quarantine.** Routing V1 quarantine remains retired/isolated: the legacy quarantine table is only a routing-kernel schema contract (`src/modules/routing-kernel/internal/convex-schema.ts:279-295`) and V1 paths return an uncacheable 410 (`src/modules/routing-kernel/retirement.ts:1-21`). It therefore does **not** automatically protect active answer/proposal paths. The answer path must prove inert web evidence, bounded fields, citation provenance, no web-derived allowed slugs/providers, and injection fixtures at every model boundary (`src/modules/answer/internal/answer-llm-prompts.ts:35-50`; `src/modules/answer-thread/internal/tool-runner.ts:214-223`; `src/modules/answer-thread/internal/turns/proposal.ts:341-375`).
6. **Storefront claim admission.** Website and search imports remain `draft_unconfirmed`, carry source labels/evidence refs, and cannot publish or trigger booking/charge/dispatch until owner review and source-write admission (`src/modules/storefront/internal/import-draft.ts:280-304`; `src/modules/storefront/internal/business-enrichment.ts:403-415`; `src/modules/storefront/storefront.actions.ts:180-189`). Hostile metadata, citations, URL schemes, and instruction strings have focused fixtures.
7. **Gardener adversarial gate.** For all three verbs—`elaborate`, `study`, and `propose_decision`—the kernel rejects non-menu actions, cyclic graphs, replay/mismatched nonce or digest, stale generation/revision, non-frontier targets, invalid transitions, and budget/depth/op-count overflow before dispatch. T15's typed refusal cases are green (`tests/unit/plan-proposal/proposal-contract.test.ts:127-145`, `tests/unit/plan-proposal/proposal-contract.test.ts:231-238`; `.planning/wayfinder/tickets/T15-ai-sdk-adoption-gate.md:14-21`; `.planning/wayfinder/tickets/T28-gardener-verbs-contract.md:7-11`).
8. **Mandate and effect fence.** A consequential action cannot release without exact accepted authority: person/agent actor, mandate scope/version/generation/use, target and material-input digest, spend/data limits, expiry/revocation, and grant evidence. A changed quote, provider, price, input, or generation requires a new approval (`src/modules/action-invocation/internal/convex-schema.ts:81-107`; `src/modules/action-invocation/contracts.ts:11-42`; `src/modules/action-invocation/dynamic-published-execution.ts:361-375`).
9. **Money replay/refund gate.** Focused tests prove idempotency mismatch refusal and reconciliation for charges/top-ups/payouts, exact original-charge refund binding, no double reversal, sufficient ledger legs, and unknown-outcome handling (`convex/moneyLedger.ts:171-184`; `convex/moneyLedger.ts:249-277`; `convex/moneyLedger.ts:301-327`; `convex/moneyLedger.ts:378-433`).
10. **Supply-chain, secret, and verification gate.** The five direct dependencies have reviewed manifest/lockfile/integrity pairs (`package.json:60`, `package.json:90-93`; `package-lock.json:2059-2063`, `package-lock.json:14525-14529`, `package-lock.json:15372-15413`); lockfile-only install and focused dependency checks pass; all 54 exposed keys are rotated with Stripe and Resend first (`.planning/wayfinder/tickets/T37-delivery-pipeline-and-repo-protocol.md:32-36`); and focused differential/adversarial tests plus the cutover smoke pass. No project-wide green claim substitutes for these focused proofs (`.planning/wayfinder/tickets/T33-cutover-migration.md:7-11`).

## Rollback statements

- **Spine/generation rollback:** stop the new framework entry point, refuse new-generation commands, cancel and clean only workflows started by the cutover, and serve the prior definition/read model from retained rows/events. Do not delete the old journal; its retention/read-boundary distinction is explicit in `convex/projectSpine.ts:388-413` and `convex/projectSpine.ts:454-460`.
- **Study/proposal rollback:** disable the proposal flag and return deterministic retrieval/boundary copy; preserve imported evidence as review-only records and do not reinterpret it as catalog supply. The answer finalizer and provider-grounding seam remain available (`src/modules/answer-thread/internal/answer-turn-safety.ts:18-40`; `src/modules/answer/internal/catalog-grounding.ts:14-36`).
- **Gardener rollback:** reject all new verb proposals at the kernel boundary and leave the prior tree revision authoritative; do not replay queued proposals after re-enable. T28 requires one mutation to compare expected generation/revision and proposal digest before apply (`.planning/wayfinder/tickets/T28-gardener-verbs-contract.md:42-45`).
- **Commerce rollback:** halt release/refund dispatch, retain pending/unknown transactions for reconciliation, and keep existing idempotency/refund guards active; never “retry by changing the key.” The source already refuses missing evidence/reconciliation states (`convex/moneyLedger.ts:378-433`).
- **Secrets/dependency rollback:** revoke any suspect key or dependency release, restore the last reviewed lockfile, and block deployment until rotation and provenance review are complete (`.planning/wayfinder/tickets/T37-delivery-pipeline-and-repo-protocol.md:32-36`; `package-lock.json:2059-2063`).
