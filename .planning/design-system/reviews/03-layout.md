# Layout Review — Agentic Economy Design System
**Analysis Date:** 2026-09-01
**Lens/Skill:** better-layout — `.claude/skills/better-layout/SKILL.md`
**Scope:** `.planning/design-system/LAYOUT.md`, `FOUNDATIONS.md` (Space & layout), `CONVENTIONS.md` (Density and surface rules), `PATTERNS.md`, and `CONCERNS.md`; verified against `DESIGN.md`, `.planning/BRAND.md`, `src/styles/globals.css`, `src/styles/base.css`, the public/operator/chat layout components, market rows/table/inspector/compare surfaces, and the mapped owner editor. The full color, typography, accessibility, and motion systems were not reviewed except where they directly affect layout.

## Scope and Coverage

This review treats the system as one market terminal with three reading densities: Public introduces and orients, Market supports fast comparison, and Operator supports persistent work. I inspected the shell seams (`AePublicShell`, `AePublicPage`, `AePageHeader`, `AeOperatorShell`, `AeOperatorSidebar`, `AeOwnerMobileNavigation`, `AeChatPage`), the shared `Sidebar`/`SidebarInset` behavior, `AeSection`/`AeRecordHeader`, operation inspection and continuation, market rows/tables/compare tray, and the owner access-route editor where the map records surface-density drift.

The strongest implementation pattern is semantic composition rather than theme duplication. Public navigation uses `ae-nav`; content uses `ae-rail`; Market uses structural `AeCapabilityTile`/`AeOperationCard` rows and `AeOperationTable`; and the Operation inspector puts the valid continuation before technical detail on small screens. The spacing authority is explicit (`8 → 16 → 32 → 48 → 72 → 96`, with `44px` touch targets), and the three surface levels are clear. The review finds several implementation divergences that make those rules less reliable at responsive boundaries.

## Verdict summary

The direction is coherent and distinctive: Public is generous without becoming a generic landing-page grid, Market is dense and comparison-led, and Operator is structurally persistent. `AePublicShell` supplies the floating `rounded-nav`/`bg-container` navigation; `AeOperatorShell` preserves navigation and orientation through child loading/error states; `AeOperationInspector` preserves the identity → price/readiness → evidence → contract/effects → next-action order; and `AeOperationTable` keeps aligned facts in a table instead of turning dense data into cards.

The main changes needed are in the shared geometry contract: Operator currently renders a flat split rather than the locked inset well; mobile Operator content always reserves owner-nav height; comparison reserves much more bottom space than its fixed tray needs; the full inspector switches layout after hydration; reusable layout primitives bypass the named spacing ladder; and one owner editor is box-heavy. Fold utilities and header measurements also need reconciliation before they are treated as dependable APIs.

## Verification

Checked the following source and map evidence statically:

- `DESIGN.md` and `.planning/BRAND.md`: three modes, semantic row/table rule, three surface levels, inset Operator well, spacing/density constraints, and 44px touch target.
- `.planning/design-system/LAYOUT.md`, `FOUNDATIONS.md`, `CONVENTIONS.md`, `PATTERNS.md`, and `CONCERNS.md`: documented rails, spacing ladder, fold behavior, shell composition, progressive disclosure, and known divergences.

- `src/components/ae/layout/AePublicShell.tsx`, `AePublicPage.tsx`, `AePageHeader.tsx`, `AeOperatorShell.tsx`, `AeOperatorSidebar.tsx`, `AeOwnerMobileNavigation.tsx`, `AeChatPage.tsx`, `AeSection.tsx`, `AeRecordHeader.tsx`, `AeRecordSheet.tsx`, `AeOperatorRouteStates.tsx`: shell ownership, safe-area padding, sticky/fixed surfaces, rail application, and route-state preservation.
- `src/components/ui/sidebar.tsx`, `src/hooks/use-mobile.ts`, and `node_modules/tailwindcss/index.css`: `SidebarInset` variant behavior, 768px `useIsMobile` threshold, `md` at 48rem, `lg` at 64rem, and the 0.25rem base spacing used for the header arithmetic.
- `src/components/ae/market/AeMarketPage.tsx`, `AeOperationCard.tsx`, `AeOperationTable.tsx`, `AeOperationInspector.tsx`, `AeOperationContinuation.tsx`, `AeCompareTray.tsx`, and `src/components/ae/website/AeSiteSection.tsx`/`AeSiteType.tsx`: market structure, progressive detail, responsive branches, tray clearance, and actual spacing consumers.
- Existing viewport-test source: `tests/e2e/a11y/engine-product-a11y.spec.ts:45-50` checks document width against the active viewport; `tests/e2e/a11y/developer-discovery-a11y.spec.ts:5-32` explicitly checks 375px width and horizontal overflow; `tests/e2e/a11y/operator-shell-a11y.spec.ts:14-16` checks width at the configured default viewport.

**Not verified:** no browser-driven visual pass was run in this read-only review. The map/test sources provide a 375px smoke and generic no-horizontal-overflow checks, but no explicit 320px case, 200% zoom case, or RTL/mirrored-layout case. Actual safe-area behavior, tray height under real text growth, hydrated inspector reflow, and final rendered inset geometry still need a browser matrix at 320px, 375px, 768px, 1024px, desktop width, and 200% zoom.

## Recommendations (priority order)

1. Repair the Operator hierarchy by selecting the existing `inset` sidebar variant, then verify the desktop well, collapsed sidebar, mobile Sheet, and owner bottom-navigation combination.
2. Make bottom clearance conditional on the actual owner mobile navigation; remove the unconditional 4rem reservation from admin/developer and suppressed-owner surfaces.
3. Replace the compare tray's `pb-96`/`pb-72` reservation with measured, safe-area-aware clearance tied to the fixed tray.
4. Remove the inspector's post-hydration branch swap through a CSS-responsive or stable media-query layout seam.
5. Migrate reusable layout stacks from `mt-*`/`gap-*` values outside the ladder to the named spacing utilities, keeping any compact exceptions explicit.
6. Reconcile the `56px` nav-stack token with the actual `pt-3 + min-h-13` shell geometry, and make the fold/chapter utility contract consistent and used.
7. Simplify the owner access-route editor to one task boundary plus whitespace/hairline grouping.
8. Add a layout verification matrix for 320px, 375px, 768px/1024px breakpoint edges, desktop rail widths, 200% zoom, safe-area insets, and RTL. Verify reading order and the continuation-first mobile inspector, not only document scroll width.
