# UI Polish Review — Agentic Economy Design System
**Analysis Date:** 2026-09-01
**Lens/Skill:** better-ui — `.claude/skills/better-ui/SKILL.md`
**Scope:** `PATTERNS.md` (Motion and transition patterns, state/recovery and surface context), `COMPONENTS.md` (base primitives, state vocabulary, iconography), `FOUNDATIONS.md` (Shape, Elevation, Motion, Focus), `CONVENTIONS.md` (token-first, component states, density/surface), and `CONCERNS.md` (drift, inconsistency, performance, and coverage). Verified against `DESIGN.md`, `.planning/BRAND.md`, `src/styles/globals.css`, `src/styles/base.css`, `components.json`, and representative UI, market, layout, website, chat, and owner components. `LAYOUT.md` and `ACCESSIBILITY.md` were not inspected as primary lenses.

## Scope and Coverage

I reviewed the mapped motion, transition, state, shape, elevation, icon, and surface rules, then checked the live source that implements them. Representative source checks included `src/components/ui/button-variants.ts`, `badge.tsx`, `card.tsx`, `dialog.tsx`, `sheet.tsx`, `alert-dialog.tsx`, `accordion.tsx`, `tabs.tsx`, `select.tsx`, `table.tsx`, and `message-scroller.tsx`; `AeOperationCard.tsx`, `AeCompareTray.tsx`, `AeOperationInspector.tsx`, `AeRouteProgressBar.tsx`, `AePublicShell.tsx`, `AeSiteNav.tsx`, `AeSiteButton.tsx`, `AeSiteFooter.tsx`, `AeCopyCommand.tsx`, `OperationComposer.tsx`, and the owner access-path editor in `AeOwnerOfferings.tsx`.

The strongest alignment is real: `globals.css` owns the `100ms`/`160ms`/`220ms` ladder and the standard/emphasized eases; `base.css` clamps animation and transition duration under `prefers-reduced-motion`; `Card` uses `rounded-card` and `shadow-soft`; market rows use square hairline structure and an inset hover state; public actions use the deliberate notched geometry and `scale: 0.96`; status badges are pills; Lucide is the configured icon family; and `AeCopyCommand` implements the prescribed `0.25`/`1` scale, opacity, and `4px`/`0px` blur cross-fade.

This is a source review, not a rendered visual certification. I did not run a browser animation panel at 10% speed, inspect every hover/focus/active/loading/empty state in a live viewport, or measure 320px/200% zoom behavior. Those items are **Not verified** below; visual impact statements are based on the cited CSS and component composition.

## Verdict summary

The design direction is disciplined and distinctive. The system has the right restraint: motion acknowledges interaction or state, the public notch is confined to public actions/footer, status pills carry state, and the market surface resists the default rounded-card grid. `AeOperationCard` and `AeCompareTray` are particularly good examples of semantic polish: the row stays square and hairline-led, while the comparison task earns a raised card and a bounded enter/exit treatment. The `AeCopyCommand` icon transition is the clearest implementation of the better-ui guidance without adding a motion dependency.

The remaining problems are seam problems rather than a wrong visual idea. Several generated or older primitives use broad transitions, ungoverned shadow/radius values, or framework-default timing; `AlertDialog` visibly diverges from `Dialog` and `Sheet`; the chat scroll affordance uses a 400ms exit on a repeated interaction; and a custom public icon button bypasses the shared Button interaction and sizing contract. Owner editing also reintroduces box-heavy grouping, and the market row's six facts are assigned five desktop columns, creating a likely orphaned last fact. No finding is HIGH because the global reduced-motion fallback exists and the reviewed controls generally retain focus and disabled affordances. The system needs targeted convergence before it can claim a consistently polished contract.

## Considered but Rejected

| Location | Candidate | Rejected because |
|----------|-----------|------------------|
| Global motion contract | Add `transition-all` or a single long transition globally so every state feels “smooth.” | This directly violates the better-ui performance rule, can animate layout properties unexpectedly, and would erase the product's deliberate `100/160/220ms` hierarchy. |
| Copy/toggle controls | Add a new Motion/Framer Motion dependency and animate every icon swap with a spring. | No motion dependency is installed, `AeCopyCommand` already proves the CSS cross-fade seam with the prescribed values, and high-frequency actions should stay quiet rather than acquire repeated spring theater. |
| Market rows | Replace the square hairline rows with rounded cards and lift them with larger shadows. | `DESIGN.md`, `FOUNDATIONS.md`, and the current `AeOperationCard` correctly reserve cards for bounded tasks; the market's terminal density is stronger when rows stay structural. |

## Recommendations (priority order)

1. Converge `AlertDialog`, `Dialog`, and the command-panel override on one raised-overlay contract: shared scrim, role-specific `rounded-card`, `shadow-overlay`, canonical duration/ease, and explicit reduced motion.
2. Remove `transition-all` from Accordion/Tabs and make every shared transition declare an exact property list plus `duration-fast/base/slow` and `ease-standard/emphasized`.
3. Shorten and tokenise `MessageScrollerButton` exits, then replace the remaining public/header/route literal `duration-*` and `ease-*` values with semantic utilities.
4. Publish the shadow-role map for dropdowns/tooltips/buttons and migrate `shadow-md`, `shadow-xl`, and `shadow-xs` usages that are not intentional exceptions. Extend the UI contract scan to shared primitives, as already suggested by `CONCERNS.md:77-81`.
5. Simplify the owner access-path editor's repeated rounded boxes and repair the market card's six-fact/five-column rhythm without losing evidence in the exact inspector.
6. Bring `AeSiteIconButton` onto the shared Button state and icon-size contract, documenting the public size only if the larger glyph is intentional.
7. Preserve the successful restraint: square market rows, semantic status pills, notched public actions, hairlines before elevation, `AeCopyCommand`'s contextual icon cross-fade, and the global reduced-motion fallback.

## Open questions for the owner

- Should every centered modal/command surface use the 15px `rounded-card`, or is a compact 10px radius an intentional exception for confirmations?
- Is the six-fact market row meant to keep `Last verified` visible at `md`, or should that fact move to progressive detail so the row remains one aligned strip?
- Is the public menu/close icon intentionally 24px, or should the public icon-button contract lock a smaller explicit Lucide size and the same active/disabled feedback as `Button`?
- Should the chat scroll affordance preserve its directional slide, provided the exit is reduced to the shared short timing, or should it fade only?

**Verdict: Needs changes**
