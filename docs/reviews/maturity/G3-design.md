# G3 design — Connect and govern Agents

**Thesis:** An owner can connect the intended Agent, recognise its exact credential and current spend authority, and change either without guessing. Source observations below are not live purchase proof; the census could not connect to local `/status` (`G3-census.md:4`). Familiar defaults: explicit spend controls (Ramp/OpenAI), named non-secret key IDs (GitHub/OpenAI), direct connection/creation entry (GitHub/Stripe), permission-specific invitations (Linear/Vercel), and separate health from purchase eligibility (Stripe), per `G3-reference.md:5-63`.

## Decisions applied

- X8: derive **known / unset / unavailable / expired** from the Convex authority owner on read; recheck owner, current grant/delegation, revision, lifecycle and expiry in the write transaction. No `undefined` budget → “Active” or “unlimited.” Expired approvals are not actionable; G8 owns that queue, not this Agent policy (`docs/reviews/maturity/00-decisions.md:20`; `convex/lib/agentAccess/spendingPolicy/material.ts:61-160`).
- PC-16 uses the existing exact owner/admin + single active Clerk-organization binding predicate; no auto-provision or bypass (`docs/reviews/maturity/00-decision-brief.md:25`; `convex/lib/principalAccount/workspace/invitation.ts:14-28`). PC-17 offers **OAuth/MCP first** and **manual key** as an explicit choice with direct destinations (`00-decision-brief.md:26`). PC-18/19 show canonical non-secret principal/credential refs, not unique-name enforcement or secret prefixes (`00-decision-brief.md:27,49`).
- X6: public connection, funding, AUD Quote and paid Call after eligibility are the entry-release target. `/status` is infrastructure health, not evidence of public admission or a completed paid Call (`00-decisions.md:18`; `src/lib/server/readiness.ts:115-145`). X4 presentation belongs to G2: G3 consumes its single AUD display rule; grant budgets are already AUD/6 and this design adds no formatter (`src/modules/agent-access/spending-policy-update.ts:17-20`).

## Contracts

- **Policy read** (`principalRef`, authenticated account owner, server `now`) returns `known` with canonical grantRef, generation/digest, exact AUD/6 limits, pause status and expiry **only** after resolving current principal → credential → active grant → delegation. `expired` means source-confirmed deadline `<= now` or expired credential/grant; `unset` means authoritative *absence of an applicable policy* (only if the canonical model actually permits it); `unavailable` means source failure, ambiguity, absent expected grant, invalid chain or truncated join. An active admission carries mandatory generation/digest and requires one current grant, so its missing grant is **unavailable**, never “unset” (`convex/lib/agentAccess/principals/records.ts:73-77`; `convex/lib/agentAccess/spendingPolicy/material.ts:104-160`). Wrong owner/not-found remain typed refusals; no data leak. Reuse `agentSpendingPolicy.readCurrent` and domain contract rather than a second policy service (`convex/lib/agentAccess/spendingPolicy/reads.ts:15-45`; `src/modules/agent-access/spending-policy-update.ts:53-60`).
- **Policy display/edit:** initial read and selected-sheet refresh use authoritative state; show limits/Active or Paused only for `known`. For `unset`, state “No spending policy set” only with verified absence; `unavailable` offers Refresh, `expired` identifies ended authority and routes to connection renewal, neither offers a money edit based on stale projections. A known zero triple is Paused, not unset. Do not substitute fallback numeric defaults or credential generation when readback fails (`src/components/ae/console/spending-limits-form/useAgentSpendingLimits.ts:60-84,113-161,200-205`). Avoid another all-owner N+1: reconcile the 25-row directory page against canonical current grant identity via indexed, bounded owner read, not the unrelated latest-64 list; unknown joins never disappear silently (`src/modules/agent-access/agent-access-console.ts:154-193,478-496`). Existing write rechecks full chain and generation in Convex; preserve idempotency/replay and refuse changes when authority drifts (`convex/lib/agentAccess/spendingPolicy/update.ts:105-119,144-183`). Account-level caps/available funding are separate checks, not promised by this Agent limit (`G3-reference.md:9-13`).
- **Invite read/write:** authenticated active account and human principal → role (ownership or `org:admin`) and exactly one active binding in Clerk namespace → organizationId for permitted view only. Return role-restricted, organization-unset, or binding-unavailable reasons without leaking organization ID to other roles. Server POST repeats `invitationContext` and Clerk invitation write; a previously allowed screen is not authorization (`convex/lib/principalAccount/workspace/invitation.ts:14-28`; `src/components/ae/settings/team-roles/team-roles.functions.ts:27-42`). Directory owner row does not establish the viewing actor's ownership (`convex/lib/principalAccount/workspace/directory.ts:123-159`).
- **Identity/revoke:** principalRef identifies Agent independent of name/rotation; credentialRef + generation identifies key; full refs remain inspectable/copyable where short display is used. CredentialRef is a locator, never the secret (`src/modules/agent-access/agent-operator-view-model.ts:63-89,97-109`). Confirmation captures selected ref, not name, and backend rechecks owner/credential; only the exact key is revoked, historical activity stays; if it was current, an eligible remaining key can be promoted, so refresh after completion/partial provider cleanup (`convex/lib/agentAccess/principals/revocation.ts:70-115,118-146,160-203`; `src/components/ae/settings/agent-keys/useAgentKeysSettings.ts:62-91`). Do not promise a specific successor before authoritative mutation.
- **Connect/status:** OAuth choice moves/focuses existing install/consent steps; manual choice lands with wizard open, with its existing sandbox/production and one-time reveal safeguards (`src/components/ae/settings/agent-keys/AeAgentKeysSettings.tsx:26-38,80-81`; `src/components/ae/console/AeAssistantInstallFunnel.tsx:40-58`). `/status` market probe indicates readiness of configured Tool API transport only; catalogue freshness and per-Tool callable state have their own sources; no health result licenses a paid Call (`src/routes/-status.functions.ts:27-38,67-96`; `src/components/ae/status/system-status/system-status.contracts.ts:58-75`). Exact inputs precede a fresh Quote; no need-mode invention (X7, `00-decisions.md:19`).

## Surprises for Joel

- The current admission carries a grant generation/digest, so an active Agent with no joined grant is not a legitimate “unset/unlimited” policy: it is an authority read failure. The global newest-64 grant join can hide the expected row (`convex/lib/agentAccess/principals/records.ts:73-77`; `src/modules/agent-access/agent-access-console.ts:154-193,478-496`).
- Revoking the current credential can promote another eligible active generation; the old name-only confirmation understates impact (`convex/lib/agentAccess/principals/revocation.ts:118-146,160-203`).
