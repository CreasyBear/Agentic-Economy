# G8 design — Operate and maintain

## Decisions applied
- **Thesis:** an operator can reach every current case or approval without mistaking a bounded page, stale authority or incomplete count for the whole worklist.
- PC-27: choose per-kind paginated queues and a linked overview, not a global merged cursor. There is no evidenced cross-kind risk score or SLA; use the relevant existing source index order and name it. This follows Stripe/Zendesk bounded queues and Convex native pagination; the four AE sources have different indexes and ownership (`convex/lib/adminConsole/reads/exceptions.ts:155-232`; [Convex pagination](https://docs.convex.dev/database/pagination)).
- PC-28: X8 requires known/unset/unavailable/expired authority to be distinguished on read and rechecked on write; an expired proposal is not approvable or in pending work. Keep the existing universal 24 hours, with expiry **at** `expiresAt` and explicit fresh proposal to renew. No action-specific TTL absent turnaround evidence (`docs/reviews/maturity/00-decisions.md:20`; `docs/reviews/maturity/00-decision-brief.md:37-38`; `convex/lib/adminConsole/approvals/approvals.ts:16-24,76-101`).
- **No expiry cron or scheduled sweep.** The indexed pending read can constrain `expiresAt > now`; the command mutation checks the same deadline. Historical proposal/audit records need not be rewritten at the deadline. A cron may skip overlapping runs; even a `runAt` job cannot replace a deadline check on reads/writes ([Convex cron jobs](https://docs.convex.dev/scheduling/cron-jobs), [scheduled functions](https://docs.convex.dev/scheduling/scheduled-functions)). Client clock refresh is still required because time passing alone does not invalidate a cached reactive query ([Convex queries](https://docs.convex.dev/functions/query-functions); `convex/lib/adminConsole/approvals/approvals.ts:175-199`).

## Contracts
**Exception queues.** Admin-only readback remains `read_admin_readbacks` (`convex/adminConsoleExceptions.ts:12-26`). Expose a compact overview with four links and bounded *observed* counts, and one `listAdminExceptionsPage({kind, partition, paginationOpts})` at a time. Use `paginationOptsValidator` / `.paginate()` and `usePaginatedQuery`'s `CanLoadMore`/`Exhausted` status, as already done for audit events (`convex/lib/adminConsole/reads/auditHandlers.ts:16-20,26-43`; `src/components/ae/admin/audit/useAdminAudit.ts:28-52`). Keep each kind's existing indexed state partitions separately pageable: uncertain Call = reconciliation-required; dispute = opened/updated/contested; source review = review_required/legacy unset; admission = submitted/under_review (`convex/lib/adminConsole/reads/exceptions.ts:19-38,155-228`). UI shows each partition's continuation under its kind rather than merging cursors or hiding a partition; this is an internal partition, not another global worklist. Within partitions preserve native index order (Call next reconciliation attempt; other rows last update) and label it accurately; retain `since`/creation where available, without claiming a cross-kind oldest-first order. Equal-time records use Convex's indexed tie-break, not a computed reorder across pages. Never `.take(500)` then claim a full total. Show `N loaded` / `at least N` while any partition has `CanLoadMore`; exact `N` only when **all** partitions of that kind are exhausted; unavailable means count unknown, not zero. Distinguish an empty page with more available from an exhausted empty queue. The overview must not label first-page samples as total backlog. A selected kind reads no other exception source; overview's four bounded samples are the only intentional multi-source read. Do not add an aggregate component or mutation-maintained counters simply to print an exact badge: Convex has no built-in count, and this workload has no proven exact-count need (`convex/_generated/ai/guidelines.md:329-332`; `package.json:77-79`). Use existing installed Convex 1.45.0, no new dependency.

**Exact case lookup.** Add `removal_dispute` and `admission_case` as *Admin Search choices*, not fictitious `AdminObjectView` variants. Parse/resolve exact dispute ID with `ctx.db.normalizeId('disputes', ref)` + `ctx.db.get`, admission by `by_caseRef`; deny malformed/not-found without leaking through unauthorised reads (`convex/lib/adminConsole/actions/removalDispute.ts:9-13`; `src/modules/capability-supply/internal/convex-schema.ts:305-310`; `convex/adminConsoleObjects.ts:30-58`). A found result navigates to `/admin/exceptions?kind=…&ref=…`; an admin-only exact read shows that very case and its current state, including a closed/completed case, without inserting historical cases into the actionable queue. Existing Provider link is secondary: its cases/disputes stop at 20 (`convex/lib/adminConsole/reads/provider.ts:119-126`), so a Provider redirect alone is not an exact-case guarantee. Keep reference in URL + detail sheet for reload/deep link and do not auto-open arbitrary malformed refs (`src/routes/_operator/admin.exceptions.tsx:30-55`; `src/lib/operator/admin-console/exception-projection.ts:12-23`).

**Approval authority.** Keep `status = awaiting_second_approval` and index `by_status_and_expiresAt`; read only `expiresAt > serverNow` with `.paginate`, smallest deadline first, page continuation beyond 50 (`src/modules/security/internal/schema.ts:30-53`; `convex/lib/adminConsole/approvals/approvals.ts:186-199`). Pending panel and action controls share **one** paginated result instead of two independent first-50 fetches (`src/components/ae/admin/audit/AdminAuditPage.tsx:69-75`; `src/components/ae/admin/audit/AdminMembershipActions.tsx:72-74`). Owner-admin alone receives command material and Approve; reviewers may inspect permitted pending metadata (`convex/lib/adminConsole/reads/auditHandlers.ts:52-54`). Before rendering actionable controls, compare deadline to a client clock refreshed at the nearest visible expiry; force a query refresh after that deadline and continue loading while additional pages exist. The server never trusts that clock for authority. A late write (`now >= expiresAt`), including preflight, refuses `approval_expired` and cannot perform the target action; existing terminal states remain terminal. Never renew by changing `expiresAt`: a new proposal reruns the current target preview and authority, obtains its own digest/ref/24h window, and keeps the old proposal/audit event. In audit history, the immutable `admin.action_proposed` event is an event-time fact (`convex/lib/adminConsole/approvals/approvals.ts:101-112,237-272`); a proposal's *current* status is read-derived `expired` when still awaiting and `expiresAt <= now`, even if nobody tried to approve. Do not mislabel the old audit event as a current valid authorization. No nonce-burning or mutation in a read.

## Cross-group file collisions
- `convex/lib/adminConsole/reads/exceptions.ts` projects G4 uncertain Calls/disputes and G5 source-authority/admission cases; G8 changes **only operator read/visibility**, never G4 money resolution or G5 publication/admission transitions (`convex/lib/adminConsole/reads/exceptions.ts:155-228`). G4 reserves a separate `/admin/support-cases` view and will leave this queue untouched; coordinate any future shared Admin navigation.
- `convex/lib/adminConsole/approvals/approvals.ts` covers G3 membership actions and G5 suppression/commercial policy; G8 changes only common approval expiry/read contract, not their target authorisation or effect logic (`convex/lib/adminConsole/approvals/approvals.ts:17-24,202-219`). G3 confirmed no planned overlapping admin-file edits.
- Admin Search's `src/lib/operator/admin-console/contracts.ts` and `src/components/ae/admin/exceptions/**` are shared between slices A/B/C; A owns contracts, B owns exception UI, C owns search and object-value contracts. Agree exact-ref return shape before coding; no concurrent same-file edits. No Market directory or money display files touched.
