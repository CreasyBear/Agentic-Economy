# G4 design — Price, resolve and explain Calls

## Decisions applied
- Joel's X4 governs buyer presentment: G2 owns the single AUD formatter in `src/modules/money/internal/display-price.ts`; G4 consumes `formatDisplayAmount`, does not introduce another formatter, and keeps exact AUD/6 in the ledger, receipt and exports. Add exact values **before** one rounded-up presentation of a total. USDC remains separately identified settlement detail (`docs/reviews/maturity/00-decisions.md:16`; `src/components/ae/activity/useAeActivity.ts:137-152,271-279`).
- Familiar contextual support means a receipt starts an **authenticated Call-specific case**, while generic Help has no CallRef. URL repair is unconditional; possessing the URL never grants access. A case is created only on explicit POST, not by opening a GET page (`docs/reviews/maturity/00-decision-brief.md:28,48`; `src/modules/capability-execution/call-recovery.functions.ts:42-47`).
- Financial rows link their actual causal object **only if proven**. Independent Tools retain independent, expiring Quotes/Calls; a harness owns task-level summation and per-Call recovery, not an AE commercial bundle (`docs/reviews/maturity/00-decision-brief.md:29-30`; `src/modules/capability-execution/quote.ts:113-139`).

## Contracts
**Support URL and case.** Input: optional raw CallRef only; generic link `/support` has none. `validateSearch` returns URL-serializable raw string/absence; malformed raw input becomes malformed *view* state after one `parseCallRef` call. Never serialize `{kind, value}`. A valid-looking CallRef may be rendered as a reference but case creation and Call status require current owner authorization. Submit takes authorized CallRef, bounded safe message and stable client-generated case command key. Atomic owner+command-key lookup/insert returns the same caseRef on retries; same key with different Call/message refuses. Store caseRef, owner/account, CallRef, message, createdAt and open status; **no raw Tool input, result or credential**. The separate, Admin-authorized `/admin/support-cases` inbox can read open cases; a submitted case is not just a `mailto:` draft. Generic Help retains direct private email and no case requirement. Missing/inaccessible Call yields generic Help/Call lookup, not a forged case. Existing authenticated status uses `authorizeOwnerRecovery` (`convex/lib/capabilityExecution/callLifecycle/callRecoveryActions.ts:229-246`); implement a direct owner check for case write, not a status GET as a write precondition.

**Ledger provenance.** Input: Formance Account history page (15 rows) already scoped to authenticated owner Account and backed by filtered native postings. Formance `BUYER_SALE_SETTLED` carries `metadata.call_digest`, not invertible CallRef (`src/modules/money/internal/formance-reads.ts:495-536,560-568`; `convex/moneyOwnerSpend.ts:26-39`). `settleManagedCall` returns ordered transaction refs; ref **[0] is buyer sale**, [1] provider (`src/modules/money/internal/formance-transaction-templates.ts:216-236`; `convex/lib/money/managedCall/transitions.ts:89-96`). In `finalizeSettlement`, after confirmed Formance bulk/readback, atomically persist scalar `buyerSaleTransactionRef = refs[0]` with `formanceSettlementRefs`, on existing `capabilityCalls`; index `(ownerId, buyerSaleTransactionRef)`. `ownerId` is AccountRef for booked Calls (`convex/lib/money/managedCall/booking.ts:75-82,99-104`). Replays must agree on both refs; conflicts refuse. For each **call_spend** page row, indexed owner+ref lookup must verify Call settled/ref[0], recomputed canonical `digestReference('call', callRef)` equals ledger `sourceDigest`, and same Account; only then set nullable `sourceRef=callRef` and link to owner-authorized receipt. No `transactionId` inference, digest inversion, reference-only trust, whole-account scans or 15-row Call-list guesses. Absent/ambiguous mappings remain null and do not falsify balance/coverage; a lookup outage must not produce a link. Historical/unmapped/funding/adjustment rows get their own transaction detail, not an invented Call. Keep original reversal `reverted`/partial-netting semantics (`src/modules/money/internal/formance-reads.ts:589-602`). Existing `sourceLinkCoverage:'unavailable'` changes to truthful per-page coverage or is deleted if unused; do not claim all ledger types can link.

**Exact money.** Monetary record and `tool.quote.price` remain exact integer units plus currency/exponent (`src/modules/capability-execution/quote.ts:113-129`). Buyer UI uses G2's display projection; signed ledger debits/credits round displayed magnitude up with sign retained. CSV/JSON convert integer AUD/6 with existing `formatExactAmount`, including exact GST/net integer split, not Number or the displayed cent string. Monthly/any task total sums *authoritative exact* values and then projects **once**; never sums per-row rounded labels. A Quote sum is only a current planning total (earliest expiry limits validity); it is not a Charge, a reserved task budget or approval for a future Call. Refusal, expired Quote, changed inputs/authority, unknown outcome, or incomplete component inventory cannot masquerade as a priced entire task (`src/modules/money/internal/exact-amount.ts:137-150,171-183`; `src/modules/capability-execution/quote.actions.ts:27-49`).

**Agent task boundary.** HTTP/MCP/CLI/chat expose existing single-Tool `tool.quote`, `tool.call`, `call.status` contracts, not an aggregate RPC (`src/modules/capability-execution/quote.actions.ts:27-49`; `src/modules/capability-execution/call-recovery.actions.ts:229-254`). Harness records `{toolRef,input,quoteRef,price,expiresAt,callIdempotencyKey,callRef?,status}` per component; every quote must be committed/current before total is called known. Persist `quoteRef` + stable per-Call key *before* each Call; after timeout/pending/unknown, read that CallRef/status or replay only the same key, never fresh-key repurchase. A failed component does not unspend a completed one. No bundled output, single total guarantee or partial-refund promise.

## Acceptance tasks

In a browser with **real router**, generic workspace Help and denied-Admin Help reach `/support` with no `callRef` or warning; receipt Help from a refused and an uncertain Call yields a raw single URL CallRef, authenticated owner-only current Call context, submitted caseRef and Admin inbox row. Wrong-owner/malformed URL cannot open or expose a case; replaying the same submit command returns the same case. An email draft is not a submitted case.
2. With a **funded, admitted x402 Tool** (Bazaar-observed timezone converter or ERC20 transfer logs after admission), purchase controlled GET and POST with sub-cent AUD where possible; Credit `BUYER_SALE_SETTLED` row shows native transaction identity and a link to the exact owner receipt, Charge/effect and recovery. Another owner, funding/reversal/unmapped row and unknown digest show no false Call link; replayed/uncertain settlement eventually acquires the *same* mapping or remains honestly unavailable. Compare exact Activity/credit/receipt/CSV gross, GST, net and monthly exact sum → one rounded-up display.
3. Agent via HTTP and MCP (CLI and chat where exposed): find two **distinct suitable** admitted contributions, provide typed inputs, get two current Quotes under same Agent/Account, add exact AUD units and enforce task ceiling before either Call. Persist each quote/key; perform first Call, interrupt, inspect CallRef/status/receipt, then independently Call the second without duplicating the first. Observe partial success/refusal and unknown dispatch via Call readback, not blind fresh-key retry. Query an impossible need and an invalid/refused Quote: no fabricated task total and no Call. Need a controlled funded paid GET/POST Tool, suitable second admitted Tool, owner+Admin actors, sub-cent price, and uncertain-dispatch/reversal fixtures; absent fixtures block **paid acceptance**, not URL, schema, or CSV source work (`docs/reviews/maturity/00-decision-brief.md:86-94`). No live payments in design phase.
4. Export Settings → Receipts with distinct sub-cent and large AUD/6 amounts. Invoice CSV gross/GST/net must match their exact money-unit split, not Activity's or Receipts' rounded screen label (`src/components/ae/settings/receipts/receipts.view-model.ts:22-35`).

## Surprises for Joel
- “Open a Call-specific case” is not today's `mailto:`: Help currently prepares an email and there is no traced buyer support-case store. An actual case needs a small owner-authorized write **and reachable operator inbox**, not just a corrected link (`src/components/ae/support/help/AeSupportHelpPage.tsx:20-39`; `src/components/ae/support/help/useSupportHelpPage.ts:5-16`).
- Durable CallRef and ordered buyer-sale reference **already coexist** on `capabilityCalls` at settlement (`convex/lib/money/managedCall/transitions.ts:89-115`); the missing piece is an indexed, owner-scoped, digest-checked projection, not decoding Formance's digest or redesigning posted money.
