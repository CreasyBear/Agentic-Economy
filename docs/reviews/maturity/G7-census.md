## PC-31 — Copyable Search cURL rejects its own body

The OpenAPI builder emits request content with a `$ref` schema **without an example** (`src/modules/discovery/internal/openapi-document-schema.ts:114-121`); Search is derived from the market action (`src/modules/discovery/internal/openapi-operations.ts:144-167`) whose input requires non-empty `query` (`src/modules/registry/tool-choice-contracts.ts:48-53`). The page labels the example copyable and says “replace any placeholder values,” although `{}` contains no placeholder (`src/components/ae/developers/api-reference/DevelopersApiPage.tsx:29-51`; `developers-api.contracts.ts:70-71`).
- **Behaviour per affected surface:** web `/developers/api` offers a copy button with `POST /api/v1/market-tools/search`, `Content-Type` and `--data '{}'`; the pasted HTTP request fails validation as reported in the register. HTTP itself correctly requires `query`; CLI `ae search "phrase"` sends it (`tools/ae/commands/search.ts:9-19,21-41`); MCP's own action contract is not generated from this cURL presenter. Chat is not affected by the example.
- **Source owner and adapters:** OpenAPI transport `src/modules/discovery/internal/openapi-operations.ts:146-167`, emission `openapi-document-schema.ts:114-121`; presenter `developers-api.view-model.ts:37-83,134-168`; page `DevelopersApiPage.tsx:29-51`; required schema `tool-choice-contracts.ts:48-53`. Test `tests/unit/discovery/openapi-document.test.ts:120-149,170-187` asserts every POST has `--data` and a *manually inserted* example is copied, but does not assert the real Search request is schema-valid or execute it. Existing register is the live failed-request evidence.
- **Root class:** presentation (contract generation lacks usable example content, while copied request implies executability).
- **Status-quo challenge:** Schema-correct documentation with an invalid copied request is not a shippable API reference; merely telling users to replace placeholders cannot cure a missing required field. A generic `{}` fallback should not masquerade as a runnable example.
- **Candidate disposition:** fix the generated example at the shared OpenAPI-to-presenter seam; ensure required input is supplied for Search while not pretending arbitrary writes can be run safely. **Ergonomic and intuitive** first successful public HTTP call.

## PC-32 — CLI cold path runs authentication-dependent steps too soon

- **Register claim on current main: holds.** `packages/cli/README.md:11-20` runs `request create` and `request list` before `ae connect`; both require a key (`tools/ae/commands/request.ts:70-83,124-136`). `ae search` is anonymous (`tools/ae/commands/search.ts:8-9,37-41`) and plain output already gives a `ref: <toolRef>` for each result (`:83-98`), but the guide neither selects/extracts that reference nor sets `AE_TOOL_REF` before using `"$AE_TOOL_REF"` for `describe` and `call`. `ae describe` is an anonymous read (`tools/ae/README.md:23-26`); `ae quote` exists separately to inspect price/budget/readiness without a Call (`tools/ae/commands/call.ts:313-317,396-415`), and `ae call` quotes then submits using the returned Quote (`:417-459`). The source guide's cold path is `search → describe → connect → quote → call → receipt → reuse` (`tools/ae/README.md:44-48`), different from the packaged guide.
- **Behaviour per affected surface:** CLI first-run script can search without credentials, then hits credential-required private request commands. If no match, request creation is appropriate only after connection; it refuses when a current Tool already matches (`tools/ae/commands/request.ts:90-108`). Search's result contains an exact `toolRef`, but the documented shell variable is unset, so `describe`/`call` receive an empty string; the CLI's `call` parser refuses a missing ref (`tools/ae/commands/call.ts:361-393`). HTTP and MCP expose their own search/describe/Quote/Call and private-demand actions; they do not inherit the shell variable. Web agent connection funnel has its own ordered MCP onboarding (`AeAssistantInstallFunnel.tsx:40-71`); chat has no shell quickstart.
- **Source owner and adapters:** packaged guide `packages/cli/README.md:11-20`; CLI source guide `tools/ae/README.md:11-16,20-48`; command code above. Tests: `tests/unit/market-terminal/request-memory.test.ts:70-103,105-124` exercise requests with a pre-installed credential; `tests/unit/market-terminal/cold-loop.test.ts:154-155` checks no-match wording; `tests/unit/market-terminal/doctor.test.ts:723-738` tests missing credential. No existing cited test runs the packaged guide line-by-line as a clean consumer.
- **Root class:** documentation (order, auth boundary and reference capture; no extra API required).
- **Status-quo challenge:** A kitchen-sink command list is not a quickstart. A mature CLI first-run journey makes the next command executable, distinguishes match from unmet demand, and does not ask for a Call before the reader has a verified input contract and current Quote.
- **Candidate disposition:** redesign the packaged quickstart around executable branches rather than unconditionally issuing private request, describe and Call commands. **Intuitive, ergonomic and safer** onboarding.

2. **What does a first-run Quickstart promise?** (a) anonymous Search/describe only, then connect/Quote/Call as a separate owner-approved journey; (b) one complete buyer journey through Quote and Call when a real admitted Tool and funded authority are available; (c) separate read-only quickstart plus conditional no-match request and optional purchase. CI confirms expected degraded status, but source cannot choose the customer-facing onboarding contract.
4. **Who owns the CLI guide?** (a) package README is the sole external guide, with essential missing command/transport/auth details folded in; (b) track a separate source guide with an explicit internal audience and keep both consistent; (c) put detailed contracts exclusively in CLI `--help`/machine manifest and keep README short. 5. **What counts as copyable/runnable API reference examples for mutating operations?** (a) give safe valid *read-only* examples and schema placeholders for writes; (b) supply schema-valid examples for all but label write effects and required authorization; (c) show generated skeletons as non-runnable and provide separate curated tutorials.
