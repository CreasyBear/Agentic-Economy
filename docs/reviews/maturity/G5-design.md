# G5 design — Publish and earn

## Decisions applied
- Joel's familiar defaults: PC-03 (a) setup in the existing Tools workspace, then resume Add Tool; PC-26 (c) money facts in the workspace, **no manual payout controls** before controlled money/entitlement proof; PC-29 scoped preflight, with server preview authoritative (`00-decisions.md:21`; `00-decision-brief.md:31-32,50`). A created Provider or parsed file is not a published/callable Tool (`G5-reference.md:9-16,33-42`).
- X4 is G2-owned. Use its buyer AUD presentment only for buyer-price equivalents; Provider earnings/settlement retain their **actual** currency and exact underlying money records. Do not turn USDC Provider obligations into imaginary AUD earnings or define a second conversion/formatter (`00-decisions.md:16`; `src/modules/money/formance-schema.ts:313-343`).
- Source correction to the census: the earnings RPC is **not an implemented earnings read**. It returns `not_found` for every authenticated owner (`convex/lib/money/earnings/providerEarnings.ts:7-29`). Both payout transfer and recorded-transfer read explicitly return unavailable (`src/modules/money/internal/payout-transfer-http.ts:99-121`). UI composition alone cannot close PC-26; source truth and a controlled money fixture are mandatory.

## Contracts
- **Identity/start.** Input: authenticated owner selecting Add Tool; read current owner identity before any source/connections/resume. `not_applicable` *only* means no Provider profile (`provider-workspace.functions.ts:235-240,540-545`): navigate to existing profile setup with an allowlisted `#add-tool` continuation; after successful `ensureProviderBusinessServer`, invalidate and navigate `/owner/operations/new`, whose loader re-reads identity. No draft/source is created before authority. Direct `/new` behaves the same. Normal visits to `/owner/operations` remain there. `unavailable` shows genuine retry; `conflict` names multiple owners without auto-selection. Failed profile save stays in form; no redirect (`useProviderWorkspaceInventory.ts:29-58`; `_operator/owner.operations.new.tsx:23-58`). Any saved-draft deep link must revalidate business/connection ownership on resume; never carry an unverified draft across identities.
- **Money read.** Input: signed-in owner, current business, durable Call/Provider-obligation ledger and recorded transfer/payout evidence. Output: per-*actual*-currency exact recorded accrual/settlement/held values and dated durable references/status **only where the source proves them**; distinguish pending, succeeded, reversed, failed, uncertain and unobserved payout. Formance accrues Provider USDC expense separately from buyer AUD sale (`formance-schema.ts:313-343`); Stripe transfer success is **not proof of bank payout** (`src/modules/money/internal/money-query-views.ts:4-45`; `src/components/ae/supply/earnings-card/earnings-projection.ts:104-135`). Do not derive gross/rake or cash-paid from a Stripe connection or fabricate zero when a source is missing. Read is owner-authorized, read-only, bounded with truthful truncation; mismatched business/ref fails closed. Source errors remain unavailable/retry; verified no rows is empty. G2's common money presentation is the only conversion policy; exact units survive in records/exports. No POST payout/transfer/recovery/Connect action is enabled by opening Earnings; existing bank onboarding links, if still reachable elsewhere, must not imply transfer permission.
- **Preflight.** `inspectJsonPayload` returns parse/top-level-presence only; presence permits **attempting** preview, not eligibility. `mcpServers: {}` may pass the client check and must still receive `agent_plugin_remote_missing` from server preview (`useSupplySourceType.ts:50-64`; `agent-plugin-source.ts:50-73`). Preview/publish stay distinct; no `valid` claim until authoritative server response.

PC-26 is a real money-read/source milestone, not a card wiring fix.
