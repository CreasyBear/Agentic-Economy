# G6 design — Retain a need; repeat a Tool

## Decisions applied
- **X2/X3:** Only G1's exhausted `kind: noMatch` permits **Save this need**. `scoped` continues the assessment and `unavailable` retries; neither writes demand. Keep the existing public `next` (broaden/next-page/retry) unchanged and equally legible in JSON and plain text (PC-41 is **done by G1**, not a G6 implementation slice). Add a separate, optional authenticated save affordance, never an anonymous write. The store is `marketDemand.record`, not a second request/ticket/alert system (`src/modules/registry/search-verdict.ts`; `src/modules/registry/tool-choice-contracts.ts`; `00-decisions.md:14-15`). **Intuitive, safer.**
- **X3 / familiar default:** Signed-in buyers save with their account session; connected Agents use the existing `market_tools:call` credential and exact-credential request authority. Do not manufacture an Agent key for web, share Agent-owned demand across credentials, or bypass G3's current-grant checks. One phrase, an explicit Save, a private request reference and existing list/status/withdraw; **no email, notifier, supplier message, consent switch, new lifecycle variants or purported future fulfilment**. Status checks currently admitted Tools on demand; it is not an alert (`src/modules/market-demand/market-demand.actions.ts`; `src/lib/server/market-demand-api.ts`). **Safer, maintainable.**
- **PC-40 / familiar default:** Make Saved Tools an **account-bound collection of identities**, available to a signed-in buyer and their connected Agent harness. A browser-only snapshot does not serve repeat use across devices or harnesses; npm/GitHub stars use an account list (`G6-reference.md:31-42`). Save/remove is explicit; never alter ranking or trigger Quote/Call. Signed-out discovery remains public; saving asks for sign-in rather than silently creating a second local collection. **Intuitive, maintainable, safer freshness.**

## Contracts
1. **Eligibility and scope:** An affordance is present iff a search is `noMatch`, `assessed.scope/coverage === complete`, `partialResults === false`, `pagination.hasMore === false`, and the caller has verified owner session or a current Agent credential with `market_tools:call`. Search read remains public. Save sends the bounded phrase (1–200 characters, matching `SEARCH_QUERY_MAX_LENGTH` on origin/main), actual search source/filters when present, and a stable idempotency key generated once per Save intent. No cursor or page number is part of a saved need. Recheck the **same complete assessed scope** at write time; a stale match or source outage refuses rather than saving a false absence. Persist selected filters for later status checks; a filtered miss must not silently become an unfiltered request. Do not claim search exhaustiveness from a lexical page. Current `create` accepts `match` without an AE Tool and defaults to `limit: 1`; tighten to genuine `noMatch` and assessed coverage (`market-demand.actions.ts:244-258`; `src/modules/common/search-query.ts`).
2. **Authority/ownership:** HTTP/MCP/CLI `marketDemand.record/list/status/withdraw` retain exact `principalId + credentialId` verification and G3 admission (`marketDemandSignals.ts:20-37,90-119`; `market-demand-api.ts:62-79`). Web/chat use Clerk-authenticated, source-authorized owner RPCs on the **same** `marketDemandSignals` table with explicit owner-owned record variants and owner indexes; Convex derives the owner from `ctx.auth`, never a browser-supplied `ownerId` or synthetic Agent credential. Account list/status/withdraw stay owner-scoped; withdrawal erases phrase and retains dedupe receipt as the existing credential path does. Do not expose credential-owned phrases to the account-wide list by accident. Search/ranking stays read-only; mutations revalidate before recording. `requestRef`, current status and 30-day matching horizon are disclosed; expiration ends matching, not an invented notification schedule or silent promise to erase history.
3. **Surface affordance:** Keep public `SearchEnvelope.next` as G1's typed read-only actions. Add optional `saveNeed: { action: 'marketDemand.record', args: { query, source?, filters? }, authority: 'owner_or_connected_agent' }` to the **authenticated search projection only**; HTTP optional credential admission, MCP bearer search/tool summary and CLI configured exact-origin connection project it from the same eligibility rule. CLI text offers `ae request create "<query>"` with source/filters when present; JSON carries the same action (CLI generates and reuses the idempotency key); MCP text names `ae_market_demand_record`; no secret/credential in output. Web Market and command-panel show one Save button calling the owner server function; signed-in chat's no-match card carries the **actual assessed query and scope**, not the model's paraphrase, to the same function. Anonymous results do not carry `saveNeed`; guest web may present a Sign in action, not a Save that fails. After Save, display requestRef, Check status and Withdraw. A refusal keeps the phrase and offers Search or Retry, not a success toast. A read-only MCP toolset cannot execute the write.
4. **Saved Tool identity and freshness:** Store `ownerId` plus discriminated identity: admitted `{ kind: 'ae_callable', toolRef }`, external `{ kind: 'external_listing', resource }` (Bazaar's resource URL; resolve a compact `id` through exact detail before saving). Uniqueness is owner + kind + identity, with bounded count **100** and idempotent save/remove. Expose owner-scoped web RPCs and authenticated Agent `market.savedTools.list/save/remove` via `POST /api/v1/saved-tools/list`, `/save`, `/remove`, existing action registry and G3 credential owner verification; no new spending authority. Only reference + createdAt is durable—no price, metadataJson, schema, credential or Call input. Resolve live registry description / indexed Bazaar resource for display; unavailable references remain removable without showing a stale snapshot. External stays `external_listing`, never becomes a callable Tool by being saved. Quotes and authority are fresh on each use. The web Saved tab and `ae saved list`/MCP list show the same owner collection; exact-origin binding holds on CLI.
5. **Existing browser data:** Do not silently lose saved items: one explicit **Import browser saves** affordance when a signed-in browser has the old `ae:directory:saved-tools:v1` document. Read resource identifiers only under the existing 2 MiB/100-item limits; resolve current identities, import idempotently, and clear the old document only after acknowledged success. Never keep dual local/account Save semantics. Signed-out users can sign in to import; corruption leaves old data untouched and reports an actionable failure. This is a bounded one-time data transfer, not a compatibility storage backend.

## Deletions
- Remove permanent localStorage/session/cross-tab `DirectorySavedToolsProvider` persistence, `StorageState`, 2 MiB snapshot serialization and stale-price card rendering; retain only the narrowly bounded legacy-import reader until old user data has an explicit transfer path (`DirectorySavedTools.tsx`; `saved-tools.contracts.ts`; `tests/unit/market/directory-saved-tools.test.tsx`). Delete incidental wording/shape tests, replace with owner isolation and real save/revisit/remove behavior.
- Do not build notification subscriptions, polling cron, Provider demand dispatch, adaptive ranking, copied Tool metadata or a parallel saved-search table. Do not edit G1's completed PC-41 projection just to add another `next` case.

## Acceptance tasks
1. On one pinned revision, signed-in Market and command-panel plus signed-in chat show **one Save this need** on a truly exhaustive no-match. Saving records once across repeat clicks; reload → owner list/status/withdraw; another buyer cannot read/withdraw it. Anonymous web/chat sees sign-in rather than a writable Save. Scoped/incomplete search and ranker/index outage do not offer or record demand; stale-before-write becomes refused. No credential, Quote or Call leaks.
2. Connected exact-origin HTTP, MCP and CLI no-match expose the same save input and actionable plain/structured continuation; `ae request create` records/replays and status/withdraw belong to the exact credential. Revoked/missing-scope credential and readonly MCP cannot save. Filtered exhaustive miss preserves the chosen scope and a 200-character valid phrase is saved intact. PC-41 read-only `next` remains unchanged.
3. Buyer saves admitted Tool and external-only Bazaar listing; another browser and connected Agent see the same identities, then Remove syncs back. Details and AUD price are fetched live, external cannot Quote, missing resource remains removable. Import old browser shortlist once with identities only; failed import never erases the old document. No live payments, Quote, Call, publication or deployment for G6 design proof.

## Surprises for Joel
- Existing `marketDemand.record` only knows credential ownership, while signed-in web has no equivalent save authority; routing through a fake key would undercut G3 (`market-demand.actions.ts:221-239`; `marketDemandSignals.ts:20-37`).
- Current create accepts `kind: match` if no AE-callable row and checks `limit: 1`, while G1's `noMatch` includes Bazaar and scope/coverage. A visible Save requires an actual same-scope recheck before mutation (`market-demand.actions.ts:244-258`; `tool-choice-contracts.ts`).
- Browser Saved Tools retain up to 2 MiB of public snapshots; an account cutover without an explicit import strands existing user data (`DirectorySavedTools.tsx:86-121,124-180`).
