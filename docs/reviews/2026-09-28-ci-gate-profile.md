## Waste, with source evidence

1. `gate → test:release:source → ... → test:release:source:after-codegen` is entirely serial and includes source integrity/build, full unit + serial integration, two browser commands, CLI consumer and another build (`package.json:22–40,56–66`). CI spells out the source prelude then runs after-codegen, rather than executing exactly `gate`; **it omits `env:example:check`** (`.github/workflows/kernel-release-gate.yml:77–104`; `package.json:38–40`). Restore parity when CI resumes.
2. Overlapping selections: focused provider/chat conformance repeats specs selected by release unit/integration; architecture's two integration specs repeat in integration (`package.json:30–36,38–40`). `tests/e2e/a11y/` lies under the first `test:e2e` selection, then `test:e2e:a11y` runs it again with one worker (`package.json:56–57`; `playwright.config.ts:5–39`). Each invocation can boot its own Vite server. Preserve the one-worker accessibility semantics in a deduplicated selection.
3. CLI builds multiply: integrity executes `npm run build`, and the final stage builds again (`package.json:22,29,40`; `tools/release/verify-release-integrity.ts:43–65`). Each public CLI pack runs `build:cli` *and* `prepack` runs the same build (`package.json:12–13`; `packages/cli/package.json:18–20`). `test:imports` adds an explicit CLI build (`package.json:61`), and Vitest's global setup rebuilds CLI for every separate Vitest process, even non-CLI suites (`vitest.config.ts:23`; `tests/setup/build-cli.global.ts:4–18`). Keep one actual integrity-wrapped release build and one CLI consumer/package guarantee; remove only redundant rebuilds after verifying artifact identity.
4. Two required CI jobs are **already parallel** (`fresh-checkout-proof` has `needs: []`); each separately checks out, pins npm, runs `npm ci`, and downloads Chromium with system dependencies. `setup-node cache: npm` caches tarballs, **not node_modules or browser binaries**; only the fresh job caches Convex binary (`.github/workflows/kernel-release-gate.yml:46–65,119–153,182–188`). Anonymous codegen additionally boots an isolated backend (`tools/release/verify-convex-generated-anonymous.ts:121–202`), independent of the fresh-checkout full stack (`.github/workflows/kernel-release-gate.yml:153–188`). These are distinct proofs; do not call one redundant merely because both use Convex.
5. Kernel has no path filter, triggers on PR **and** main pushes, and cancels in-progress runs **only for PRs**, not main; repeated main pushes can consume simultaneous minutes (`.github/workflows/kernel-release-gate.yml:3–43`). No Node matrix exists: CLI package smoke invokes Node 20 and 22 within one job (`scripts/test-cli-package.ts:174–241`). React Doctor separately runs on every PR/main push and already cancels both; it has `blocking: error` despite comments calling it advisory (`.github/workflows/react-doctor.yml:9–26,38–53`). Both workflows are currently disabled.
6. One explicit `tsc --noEmit`, **not duplicate typechecks**, runs over src/Convex/tests/tools; no incremental or `tsBuildInfoFile` is configured (`package.json:23,40`; `tsconfig.json:1–61`). Vitest specifies no pool/isolation/worker settings globally; don't claim these defaults explain the unit duration without profiling (`vitest.config.ts:14–31`). Serial integration and one-worker accessibility **are** explicit (`package.json:31,57`). Local-only incremental `.tsbuildinfo` may help repeat checks; retain clean nonincremental release verification.

## Proposal A — local acceptance now

Add a separate `npm run check` (do **not** relabel a subset as `gate`): `lint && deps:check && typecheck && test:imports && test:ts-standards && test:ui-contract`, using existing npm scripts (`package.json:23–25,60–66`). CI timings of those constituent stages in run `36389507077` sum to ~2.5 minutes; allow **~3–5 minutes locally**, unmeasured on Joel's hardware. Run affected unit/integration tests alongside that check for each behavioral change; they are not implicitly covered by it. Exclude isolated Convex generation, all-suite Vitest, Playwright, npm packaging, duplicate builds and live credentials. Run full `npm run gate` before each merge to main and for each alpha-release candidate (once per revision; do not repeat unchanged proof). Existing gate is broad, but it is not a substitute for a live local stack/paid-path proof when that is the release claim.

## Proposal B — alpha CI when minutes return

PR: **one** cheap required `check` job with a Node 22 lockfile-keyed node_modules cache (on miss `npm ci`, avoid carrying a stale or cross-platform install), npm package cache as fallback, and the Proposal A commands. Use `concurrency.group` by PR/ref and `cancel-in-progress: true`. Avoid a naive top-level `paths` filter on a required check: a docs-only PR can leave a required check pending; use a lightweight change-detection/skip job that emits a successful required result, or remove the requirement for that path. Always run for workflow/config/lockfile/tooling changes. Expected **~4–6 billed runner-minutes per code PR** (estimate from current step timings plus setup/cache overhead, not measured after a change); docs-only ~0–1 minute. No browser install, full test suite, Convex boot or package-consumer smoke per PR.

Main only: parallel source build/integrity+Convex generation and focused fresh-stack smoke, filtered by relevant paths; locally run the full gate once *before* merge so main does not pay the existing 43-minute CI bill on every commit. Alpha tag/manual release: full source gate, fresh checkout, full browser/CLI-package evidence and authenticated staging proof when credentials/consent are available; paid gateway remains explicitly approved `workflow_dispatch` only (`.github/workflows/kernel-release-gate.yml:239–490`). Preserve branch-protection check names and sanitized evidence on any split. Cache Playwright Chromium by OS+locked Playwright version on jobs that actually need it, with Linux dependencies installed as required; source/fresh jobs already run concurrently, so split **unit, integration, browser** into parallel jobs only after their shared setup/artifact and evidence dependencies are made explicit. No extra Node matrix; leave React Doctor off as separate every-push CI until its actionable signal merits the cost. Deletion targets: overlapping suite invocations, second accessibility pass, redundant CLI builds, stale React Doctor advisory comment/config contradiction, and duplicate all-push release triggering—not release proof, reproducibility checks, or Convex authority validation.
