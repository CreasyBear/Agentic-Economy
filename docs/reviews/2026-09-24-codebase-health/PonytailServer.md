## Handrolling: replacement proof and KEEP decisions

- **REPLACE candidate — duplicate cursor envelope:** `src/modules/capability-supply/supply-management-service.ts:115-139` → existing internal implementation `src/modules/registry/opaque-cursor.ts:24-55`. Same shape, Base64 codec and scope check; different maximum lengths and module boundary mean a common codec plus wrappers is needed, not a blind import. Potential net -10 to -20 LOC, *conditional*.
- **REPLACE candidate — ordered grouping:** `src/modules/market/directory-card.view-model.ts:174-186` and `src/modules/market/tool-view-model.ts:146-169` → native `Map.groupBy` (ES2024 configured at `tsconfig.json:5`, installed TS API at `node_modules/typescript/lib/lib.es2024.collection.d.ts:19-28`, observed Node 22 runtime). It preserves the explicit `Map` insertion-order contract; browser compatibility is a rollout prerequisite.
- **REPLACE candidate — array chunk:** `src/modules/market/flow-tape.ts:87-91` → declared `es-toolkit/array` `chunk`, verified installed declaration and implementation; size error handling is stricter and should be intentional.
- **KEEP — rate limiting:** `src/lib/server/rate-limit.ts:60-91` forwards signed HTTP admissions; `convex/lib/rateLimit.ts:1-21` already imports and uses declared `@convex-dev/rate-limiter` (`package.json:80`). The HTTP adapter is not a second rate-limit algorithm.
- **KEEP — provider schema normalizer/dereferencing:** `src/modules/capability-supply/internal/admit-provider-schema.ts:66-111` adds domain-specific credential stripping, required-input closure and output-evidence planning. Node-side dereference already uses declared `@scalar/openapi-parser` (`schema-deref.ts:1-30`, `package.json:93`); `schema-deref-shared.ts:7-13,27-90` is local-only Convex-safe expansion with node/depth limits and cycle behavior. Parser replacement is not a drop-in for its admission rules; no proof the Node parser bundles in the Convex isolate. **Do not count 469 lines as saved.**
- **KEEP — JSON Schema validation and tool strictness:** `src/modules/capability-contract/internal/pointed-schema.ts:1,37-51,290-317` already uses declared `@cfworker/json-schema` plus `structuredClone`; `src/modules/actions/strict-schema.ts:21-30,58-84` enforces a stricter tool-vendor policy than ordinary schema validation. `src/modules/capability-contract/internal/json-value.ts:44-54,98-141` imposes a bounded, AE-supported keyword/reference profile, not generic schema validity; installed validator exports `Validator.validate(instance)` but no schema-meta-validation API (`node_modules/@cfworker/json-schema/dist/esm/validator.d.ts:7-10`). The separate keyword allowlist in `tool-projection-wire-schema.ts:11-61,99-153` projects a different wire profile: consolidate only after comparing those policies, not via a library name match.
- **KEEP — exact money:** `src/modules/money/internal/exact-amount.ts:6-20,76-111,114-150` already uses `decimal.js` for decimal parse/scale (`package.json:113`) and `BigInt` for exact atomic arithmetic; a plain Decimal replacement would lose currency/exponent equality and canonical unit validation.
- **KEEP — OAuth device polling:** `tools/ae/commands/connect.ts:314-407` handles persisted pending state, RFC device `slow_down`, Retry-After, expiry and resumability, unlike an ordinary retry. For the ordinary just-issued-key retry at `connect.ts:200-204`, it already uses declared `es-toolkit` `retry` (import line 13). `oauth4webapi` is declared (`package.json:119`), but no observed server-side drop-in API covers AE authorization-details policy at `src/lib/server/agent-access-oauth/protocol.ts:94-189`.
- **KEEP — stable identity and Base64 portability:** `src/modules/common/stable-hash.ts:9-24` sorts JSON keys before `canonicalDigest` hashes them (`canonical-digest.ts:18-29`); `JSON.stringify` alone does not provide this identity contract. `base64-codec.ts:3-35` is a small cross-runtime byte codec; current TypeScript lib has no `Uint8Array.toBase64/fromBase64` declaration (checked installed `node_modules/typescript/lib`), so a Node-only `Buffer` replacement is not semantically equivalent in Convex/browser code. `src/lib/export/csv-export.ts:70-82,97-130` is a tiny correct CSV escape/CRLF emitter with no declared CSV library; adding a dep just for that is not a demonstrated net simplification.
- **KEEP — error envelopes:** `src/lib/server/problem.ts:19-30` builds standard RFC 9457 response headers/JSON via the canonical `buildProblem` imported from `src/lib/errors.ts`; `tools/ae/lib/output.ts:108-153` projects that shared model for CLI continuations. Not independent error standards.
- **One-implementation interface/config layers:** No safely deletable production port/config abstraction established from source inspection. The dereferencer has *two* actual runtime implementations (`schema-deref.ts:19-30`, `schema-deref-shared.ts:13-90`); the release smoke `GatewayCallConfig` allows injecting `fetch/now/sleep` (`tools/release/tool-gateway-production-smoke-call.ts:38-46`) and has a live-network script boundary. `tools/release/render-env-example.ts:7-13,65-71` source-parses a Convex config because importing that runtime definition fails outside Convex; replacing its 25-line parser with a new abstraction is not a demonstrated deletion. Do not classify these as YAGNI without callsite/behavior proof.
