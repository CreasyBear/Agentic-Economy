### What Jev can express **directly**

- **(a)** `choice` with a criterion for each shortlisted Tool ref plus a `none` criterion: one bounded choice, then verify returned ref still belongs to the supplied set. Current [`source-assessment.ts` L57–77](../../../src/modules/capability-supply/source-assessment.ts#L57-L77) already uses exactly this closed-list pattern. Unlike cascade's index, stable refs survive reordering. A `choice` does *not* supply candidate-relative scores.
- **(b)** one `score` question **per candidate** for an ordinal rubric, or current one `noul` per candidate for relevance probability; sort in code and combine independently with [`tool-selection-score.ts` L36–69](../../../src/modules/registry/tool-selection-score.ts#L36-L69). Current [`tool-reranker.ts` L320–408](../../../src/modules/registry/tool-reranker.ts#L320-L408) and [`x402-directory-reranker.ts` L35–80](../../../src/modules/market/x402-directory-reranker.ts#L35-L80) already do Noul scoring and stable ties. `score` is ordinal, not a trading-style calibrated 0–100 forecast.
- **(c)** `choice` for mutually exclusive class labels, or `noul` for binary suitability. Keep eligibility/price/reliability and final routing in code; don't let a model invent evidence. **(d)** requires separate calls/agents and debate state; three primitives can encode a *judge's final choice*, not parallel argument generation or voting. None of these repositories uses TypeSafe System One; their *decision shapes*, not SDK adapters, are the transferable finding. [`jev-client.ts` L11–13, L50–74, L118–168](../../../src/modules/decision-engine/jev-client.ts#L118-L168) validates the question type, allowed choice, score bounds, and Noul bounds and defaults to 1,500 ms (5,000 ms discovery).

## Top five patterns worth porting, ranked

1. **Bounded one-of-K over a small retrieval shortlist** — cascade [`llm_picker.py` L41–67, L271–353](https://github.com/bernard777/tool-selector-cascade/blob/e959f4b3eb4d34db27e335a249688d6ba2d57c14/src/tool_selector_cascade/levels/llm_picker.py#L41-L67) is the closest conceptual match. Ask Jev `choice` among *current* top refs + `none`, not an unbounded catalog prompt; check returned ref against immutable input. On unavailable, use the existing deterministic winner, not a fabricated model answer. Under a near tie, `none` should mean “do not assert a unique semantic winner,” **not** refuse a usable deterministic ranked list.
2. **Deterministic evidence score plus bounded model relevance** — AlphaSift [`ranker.py` L155–184](https://github.com/ZhuLinsen/AlphaSift/blob/9f522747caafd3c0b1ddb7e14d5cf44c8580b6cf/alphasift/ranker.py#L155-L184) keeps prior score and bounds model influence. aecon already has call reliability/payer/price/user-history weighting [`tool-selection-score.ts` L27–42](../../../src/modules/registry/tool-selection-score.ts#L27-L42): preserve that scorer as the operative fallback and use Noul only on relevant candidates, rather than translating AlphaSift's arbitrary 40% stock weighting wholesale. Check criterion coverage (the gateway already validates all answers).
3. **Whitelist model identities; keep the execution set closed** — toolpick [`reranker.ts` L23–65](https://github.com/pontusab/toolpick/blob/3c49fe2cc56f70502151dc194b6e0afe8a5dd200/src/reranker.ts#L23-L65) rejects unknown names, dedupes and falls back after an exception. aecon should keep the stronger stable `toolRef`/directory identity check, not copy toolpick's unchecked *valid-but-empty* result or expose its per-step all-tools escalation to a single purchase decision. `choice` already validates criterion keys at [`jev-client.ts` L156–168](../../../src/modules/decision-engine/jev-client.ts#L156-L168).
4. **Separate capability classification from commercial selection** — stock_picker_bot [`screener.py` L842–858, L961–983](https://github.com/adigunners/stock_picker_bot/blob/a9cddee9d8f613631b22d0908ef00fece7cae5a6/backend/app/services/screener.py#L842-L858) asks a narrowly scoped model question and lets code score the result. In aecon, suitability `noul` says whether a Tool can perform the buyer's contribution; price, reliable delivery, recent AE Calls and preference remain deterministic. Do *not* port the unverified search-grounding claim or earnings fallback chain.
5. **White-box confidence and an explicit no-strong-winner route** — screener [`nodes.py` L546–569, L625–653](https://github.com/thisisnish/multi_agent_stock_screener_opensource/blob/7dc6265cd99abaa5ffd215dd092275ada680b667/screener/agents/nodes.py#L625-L653) computes confidence outside the Judge and can HOLD despite a model verdict. For aecon, derive tie/low-relevance behavior from validated candidate scores and still show ranked options or deterministic winner when Jev is unavailable. Do **not** port Bull/Bear/Judge network fan-out or infer model self-confidence is calibrated.

- [freqtrade/freqtrade](https://github.com/freqtrade/freqtrade), [`freqtrade/templates/sample_strategy.py` L375–430](https://github.com/freqtrade/freqtrade/blob/f6a7b767a31720b2f34059dd7b166b28abef3f09/freqtrade/templates/sample_strategy.py#L375-L430): representative stock/sample strategy enters on RSI crossover + trend/band/volume Boolean expressions (`dataframe.loc[(qtpylib.crossed_above(...)) & ... , "enter_long"] = 1`), not a model-prompted candidate chooser. - [lokwkin/stockidea](https://github.com/lokwkin/stockidea), [`src/stockidea/screener/service.py` L93–156](https://github.com/lokwkin/stockidea/blob/9021da1428c94f0461ca911c3b1f971356817549/src/stockidea/screener/service.py#L93-L156): the agent may author or backtest a strategy upstream, but actual `pick` retrieves index constituents, `apply_rule(...rule_func, sort_func...)`, and takes `filtered[:max_stocks]`; no model chooser in this decision-time screener. - [trade-agent](https://github.com/mocasus/trade-agent) is **not** a negative about LLM use: its model *does* make BUY/SELL/HOLD for one fixed symbol; it is a negative *for cross-candidate selection*. [TradingAgents](https://github.com/TauricResearch/TradingAgents) likewise evaluates a preselected instrument; its debate is not a stock/tool retriever.
