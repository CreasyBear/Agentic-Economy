# Evaluation seam first

**Decision:** instrument before changing selection semantics. Today the buyer path retrieves at most ten Tools, orders them by observed evidence, then asks one Jev `choice` over the need and `toolRef`/title/summary only (`src/modules/capability-execution/procure-engine.ts:194-232,409-435`; `src/modules/registry/tool-selection-score.ts:27-69`). The request has an `unsupported` option already (`procure-engine.ts:423-427`). Its gateway currently tries a secondary LLM after Jev failure before deterministic evaluation (`src/modules/decision-engine/decision-gateway.ts:44-75`). Inference telemetry is console-only and contains no candidates or pick (`src/modules/decision-engine/inference-observation.ts:14-31`). Neither a production accuracy claim nor a calibrated cutoff is currently measurable.

1. **Persist one bounded decision snapshot, not a new market outcome.** At `procure-engine.ts:203-232,429-455`, allocate a selection ID and write a best-effort, idempotent record: decision time, privacy-safe evaluation-intent reference (and only consented/redacted need text in a restricted evaluation set), preference, retrieval-ordered candidate `toolRef`s (maximum ten), each candidate's deterministic *post-decay* score and evidence-availability flag, evidence-ranked order/top-1, Jev returned label (`unsupported` included) and model/version when present, accepted pick, attempted/deciding tier, separate Jev concentration confidence or `null`, elapsed gateway milliseconds, and outcome `picked | no_match | operational_fallback`. Preserve both retrieval and evidence orders; log no endpoint, credentials, raw input schema, or untrusted provider prose. An unavailable evidence query supplies zeros (`procure-engine.ts:203-230`), so its record must not be indistinguishable from genuine zero evidence. A trace-write failure must never change the selection result; include its latency in end-to-end measurements.
2. **Put the snapshot alongside evidence, not inside aggregate counters.** Declare a dedicated selection-decision table/index on selection ID and selected ref in `src/modules/market/internal/convex-schema.ts:264-282`; expose a service-authenticated, idempotent writer adjacent to `convex/marketListingEvidence.ts:74-85` (its existing selection-evidence query), rather than adding a new `marketEvidenceFacts.kind`. `convex/marketEvidence.ts:25-50` idempotently records Call facts by `sourceRef`, with optional `toolRef`/duration; `convex/marketListingEvidence.ts:27-35,191-206` aggregates completed-call evidence and reads latency samples. `convex/lib/market/listing/buyerCompletedCall.ts:69-125` reads terminal `capabilityCalls` and **excludes buyer-input/authority/spend refusals from provider failures**. Keep the selection snapshot private and bounded; use a read-only evaluation export, not a public search response.
3. **Make the later Call join real.** The `need` response currently exposes only `next: {kind:'exact',toolRef}` (`src/modules/capability-execution/procure.ts:68-85`); `exact` accepts no selection ID (`procure.ts:12-25`), so matching by user/tool/time alone falsely attributes independent purchases. Carry the selection ID through `next`, the subsequent `exact` request and Quote/Call initiation (`procure-engine.ts:266-273,299-350`); validate it against the original principal and selected ref. Persist the resulting `callRef` onto the decision record when known; join by `capabilityCalls.by_callRef`, not timestamps (`src/modules/capability-execution/internal/convex-schema.ts:326-335,383`). `quoteRef` can link a Quote before `callRef` exists. If the buyer overrides the suggested Tool, record the override separately and do not label that Call as the model's chosen-ref outcome. `capabilityCalls` stores terminal state, and finalization patches it (`src/modules/capability-execution/internal/convex-schema.ts:360-383`; `convex/lib/capabilityExecution/callLifecycle/dispatchFinalize.ts:107-117`). Join only completed or provider-side failed Calls under the same predicates as `buyerCompletedCall.ts:107-125`; pending, cancelled, no follow-up and buyer-side refusal are **unobserved**, not failed. An exact Call without a linked selection is excluded, not assigned to the most recent decision.
4. **Fix the confidence-1 lie before computing any rate.** `procure-engine.ts:439-440` turns both `deterministic_rule_engine` and `safe_refusal` into candidate zero with confidence `1`, and `select` applies the same `0.60` cutoff to all tiers (`procure-engine.ts:232-235`). Return tier and optional model concentration separately from the selected ref; for operational failure use the already ranked first candidate without claiming model confidence, and record `safe_refusal` distinctly from successful deterministic evaluation. A real Jev `unsupported` is a semantic no-match, not an outage. Jev `choice.confidence` measures distribution concentration, **not** correctness ([TypeSafe confidence](https://docs.typesafe.ai/confidence.md)); never score deterministic fallback as a confident Jev hit.

**Offline comparison unlocked:** freeze catalog version, candidate list/order, scorer preference/evidence snapshot, model alias/version and independently annotate acceptable refs plus per-candidate utility for held-out buyer needs (hard negatives and true no-match cases included). Replay the *same offered ten* through current `choice` and ranker. Report Jev top-1 and deterministic top-1 accuracy against acceptable refs; positive-case recall@k at k=1/3/10 = acceptable refs in ranked prefix / acceptable refs in the offered shortlist, plus retrieval recall against the frozen catalogue; and separate no-match precision/recall. Define deterministic exact-tie rate as decisions with equal top-two scores / decisions with at least two candidates; report near-tie rate separately at a predeclared score gap. Regret rate = decisions selecting below the highest adjudicated-utility offered ref / eligible decisions, with mean utility gap, separately for Jev and deterministic top-1. Break out disagreement rate, fallback tier, new Tool, provider, price band, near ties and catalog/version drift; reverse candidate order **offline** to measure position flips. Stratify linked Call completions/provider failures by selected ref and tier, but never impute unchosen Tools' outcomes or treat observational differences as causal regret. Record gateway p50/p95/p99 and operational-fallback share against the 1,500 ms buyer budget. First inspect shadow results and a randomly sampled agreement control; promote no model-policy change without better held-out suitability/no-match rates **and** acceptable latency. This is the shadow/disagreement shape in [the quant report](2026-09-29-quant-and-cascade.md) ([AWS shadow tests](https://docs.aws.amazon.com/sagemaker/latest/dg/shadow-tests.html)); third-party accuracy does not substitute for aecon labels.
