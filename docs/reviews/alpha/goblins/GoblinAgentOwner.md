# GoblinAgentOwner — owner connecting and governing Agents

**Lens:** owner connecting and governing Agents.
**Journeys:** `/agent-access` directory and status filters; Connect an Agent (OAuth/MCP vs manual key); key-issue wizard including a sandbox dev key; spending-limit edit; authority-state display; revoke dialog then Cancel; agent detail sheet; CLI `ae connect` through the consent page. Unhappy paths: refresh mid-wizard, Back, invalid limits, two tabs editing the same limits.
**Sign-in:** one-time local Clerk ticket from `npm run -s dev:sign-in-url` opened in a private browser context. The ticket and issued secrets were not recorded. Live app `http://127.0.0.1:3024`. Viewport for the reveal measurement was 1280×900.
**Side effects:** two sandbox keys were issued (`Goblin sweep dev key`, `Goblin sweep layout`) and left in place. Neither was revoked. A spending-limit save on the first key moved the monthly cap from A$20.00 to A$21.00, then a later save restored A$20.00. CLI device consent was opened and not approved; the CLI was stopped so the request can expire. MFA was not completed.

## GREEN verified

- Connect an Agent offers "Connect with OAuth / MCP" and "Issue a manual key". OAuth/MCP expands setup (Codex `mcp add` / `mcp login`, "Approve access in the browser", Hide setup, Check connection).
- Wizard validation keeps the typed name and limit strings and creates no key: empty name ("Agent name is required."), letters, zero, negative, per-call above daily ("Per-call limit cannot exceed daily limit."), and blank production limits. Each says no secret was created and A$0.00 was deducted.
- Sandbox issue reaches "Save your secret key / Step 2 of 2" with the secret masked until shown. Closing it is blocked only by finding 1.
- Revoke dialog for the new sandbox key opens; Cancel closes it and the Revoke button is still there. The key was not revoked.
- Agent detail opens from `?caller=`, shows Connected, Work within limits, A$20.00 monthly, and 0 calls. Refresh keeps the caller and the sheet. Back returns to `/agent-access` without the caller.
- Limit edit rejects "nope" ("Limits must be valid AUD amounts… Enter a number in each field, then save again.") and 80 / 10 / 5 ("Daily limit cannot be less than per-call limit."). The invalid values stay in the fields. A$0.00 was unchanged.
- Two tabs: the first save of monthly A$21.00 applied. The second tab's save of A$22.00 was refused with "Policy changed since you opened it… Current limits were not changed. Reload the agent, then apply your limits again." Reload and a following save restored A$20.00.
- Unknown `prn_` and a non-canonical caller both show "Agent not found… Return to Agents" while the directory stays usable.
- Signed-out `/agent-access` redirects to `/sign-in` with a redirect parameter and heading "Sign in to connect an Agent".
- `ae connect` against `http://127.0.0.1:3024` with an empty config directory prints a `/agent-access/authorize?user_code=…` URL. After the workspace pending shell, the signed-in page shows "Connect Agentic Economy CLI", sandbox, admitted tools, exact limits, "Connect agent", and "Decline". Refresh keeps that page. Back returns to `/agent-access`. Connect agent was not clicked.

## Could not reach and why

- MFA and a finished `ae connect`: stopped on the consent page on purpose. No email code was entered and Decline was not clicked, so this does not retest worksheet J6·A1.
- "Remove agent everywhere": the Technical details control was found but the click did not open the confirm dialog within 30s. Nothing was removed.
- Sign-in return after the signed-out redirect: the redirect parameter is present; a second sign-in was not completed, so the return URL was not proven.
