# Journey transitions: research-backed design rules for AEcon

**Scope and evidence (28 September 2026).** This is a decision guide, not a claim that any fix has landed. Examples are from the live alpha sweeps linked below; an interrupted probe, a blocked downstream step, and an observed defect are different kinds of evidence. Keep protected identity, payment, authority, and Provider checks intact; recover the user's *journey* without inventing success.

## 1. Model the journey, not just its screens

1. **Inventory journeys by user goal, then draw states and event-labelled edges.** For each journey record entry URL/actor, authoritative record/reference, each screen/action, success/final state, and what the user sees and can do for invalid input, refusal, pending, interruption, timeout/outcome unknown, cancellation, refresh/back, expired identity, direct link, and return from an external site. For every *nonfinal* state, name an allowed onward/retry/back/status-check path and owner; a final success/refusal can end deliberately. Harel's original statecharts introduced hierarchy, orthogonality and history for complex reactive systems; Stately describes states, events, transitions and final states. This is a **journey-review method derived from those sources**, not a claim that XState must be installed. [Harel, *Statecharts* (1987)](https://www.sciencedirect.com/science/article/pii/0167642387900359); [Stately statecharts](https://stately.ai/docs/state-machines-and-statecharts). **AEcon:** Provider Draft must have a real continuation edge: the saved detail currently says “Continue setup” without an action ([provider sweep, row 3](./sweep-provider.md)).
2. **Separate parallel facts from one fictional linear status.** A provider draft/validation/publication state, a payment/session/ledger-credit state, and identity/connection state can evolve independently; depict guards and their authoritative source, including webhook-vs-browser arrival order. Statecharts' parallel states and guards make hidden combinations reviewable; test transitions, not just a list of pages. [Stately parallel states](https://stately.ai/docs/parallel-states); [Stately guards](https://stately.ai/docs/guards); [Harel](https://www.sciencedirect.com/science/article/pii/0167642387900359). **AEcon:** Stripe's return occurred but the A$5 funding command remained processing and balance A$0.00; do not collapse `returned` into `credited` ([buyer sweep, row 1](./sweep-buyer-account.md)).
3. **Make a journey inventory whose rows are runnable.** Suggested rows: public find/filter/detail → save; Provider identity → source preview → candidate → Draft → review → submit → validate → published/withdrawn; buyer fund → payment return → credit/receipt; Tool → exact-input Quote → explicit Call approval → Call receipt → Activity/Help; chat/new/thread/share; Agent connect → OAuth return. For each, annotate golden, invalid-input, denied/not-current, server/network failure, duplicate click, leave/return and direct URL; explicitly mark unproven edges. Stately says finite state/event models enable testing all transitions. [Stately state machines](https://stately.ai/docs/state-machines-and-statecharts). **AEcon:** the fund → Quote → Call → receipt chain is *unproven* after funding stayed pending and chat would not create an exact-input Quote ([buyer sweep, rows 1–2, 26](./sweep-buyer-account.md)).

## 2. Navigation, waiting and local failure

4. **Assign a visible state to each navigation phase, close to its owning route.** TanStack Router matches/validates search, runs `beforeLoad`, then loads routes, with `pendingComponent` and `errorComponent`; `pendingMs` defaults to 1,000 ms and `pendingMinMs` to 500 ms when shown. Set pending/error UI and recovery at the smallest useful route/section, keep previously useful content visible where safe, and avoid a global error for optional panels. [Router loading lifecycle](https://tanstack.com/router/latest/docs/guide/data-loading); [route options](https://tanstack.com/router/latest/docs/api/router/RouteOptionsType); [React error boundaries](https://react.dev/reference/react/Component#catching-rendering-errors-with-an-error-boundary). **AEcon:** an optional chat share/sidebar query currently can replace the transcript and composer; transient chat authority failure can replace `/t/*` with “Couldn’t open chat” ([UI fragility, J5–J6](./fragility-ui.md)).
5. **Preload likely destinations, but never treat a preload or an optimistic view as authority.** TanStack supports Link intent/viewport/render preloading, with speculative `beforeLoad` and loader reuse; navigate with typed `from`/`to`/`params`/`search` rather than interpolated URLs, and use router `onEnter`/`onStay`/`onLeave` only when lifecycle coordination is needed. [Router preloading](https://tanstack.com/router/latest/docs/guide/preloading); [navigation](https://tanstack.com/router/latest/docs/guide/navigation); [route lifecycle options](https://tanstack.com/router/latest/docs/api/router/RouteOptionsType). **AEcon:** a Tool detail → Quote handoff should preserve its ToolRef and exact inputs; catalogue Search → detail may preload, but fresh Quote authority must still be checked ([buyer sweep, row 2](./sweep-buyer-account.md)).
6. **Put restorable navigation state in validated URLs, not an ephemeral component variable or opaque human-facing token.** TanStack search params are shareable/bookmarkable and survive refresh/back; `validateSearch` may supply sensible fallbacks for malformed *navigational* values, but throwing routes to error. `loaderDeps` must include the validated params the loader actually uses. Keep raw internal cursor out of UI copy; a malformed cursor should recover to a truthful first-page state, not silently claim an exhaustive no-match. [Router search params](https://tanstack.com/router/latest/docs/guide/search-params); [data loading](https://tanstack.com/router/latest/docs/guide/data-loading). **AEcon:** malformed `/market` `providerCursor`/filter currently turns browse into MarketError ([UI fragility, J11](./fragility-ui.md)); an advertised registry cursor also fails on the next page ([agent sweep, row 14](./sweep-agent-surfaces.md)).
7. **Keep a dirty editor's draft while allowing deliberate leave.** Router `useBlocker` handles in-app navigation; enable `beforeunload` only while truly dirty for refresh/tab close, and clear the blocker after saving. A browser bfcache restore can revive an old JS heap, so on `pageshow.persisted` recheck sensitive/auth/payment state rather than assuming a fresh loader ran; never rely on `unload`. [Router navigation blocking](https://tanstack.com/router/latest/docs/guide/navigation-blocking); [web.dev bfcache](https://web.dev/articles/bfcache). **AEcon:** Provider onboarding should resume its saved Draft after navigation or HMR, not restart Add Tool; the interrupted MCP preview after Vite reload proves no result, not a valid continuation ([provider sweep, rows 3 and 30](./sweep-provider.md)).
8. **Use React concurrency for responsiveness, not transaction truth.** `useTransition` gives `isPending` for nonurgent updates/actions; Suspense shows a fallback only for Suspense-enabled reads (not ordinary Effect/event-handler fetches); `useOptimistic` is temporary and reverts to the supplied real value after failure. Keep already mounted content legible; scope an error boundary to the failing optional child. [React `useTransition`](https://react.dev/reference/react/useTransition); [Suspense](https://react.dev/reference/react/Suspense); [`useOptimistic`](https://react.dev/reference/react/useOptimistic); [error boundary](https://react.dev/reference/react/Component#catching-rendering-errors-with-an-error-boundary). **AEcon:** a pending Save or funding action may show “Saving…”/“Checking payment…”, but must not optimistically claim a credited balance; optional chat panels should not unmount transcript ([buyer sweep, row 1](./sweep-buyer-account.md); [UI fragility, J6](./fragility-ui.md)).

## 3. Error recovery and progress are product states

9. **Use different treatments for correctable input and service failure.** GOV.UK puts a focused, linked summary at page top *and* a matching inline error next to each invalid answer, retains both valid and invalid fields, and does not use form-error styling for a service failure or denied entitlement. Its “problem with the service” page says what happened to answers and what users can do; NN/g calls for proximal, human-readable, specific, actionable errors preserving input. [GOV.UK error summary](https://design-system.service.gov.uk/components/error-summary/); [error message](https://design-system.service.gov.uk/components/error-message/); [service problem](https://design-system.service.gov.uk/patterns/problem-with-the-service-pages/); [NN/g error guidelines](https://www.nngroup.com/articles/error-message-guidelines/). **AEcon:** OpenAPI Submit returned a generic error and disabled submit/edit despite Draft staying unvalidated; separate an input correction, a real authority refusal, and a transient service failure with a concrete status/continue path ([provider sweep, rows 1, 4](./sweep-provider.md)).
10. **State progress honestly, with a next action.** NN/g's heuristic calls for timely visible status; its response-time limits are ~0.1 s immediate, ~1 s noticeable, ~10 s attention boundary. After long waits show genuine time/step progress where known, or completed/remaining steps if not; do not invent a percent or endlessly spin. [NN/g visibility](https://www.nngroup.com/articles/visibility-system-status/); [response times](https://www.nngroup.com/articles/response-times-3-important-limits/); [long waits](https://www.nngroup.com/articles/designing-for-waits-and-interruptions/). **AEcon:** the funding screen's repeated “Payment is still processing” after return needs an exact-reference status, what is awaited and a safe way to revisit/escalate, not a fictitious countdown or a new top-up CTA ([buyer sweep, rows 1, 11](./sweep-buyer-account.md)).
11. **Make save, review and confirmation materially distinct.** For multi-session services, GOV.UK shows task status on return; its check-answers page allows changes before final submission, while confirmation appears only after completion and includes reference/next steps and supports revisiting the bookmarked page. Baymard finds misleading third-party-payment button copy confuses users: label the *next actual action* (“Continue to secure payment”), not “Order complete” before redirect. [GOV.UK multiple tasks](https://design-system.service.gov.uk/patterns/complete-multiple-tasks/); [check answers](https://design-system.service.gov.uk/patterns/check-answers/); [confirmation](https://design-system.service.gov.uk/patterns/confirmation-pages/); [Baymard payment selection](https://baymard.com/research-articles/payment-method-selection); [Baymard confirmation](https://baymard.com/research-articles/order-confirmation-page). **AEcon:** Provider “identity Completed” reopens with blank required website/ABN, while saved Draft has no continuation; separate saved facts, Review, submitted validation, and published confirmation ([provider sweep, rows 3, 5](./sweep-provider.md)).

## 4. Mutation, identity and off-site return boundaries

12. **Prevent double-submit in UI *and* enforce idempotency at the server boundary.** Disable the one pending control with meaningful status, retain a stable attempt/reference across timeout and retry, and make the canonical state queryable before offering a new command; a disabled button alone cannot survive refresh, concurrent tabs or a lost response. Stripe specifies idempotency keys for safe retries and *once-per-session*, concurrency-safe fulfillment. Where a native HTML POST responds with a separate result page, HTTP 303 makes the follow-up GET refresh-safe (Post/Redirect/Get); do not pretend PRG alone prevents duplicate writes from repeated POSTs. [NN/g status feedback](https://www.nngroup.com/articles/visibility-system-status/); [Stripe idempotency](https://docs.stripe.com/api/idempotent_requests); [Stripe fulfillment](https://docs.stripe.com/checkout/fulfillment.md?payment-ui=stripe-hosted); [HTTP 303](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status/303). **AEcon:** Provider's Find Tools pending lock worked, but failed Submit left controls disabled; funding top-up stayed processing—check the original funding reference before any second attempt ([provider sweep, rows 1, 14](./sweep-provider.md); [buyer sweep, row 1](./sweep-buyer-account.md)).
13. **Treat Checkout return as a status lookup, not payment proof.** Stripe's hosted success URL can include literal `{CHECKOUT_SESSION_ID}`; server retrieves the Session to render its status. Fulfillment must also run from signed webhooks because users may never land on success, and both webhook/landing paths may race or repeat. Check `payment_status` and reconcile the one fulfillment reference; show `processing`, `paid-but-credit-pending`, `credited` or `failed` only when authoritative records support them. [Stripe custom success page](https://docs.stripe.com/payments/checkout/custom-success-page.md?payment-ui=stripe-hosted); [Stripe fulfillment](https://docs.stripe.com/checkout/fulfillment.md?payment-ui=stripe-hosted). **AEcon:** the observed Stripe test redirect returned to `/owner/credit?funding=…` with A$0.00 and no receipt; webhook/reconciliation cause was **not established** ([buyer sweep, rows 1, 6, 26](./sweep-buyer-account.md)).
14. **Resume intended destinations after re-auth, and validate OAuth returns.** Clerk uses a previous-page `redirect_url` after sign-in; a *force* redirect overrides it, whereas a fallback only applies without an intended URL. At OAuth callback, validate a one-time CSRF-bound state (or applicable PKCE/OIDC nonce), expected issuer when multi-issuer, registered redirect URI and same owning attempt before mutating a connection; surface denied/expired/missing attempt with a way back, never convert missing authority into success. [Clerk redirect URLs](https://clerk.com/docs/guides/development/customize-redirect-urls); [OAuth Security BCP RFC 9700 §2.1](https://www.rfc-editor.org/rfc/rfc9700#section-2.1); [GOV.UK service problem](https://design-system.service.gov.uk/patterns/problem-with-the-service-pages/). **AEcon:** sign-out → protected Credit currently redirects to sign-in then lands `/market`, not the intended Credit screen; missing OAuth attempt already has a recovery link ([buyer sweep, row 15](./sweep-buyer-account.md); [provider sweep, row 13](./sweep-provider.md)).

## 5. Proof: exercise edges, not just page loads

15. **Make a journey matrix with one real golden run and named unhappy edges per journey.** Assert the user-visible state and the authoritative record/reference after each mutation and return. Inject a transport abort, explicit HTTP failure, slow response and delayed/out-of-order return where applicable using Playwright `page.route`/`context.route`, `route.abort`/`route.fulfill`; test expired auth, malformed deep link, back/refresh/bfcache, repeated submit and post-webhook refresh. Mock *one* failing dependency per test, not the whole app into a fictional success. [Playwright network](https://playwright.dev/docs/network); [Stately transition testing](https://stately.ai/docs/state-machines-and-statecharts); [web.dev bfcache](https://web.dev/articles/bfcache). **AEcon:** reproduce chat's optional-query failure without replacing transcript, and Provider failed Submit with a recoverable Draft; genuine funding/Quote/Call proof remains blocked by the observed return and Quote failures ([UI fragility, J5–J6](./fragility-ui.md); [provider sweep, row 1](./sweep-provider.md); [buyer sweep, row 26](./sweep-buyer-account.md)).
16. **Keep a visual state catalogue keyed to the journey-state inventory**—idle, pending, invalid, refused, retryable failure, unknown monetary outcome, restored draft and actual confirmation, at desktop/mobile and keyboard focus. Use Playwright screenshots/`toHaveScreenshot` for *layout* regressions with stable fixtures and the same rendering environment; do not treat snapshots as evidence that Stripe credited funds or a Provider published. [Playwright screenshots](https://playwright.dev/docs/screenshots); [visual comparisons](https://playwright.dev/docs/test-snapshots); [GOV.UK error summary](https://design-system.service.gov.uk/components/error-summary/). **AEcon:** protect the pointer Save action obscured by a stretched card link and the draft detail's missing Continue control, not merely attractive static screenshots ([buyer sweep, row 3](./sweep-buyer-account.md); [provider sweep, row 3](./sweep-provider.md)).

**Decision order:** first restore truthful entry/exit for blocked journeys (funding return/receipt, exact-input Quote/Call, Provider failed Submit/Draft continuation); then localize route failure and restore URL/back/auth state; finally cover each edge with journey-level proof. No new statechart dependency is implied until a concrete interaction is too complex to express with the existing route/hook contracts.
