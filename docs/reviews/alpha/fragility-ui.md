# Web runtime takedown map — 28 September 2026

**Rule:** A core journey depends on Convex, signed-in identity where needed, and the Provider being called; optional ranking, FX, analytics, metadata, and telemetry cannot veto it. Source inspection below identifies *possible triggers*, not claims that every outage has been reproduced. Estimates are rough lines removed/added for the smallest isolation/cutover, not implementation commitments. A failed authority check must **not** fail open into a protected action.

**Severity:** app-down = a failure can replace all web routes with a failed request or root error screen; journey-down = a route/whole feature becomes unavailable; degraded = a useful part of a route is lost or delayed. **21 distinct takedown points: 4 app-down, 11 journey-down, 6 degraded.**

## Existing isolation worth preserving

- Operator leaf routes have their own pending/error boundary, while the pathless operator layout owns auth (`src/lib/operator/route-options.ts:11-43`); keep this split, not one global boundary.
- `/activity` uses `Promise.allSettled`: usage/spend failure leaves Call history accessible (`src/routes/_operator/activity.tsx:40-62`). Provider workspace separately catches secondary reads (`src/routes/_operator/owner.operations.tsx:19-29`). Saved Tools catches individual descriptor failures (`src/lib/server/saved-tools-api.ts:135-156`).
- Directory browse falls back to upstream on some index-unavailable cases, while excluded filter/cursor combinations deliberately remain unavailable (`src/modules/market/x402-directory-index.server.ts:115-166`); never silently broaden a scoped result and call it an exhaustive no-match.
- Root hydration intentionally uses `useSyncExternalStore` with a server snapshot for chrome (`src/components/ae/layout/app-shell/useAppShellState.ts:123`); no proven hydration-wide outage from that path. The concrete browser-storage exception is J7.

**Read-only smoke:** `GET /market` → 200 (10.91s), `GET /t/new` → 200 (0.019s), `GET /status` → 200 (0.55s), `GET /about` → 200 (0.019s) on the running local stack. These do not exercise signed-in UI, serverFn failure injection, a WebSocket disconnect or payment.
