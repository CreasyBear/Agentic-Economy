# Findings

**Boundary, not a new trading engine.** aecon's buyer selector already retrieves up to ten candidates (`CapabilityProcurementEngine.procure`, `src/modules/capability-execution/procure-engine.ts:194-232`), scores them locally with a Laplace-smoothed completion rate, adoption, price and prior use (`scoreToolEvidence`, `rankToolsForSelection`, `src/modules/registry/tool-selection-score.ts:27-69`), then asks Jev a `choice` with an `unsupported` option (`routeAndSelect`, `procure-engine.ts:409-456`). On an unavailable decision tier it chooses the first evidence-ranked candidate, whereas a model choice below 0.60 or `unsupported` produces `no_matching_tool` (`procure-engine.ts:232-235,439-455`). The fallback is **not** a proof that the first candidate can do the task. The Jev client defaults to **1,500 ms for this selection**; `purpose: 'discovery'` has **5,000 ms**, not 1,500 (`jev-client.ts:11-13,54-71`). Discovery bypasses the secondary and deterministic gateway tiers (`decision-gateway.ts:14-20`); registry and directory callers instead explicitly preserve lexical matches/original pages on operational failure (`tool-reranker.ts:126-195,377-408`; `x402-directory-reranker.ts:59-80`). The comment claiming a 10-second discovery budget at `jev-client.ts:45` disagrees with the executable constant; this review uses the constant. The gateway's `<350ms` comment is not a measured p95 (`decision-gateway.ts:22-28`). No cited external model study measures Jev on aecon's prompts.

**Decision shapes and candidate provenance.** These results are *other systems' measurements*, not aecon forecasts; where the abstract gives no latency, cost, or human-override rate, that measurement is **not reported in the fetched source**.

**Safe to port now (decision policy, not a claim of demonstrated improvement):** (1) Preserve bounded retrieval and the existing one-call typed Jev choice, then use evidence rank as outage fallback; never replace semantic suitability with a raw finance/credit probability. (2) Evaluate top-1 success and top-k recall separately on buyer intents, `unsupported` cases, missed required capabilities, alternative rankings, and later completed/failed Calls; stratify by new Tool, provider, price, and search method. (3) Run comparisons offline or asynchronously in shadow mode before changing selection; include randomly sampled agreements as well as disagreements to avoid biased estimates. These three are compatible with the existing 1.5 s selector only insofar as they add **zero synchronous inference calls**.

**Needs a build and timing proof:** calibrated abstention/conformal sets need outcome labels, drift monitoring and coverage checks; small-first cascades need a distinct small model and *one total* deadline; explicit top-k token logprobs need a confirmed Jev/SDK surface, multi-token candidate scoring and calibration; prefix/cache/continuous batching needs actual provider support and hit/queue telemetry; quote competition needs fresh executable quotes, price/fee/slippage guardrails and provider-side verification. Measure end-to-end p50/p95/p99 and timeout/fallback rate on **aecon** requests before calling any approach 1.5 s safe. Shadow and canary are rollout methods, not substitutes for a held-out labeled set or a truthful production outcome metric.

# Rejected

- **Finance marketing as proof of real-time alpha.** The news and momentum papers report backtest signals, not a Jev buyer-routing improvement; PACE's **0.65 bps** is historical exchange-data execution, not a deployed subsecond smart router ([signal](https://arxiv.org/abs/2412.19245), [momentum](https://arxiv.org/abs/2510.26228), [PACE](https://arxiv.org/abs/2607.28410)). Stripe's **<100 ms / 0.1%** figures are **first-party marketing/engineering self-report, not independently verified in fetched evidence**, and Radar uses DNN/rules rather than Jev ([Stripe](https://stripe.dev/blog/how-we-built-it-stripe-radar)). CoW gives implementation and timeout guidance, **no measured LLM effect** ([CoW](https://docs.cow.fi/cow-protocol/integrate/api)). No credible source fetched provides a Jev trading Sharpe, override rate or live routing uplift; such claims are **unverified**.
- **Blind hard-gating of Bazaar tools from Jev `noul` / static threshold.** A model error would turn a callable listing into an apparent absence; existing directory reranker explicitly preserves all rows and only reorders them (`x402-directory-reranker.ts:16-21,70-80`). Conformal coverage from QA does not transfer without exchangeable labeled aecon selections ([conformal paper](https://arxiv.org/abs/2403.01216)).
- **A second serial model call or many parallel per-candidate calls inside 1,500 ms.** No fetched source reports aecon/jev p95 under such load; the SDK selector currently makes one `systemOne` request (`jev-client.ts:117-125`), and discovery's 5 s exception does not apply to buyer `routeAndSelect` (`jev-client.ts:54-71`).
- **Token `top_k` as probability that k Tools are relevant.** OpenRouter documents `top_k` as next-token sampling, distinct from `top_logprobs`; neither exposes a guaranteed Jev SDK tool-posterior ([parameters](https://openrouter.ai/docs/api-reference/parameters)).
- **Turning synthetic AML, credit, insurance or financial signal research into automated payment/credit/underwriting authority.** Dataset classification and average document throughput do not establish operational oversight, calibrated false-positive costs, or 1.5 s p95 ([AML](https://arxiv.org/abs/2604.19755), [CALM](https://arxiv.org/abs/2310.00566), [claims](https://arxiv.org/abs/2601.01897)).
