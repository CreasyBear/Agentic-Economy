## Handrolling

1. **Cryptographic equality**: `src/lib/server/constant-time.ts:1-9` hand-rolls comparison; Node `crypto.timingSafeEqual` supplies an explicit fixed-buffer cryptographic primitive. This affects signature/token checking, not cosmetic formatting (TS-06). Handle length/fixed-length representation deliberately; blindly swapping APIs is not sufficient.
2. **Accept/media negotiation**: `src/lib/http/agent-content-negotiation.ts:49-57` implements an incomplete HTTP `Accept` parser. The locally installed `negotiator` API `mediaTypes(available)` exists at `node_modules/negotiator/index.js:66-73`, with q parsing at `node_modules/negotiator/lib/mediaType.js:53-90`. It is **not** a direct `package.json` dependency; declare it if adopted, rather than relying on a transitive package (TS-05).
3. **Cookie header parsing and serialization**: `src/lib/http/cookies.ts:11-35` splits raw cookie headers and concatenates Set-Cookie attributes. Installed `cookie` has `parse` and `serialize` at `node_modules/cookie/index.js:11-16,88-100`, including cookie-name/value validation; this is transitive and would need declaration. TanStack Start's `getCookie`/`setCookie` also exist in its server core (`node_modules/@tanstack/start-server-core/dist/esm/request-response.d.ts:64-84`), but operate on the active request event and are **not** a drop-in for the pure `readCookie(header)` helper. Compare behavior for duplicate names, malformed percent-encoding and provided Request boundaries before changing.
4. **URL slug normalization (lower confidence, not a direct substitution)**: `src/modules/market/x402-directory-index.ts:198-206` and `src/modules/capability-supply/internal/facilitator-discovery-ingest.ts:467-474` independently regex-normalize path/host tokens, while canonical `normalizeSlug` delegates to installed `@sindresorhus/slugify` (`src/modules/common/normalize-slug.ts:1-9`, `package.json:97`). Their caps/identity contracts differ (120 chars, 72 chars, digest suffix), so changing existing published identifiers without a route/identity parity check would be unsafe.
