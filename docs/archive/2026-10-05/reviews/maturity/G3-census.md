## PC-15 — An “Active” spending policy with unknown limits
- Register claim on current main: **holds as a possible state; specific observed Agent unverified here**. The badge uses `!isSpendingPaused(detail.grant?.budget)`; an absent budget is explicitly **not paused**, hence “Active” (`src/modules/agent-access/spending-limit-policy.ts:90-96`; `src/components/ae/console/spending-limits-form/AeAgentSpendingLimitsForm.tsx:49-62`). All three readouts then format absent grant amounts and the gauge says “no monthly ceiling configured” if both ceiling projections are absent (`src/components/ae/console/spending-limits-form/useAgentSpendingLimits.ts:60-74,385-389`; `src/modules/agent-access/spending-limit-policy.ts:182-191`). The source projection test explicitly covers no-grant → missing monthly limit (`tests/unit/routes/agent-access-console.test.ts:261-267`). This does **not** establish that Convex has no enforceable grant for the observed Agent.
- Behaviour per affected surface: **Web:** directory and record sheet draw identity/status from canonical Agent records but spend limit from a separately joined grant; header monthly limit and three policy facts are unavailable without that join (`src/components/ae/console/agent-operator-console-model.ts:110-135`). **Chat:** no owner policy-edit display in this traced seam. **HTTP/MCP/CLI:** authenticated `agentAccess.whoami` exposes principal, credential, scopes, and authority mode, **not numeric limits** (`src/modules/agent-access/account.actions.ts:21-35,56-67,241-296`); `ae account status` shows the same identity/mode (`tools/ae/commands/account.ts:59-73`). No paid probe performed.
- Source owner and adapters: **Convex authority** = `agentAccessGrants` readbacks (`convex/lib/agentAccess/policy/reads.ts:18-53`), canonical Agent/credential (`convex/lib/agentAccess/directory/reads.ts:46-67,99-149`), current authenticated owner policy read (`convex/lib/agentAccess/spendingPolicy/reads.ts:15-45`). Web join loads up to **64** owner grants and keys separately, drops keys without matching grant, and selects current key by provider ID (`src/modules/agent-access/agent-access-console.ts:150-193,326-403,478-497`); the 64-row bound is a potential, **unproven** explanation for the observed mismatch. Enforcement obtains the current grant during Quote and checks per-Call plus day/month and organization ceilings (`convex/lib/capabilityExecution/quotes/issueQuote.ts:125-135,157-181`), then rechecks current periods at Call reservation (`convex/lib/capabilityExecution/callLifecycle/admissionRefusal.ts:135-187`); it does not derive authority from the UI badge. Owner edits require ownership and a matching grant generation (`convex/lib/agentAccess/spendingPolicy/update.ts:105-119,144-183`). Tests: `tests/unit/routes/agent-access-console.test.ts:179-267`, `src/components/ae/console/spending-limits-form/useAgentSpendingLimits.test.ts:64-140`, `src/modules/agent-access/spending-limit-policy.test.ts:118-120`.
- Root class: **presentation** plus potentially **authority** projection mismatch; actual missing-grant cause is not proven.
- Status-quo challenge: a mature control plane must not call unknown effective spending authority “Active” or state that a ceiling is unconfigured when its readback is absent. Current status is a default Boolean, not a current policy confirmation.
- Candidate disposition: **redesign** the known/unknown/paused display around an authoritative current read; safer and more intuitive. Diagnose missing grants in a controlled owner fixture before changing enforcement.

- Behaviour per affected surface: **Web:** no invitation control or explanation when context is null; permitted actors can send email with selected admin/member Clerk role, with server rechecking context (`src/components/ae/settings/team-roles/components/TeamInviteForm.tsx:7-19`; `team-roles.functions.ts:27-42`). **Chat/HTTP/MCP/CLI:** no team-invitation adapter found in this owner Team path; the machine `whoami` contract is Agent identity, not Team membership (`src/modules/agent-access/account.actions.ts:56-67`).
- Source owner and adapters: **Convex authority** = active account selection, access fact (`ownership` or `org:admin`) and **exactly one active** `accountExternalOrganizationBindings` record with Clerk organization namespace (`convex/lib/principalAccount/workspace/invitation.ts:14-28`); directory uses a weaker any-access read (`convex/lib/principalAccount/workspace/directory.ts:93-110`). Tests: `tests/unit/convex/workspace-team-directory.test.ts:245-379` tests directory authorization but not this invite predicate; no targeted `invitationContext`/`canInvite` behaviour test found.
- Root class: **authority** (role and external organization binding) plus **presentation** (silent disabled capability); not evidence yet of a wrong role mapping.
- Status-quo challenge: hiding an action with no reason leaves a valid owner unable to distinguish intended restriction from missing organization configuration. The no-members invitation copy, if ever reachable, is inconsistent with a hidden form.
- Candidate disposition: **redesign** the eligibility/explanation against the existing Convex predicate; intuitive and safer. Whether this account should have a Clerk organization is an external-configuration question, not an excuse to bypass authorization.

## PC-19 — Revoke confirmation omits credential identity

- Root class: **presentation** of consequential authority.
- Status-quo challenge: a destructive confirmation that omits the object identifier defeats its purpose when labels collide; it can also conceal that revoking the current credential promotes a predecessor or leaves cleanup pending.
- Candidate disposition: **fix** confirmation and accessible row identity using existing canonical ref/generation/current status; safer. Do not infer that the backend revokes by name.
