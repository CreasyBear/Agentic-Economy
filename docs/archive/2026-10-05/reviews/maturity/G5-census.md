- **Source owner and adapters; tests:** Public CTA `AeSupplyLanding.tsx:81-85`; owner route loader `_operator/owner.operations.new.tsx:23-58`; identity mapping `provider-workspace.functions.ts:235-240,540-545`; first-owner setup `WorkspaceInventoryGate.tsx:6-15`. `tests/unit/ui/supply-funnel-landing.test.tsx:9-20` asserts the direct Add Tool href; `tests/unit/ui/provider-workspace.test.tsx:62-93` and `provider-workspace/useProviderWorkspaceInventory.test.ts:81-104` cover workspace setup, but not the public CTA → missing identity → return → resume sequence. `tests/unit/routes/supply-owner-routes.test.tsx` covers index/detail, not the new-source route.

## Hard questions for Joel
1. **Where should the public Add Tool CTA take a first-time owner?** (a) Tools workspace/profile setup, carrying intent to source start; (b) retain `/new` but show inline identity setup and resume; (c) split newcomer and existing-Provider entry CTAs. Evidence: direct CTA `AeSupplyLanding.tsx:81-85`, missing-identity mapping `provider-workspace.functions.ts:540-545`, current workspace setup `WorkspaceInventoryGate.tsx:6-15`. Source cannot choose the intended onboarding promise, though it proves the present error wording is wrong for `not_found`.
2. **What is the Provider Earnings destination and permission boundary?** (a) show full authoritative earnings facts plus existing payout actions in the workspace; (b) show facts there and place payout initiation in a separate explicit money step; (c) omit payout initiation until a controlled settlement fixture proves it safe, but retain earnings/readback visibility. Evidence: fetched-but-discarded readback `AeProviderWorkspace.tsx:120-128`, orphan card `AeSupplyEarningsCard.tsx:74-136`, per-currency machine read `supply-actions.ts:395-412`. Source cannot determine launch payout policy or real settlement availability.
3. **What should a Plugin success badge certify?** (a) JSON parses and expected keys are present, stated plainly; (b) run local shared full-source validation and distinguish usable remotes from syntax; (c) only show authoritative server preview success, with neutral preflight feedback. Evidence: shallow check `supply-source-native-start-presentation.ts:36-53`, remote admission `agent-plugin-source.ts:33-73`, preview correction `source-preview.ts:350-369`. Source cannot choose the promised immediacy or acceptable extra validation cost.
4. **What constitutes G5 end-to-end acceptance?** (a) onboarded Provider safely previews/publishes a real admitted source, appears for a relevant buyer, and inspects earned/paid facts with a controlled ledger; (b) launch only publication/discovery with Earnings explicitly deferred and no payout promise. Register requires the former for the group journey (`docs/reviews/2026-09-26-papercut-register.md:112,134`), while source/tests cannot provide a real Provider fixture, actual buyer selection or settled money proof. This decision sets release promise rather than inferring it from green tests.
