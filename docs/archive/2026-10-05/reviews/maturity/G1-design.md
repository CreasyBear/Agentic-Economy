# G1 design — Find a suitable Tool

## Decisions applied
- **X1:** Keep the ~15k-row x402 Bazaar *inside* AE search, not in an abandoned side directory. Return one bounded list of admitted and external-only results, differentiated by `access`; remove `groups` entirely. Classify stable public metadata at index write, paginate, then describe an exact item on demand. This replaces repeated/duplicate read work, not an extra model hint. **Performant/intuitive:** the observed MCP weather response was 39,416 bytes, 37,777 in `groups`; five raw external rows were 108,128 bytes (`docs/reviews/2026-09-26-papercut-register.md:31,36`). Anthropic [deferred tool loading](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-search-tool) exposes only discovered definitions; [Composio](https://docs.composio.dev/toolkits/meta-tools/search_tools) searches for 4–6 actions per task under toolkit slugs and exposes schema/connection next steps; [Smithery](https://smithery.ai/docs/api-reference/servers/list-all-servers) defaults to ten summary servers and separates [detail](https://smithery.ai/docs/api-reference/servers/get-a-server); the [official MCP Registry](https://github.com/modelcontextprotocol/registry/blob/main/docs/reference/api/generic-registry-api.md) uses opaque paginated list and version detail. **Do not** install Anthropic's proprietary tool-search API or Composio just to implement their presentation pattern.
- **X2:** `match`, `scoped`, `no-match`, `unavailable` have one transport-independent meaning. An unassessed lexical page or unclassified catalogue tail is **scoped**, never exhaustive no-match; ranker failure is **unavailable** with retry. `next` is identical in structured and human-readable surfaces. No misleading degraded candidates. **Safer/intuitive:** lexical page misses an admitted synonymous Tool and chat independently filters its first page (`convex/lib/capabilitySupply/tool/reads.ts:37-67`; `convex/lib/chat/tools/search.ts:71-115`). [GitHub](https://docs.github.com/en/rest/search/search#timeouts-and-incomplete-results) separates incomplete from zero results; [Algolia](https://www.algolia.com/doc/guides/building-search-ui/going-further/conditional-display/react) distinguishes errors and zero results.
- **X3/X7:** Offer **Save this need** only on genuine exhausted no-match and where a connected identity can complete G6's action; no storage/alert variants here. Need mode selects, then requests caller-supplied exact inputs; discovery never fabricates them. **X4/X5:** G2 owns the sole immediate-conversion rounded-up AUD display rule and point-of-entry recipient disclosure; G1 consumes the formatter, never forks it. Exact Quote/Call, authority, source pricing and current callability remain separate from discovery. **Safer:** `src/modules/registry/internal/listing-projection.ts:18-44,120-140`; `docs/reviews/maturity/00-decisions.md:13-19`.
- **Jev decision:** Compute source-backed `actionClass` (`retrieve | transform | analyze | create | mutate | other | unclassified`) × `objectClass` (`web | document | image | location | chain | data | other | unclassified`) at index write using declared category, method, tags and schema only, not claims inferred from Provider prose. Existing unchanged Bazaar rows receive this projection through the existing refresh/backfill path, not just future Provider updates. Unknown rows remain navigable as `unclassified`; candidate retrieval includes them when its class would otherwise exclude them, and preserves request wording. Do **not** add a Jev call per Bazaar row, facet/page or additive chat hint. Jev may replace an existing classification job on changed source digests only after held-out retrieval/first-three benefit and total work/latency are proved. **Performant/maintainable:** index writes already compute category/search text/eligibility (`convex/lib/market/directoryIndex/ingestion.ts:95-155`; `convex/lib/market/directoryIndex/providerRows.ts:103-135`); eight-query Jev trial improved first result on two but not catalogue recall (`output/jev-bazaar-eval-2026-09-20/REPORT.md:7-28`), 32 paired loops found no turn reduction and higher cost (`output/jev-agent-loop-2026-09-20/REPORT.md:18-34`). ADR recommends source-time interpretation and warns reranking cannot rescue missing candidates (`docs/adr/0003-jev-market-journey-intelligence.md:64-76,129-146`); programme rejects additive hints (`research/jev-experiment-programme.md:10-19,45-65`); held-out provider matching was 11/12 for both Jev and existing adapter, not production proof (`output/jev-journeys-2026-09-20-v2/REPORT.md:9-24,56-64`). `package.json:69-167` already carries the TypeSafe SDK, Convex, Zod and Decimal; no dependency proposed.

## Contracts
- **Request:** retain canonical search `query` 1–256, `source`, filters, cursor; default source searches current/admitted **and** Coinbase Bazaar (explicit source can narrow), default page **8**, maximum **12**. Market/Bazaar directory query remains **≤200** until index limit is proven compatible. For 201–256 canonical default search, assess admitted only, return `scoped` with explicit “Bazaar query limit 200; shorten to continue”; explicit `source: coinbase` returns field validation, not an invented no-match. Facets apply on server before pagination, not just current page: `actionClass`, `objectClass` (source-backed or unclassified), existing provider category, Provider, network, listed price band, and `access` (`ae_callable` vs `external_listing`). Existing `marketDirectoryFacets` holds counts over the completed generation; never present partial page counts as whole-catalogue counts (`src/modules/market/internal/convex-schema.ts:120-169,230-245`; `convex/lib/market/directoryIndex/browse.ts:105-145`). [Algolia faceting](https://www.algolia.com/doc/guides/managing-results/refine-results/faceting) distinguishes indexed facets/counts from filters; [OpenRouter models API](https://openrouter.ai/docs/api/api-reference/models/get-models) separates q/category/provider/price and now documents offset+limit; no assumption of infinite single-list results.
- **List row:** stable `id` (ToolRef if admitted; opaque directory document ID if external), `source`/`access`, title ≤72 Unicode characters, one source-grounded fit cue ≤100, provider ≤48, `actionClass`, `objectClass`, category, readiness/callability, indicative **G2-formatted AUD** buyer price when convertible (otherwise price unavailable; never display USDC as buyer price), `detailRef`/URL and a single `describe` action. External rows explicitly `external_listing`, no AE Quote/Call action. Joining an external sourceRouteRef to a live publication collapses to the admitted ToolRef, never two rows; Quote rechecks eligibility (`convex/lib/market/directoryIndex/browse.ts:20-34`; `src/modules/registry/internal/listing-search.ts:42-50`). No metadata JSON, endpoint input/output schemas, giant descriptions, nested evidence or repeated per-row next actions in list. **Budget:** ≤16 KiB UTF-8 JSON for one canonical search response (MCP structured *included*, not only prose); ≤16 KiB for GET `/api/v1/registry` with **12 max** rows. Byte budget is AE's explicit design cap to validate against observed 39/108 KiB, not a competitor SLA. Bound strings at projection, fetch compact index fields rather than rich row, and reduce page length *before* forming continuation when necessary; never cut valid JSON or conceal omitted results. Search `nextCursor` is opaque and scoped to source generation + query/filter/order; on stale cursor return invalid-cursor/restart, not silent gaps. Limit/count describe returned page, not imaginary 15k total.
- **Detail:** admitted `POST /api/v1/market-tools/describe` retains exact ToolRef, schema, provenance and current eligibility; external `GET /api/v1/registry/detail?id=<opaque-id>` uses an indexed exact-generation/document-ID read (`marketExternalRegistryEntries` indexed at `src/modules/market/internal/convex-schema.ts:51-103`) to return source JSON/schema on explicit inspection with an `external_listing` warning, never admission by description. Human `/tools/<provider>/<slug>` is its existing detail peer (`convex/lib/market/directoryIndex/lookup.ts:22-42`). Detail freshness is source-labelled; never derive ToolRef by matching title/host.
- **Outcome:** `kind: match | scoped | noMatch | unavailable`, `query`, `results`, `assessed: {source, scope, generation/completedAt, examined, coverage}`, `pagination`, `next` actions. `match` only evidence-assessed relevant rows (external may fit a need but remain not AE-callable); `scoped` means assessed subset/filters with unassessed continuation or incomplete source, not “nothing exists”; `noMatch` only after all eligible candidate inventory under stated sources/filters was assessed with no suitable item, not after a last lexical page; `unavailable` on ranker/index failure, no fallback recommendation. At 15k rows an impossible natural-language need normally returns **scoped** until completeness is proven; do not spend unbounded model calls to manufacture “noMatch.” Preserve source-specific `next-page` cursors, `broaden` only when useful and `retry` for unavailable; G6 owns the actually authorized `save-need` action, which G1 exposes only for signed-in/connected exhausted no-match once that action is connected (existing read-only continuation is `src/modules/registry/next-action.ts:3-17`; existing demand write rejects incomplete results at `src/modules/market-demand/market-demand.actions.ts:218-265`). Prohibit `partialResults=false` on unassessed source. Canonical HTTP JSON, MCP `structuredContent` and `content`, CLI `--json` and plain, chat answer/card and Market use this one verdict and actionable next arguments; plain text may shorten row details but not omit scope/cursor/action. Chat generation must save a substantive final response; if an already-authorized Call may have occurred, preserve CallRef and offer status inspection/edit question rather than resending (`convex/lib/chat/generate/run.ts:84-113`). Freshness states label x402 scan vs supply reconciliation separately (`src/modules/market/x402-directory-index.server.ts:81-96`; `src/modules/registry/tools.actions.ts:29-52`). No fresh currency formatter or price inference in this group.
