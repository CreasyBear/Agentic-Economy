# G2 reference — Make a truthful choice

**Scope:** PC-04, 07, 08, 09, 20, 24, 25, 30, 33, 34, 42. The AE descriptions below are the [27 September papercut register](../2026-09-26-papercut-register.md), not a new source or paid-Call audit. Competitor behaviour is documented behaviour unless explicitly noted; a listing, sample response, or quoted plan does not prove successful delivery. Each table uses official product documentation or a maintained first-party design system. The same product appears in multiple tables because these are separate decision moments, not 30 independent competitors.

## Behaviour: know whether a result is callable before choosing it (PC-04)

| Product | How it behaves | Official source URL |
|---|---|---|
| OpenRouter | Model-endpoint records separate provider, price, supported parameters and recent uptime/latency; routing takes provider restrictions, parameter requirements and fallback settings. An endpoint metric is not a promise that a later request succeeds. | [Endpoint API](https://openrouter.ai/docs/api/api-reference/endpoints/list-all-endpoints-for-a-model); [provider routing](https://openrouter.ai/docs/guides/routing/provider-selection) |
| RapidAPI | API listing shows Provider, endpoints and pricing. A paid API requires plan selection before testing; approval-gated plans show a request-access and pending state rather than an immediately callable endpoint. | [API listing](https://docs.rapidapi.com/docs/api-listing-overview); [connecting to an API](https://docs.rapidapi.com/docs/connecting-to-an-api) |
| AWS Marketplace | Product detail leads to offer selection, pricing dimensions and EULA before a SaaS subscription; the buyer is not told that viewing a listing equals a usable subscription. | [SaaS usage subscriptions](https://docs.aws.amazon.com/marketplace/latest/buyerguide/saas-subscriptions.html) |
| Mercator | Search documents estimated price, input requirements and health; `resolution=live` can attempt bounded Provider probes. Inspection and quote remain separate free steps, and the [local research](../../../../../research/MERCATOR-DOCS-CAPABILITY-MAP-2026-09-27.md) observed only static search, not a successful paid call. | [Search services](https://mercator.sh/docs#search-services); [describe a service](https://mercator.sh/docs#describe-a-service) |

**Familiar pattern:** Show supply mode, access prerequisite and known readiness **on the result**, then confirm availability against the actual operation at selection/quote. Distinguish observed health, unverified health and non-callable catalogue entries. **AE reason to differ:** An admitted AE Tool and executable x402 Call have stronger authority and payment prerequisites than a generic API listing; show that distinction, not an invented universal “online” badge. Current register: one selectable-looking result only reveals external payment/unknown readiness after click.

## Behaviour: distinguish buyer price and currency from upstream price (PC-09)

| Product | How it behaves | Official source URL |
|---|---|---|
| Stripe | Explicitly distinguishes integration, customer presentment/charge and merchant settlement currencies. Localized checkout displays the customer's price at checkout; an FX quote or manually set price is a separate policy. | [Currencies](https://docs.stripe.com/currencies); [localize prices](https://docs.stripe.com/payments/currencies/localize-prices) |
| AWS Marketplace | Buyer reviews the price of each billable dimension in the **preferred currency**, chosen offer and EULA before accepting. Usage-based SaaS charges land on the buyer's AWS bill. | [SaaS usage subscriptions](https://docs.aws.amazon.com/marketplace/latest/buyerguide/saas-subscriptions.html) |
| RapidAPI | Pricing tab exposes public plans; paid APIs require subscription before testing and the consumer is warned about overage outside the plan quota. These are RapidAPI's buyer plan terms, not the API Provider's cost of running the endpoint. | [API listing](https://docs.rapidapi.com/docs/api-listing-overview); [connecting to an API](https://docs.rapidapi.com/docs/connecting-to-an-api) |
| OpenRouter | The model/endpoint API publishes billable unit prices for each provider endpoint, and routing supports a hard `max_price` constraint; model catalogue price and a selected endpoint's rate need not be treated as the same fact. | [Model endpoints](https://openrouter.ai/docs/api/api-reference/endpoints/list-all-endpoints-for-a-model); [max price](https://openrouter.ai/docs/guides/routing/provider-selection#max-price) |

**Familiar pattern:** Lead with the amount, unit and currency the **buyer** will actually owe; label any upstream/provider rate as a separate fact, with applicability and validity. An estimate is not a binding quote. **AE reason to differ:** AE's buyer-facing AUD Quote and upstream USDC/x402 transfer are distinct obligations. A directory-only external-payment Tool must not imply an AE AUD Call price. Current register: chat promises AUD, while some catalogue surfaces show USDC/external payment without the role distinction. Crosses G4's exact Quote/Charge/receipt boundary.

## Behaviour: disclose data recipient at query entry and Tool-input entry (PC-24, PC-25)

| Product | How it behaves | Official source URL |
|---|---|---|
| AWS Marketplace | Its natural-language procurement entry expressly warns before entry that submitted information can be visible to others, and says not to enter confidential or personal information; it also states that agent mode does not execute purchases. This warning is specific to that surface, not a generic AWS privacy rule. | [Agent mode — Security and capabilities](https://docs.aws.amazon.com/marketplace/latest/buyerguide/agent-mode.html#agent-mode-security) |
| OpenRouter | Shows provider-level retention/training information and per-request policy filters before an inference request. Its ZDR guide explicitly says ZDR routing **does not cover enabled third-party tools/plugins**, whose policies must be reviewed separately; provider-policy tags are its best knowledge, not independent guarantees. | [Provider logging](https://openrouter.ai/docs/guides/privacy/provider-logging); [ZDR](https://openrouter.ai/docs/guides/features/zdr); [routing](https://openrouter.ai/docs/guides/routing/provider-selection) |
| Apple App Store | Product-page privacy label describes types of data collected, purpose, links to identity and tracking, including integrated third-party partners. Apple narrowly defines “collect” for its label as off-device access longer than required for a real-time request; this **does not** mean a real-time transfer needs no AE point-of-entry explanation. | [App privacy details](https://developer.apple.com/app-store/app-privacy-details/) |
| RapidAPI | Its hosted proxy receives and forwards request to the API Provider; request/response logging and provider access depend on gateway configuration. A browser form alone therefore does not establish who sees submitted arguments. | [Rapid Runtime gateway](https://docs.rapidapi.com/docs/hub-listing-gateway-tab) |

**Familiar pattern:** State the recipient, data category and applicable retention/handling limits **before submitting sensitive query or Tool inputs**; distinguish matching/ranking gateway from the chosen executing Provider, and never promise ZDR for a separate tool on the strength of an inference setting. **AE reason to differ:** Agent authority and Tool data-use policy may impose harder limits than a disclosure alone. The register verifies missing nearby notices, **not** the actual ranking recipient or whether a sampled degraded query reached it; verify those before making a public routing claim. For Tool inputs, technical schema disclosure by itself is not a human-readable recipient notice.

## Anti-patterns mature products avoid

- **Listing ≠ availability or price:** An AWS listing precedes offer terms, RapidAPI approval can be pending, and OpenRouter routes among changing endpoints. [AWS](https://docs.aws.amazon.com/marketplace/latest/buyerguide/saas-subscriptions.html) · [RapidAPI](https://docs.rapidapi.com/docs/connecting-to-an-api) · [OpenRouter](https://openrouter.ai/docs/guides/routing/provider-selection).
- **One “price” for three different obligations:** Charge/presentment/settlement are distinct, and usage-based rates depend on the chosen billable dimension. [Stripe](https://docs.stripe.com/currencies) · [AWS](https://docs.aws.amazon.com/marketplace/latest/buyerguide/saas-subscriptions.html).
- **Assuming provider privacy extends to every third-party Tool:** OpenRouter explicitly excludes enabled plugins/tools from ZDR routing; RapidAPI's gateway can forward and log request content. [OpenRouter](https://openrouter.ai/docs/guides/features/zdr) · [RapidAPI](https://docs.rapidapi.com/docs/hub-listing-gateway-tab).
- **Presenting mixed-origin statistics as one platform metric:** AWS separates sourced review ratings; OpenRouter names provider and time-window per performance or usage fact. [AWS](https://docs.aws.amazon.com/marketplace/latest/buyerguide/buyer-product-reviews.html) · [OpenRouter](https://openrouter.ai/docs/api/api-reference/endpoints/list-all-endpoints-for-a-model).
- **Cramping or hiding critical mobile actions:** Carbon avoids cramped table containers, Apple surfaces useful first-column data and excludes fixed controls from the action-safe area. [Carbon](https://carbondesignsystem.com/components/data-table/usage/) · [Apple Table](https://developer.apple.com/documentation/swiftui/table) · [Apple safe area](https://developer.apple.com/documentation/uikit/positioning-content-relative-to-the-safe-area).

## Questions the references raise for AE

1. **What belongs in the primary catalogue?** (a) only AE-callable Tools, with externally priced entries in a separately labeled directory; (b) mixed results with explicit type/readiness filters and distinct actions; (c) remove non-callable entries. The register shows confusion, while AWS and RapidAPI demonstrate that listing and buyer access are different facts; neither settles AE's release promise. [AWS](https://docs.aws.amazon.com/marketplace/latest/buyerguide/saas-subscriptions.html) · [RapidAPI](https://docs.rapidapi.com/docs/connecting-to-an-api).
2. **Where does the buyer see USDC upstream price?** (a) technical/Provider detail only; (b) secondary labeled line beside the AUD buyer estimate; (c) show USDC on external-payment rows only, with no implied AUD AE Call. Stripe's currency distinction is clear, but AE's intended mixed catalogue and currency policy are Joel's decisions. [Stripe](https://docs.stripe.com/currencies).
3. **What exactly can leave the search box?** (a) disclose and permit bounded third-party ranking; (b) require a local-only/private search mode; (c) disable external ranking for this entry point. Verify current recipients/retention first. OpenRouter distinguishes routing providers from separately enabled tools, while AWS warns at natural-language input; neither can decide AE's actual routing policy. [OpenRouter](https://openrouter.ai/docs/guides/features/zdr) · [AWS](https://docs.aws.amazon.com/marketplace/latest/buyerguide/agent-mode.html#agent-mode-security).
4. **Which inputs may an Agent construct after a `need` match?** (a) preserve selection and ask only for missing authoritative fields; (b) derive supported, nonsensitive fields from the stated need before Quote; (c) always require a separately submitted exact request. Mercator's Quote still requires exact inputs and has no proved automatic argument derivation. [Mercator](https://mercator.sh/docs#quote-a-plan).
5. **Which comparison stats are allowed to appear as “Calls”?** (a) AE-paid Calls only; (b) external activity with explicit origin and different terminology; (c) remove activity from comparisons until AE-observed usage exists. AWS and OpenRouter demonstrate source/window distinctions, not the legitimate AE taxonomy. [AWS](https://docs.aws.amazon.com/marketplace/latest/buyerguide/buyer-product-reviews.html) · [OpenRouter](https://openrouter.ai/docs/api/api-reference/analytics/get-user-activity).

**Boundary summary:** G1 owns reliable fit, current supply and honest no-match; G2 owns decision-ready representations and viable alternatives. G4 owns binding AUD Quote, charge and receipt; G5 owns Provider-supplied schema/admission and claims; G6 owns retained demand after no alternative; G7 owns developer-facing spec/examples. No cited competitor's catalogue claim is evidence of a successful AE or competitor paid Call.
