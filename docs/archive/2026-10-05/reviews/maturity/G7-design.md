# G7 design — Fresh developer

## Decisions applied

- X6 makes public connect, funding, Quote and paid Call an entry-release path; public installation is not optional (`docs/reviews/maturity/00-decisions.md:18`). **Choose one channel: a version-pinned GitHub Release archive**, built once on the release tag and attached to that public release with a SHA-256 checksum and a GitHub Actions build-provenance attestation. Install the *downloaded, verified file* with npm; do not present npm publication or the AE website's deploy-built tarball as alternate channels. GitHub documents [`actions/attest@v4` with `subject-path`](https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations/use-artifact-attestations) and [`gh attestation verify` with repository, signer-workflow, source-ref and source-digest constraints](https://cli.github.com/manual/gh_attestation_verify); [`gh release verify-asset`](https://cli.github.com/manual/gh_release_verify-asset) additionally binds an asset to a release **only when a release attestation is actually issued**. A published checksum alone does not prove publisher identity. npm provenance is mature [for actual npm publication](https://docs.npmjs.com/generating-provenance-statements/) but is not provenance for the currently unpublished archive (`packages/cli/README.md:7-9`, `packages/cli/package.json:22-25`). This is the familiar GitHub CLI release pattern, not an AE-specific exception (`docs/reviews/maturity/G7-reference.md:5-16`).
- The release workflow must run on the approved, protected `v<packages/cli/package.json version>` tag, after source gate, verify the **same packaged bytes** with the existing prepacked package verifier, attest that tarball, publish the checksum and archive together, and never repack after attesting. Verify release visibility and attestation as an unauthenticated outsider before printing install commands. `npm run build` currently repacks a second archive into the web deploy (`package.json:12-14,22`), while `src/lib/cli-distribution.ts:27-36` advertises that other URL; remove the deploy-built channel and its unused install helpers rather than maintaining two release truths. Existing Node >=20 and compiled binary contract remains (`packages/cli/package.json:7-20`). No npm dependency is required for the design (`package.json:7-23`; `packages/cli/package.json:17-25`).
- X2 governs the Search no-match/continuation response; X7 means never invent input. G7 demonstrates the accepted G1 shape rather than redefining Search; one current `toolRef` is carried into describe, exact input Quote and Call (`docs/reviews/maturity/00-decisions.md:14,19`). X4 price presentation belongs to G2; the guide does not introduce another formatter (`docs/reviews/maturity/00-decisions.md:16`). Adopt the brief's after-connect doctor, safe-read examples/non-runnable write skeletons and sole tracked packaged guide (`docs/reviews/maturity/00-decision-brief.md:34-36,52`).

## Contracts

1. **Release artifact:** input = approved source SHA/tag and package version; output = single `aecon-cli-<version>.tgz` attached to the corresponding public GitHub Release, checksum and verifiable provenance for the identical bytes. Verify tag/version, SHA-256 and `gh attestation verify <file> -R CreasyBear/Agentic-Economy --signer-workflow <exact release workflow> --source-ref refs/tags/v<version> --source-digest <approved SHA>` before `npm install --global ./<file>`; the release URL/repository are pinned, never `latest`. Checksum checks transmission; signed attestation checks build origin; neither asserts code safety. If the release repository remains private or attestation lookup fails for a fresh unauthenticated outsider, no public installation claim is valid. Current CI uploads only short-lived source evidence (`.github/workflows/kernel-release-gate.yml:106-117`); its package verifier checks reproducibility and executable semantics, not hosted availability (`scripts/test-cli-package.ts:145-160,164-235`).
2. **Quickstart:** Search is anonymous; extract `AE_TOOL_REF="$(ae search 'convert a time between time zones' --json | jq -er 'select(.kind == "matched") | [.results[] | select(.readiness == "ready") | .toolRef][0] // empty')"`; only proceed if nonempty. A scoped result follows its next page, exhausted no-match follows its named next action, unavailable retries; never coerce those into a Tool (`src/modules/registry/tool-choice-contracts.ts:93-97,148-149`; `tools/ae/commands/search.ts:50-80`). `ae describe "$AE_TOOL_REF" --json` supplies the selected Tool's input schema; a human or caller supplies **exact** `AE_INPUT` from that schema, not a universal example. `ae connect` precedes `ae doctor --json` and paid commands. `ae quote "$AE_TOOL_REF" --input "$AE_INPUT" --json` is a non-executing preflight; `ae call "$AE_TOOL_REF" --input "$AE_INPUT" --wait --json` obtains a **fresh Quote internally** before submitting its Call, not a submission of the previous Quote (`tools/ae/commands/call.ts:313-317,396-415,417-459`). Explain funding/authority refusal and preserve CallRef/status/recovery rather than blind retry. Provider credential is separate (`tools/ae/README.md:26-41`).
3. **API examples:** input = normalized OpenAPI operation/registered schema; output = copyable complete Search request or explicitly labelled non-runnable request template. Add Search example to normalized operation/media example, not a second validation schema; presenter reads it (`src/modules/discovery/internal/openapi-operations.ts:146-167`; `openapi-document-schema.ts:114-121`; `developers-api.view-model.ts:134-168`). HTTP POST is not synonymous with a write (Search itself is POST). Default absent-example body is not `{}` portrayed as runnable; do not generate arbitrary values for required fields, credentials, Call identity or irreversible effects. The OpenAPI schema remains machine authority; template never advertises successful execution.

## Acceptance tasks

1. **Outside release:** after approved source gate, from a fresh unauthenticated machine obtain exact tagged asset/checksum over public GitHub Releases, verify digest and signer/source identity with `gh attestation verify`, install the downloaded archive, observe `ae --version` equals tag and `ae --help --json` shows Search/connect/Quote/Call; old `/downloads/...tgz` is not advertised. Fixture required: genuinely public repo/release (or explicitly approved public release home) and GitHub-hosted attestation reachable without a private-repo token. No source checkout or local tarball substitutes.
2. **HTTP/web:** copy Search from `/developers/api`, send against the pinned served origin and observe a valid Search response rather than missing-`query` 400; inspect write template for no runnable Copy action. Fixture required: configured served origin and admitted x402 supply to verify useful results; input-valid no-match may be observed without supply.
3. **CLI customer path:** with fresh eligible outsider, run install → version → Search for a real admitted Bazaar-observed x402 Tool (timezone converter or ERC20 transfer logs) → extract ready Tool ref → describe → connect → doctor → caller-supplied schema-valid input → AUD Quote → explicit funded Call → inspect durable CallRef/status/receipt. If Quote refuses insufficient funding/authority, follow owner continuation; do not trigger payment in design review. Fixture required: public account, approved funding/eligibility, admitted callable Tool with known actual input and controlled paid GET/POST effects; a Bazaar listing alone or sandbox fixture is insufficient. Use G2's display rule, not a G7 formatter.
4. **Negative paths:** impossible need must not leak an unrelated Tool into the ref selector; follow G1's scoped/exhausted continuation and, only after connect, any admitted save-need option. Test unconnected and unfunded Quote refusals (no Call), unavailable/ranker-failure retry (not no-match), and uncertain Call recovery via the existing same-ref/status path, never a second blind purchase. Fixture required: controlled impossible query and refusal/uncertain-dispatch actors; no live payment in this design phase. Replay HTTP/MCP/chat Search context where applicable; they inherit G1's Tool choice, not CLI installation.

## Surprises for Joel

- `git remote get-url origin` reports `https://github.com/CreasyBear/Agentic-Economy.git`, but an unauthenticated `https://api.github.com/repos/CreasyBear/Agentic-Economy` returned 404 on 27 Sep; public repository/release accessibility is **not proved**. Public GitHub Release plus outsider-verifiable attestation is a hard prerequisite for the chosen channel, and may require approving public release visibility. GitHub documents private attestations use its non-public Sigstore instance ([artifact-attestation overview](https://docs.github.com/en/actions/concepts/security/artifact-attestations)); do not call a private release public merely because a local CI run passed.
- `ae quote` is standalone preflight but `ae call` **re-quotes** before submission (`tools/ae/commands/call.ts:396-415,447-459`). Quickstart must not imply that the earlier QuoteRef is submitted unchanged; G4 must confirm the paid purchase contract.
