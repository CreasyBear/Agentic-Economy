# G7 reference — Enable a fresh developer

Scope: PC-06 (install), PC-11 (doctor), PC-31 (API example), PC-32 (quickstart), PC-38 (maintained source guide). AE's current behaviour below comes **only** from the [papercut register](../2026-09-26-papercut-register.md#highest-priority-register); this phase does not inspect AE source or claim an AE change. References are first-party documentation and maintained repositories, read 27 September 2026.

## Behaviour: Install a CLI and verify the artifact before execution (PC-06, PC-38)

| Product | How it behaves | Official source URL |
|---|---|---|
| Stripe CLI | Maintained repository README gives commands for npm, Homebrew, signed apt repository and WinGet; for manual installation, it links the official release page and names archive patterns, extraction and `PATH` placement. The README does **not** provide a manual-archive checksum-verification recipe; do not claim it does. | [Stripe CLI installation](https://github.com/stripe/stripe-cli#installation) |
| GitHub CLI (`gh`) | Its install landing page names supported platform/package-manager routes and direct release assets; its Linux instructions publish signing-key fingerprints and show how to inspect the downloaded key. `gh release verify-asset` separately verifies a *downloaded release asset* against a signed release attestation, including digest and release association (when such an attestation is available). | [CLI install](https://cli.github.com/), [Linux signing/install](https://github.com/cli/cli/blob/trunk/docs/install_linux.md), [release asset verification](https://cli.github.com/manual/gh_release_verify-asset) |
| Vercel CLI | Install instructions give package-manager commands, `vercel --version` as a smoke check, authentication prerequisites, and a separate opt-in native-binary route. They do not present a manual-archive checksum procedure for the standard package-manager route. | [Vercel CLI overview](https://vercel.com/docs/cli) |
| Homebrew | Its installer documents the supported installation location and requires following post-install shell `PATH` directions; the installer tells the user what it will do and requests confirmation. This is a package-manager installation path, not evidence that an unrelated downloaded archive was independently authenticated. | [Homebrew installation](https://docs.brew.sh/Installation) |

**Familiar pattern:** Name a real distribution channel, platform/architecture, install command and first version check in one followed path; if offering raw archives, link the specific publisher release location and separately explain how that artifact is authenticated before execution. Package-manager provenance and a bare checksum from the same potentially compromised page are not interchangeable with a signed attestation or independently trusted signing key ([Stripe](https://github.com/stripe/stripe-cli#installation), [GitHub](https://github.com/cli/cli/blob/trunk/docs/install_linux.md), [GitHub release verification](https://cli.github.com/manual/gh_release_verify-asset), [Vercel](https://vercel.com/docs/cli)). The register says AE's archive guide gives neither URL nor retrieval/verification sequence and npm publication is pending; the untracked source guide cannot serve a fresh checkout ([register PC-06 and PC-38](../2026-09-26-papercut-register.md#highest-priority-register)).

**AE reason to differ:** No AUD/authority/x402 reason to differ on install provenance or tracked docs. If neither a publicly downloadable authenticated artifact nor a published package exists, say explicitly that external installation is unavailable; do not supply a fictional command. What channel to release first remains a product/release decision.

## Behaviour: Diagnose expected degraded states without misreporting success (PC-11)

| Product | How it behaves | Official source URL |
|---|---|---|
| GitHub CLI | `gh auth status` checks known accounts and reports issues; ordinary output exits `1` for an authentication problem, but `--json` exits `0` for those same problems unless a fatal error occurs. Automation must read the JSON fields rather than presume its process status has identical meaning. | [gh auth status](https://cli.github.com/manual/gh_auth_status) |
| Flutter | `flutter doctor` inventories installed toolchains. Troubleshooting shows named `[!]` Android-toolchain and license conditions with the command that addresses each. The referenced CLI page does not promise a universal warning-to-exit-code mapping; do not infer one. | [Flutter CLI](https://docs.flutter.dev/reference/flutter-cli), [installation troubleshooting](https://docs.flutter.dev/install/troubleshoot) |
| Homebrew | The troubleshooting runbook has users read every `brew doctor` warning, correct those relevant to the failing command, then retry it; it explicitly discourages blindly applying destructive fixes. This is a diagnostic report, not a declaration that each warning blocks every operation. | [Homebrew troubleshooting](https://docs.brew.sh/Troubleshooting) |
| npm | `npm doctor` states its prerequisites (registry reachability, executable Git/Node, writable directories, cache integrity), explains what each check tests and permits named subsets of checks. A custom registry without the expected endpoint can cause a diagnostic failure even if the CLI itself runs. | [npm doctor](https://docs.npmjs.com/cli/v11/commands/npm-doctor/) |

**Familiar pattern:** A diagnostic identifies which capability is available, skipped, warned or blocked and what action changes it; document process status *independently* from structured check statuses so automation and humans reach the same interpretation ([GitHub](https://cli.github.com/manual/gh_auth_status), [Flutter](https://docs.flutter.dev/install/troubleshoot), [npm](https://docs.npmjs.com/cli/v11/commands/npm-doctor/), [Homebrew](https://docs.brew.sh/Troubleshooting)). AE's register reports `ae doctor --json` exits `1` before connection, with `quoting: skipped` and `purchase: warn`, and its package guide does not explain that expected state ([register PC-11](../2026-09-26-papercut-register.md#highest-priority-register)). An exit `1` need not be changed merely because it is expected; the missing contract is *what it means and which command remains safe to run*.

**AE reason to differ:** Authority, funding and x402 settlement justify grading **public discovery** separately from **authenticated Quote** and **funded Call** readiness; failing a purchase-readiness check must not imply that the installed binary or public reads are broken. They do not justify hiding a degraded status, masking a real failure with exit `0`, or making `--json` unexpectedly change semantics without documentation.

## Behaviour: Copy a valid API request rather than a guaranteed validation error (PC-31)

| Product | How it behaves | Official source URL |
|---|---|---|
| Stripe API | Create Customer shows a complete cURL request with plausible `name`/`email`, the required authentication placeholder and a representative response ID. Create PaymentIntent supplies required positive `amount` and lowercase `currency`; it illustrates request validity without implying that a payment was completed. | [Create Customer](https://docs.stripe.com/api/customers/create), [Create PaymentIntent](https://docs.stripe.com/api/payment_intents/create) |
| GitHub REST API | Getting-started docs spell out method, path, authentication and required path/body/query parameters, provide a valid read request (`/octocat`) and explicitly say to replace `{owner}`/`{repo}` with actual values when using resource endpoints. | [Getting started with REST](https://docs.github.com/en/rest/using-the-rest-api/getting-started-with-the-rest-api) |
| Vercel REST API | Get User documents `GET /v2/user`, bearer authentication, copyable cURL/fetch requests and a response shape. The token placeholder is an identified credential substitution, not a missing required JSON body. | [Get the User](https://vercel.com/docs/rest-api/user/get-the-user) |

**Familiar pattern:** The default code sample supplies every *ordinary required* value with realistic non-secret examples, marks credentials and truly resource-specific identifiers explicitly, identifies the resulting object, and separates successful request validation from downstream commercial success ([Stripe Customer](https://docs.stripe.com/api/customers/create), [Stripe PaymentIntent](https://docs.stripe.com/api/payment_intents/create), [GitHub REST](https://docs.github.com/en/rest/using-the-rest-api/getting-started-with-the-rest-api), [Vercel REST](https://vercel.com/docs/rest-api/user/get-the-user)). AE's copyable Search example sends `{}` even though `query` is required and returns `400` when copied ([register PC-31](../2026-09-26-papercut-register.md#highest-priority-register)).

**AE reason to differ:** None for Search's required text query: use a concrete, non-secret need. For Quote/Call, AE's Tool/Quote/Call contract and AUD/x402 payment require *real selected Tool refs, input matching that Tool's schema, authority and explicit paid-action framing*; never pretend a fixture ID, a made-up credential or a successful HTTP status proves a purchasable result.

## Behaviour: Run the first workflow in dependency order and carry identifiers forward (PC-32, PC-38)

| Product | How it behaves | Official source URL |
|---|---|---|
| Stripe CLI | Installation precedes browser-based `stripe login`; the resource guide then shows authenticated `customers create` using actual example values and `customers retrieve` with a customer-shaped ID. `stripe login list` reveals authorized sandbox/live contexts rather than leaving account context implicit. | [Install](https://github.com/stripe/stripe-cli#installation), [login and contexts](https://docs.stripe.com/cli/login), [resource examples](https://docs.stripe.com/cli/resources) |
| GitHub CLI | Installation is public; `gh auth login` documents browser/automation auth, and REST getting-started explicitly orders setup → authenticate → choose endpoint → request. `gh` supports `--json fields --jq expression` on applicable commands, and `gh api --jq` can select response fields for reuse by another shell command. | [Install](https://cli.github.com/), [login](https://cli.github.com/manual/gh_auth_login), [REST getting started](https://docs.github.com/en/rest/using-the-rest-api/getting-started-with-the-rest-api), [formatting](https://cli.github.com/manual/gh_help_formatting), [API CLI](https://cli.github.com/manual/gh_api) |
| Vercel CLI | CLI overview orders install/version check before `vercel login`; `vercel whoami` shows current identity, `vercel link` binds the local directory to a project and deployment commands use that context. Deploying from CLI defines stdout as the deployment URL so a script can capture the next identifier without parsing decoration. | [CLI install/version/auth](https://vercel.com/docs/cli), [whoami](https://vercel.com/docs/cli/whoami), [link](https://vercel.com/docs/cli/link), [deployment URL](https://vercel.com/docs/cli/deploying-from-cli) |

**Familiar pattern:** One tracked, publicly reachable guide is executable top-to-bottom: install → verify → connect/authenticate → harmless first read → first *clearly labelled* write; introduce a variable immediately after the command that returns its ID, show exactly which JSON field to select and check the empty/no-result branch before reuse. Use a supported built-in projection (`--jq`/`--format`) or documented JSON plus `jq`, not a hard-coded response ID or an unexplained `$AE_TOOL_REF` ([GitHub formatting](https://cli.github.com/manual/gh_help_formatting), [GitHub API](https://cli.github.com/manual/gh_api), [Vercel deployment stdout](https://vercel.com/docs/cli/deploying-from-cli), [Stripe resources](https://docs.stripe.com/cli/resources)). AE's current quickstart uses authenticated request commands before `ae connect` and a Tool-ref variable without extraction; its purported maintained source guide is absent from fresh checkouts ([register PC-32 and PC-38](../2026-09-26-papercut-register.md#highest-priority-register)).

**AE reason to differ:** Public discovery can legitimately precede authentication; **paid** Call cannot precede the applicable authority, Quote and approval/funding prerequisites. That contract changes which step qualifies as a safe first write, not the requirement for a top-to-bottom runnable guide. Whether the first write is a non-commercial retained-demand request, a Quote, or a paid Call is unresolved; do not represent those as interchangeable.

## Anti-patterns mature products avoid

- **Mystery artifacts and unsigned claims:** an archive instruction without publisher URL, platform, extraction and a *verifiable* integrity/authenticity path is not an install guide; compare Stripe's direct release link and GitHub's signing and attestation instructions ([Stripe](https://github.com/stripe/stripe-cli#installation), [GitHub install](https://github.com/cli/cli/blob/trunk/docs/install_linux.md), [asset attestation](https://cli.github.com/manual/gh_release_verify-asset)).
- **Doctor as an unexplained binary gate:** a warning about a not-yet-configured purchase path should name that path, corrective action and available reads; JSON consumers must know whether to inspect fields or exit status ([gh auth status](https://cli.github.com/manual/gh_auth_status), [Flutter troubleshooting](https://docs.flutter.dev/install/troubleshoot), [npm doctor](https://docs.npmjs.com/cli/v11/commands/npm-doctor/)).
- **Copy buttons for invalid examples:** required input absent from the pasted request is not a useful sample; Stripe, GitHub and Vercel distinguish populated fields from credential placeholders ([Stripe](https://docs.stripe.com/api/payment_intents/create), [GitHub](https://docs.github.com/en/rest/using-the-rest-api/getting-started-with-the-rest-api), [Vercel](https://vercel.com/docs/rest-api/user/get-the-user)).
- **Untracked or out-of-order source-of-truth guides:** keep the public entry path in a released, maintained location and derive the next command's ID from the preceding output rather than asking the reader to guess ([Stripe CLI maintained README](https://github.com/stripe/stripe-cli#installation), [GitHub `--jq`](https://cli.github.com/manual/gh_help_formatting), [Vercel deployment URL](https://vercel.com/docs/cli/deploying-from-cli)).

## Questions the references raise for AE

1. **Release channel:** publish the npm package, distribute a signed/attested archive with versioned URLs, or explicitly defer public CLI installation? The [Stripe package/asset routes](https://github.com/stripe/stripe-cli#installation) and [GitHub signed package and attestation routes](https://github.com/cli/cli/blob/trunk/docs/install_linux.md) show options; AE's register reports npm unpublished and archive retrieval unspecified ([PC-06](../2026-09-26-papercut-register.md#highest-priority-register)). The documentation study cannot establish what artifact Joel will actually ship.
2. **Doctor's automation contract:** should expected unconnected/unsupported-purchase status be exit `1` with clear documented partial-readiness checks, or exit `0` for the diagnostic process with explicit structured failures, or distinct exit codes for operational/fatal/partial states? [`gh auth status` changes behavior with JSON](https://cli.github.com/manual/gh_auth_status), while [Flutter](https://docs.flutter.dev/reference/flutter-cli) and [npm](https://docs.npmjs.com/cli/v11/commands/npm-doctor/) focus on named checks; references cannot choose AE's automation policy.
3. **First write and fixture:** after a public Search or authenticated read, is the supported tutorial's first write a harmless demand record, a non-executing Quote, or a controlled paid Call? If paid, what admitted Tool, caller authority and spending fixture can a fresh external developer actually use? [Stripe distinguishes creation from payment confirmation](https://docs.stripe.com/api/payment_intents/create); [AE's G7 promise](../2026-09-26-papercut-register.md#grouped-register-customer-promise-and-failure-pattern) asks for find → Quote → Call, but neither source nor references can promise an external safe paid fixture.
4. **Canonical publication home:** should the tracked `packages/cli/README.md`, public developer pages or one generated-from-source reference own command/transport details, with the others linking to it? The register says the source guide is untracked ([PC-38](../2026-09-26-papercut-register.md#highest-priority-register)); [Stripe's maintained CLI README](https://github.com/stripe/stripe-cli#installation) and [Vercel's CLI reference](https://vercel.com/docs/cli) demonstrate two valid homes but not AE's ownership decision.

**Cross-group boundaries:** G1 owns whether Search returns a usable Tool/no-match before an ID can be extracted ([G1 register](../2026-09-26-papercut-register.md#grouped-register-customer-promise-and-failure-pattern)); G3 owns connection and agent authority; G4 owns binding Quote, paid Call, receipts and recovery; G6 owns retained-demand writes; G5 owns whether a Provider has published a callable Tool. G7 should document those contracts as they are accepted, not invent a parallel fixture or redefine their semantics ([grouped register](../2026-09-26-papercut-register.md#grouped-register-customer-promise-and-failure-pattern), [maturity protocol](../../designs/2026-09-27-maturity-subagent-protocol.md#the-group-cycle)).
