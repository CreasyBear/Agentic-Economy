## Hard questions for Joel
1. **Market scope:** Should Tools prioritize only admitted AE-callable Tools (with external directory supply in a clearly separate area), retain a mixed list with explicit upfront badges/filters, or be an external-directory browse with a distinct “Buy through AE” path? Source cannot choose the product's browse promise; an empty admitted inventory might warrant honest no-match rather than a faux purchase shelf.
2. **Price language:** Should a directory row lead with “Provider-listed USDC, external only” and show buyer AUD only when a valid Quote is available, or omit external prices from the main buyer comparison altogether? A stale upstream figure cannot be converted into a committed AUD price; source cannot settle informational value.
3. **Callable alternative:** If no admitted eligible equivalent exists, should the CTA lead to an explicit no-match + request retention, show non-callable related research labeled as such, or disappear? Source cannot prove a suitable alternative for the observed Web search Tool.
4. **Query disclosure boundary:** What recipient label and field summary should appear for Market URL search, Market hero→chat and canonical Agent search respectively when gateway choice is deployment-configurable? Options: dynamically show configured recipient; stable “external ranking provider” plus inspectable detail; or avoid remote ranking for sensitive searches. Current checkout cannot identify a given deployed recipient/request.
5. **Input disclosure/contract:** Which public facts must be available *before* chat/price inspection (Provider identity, required fields, recipient, purpose, timing, public record)? For an opaque PDF file schema: block admission/callability until enough fields are declared, allow with an explicit incomplete-contract warning, or treat Provider prose as authority? The single observed response and abstract schema validation cannot decide for all Providers.
6. **Need purchase:** Should `kind: need` resolve only to a non-purchasing candidate+missing-arguments response; permit a structured caller-authorised input continuation followed by Quote; or remain a one-shot purchase only when all required arguments can be explicitly sourced from the caller? How is the original idempotency key related to the new exact material? Current terminal refusal binds its own material and cannot be replayed with different input. Should free Tool parameter invention also stop?
7. **Market analytics/mobile:** Should “Where the USDC went” be removed from buyer Tools, moved behind a clearly named analytics view, or retained as a collapsed explainer? On mobile, should Tool rows become stacked decision cards or keep scrollable tables with persistent price/Compare and a visible swipe cue? The source only establishes current hierarchy, not buyer demand for flow data or the preferred responsive presentation.
