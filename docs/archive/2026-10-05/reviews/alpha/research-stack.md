# AEcon stack resilience: vendor-documented decisions

Research date: 28 September 2026. Installed versions checked locally: Convex 1.45.0, Aggregate 0.2.2, TanStack Router 1.170.16, Start 1.168.26, Clerk TanStack Start 1.5.9. Vendor pages are current documentation, not a guarantee that every newer documented option exists in the installed versions. AEcon-specific examples below refer to the read-only findings in `fragility-backend.md`, `fragility-ui.md`, `fragility-external.md`, and `sweep-agent-surfaces.md`; their risks are not all reproduced incidents.

## 1. Principles and operational rules

### Convex: let transactions do their job, distinguish background effects

1. **Keep queries pure and bound their reads.** Convex automatically retries *internal* query/mutation errors; developer, application and read/write-limit failures need an actual fix or appropriate UI. A query throwing from `useQuery` reaches a React error boundary, while rerunning the same deterministic failing query with the same arguments cannot fix it. The [transaction limits](https://docs.convex.dev/production/state/limits#transactions) are 16 MiB read, 32,000 documents scanned, 4,096 index ranges and 16 MiB written per query/mutation; use selective indexed reads/pagination rather than whole-table `.collect()`. [Convex error handling](https://docs.convex.dev/functions/error-handling/#errors-in-queries), [limits](https://docs.convex.dev/production/state/limits#transactions).
2. **Do not write an external retry/lock layer around normal mutations.** Convex mutations commit atomically and are deterministic, so Convex reruns OCC-conflicted transactions itself; exhausted retries can still expose a write-conflict error. Fix *measured* contention by narrowing the read set, reducing repeated mutations or hot-document writes. A failed mutation rejects the caller promise and rolls back optimistic state; a React boundary will not catch that event-handler rejection. [OCC](https://docs.convex.dev/database/advanced/occ#when-occ-loses-determinism-wins), [write-conflict remediation](https://docs.convex.dev/error#remediation), [mutation errors](https://docs.convex.dev/functions/error-handling/#errors-in-mutations).
3. **Treat an action's external effect as ambiguous on failure.** Actions can call third parties but are not automatically retried: after a timeout the provider might already have charged or fulfilled. Make the caller choose a retry only after checking durable effect state and using an external idempotency key where supported; this last design is an AEcon consequence of the documented ambiguity, not a Convex exactly-once promise. [Convex action errors](https://docs.convex.dev/functions/error-handling/#errors-in-action-functions), [actions](https://docs.convex.dev/functions/actions).
4. **Schedule essential work transactionally; distinguish cron skipping from retries.** Scheduling in a mutation commits atomically with its writes; scheduling in an action can persist even if the action later fails. Scheduled mutations execute exactly once with internal-error retries; scheduled actions are at-most-once and can permanently fail, so recovery needs a state-checking mutation. Scheduled auth does **not** propagate automatically. Crons allow at most one running invocation per job and can *skip* subsequent ticks when a previous run is still active. [Scheduled functions](https://docs.convex.dev/scheduling/scheduled-functions#scheduling-from-mutations), [scheduled error handling](https://docs.convex.dev/scheduling/scheduled-functions#error-handling), [cron error handling](https://docs.convex.dev/scheduling/cron-jobs#error-handling).
5. **Aggregate membership is its own integrity contract, not a magic cache.** Convex component mutation writes participate in the top-level mutation transaction unless a component exception is caught, in which case the component's writes alone roll back. The Aggregate maintainer specifies updating table and aggregate in the same mutation, with `insertIfDoesNotExist`/`replaceOrInsert`/`deleteIfExists` while backfilling or reconciling divergent membership; verify the selected APIs against installed 0.2.2 before implementation. Splitting canonical publication from an optional discovery projection is a product decision that sacrifices atomic projection freshness, so preserve an explicit repair path. [Components transactions](https://docs.convex.dev/components/using#transactions), [Aggregate README: table updates and backfill](https://github.com/get-convex/aggregate#attach-aggregate-to-an-existing-table).

### TanStack Start and React: right-sized failure boundaries

6. **A route error is not an application outage.** `beforeLoad`/loader errors go to the nearest route `errorComponent`, then ancestor/default; a `pendingComponent` is for an unresolved loader, not for error recovery. `reset()` retries route rendering after state is fixed; rerun loaders via router invalidation only when their inputs or underlying conditions changed. Use `notFound()`/`notFoundComponent` for a genuinely absent resource, not a failed backend lookup or missing optional enrichment. [Start error boundaries](https://tanstack.com/start/latest/docs/framework/react/guide/error-boundaries), [Router loading lifecycle](https://tanstack.com/router/latest/docs/guide/data-loading#the-route-loading-lifecycle), [not-found errors](https://tanstack.com/router/latest/docs/guide/not-found-errors#overview).
7. **Do not mistake an event rejection for a render failure.** React boundaries catch errors in descendants during render, not event handlers, arbitrary async callbacks or server-side rendering; Convex's mutation guidance likewise says to catch a rejected mutation promise at the call site. A Start server function called in a loader can throw into its route boundary, whereas an event-triggered server function returns/rejects at that call site. Start's own docs say to use server *routes*, not app-only server functions, for external callers; a custom `src/start.ts` must explicitly include CSRF middleware for app server functions. [React boundaries](https://react.dev/reference/react/Component#catching-rendering-errors-with-an-error-boundary), [Convex mutation errors](https://docs.convex.dev/functions/error-handling/#errors-in-mutations), [Start server functions](https://tanstack.com/start/latest/docs/framework/react/guide/server-functions#same-origin-requests).
8. **Use existing successful loader data when it is actually valid.** Router's built-in stale-while-revalidate defaults to a background refresh of stale successful matches; it has no persistent storage and does not justify reusing old auth, funds, quotes or consent after a required recheck. Keep auxiliary widgets outside the blocking route load and give query-driven panels their own boundaries. [Router caching defaults](https://tanstack.com/router/latest/docs/guide/data-loading#some-important-defaults), [Convex query boundaries](https://docs.convex.dev/functions/error-handling/#errors-in-queries).

### Clerk: browser identity and machine access are distinct

9. **Middleware makes identity available; it does not grant access.** Clerk's TanStack Start middleware is installed in request middleware; check `auth()`/authorization in each protected handler and page boundary. For user-delegated API keys, Clerk prescribes `Authorization: Bearer` and `acceptsToken: 'api_key'` (the backend's default is session tokens); M2M tokens serve service-to-service operations. Do not let a missing Clerk key silently produce a public protected handler, or require a browser session for a machine-only API. [Clerk middleware](https://clerk.com/docs/reference/tanstack-react-start/clerk-middleware), [authenticateRequest](https://clerk.com/docs/reference/backend/authenticate-request#acceptstoken), [API keys](https://clerk.com/docs/guides/development/machine-auth/api-keys#using-api-keys-in-requests).
10. **Test bot and MFA flows with the right mechanism, not a spoofed agent string.** Clerk lists `User-Agent` among request headers relevant to session authentication and provides short-lived, instance-scoped Testing Tokens to bypass bot detection in automated Frontend API tests; no vendor source establishes that changing `User-Agent` is a supported production authentication remedy. Test emails `+clerk_test` and email-code `424242` work under development test mode, but this code is **not** a universal TOTP/second-factor bypass. MFA sign-in can require `needs_second_factor` and the enabled real strategy. [Request headers](https://clerk.com/docs/guides/development/making-requests#required-headers), [Testing Tokens](https://clerk.com/docs/guides/development/testing/overview#testing-tokens), [test emails](https://clerk.com/docs/guides/development/testing/test-emails-and-phones), [MFA](https://clerk.com/docs/guides/development/custom-flows/authentication/multi-factor-authentication).

### Stripe, Vercel and OpenRouter: bound the indispensable; move enhancements out of the path

11. **Stripe funding requires confirmed, idempotent fulfillment, not a redirect assertion.** Stripe requires a verified webhook because customers may never reach the landing page; handle `checkout.session.completed` and delayed `checkout.session.async_payment_succeeded` as appropriate, retrieve/check Checkout Session `payment_status`, and make fulfillment safe when webhook and success-page attempts overlap. Stripe *also recommends* triggering the same fulfillment function from the success page to reduce wait; doing so is optional here only if the webhook path plus read-only status gives adequate buyer UX. Verify the raw webhook body/signature and acknowledge promptly. [Checkout fulfillment](https://docs.stripe.com/checkout/fulfillment.md?payment-ui=stripe-hosted), [webhook body and response](https://docs.stripe.com/webhooks#create-a-handler), [success page session retrieval](https://docs.stripe.com/payments/checkout/custom-success-page.md?payment-ui=stripe-hosted).
12. **Idempotency has two different scopes.** Stripe's API idempotency key is for the *same POST with the same parameters*: it stores even a first `500`, and keys may be pruned after at least 24 hours. It does not deduplicate incoming webhook event delivery or guarantee once-only internal crediting; AEcon must commit one Convex credit per business payment/session. Locally, use `stripe listen --forward-to localhost:<actual-port>/<actual-webhook-path>` and its CLI-specific signing secret; verify a completed Checkout event, not only a synthetic generic event. [Stripe idempotent requests](https://docs.stripe.com/api/idempotent_requests), [Stripe local webhook listener](https://docs.stripe.com/webhooks#test-locally-without-a-registered-url).
13. **Separate configuration scope from timeout scope.** Vercel env values are scoped to Development/Preview/Production and changes affect *new deployments only*. Function max duration is a termination ceiling, not an outbound OpenRouter/FX/Provider deadline; on timeout the invocation can return 504. Diagnose a slow first request versus warm requests before adding cold-start machinery; Vercel recommends smaller bundles and moving expensive initialization outside handlers. [Vercel env](https://vercel.com/docs/environment-variables#environments), [duration](https://vercel.com/docs/functions/configuring-functions/duration#consequences-of-changing-the-maximum-duration), [cold starts](https://vercel.com/docs/functions/debug-slow-functions#5-check-for-cold-starts).
14. **OpenRouter already has a routing layer; do not stack an invented one on top of discovery.** `provider.allow_fallbacks` defaults true for another provider of the selected model; an explicit `models` array can switch models on rate limits, downtime, context errors or moderation. The `preferred_max_latency` option is a preference, **not** a timeout. The API documents 401 invalid credentials, 402 no credit, 408 timeout, 429 rate limit, 502 provider error and 503 no eligible provider; a stream can emit an error *after* HTTP 200. Honor bounded client deadlines and inspect stream events, while retaining deterministic tool facts already retrieved. [Provider selection](https://openrouter.ai/docs/guides/routing/provider-selection), [model fallbacks](https://openrouter.ai/docs/guides/routing/model-fallbacks), [errors and stream semantics](https://openrouter.ai/docs/api_reference/errors-and-debugging).

## 2. Anti-patterns to delete (not the underlying authority checks)

- **Global optional-integration boot/readiness validation**: missing model, telemetry, Stripe or directory-scan config must not cause unrelated public routes to throw; Vercel confirms env drift survives until a new deployment, while TanStack offers route-level failure boundaries. Remove global optional gates; preserve required identity/payment checks *at their actual operation*. [Vercel env](https://vercel.com/docs/environment-variables), [Start boundaries](https://tanstack.com/start/latest/docs/framework/react/guide/error-boundaries). Local evidence: `fragility-external.md` A1/D1; `fragility-ui.md` A1/A2.
- **Catching a deterministic Convex query error and blindly retrying it or inventing empty results**: fix input/schema/index/budget, and scope any UI fallback to its failed query, never report a backend failure as a real no-match. [Convex query retry note](https://docs.convex.dev/functions/error-handling/#errors-in-queries), [transaction limits](https://docs.convex.dev/production/state/limits#transactions). Local evidence: `fragility-backend.md` J10/D3; `fragility-ui.md` J2/J6.
- **One global React boundary or one `Promise.all` of required and cosmetic reads**: Convex explicitly documents independent boundaries to keep unaffected UI alive; React cannot catch event and SSR failures there. Remove optional reads from page-wide loader/parent-provider gates. [Convex query boundaries](https://docs.convex.dev/functions/error-handling/#errors-in-queries), [React boundary limitations](https://react.dev/reference/react/Component#catching-rendering-errors-with-an-error-boundary). Local evidence: `fragility-ui.md` A4/J1/J6.
- **Blind re-submit of a consequential action after timeout**: Convex actions are not retried precisely because effect completion is unknowable. Preserve CallRef, charge/settlement journal and reconciliation, not speculative success or a second payment. [Convex action error semantics](https://docs.convex.dev/functions/error-handling/#errors-in-action-functions). Local evidence: `fragility-external.md` J13/J14/J16.
- **Hiding all market search behind Jev ranking, a fresh FX fetch or an unfinished analytics scan**: OpenRouter documents routes and failures, not guaranteed availability; Convex documents bounded reads and atomic persisted state. Keep admitted deterministic Tool results and the last completed directory generation; a Quote needs a validated bounded-age exact rate, never a guessed number. [OpenRouter errors](https://openrouter.ai/docs/api_reference/errors-and-debugging), [Convex transaction limits](https://docs.convex.dev/production/state/limits#transactions). Local evidence: `fragility-external.md` J3/J5/J6; `fragility-backend.md` J2/D3.
- **Success-page-only crediting, duplicate webhook writers, or '2xx then hope'**: webhooks are required; a success-page fast path, if used, must call the *same* once-only business transition, and an ack must follow durable acceptance rather than discard unfinished work. [Stripe fulfillment](https://docs.stripe.com/checkout/fulfillment.md?payment-ui=stripe-hosted), [webhook receiving](https://docs.stripe.com/webhooks#create-a-handler), [Stripe idempotency boundary](https://docs.stripe.com/api/idempotent_requests). Local evidence: `fragility-external.md` J9.
- **User-Agent spoofing or test-mode codes as production auth fixes**: bearer key verification and explicit accepted token type are the documented machine boundary; Testing Tokens only serve automation, while MFA requires a real enabled factor. [Clerk machine auth](https://clerk.com/docs/reference/backend/authenticate-request#acceptstoken), [Testing Tokens](https://clerk.com/docs/guides/development/testing/overview#testing-tokens), [MFA](https://clerk.com/docs/guides/development/custom-flows/authentication/multi-factor-authentication). Local observation: `sweep-agent-surfaces.md` #18 shows the same valid key returning 401 with `Python-urllib/3.14` but 200 with other user agents; **cause is not established by vendor documentation**.

## 3. Application to AEcon's exact stack (one decision per surface)

- **Convex data/OCC:** paginate owner funding history and isolate optional analytics queries; do not shard provider-lead writes without observed conflicts. [Limits](https://docs.convex.dev/production/state/limits#transactions), [OCC remediation](https://docs.convex.dev/error#remediation); `fragility-backend.md` J10/D7.
- **Convex scheduler/crons:** keep paid Call reconciliation cron registered independently of optional scan/metrics; detect missed/failed work from durable state, not an assumed next cron tick. [Cron skipped runs](https://docs.convex.dev/scheduling/cron-jobs#error-handling), [scheduled action failure](https://docs.convex.dev/scheduling/scheduled-functions#error-handling); `fragility-backend.md` J8.
- **Aggregate component:** make replayed facet membership updates idempotent where divergence is possible; don't make a noncritical search projection transactionally veto a valid canonical Provider publication without a documented product reason. [Aggregate reconciliation](https://github.com/get-convex/aggregate#attach-aggregate-to-an-existing-table), [component transactions](https://docs.convex.dev/components/using#transactions); `fragility-backend.md` J3/J4.
- **TanStack Start/React:** leave Market's canonical data as the loader dependency, put optional recipient/SEO/evidence and chat sidebar queries in separately bounded leaves; use `notFound()` only on actual absence. [Router lifecycle](https://tanstack.com/router/latest/docs/guide/data-loading#the-route-loading-lifecycle), [not-found](https://tanstack.com/router/latest/docs/guide/not-found-errors#overview); `fragility-ui.md` J1/J2/J6.
- **Clerk:** route public catalogue independently of an unnecessary Clerk-dependent entitlement widget while preserving `auth({ acceptsToken: 'api_key' })` and scope/current-key checks for CLI/MCP/HTTP mutations; investigate `Python-urllib` 401 with request/auth debug data rather than alter identity rules. [Clerk middleware](https://clerk.com/docs/reference/tanstack-react-start/clerk-middleware), [API keys](https://clerk.com/docs/guides/development/machine-auth/api-keys#using-api-keys-in-requests); `src/start.ts:117-129`, `src/lib/server/agent-access-auth.ts:159-191`, `sweep-agent-surfaces.md` #18.
- **Stripe:** keep signed webhook and Convex once-only funding credit, expose pending funding status and retrieve Session for confirmation; test the actual funding event locally with the correct CLI secret. [Stripe fulfillment](https://docs.stripe.com/checkout/fulfillment.md?payment-ui=stripe-hosted), [local listener](https://docs.stripe.com/webhooks#test-locally-without-a-registered-url); `fragility-external.md` J9.
- **Vercel:** scope model/telemetry/secret-rail env to features, audit Preview versus Production settings on deployment, and put a short budget on the provider-consequence bridge and CLI transport instead of waiting for the function ceiling. [Env deployment semantics](https://vercel.com/docs/environment-variables), [duration](https://vercel.com/docs/functions/configuring-functions/duration); `fragility-external.md` A1/J13/J16.
- **OpenRouter/Jev:** ranking or answer synthesis can time out while deterministic search/finished tool output survives; a provider/model fallback is useful only within a bounded optional model budget, not as a new buyer-path prerequisite. [Routing](https://openrouter.ai/docs/guides/routing/provider-selection), [errors](https://openrouter.ai/docs/api_reference/errors-and-debugging); `fragility-external.md` J3/J8.

## 4. Genuine tensions and alpha choice

- **Stripe's two fulfillment triggers versus fewer moving parts.** Stripe recommends both webhook and landing-page calls into one concurrency-safe function for instant access, but requires webhook because the redirect can be missed. For a solo-founder alpha, use webhook plus a read-only Session/status success page *if pending access is acceptable*; if instant credit is a core acceptance criterion, add the landing-page trigger only after both converge on the very same idempotent Convex credit transition. Never implement two credit paths. [Stripe fulfillment](https://docs.stripe.com/checkout/fulfillment.md?payment-ui=stripe-hosted).
- **Atomic aggregate vs isolated projection.** Aggregate docs want aggregate and table updates in one transaction so readers never see divergence; Convex components then roll back the top-level mutation on uncaught component failure. AEcon should keep *authority/callability* changes atomic, but make optional Bazaar/search/analytics projection asynchronously repairable if that is the actual publication takedown; show honest projection freshness until repaired. [Aggregate README](https://github.com/get-convex/aggregate#usage), [component transactions](https://docs.convex.dev/components/using#transactions); `fragility-backend.md` J4.
- **Vendor retries and fallback versus no hedging.** Convex retries deterministic transactional conflicts but not side-effecting actions; OpenRouter defaults to provider fallback and supports model fallback on errors, potentially changing model behavior even after moderation refusal. Keep Convex's built-in OCC retry; use at most bounded vendor routing for optional Jev *when it has been shown to help*, with deterministic indexed retrieval otherwise; never turn a paid Call's ambiguous effect into an automatic new attempt. [Convex OCC](https://docs.convex.dev/database/advanced/occ#when-occ-loses-determinism-wins), [action errors](https://docs.convex.dev/functions/error-handling/#errors-in-action-functions), [OpenRouter model fallback](https://openrouter.ai/docs/guides/routing/model-fallbacks).
- **Global catch versus surgical boundaries.** Convex shows either one app boundary or separate boundaries; Start allows route-local error components. Pre-alpha AEcon should use one last-resort root boundary plus small boundaries only where a nonessential leaf could mask a core journey, rather than dozens of invented degraded states. Auth, funds, Provider effect and money evidence must still fail closed at their *operation* boundary. [Convex query boundaries](https://docs.convex.dev/functions/error-handling/#errors-in-queries), [Start error boundaries](https://tanstack.com/start/latest/docs/framework/react/guide/error-boundaries); `fragility-ui.md` A4/J6.
- **Vendor documentation divergence.** Convex's scheduled-functions prose says 1,000 jobs/8 MB aggregate arguments, while its limits table currently says 1,000/16 MiB total and 4 MiB per scheduled argument. Do not design near either ceiling; use small IDs, bounded batches, and verify the installed deployment's limits before relying on numerical headroom. [Scheduler prose](https://docs.convex.dev/scheduling/scheduled-functions#scheduling-functions), [limits table](https://docs.convex.dev/production/state/limits#execution-time-and-scheduling).
