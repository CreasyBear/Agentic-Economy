# External-service and configuration takedown map — 28 September 2026

**Remit.** Identify a single external dependency, configuration value or defensive branch that can stop an AEcon journey. Source inspection was read-only; the only runtime probes were `GET /api/health` (200) and `GET /api/ready` (ready; config and Convex ready, commercial catalogue fresh/quoting ready/funding configured) on the already-running local stack. This is a failure-injection map, **not** a claim that those services are currently down. `±` estimates below are approximate lines removed/added, not executed changes. Severity counts are **4 app-down/boot-blocked, 16 journey-down, 6 degraded/operational**. Deployment-only and conditional risks are explicitly labelled.

**Rule of decision.** The standing directive at `docs/reviews/maturity/00-decisions.md:9-17` requires Convex, identity when signed in, and the called Provider as genuine journey dependencies. Jev/OpenRouter ranking, FX *refresh*, discovery scans, analytics and answer prose are enhancements. Fail open only to deterministic **existing** retrieval/validated bounded last-good FX; do **not** invent inputs, identity, pricing, funds, signing authority, Provider success, or settlement. Keep Bazaar in search (`00-decisions.md:21-23`).

## Defensive machinery to cut, and fences to retain

- **Cut:** global all-integrations boot/readiness checks (A1/D1); optional local seed/scan prerequisites (A4); ranker-failure `degraded → unavailable`/duplicate chat retry and early Bazaar exit (J3/J4); synchronous upstream source browse despite persisted publications (J6); direct SDK cold-start fallback presented as sufficient indexed browse (J7); generic model retry after completed factual tool results (J8); awaiting telemetry in request finalization (D2). These multiply failure states instead of protecting truth. The fixes above estimate changes separately; do not sum blindly where one cut serves two rows.
- **Retain:** Clerk JWT verification and server-source authority (`convex/auth.config.ts:3-20`; `src/lib/server/convex-source.ts:123-155,249-273`); bounded-age, exact AUD conversion and Quote evidence (`src/modules/money/internal/executable-rate.ts:183-237`); Stripe signed/idempotent webhook (`src/modules/money/internal/stripe-webhook.ts:84-127`); Formance funds/reservation reconciliation (`src/modules/money/internal/formance-writes.ts:29-88`); x402 fresh challenge and outcome-unknown fencing (J14); OIDC secret-custody and Vercel attested effect journal (J12/J13). Removing those would create unsafe money/authority outcomes, not reduce fragility.
- **Timeout/retry accounting:** Jev discovery 10s/zero retries, interactive 1.5s/zero, noninteractive default one retry (`jev-client.ts:44-46,96-114`); FX fetch 10s (`reference-rate-fetch.ts:6-35`); Stripe two network retries (`stripe-money-client.ts:26-31`); Formance default 10s/no auto-retry (`formance-config.ts:15-18,233-253`); upstream scan three attempts (`x402DirectoryIndexRefresh.ts:14-24`); Provider x402 unpaid/paid requests bounded (`route-transport-x402.ts:324-329,659-667`); CLI and Vercel bridge missing explicit deadlines (J13/J16). Do not insert blind retries on consequential Calls.

**Priority:** (1) A1 + D1 decouple boot/readiness, (2) J3 + J4 preserve deterministic search, (3) J5 persist bounded last-good FX, (4) A4 let local boot survive optional seed/scan, (5) J6 move source-filtered Bazaar browse onto persisted rows. The local health/readiness observation proves only the current configured stack, not outage behavior.
