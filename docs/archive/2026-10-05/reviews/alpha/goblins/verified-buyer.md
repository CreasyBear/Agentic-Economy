## Rejected / overstated

- **“History search keeps stale hit indefinitely” rejected.** `[RUNTIME]` signed-in `weather` → `zzzz-no-such-chat-qa` showed **“No conversations found”** after 2.8 s. `useStickyRows` temporarily shows last rows only while the new query is undefined, then replaces them with resolved `[]` (`src/components/ae/chat/chat-session/ChatHistoryPanelContainer.tsx:14-25`; `src/components/ui/data-state.ts:47-61`). A brief stale flash is real; the claimed stuck no-match is not established.
- **“Offline send drops typed prompt” rejected as stated.** Catch leaves `prompt` untouched; it is cleared only after successful `startTurn`/anonymous completion (`src/components/ae/chat/chat-session/useChatSession.ts:263-305`). My offline probe still had its draft while sending; reconnecting before the request failed allowed it to submit, so that probe does **not** prove an offline failure lost input.
- **“All routes without own error/pending/notFound are unprotected” rejected.** Router defaults exist (`src/router.tsx:7-15`); operator leaves inherit common options (`src/lib/operator/route-options.ts:11-19,34-43`). A root render error may replace the shell, but no triggered root failure was verified in this cluster.
- **“Every failed catalogue Next is a dead end” rejected.** Failed Tool/Provider continuation retains the current page and Next retries (`src/components/ae/market/AeX402Directory.tsx:64-103,547-553`; `src/components/ae/market/useProviderCataloguePages.ts:121-175`); first-wave fault probe agreed. This is distinct from route-wide tab/sort failure B03.
- **“An offline full-document load should show the app's retry” rejected.** Chrome's `ERR_INTERNET_DISCONNECTED` is a browser document-load failure before app code runs, unlike an already mounted SPA's request fault.
- **“No signed-in Stop means paid effects are unprotected” rejected.** Anonymous `AbortController` supplies Stop; signed-in turns are durable server work (`src/components/ae/chat/chat-session/useChatSession.ts:177-235,440-448`). Cancellation/paid effect semantics cannot safely be inferred from button parity.
- **“Invalid market view is a 500” rejected.** `/market?view=not-a-view` returned 200; its raw-value document title is a minor SEO/head mismatch (`src/routes/market.tsx:31-40`, `src/modules/market/market-route-data.ts:116-128`), not a journey blocker.
- **“Read-only share Select completed a purchase” rejected.** Only local selection is wired; no Quote/Call was exercised (B12).
- **“All slow transitions show no pending state” overstated.** Router has 150 ms default; Market explicitly waits 1,000 ms before replacing results with its pending skeleton (`src/router.tsx:10-15`; `src/routes/market.tsx:25-29,45-47`). First-wave slow samples saw prior content plus busy state, not an infinite spinner.
