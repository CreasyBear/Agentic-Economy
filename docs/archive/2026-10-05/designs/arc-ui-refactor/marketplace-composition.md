# Familiar marketplace, composed from Arc

**Decision brief — 2026-10-02.** Source and API architecture; the first compact catalogue composition is implemented and source-tested. These are 20 verified Arc registry items, distributed across the journey. They are not 20 blocks stacked on the home page. New composition and interaction targets below remain unmeasured in a browser.

The customer’s job: find a useful Tool, understand its contribution and material cost/access facts, compare plausible alternatives, then continue through the existing setup or chat purchase path. Follow **orient → browse → inspect → compare → act**, applying Arc Pro’s [Page composition workflow](https://uiarc.dev/docs/ai#pro-skills): brief, regions, states, verified sources, build, parity checks.

## Apply human cognition to the page

| Principle and evidence | Concrete rule | Observable check |
| --- | --- | --- |
| [Recognition over recall](https://www.nngroup.com/articles/recognition-and-recall/) | Keep Tool names, Saved state, active refinements and selected comparison peers visible. Restore the market return context. | Inspect and return without reconstructing the query, selections or current browse page. |
| [Information scent](https://www.nngroup.com/articles/information-scent/) | Name the contribution, output, Provider/source and destination. Use precise Inspect, Compare and setup labels. | A buyer can predict what a Tool returns and where its action leads. |
| [Progressive disclosure](https://www.nngroup.com/articles/progressive-disclosure/) | Show price, access, input recipient and consequential restrictions at the decision. Put full schemas and secondary source details behind disclosures. | No accordion or drawer must be opened to discover a material purchase restriction. |
| [Product-list information](https://baymard.com/research-articles/product-listing-information) and [comparison tables](https://www.nngroup.com/articles/comparison-tables/) | Give each visible Tool the same essential fields; align attributes across selected peers. Missing data remains explicitly unknown. | Screening does not require repeatedly opening details just to recover cost/access facts. |

Cognitive-load audit: orientation has two initial decisions—catalogue destination and query. Browse adds optional refinement, order and selection; technical configuration belongs to the later use surface. Visible records are recognition cues, not a fixed “seven items” memory limit. Remove the large prompt hero and repeated control rows. Keep a compact title, catalogue search, four existing destinations and results. The separate Ask an agent action opens chat; it is not another search input.

Gestalt audit: put identity, contribution and commercial facts inside one record boundary; keep more space between records than between their fields. Align repeated fields and give the same control the same appearance. Use a strong boundary only for a separate decision or foreground surface. Selection may be emphasized; unknown readiness must not look like a positive badge. These are source-level rules; salience and spacing still require later visual measurement.

## Compose five surfaces

| Surface | Region recipe | Primary action and compactness |
| --- | --- | --- |
| Orient / find, `/market` | Compact heading → SearchField → URL Tabs → conditional ChipGroup, FilterToolbar and Sort Select. Secondary Ask an agent link. | Search submits the catalogue query. Results should begin in the first desktop viewport; no tall hero or chat composer above them. |
| Browse Tools / Providers / Saved | ProductListing for galleries; Integrations for Provider identity records; SortableDataTable for compact results. Carousel only for a short supplied collection. | Inspect a record. Save and Compare remain independent, truthfully controlled actions. Preserve current tables until the new display preference actually works. |
| Inspect Tool / Provider | Breadcrumb → ProductDetail preview/identity and decision column → Accordion reference. Provider profiles retain distinct Business and Host source scopes. | Existing state-derived setup or alternative-search action. Show published JSON/schema material with correct labels; no image gallery is implied. |
| Compare | Existing tray → existing controlled modal → ComparisonTable. Drawer is reserved for refinements, not a second nested comparison overlay. | Inspect a chosen Tool. Keep selected identities and critical facts visible together; do not designate a winner from incomplete data. |

One foreground surface has one primary action. ProductDetail already supplies its gallery/disclosure behavior; do not nest a second carousel or accordion engine into it. Creativity comes from useful published contribution previews and Arc’s authored selection/reflow, after the basic journey is familiar.

## Data and interaction contracts

**Requires:** Existing typed route/search, Tool/card, Provider identity and observed chat projections. **Ensures:** Exact native destinations, URL selections, projected prices, source distinctions, action eligibility and recovery survive composition. **Invariant:** Funding is not authority; directory membership is not admission; Host is not Business; delivery/payment/purchase states stay distinct. **On violation:** Preserve missing, unavailable, refusal and uncertainty states; omit unsupported actions rather than simulate success.

- `market-route-data.ts`, catalogue/search controllers and `useMarketCompare` remain state owners. Cards, tables and controls consume their values and callbacks.
- Browse currently returns up to 24 Tools through opaque cursors. Provider pages group up to 12 supplied hosts. Display “N on this page”; generation coverage is not a filtered result count. Use previous/next Buttons, not a fictitious numbered total.
- Mixed keyword search returns up to eight results and applies only category, Provider, network and price-band refinements. Keep the current disclosure about other unapplied catalogue refinements; a generic Arc filter cannot silently claim more capability.
- Comparison currently accepts four directory resource refs in URL `compare`; missing/pending selections remain removable. Mixed search has no Compare action. A broader identity adapter is separate work, not implied by this composition.
- Grid/Table now consumes a validated URL `layout` display preference, with Table as the default. It is excluded from catalogue loader dependencies and server requests; layout navigation preserves query, refinements, cursor page and comparison. Mixed keyword results retain their distinct current presentation and action contract.
- Admitted Tools supply input examples and input/output schemas. Directory entries may supply input/output JSON examples. Label schemas as contracts and examples as published examples; identity icons are not output previews.
- Ask an agent opens `/t/new`. Existing `/t/new?q=…` links auto-submit after session initialization; retain that behavior explicitly. Public Tool detail owns setup/alternative links, while chat owns Run, fresh Quote, Call, required approvals and remedies.
- Prices remain formatted by existing money/card projections. Do not convert exact money to the Pro storefront’s numeric physical-product prices.

## Source adaptation, without replacement engines

Use actual Arc exports when their controlled API fits. For domain-specific Pro blocks, adapt the licensed source in the existing Arc market/chat port, replacing sample models with the existing Aecon contracts. An unused demo import plus newly invented lookalike CSS is not adoption.

ProductListing’s default color/size/cart filters and client-only sort do not own Aecon’s server catalogue. ProductDetail’s required physical variants/reviews/shipping and fallback simulated request do not describe a Tool purchase. Integrations and AgentRun have no input props and simulate their records/events. EmptyStates also includes demo state transitions. Remove those sample assumptions and bind real state; keep the authored applicable regions and interactions.

SearchField, Tabs, ChipGroup, FilterToolbar, Select and comparison support controlled values. SortableDataTable owns local sort internally; its `onSortChange` callback is not a controlled server-sort API. The browse adaptation disables local column sorting and renders native rows without Motion or column measurements; the Arc Select sends ordering changes to the existing server catalogue controller. Never imply that sorting the loaded page reorders the whole market.

Keep existing Base UI-backed Arc Drawer and controlled Dialog safeguards. Registry Tabs/Select/DropdownMenu/Accordion declare Radix dependencies absent from this checkout. Actual Tabs and Select sources now use the existing Base UI primitives without added packages. Future DropdownMenu/Accordion integration must resolve that primitive boundary explicitly. Do not write substitute focus, portal, dismissal or drag engines. Breadcrumb’s upstream Next link must use the existing TanStack/native navigation boundary.

**Complexity decision:** Keep one projection/controller per existing family and adapt its actual Arc owner. The cost is licensed-source maintenance and a small Grid/Table state extension; the benefit is consistent authored regions without duplicate state ownership. Reject a new marketplace framework, generic universal card, local search/filter engine, generated recommendation feed, large project header and a second purchasing controller. Twenty selected registry items do not require twenty new abstractions.

## States and implementation batches

| State | Required composition behavior |
| --- | --- |
| Pending | Skeleton mirrors actual regions; named busy state, decorative shapes hidden, no operative record actions. |
| Success | Supplied records, exact scope/count, native destinations and eligibility. |
| Empty | Distinguish no matches, no Saved Tools and no published example; retain query/context and one useful recovery action. |
| Error / partial | Preserve valid observations and explicit unavailable facts; retry through the current owner without fake completion. |
| Limited / unauthorized | Keep source/admission distinctions and state-derived setup/refusal; unknown values never become false or ready. |

1. **Coordinator:** Freeze route/projection contracts, comparison safeguards and shared Arc dependencies. The separate CSS polish owner has released all files; preserve its completed fixes.
2. **Browse worker:** Own the catalogue header/control slice, at most three named presenter files. Replace the hero prompt with compact orientation; use supplied refinements and correct search scope.
3. **Records worker:** Own the Tool/Provider result slice, at most three named files. Apply the actual blocks and table, with exact price/source/selection parity. Coordinator integrates the display-state extension.
4. **Detail/chat worker:** Own a bounded detail or observed-run slice, at most three named files per batch. Preserve published-material labels, existing action routes and real event state.

Workers receive explicit ownership and contracts, are told they share the checkout and must preserve others’ changes, then freeze their slice. The coordinator checks actual code and observable behavior before advancing the existing progress counter. No overlapping shared-foundation edits or parallel controller rewrites.

Verify query submission/back navigation, view/refinement/cursor persistence, rapid four-item comparison and missing selections, independent Save/Compare actions, displayed exact money and source scope, pending/error/unknown states, published-only previews and action ownership. Run affected tests and `npm run check`; `npm run gate` remains required before merge. Later measure keyboard/focus and 360/390/768/1024/1440px layouts in both themes, including full text wrapping and 44px touch actions; no current visual acceptance is claimed.


## First implemented catalogue batch — 2026-10-02

The built-in imagegen [illustrated the direction](concepts/marketplace-20261002.png) before implementation; its [exact prompt](concepts/marketplace-20261002.prompt.txt) is retained. The image is an illustrative concept, not runtime evidence.

Joel then prioritized excellent, fast tables. Tool and Provider browse now default to the actual Arc SortableDataTable, retaining native unanimated rows and server catalogue ordering. A compact Arc SearchField, Tabs and Select replace the prompt hero, legacy tabs and five-sort-button strip. SegmentedControl exposes optional ProductListing galleries. The existing filter state is composed inside the Arc Drawer, with one search field in the header and one real chat destination. Provider gallery price/activity retain their shown-Tool scope. No new packages or state engines were added.

This implements the catalogue region of the 20-item architecture. The architecture remains a roadmap for other regions; it does not assert all 20 items were newly integrated. Source tests cover query validation, routing/context, exact source facts, native save/comparison actions, the four-Tool cap and continuation/recovery. Browser, responsive and performance measurements remain deferred until the source sweep is complete.
