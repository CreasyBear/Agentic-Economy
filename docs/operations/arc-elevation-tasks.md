# Arc elevation task cards: E0 to E2

This is the execution breakdown of [the restore matrix](arc-elevation-plan-2026-10-06.md#3-restore-matrix-every-vendored-entry). Paths are repository-relative in `aecon-arc-elevation`; `owner` grants first claim, not a limit on consumer blast radius. Vendored states: PRISTINE (default), PATCHED (minimal upstream a11y/semantic correctness only), or moved-out KEEP. E0 makes no source, test or generated-file edits. E1/E2 restore by registry command, never by adapting Arc to AE feature APIs; the sole exception is a documented PATCHED correctness change. No unlicensed Pro reconstruction.

## Common contract, inherited by every card

- **S (restore card steps):** (1) inspect every registry `files[].target` and public prop/slot before `npx shadcn@latest add @uiarc/<id> --overwrite --yes` or `@uiarc-pro/<id> --overwrite --yes` (one ID, except an explicit shared-output bundle); shadcn strips leading CSS comments, so immediately rehydrate **each installed target** from the registry JSON `files[].content`, SHA-256-check bytes against that field, then copy to the vendored target; (2) migrate AE DTOs, state, money, security and callbacks to `src/components/ae/<domain>/<feature>/` or one shared `src/components/ae/shared/arc/<item>/` adapter through documented public props; (3) own and migrate **every broken consumer** under the claim protocol, including tests with behavioural assertions intact; (4) delete obsolete copies/selectors only after their final importer disappears. If pristine API cannot express a required feature, check another Arc item via MCP (Pro allowed), then record moved-out KEEP and relocate AE implementation outside `arc/` only when no item fits. Minimal missing a11y/semantic correctness may be PATCHED, marked in-file `// arc-patch: <reason>` and documented per card; feature props such as `compact`, `readOnly`, `sortValue`, manual/TanStack sorting, `labelMode`, `animateContent`, `render`, native-button ports and `className(state)` are **not** patches. No synthetic data or empty hooks.
- **C (consumer card steps):** (1) depend on installed source ID(s), no second install/vendor write; (2) use the pristine public API, a single AE edge adapter, or a documented moved-out KEEP, preserving native/TanStack links, controlled values and async callbacks; (3) migrate listed owner files and any newly broken consumer under the claim protocol; (4) remove private CSS imports and dead AE-local styles after the last user leaves. For each non-owned absolute path, run `grep -qF "<abs path>" /tmp/arc-claims.tsv || printf '%s\t%s\n' "<abs path>" "<your card id>" >> /tmp/arc-claims.tsv`, re-grep and confirm **your ID is the first matching claimant**; if another card claimed first, send its agent the exact required edit and let it apply it. Use hash-checked `edit` for shared files, re-reading on conflict.
- **P (parity checklist, refactor-to-arc §5):** [ ] Tab order, composite Arrow/Home/End, Escape, trap/return focus; [ ] same accessible names, form `name`/submitted values, raw drafts and validation messages; [ ] same analytics and meaningful `data-testid` at the real root/action; [ ] same guarded callbacks, authorization and pending/empty/error/success without synthetic success; [ ] 390/1440px reflow, plus 320/768/1024px when layout changes, light/dark, reduced motion, 44px targets and **visible AE-edge `:focus-visible`** (repo WCAG overrides Arc's no-outline advice); [ ] filtered typecheck, scoped existing tests, affected lint and direct interaction smoke. Charts retain missing ≠ zero and exact BigInt/money. User-visible behavioural assertions (roles, names, keyboard/focus, submitted values, destinations, meaningful copy) stay identical or stricter. Existing tests may be retargeted to the component now covered; incidental DOM ids/classes/wrappers or copyright formatting may be converted to behavioural assertions, never deleted to pass. `docs/operations/arc-patches/<card-id>.md` holds each card's PATCHED diff/reason/upstream-report text or moved-out KEEP reasoning; E1-G0 merges these into `arc-vendor-patches.md` at wave end. P applies to every E1/E2 card.
- **Skill sources:** `~/.claude/skills/arc/SKILL.md` §§Install/Wire/Never do; `components.md` §§How to decide/Wiring; `composition.md` §§States/React correctness; `copy.md` §§Rules; `design.md` §§Color/Type; `checklist.md` §§Review/Accessibility/Responsive; `arc-pro/arc-pro.md` §§Pro access; `full-page-generation.md` §§Install/Build; `refactor-to-arc.md` §§4–5; `accessibility-audit.md` §§3–6; `motion-recommendations.md` §§3–5; `responsive-optimization.md` §§1–4.
- **Evaluator syntax:** `T(regex)` = project TypeScript gate with diagnostics filtered to the card's exact owner paths: capture `npm run typecheck -- --pretty false`, preserve and require exit code 0, print matching diagnostics with `grep -E 'regex'` (filter reporting, never suppress errors). `V(paths)` = `npx vitest run <space-separated exact existing test paths> --no-file-parallelism`. Named tests were located by grep of consumer imports/Arc imports. GateOwner runs T after the card's full owner set settles; no build or whole test suite.
- **Parallel:** different cards marked `∥` may run together **after their dependencies**. For the same registry ID, only its S card installs; dependent C cards run after it and may run in parallel with each other. GateOwner owns shared configuration and generated files and runs last in each wave; no other card writes those files. Serialized cutovers where explicitly indicated. E1 and E2 are sequential barriers; no wave-crossing parallel writes.
