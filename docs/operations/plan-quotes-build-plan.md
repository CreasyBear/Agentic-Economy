# Plan Quotes — atomic build DAG

Status: implementation plan, not shipped functionality (2026-10-05). Source contract: `docs/designs/2026-10-05-plan-quotes-rfc.md:39-329`; tracking register: `docs/operations/mercator-parity-register.md:5-63`. Binding execution shape: one `@convex-dev/workflow` per committed, authorized Plan, started only after durable Hold evidence; Triggers bridge financially conclusive Call transitions into Workflow events, while existing Call lifecycle/workpool owns payments, dispatch and reconciliation (`docs/designs/2026-10-05-plan-quotes-rfc.md:196-202`; `convex/capabilityProviderOffboarding.ts:44-49`; `convex/lib/capabilityExecution/callLifecycle/dispatchEnqueue.ts:15-46`). Deadlines use Workflow cancellation, not a sweep cron; one Hold debits account, spending periods and legal exposure once, and Node Calls draw from that Hold (`docs/designs/2026-10-05-plan-quotes-rfc.md:60,198-202`). No new general-purpose planner, aggregate SKU, ledger, provider credential or paid retry. ADR 0006 separates buyer Plans from Provider packages (`docs/adr/0006-mercator-capability-foundations.md:12-16`); F2 conventional asynchronous providers, F4 binary artifact retrieval, F5 heterogeneous supplier evidence and literal MPP/SPT rails remain separate.

## Execution contract and gates

Waves W0–W6 execute in order; within each wave, only tasks whose dependencies are complete may start, and its GateOwner closes the barrier before the next wave. Each numbered task below has at most two **manually owned** exact files; `new` marks a proposed file. `Files` are exclusive write ownership for that wave; existing files cited as reuse are read-only unless explicitly owned. One implementor/task; independent tasks can overlap only when their listed files do not overlap. Each `Review` has three semicolon-separated reviewer checklist items; money/authority tasks additionally go to a security reviewer. The evaluator is **one** targeted command per task, not a wave-wide build. A grep evaluator is structural only: the wave owner also runs the real CLI/MCP/HTTP journey below. No implementor runs a formatter, build or project-wide tests mid-wave. The orchestrator alone runs `npm run check` and the relevant local journey after the wave barrier.

**GateOwner rule.** W1–W6 each end with exactly one `W*-TG`. Its two manually owned files are `src/modules/module-boundaries.ts` and `tests/fixtures/convex-api-kind-snapshot.json`; generated `convex/_generated/` is the **exclusive mechanical output** of that same GateOwner's `npm run generate:convex`, never an independently assigned task or a third hand-edit target. GateOwner only changes the module's `entrySurfaces` and RPC snapshot when the wave's landed source requires it; first migrate string-literal RPC references (`tests/imports/convex-api-kind-snapshot.test.ts:15-35`). No other task edits these paths; generated files are not edited by hand. W1/W4/W5/W6 GateOwner does not manufacture snapshot changes when no new RPC exists. W2 schema owner completes before W2-TG; W3 façade owner completes before W3-TG. The gate evaluates `node tools/dev/run-with-cleanup.ts node_modules/.bin/vitest run tests/imports/convex-api-kind-snapshot.test.ts` and the orchestrator separately checks generated/API/module boundaries at the barrier.

**Demo supply and honest fallback.** The current checkout has **no `seed:dev` script** in `package.json` and no curated geocode/weather seed: the local launcher calls `devSeed:publishSandboxTool` (`tools/dev/local-dev.ts:648-655`), whose actual seed publishes fixed-AUD Frankfurter FX and optionally Base Sepolia x402 (`convex/lib/dev/seed/sandboxPublication.ts:74-101,111-139`; `sandboxReference.ts:23-55`; `sandboxTestnet.ts:76-105`). W2-T2 adds two sandbox-only, public-keyless, admitted fixed-AUD Tools using the existing seed publisher: Open-Meteo geocode (`https://geocoding-api.open-meteo.com/v1/search`, GET `name`) → Open-Meteo weather (`https://api.open-meteo.com/v1/forecast`, GET `latitude`, `longitude`, `current=temperature_2m`). The exact declared edges are `flow://geo/output#/results/0/latitude` → weather `latitude` and `flow://geo/output#/results/0/longitude` → weather `longitude`; require upstream `results[0]` and target number schemas, actual provider output and current admission before claiming success. Seed prices are sandbox-only, not supplier entitlements or live x402 equivalence. If those hosts/outputs or admission fail, fall back to existing Frankfurter `flow://fx/output#/base` → testnet `{value: ...}` only when the optional testnet Tool was actually published and its deferred `managed_x402` price has **independently proven** finite ceiling; otherwise show `deferred_node_dynamic_price`/`tool_not_admitted` and stop, never fake a successful paid Plan. A two-node FX→FX fixed-price regression with `/base` is useful for plumbing but not evidence of two distinct Providers (`sandboxReference.ts:34-55`; `sandboxTestnet.ts:89-105`; RFC `:188,238-244`). Never purchase a production Tool for this demo.
