# Arc showcase: providers, operators and workspace controls

**Status:** ranked page plans only, not a shipped migration or permission to invent product data. This provider/operator companion to the [buyer showcase](arc-showcase-buyer.md) covers the current supply and operations surfaces. Routes, available facts and refusals below come from this worktree on 2026-10-06. No demo records, implied sales, or projected payout totals.

## Brief and integration contract

**Audience:** prospective Providers, existing business owners publishing and maintaining Tools, and authorized internal Admins. **Jobs:** connect a source and publish one Tool; maintain readiness and reconcile recorded obligations/transfers; inspect purchase/account evidence, operational metrics, audit and money controls; manage workspace identity, Agents and spending. **Primary actions:** progress Add Tool to an attested listing; connect a verified endpoint; open a Tool status; inspect a purchase or account; review a policy; complete one setting change. Each page's action and data are explicit below. **Data:** only public supply readbacks, owner-scoped Tools/connections/earnings, operator-authorized purchase/account/audit/policy reads, completed-day snapshots and Clerk/workspace settings. **Surfaces:** `/for-providers`, authenticated `/owner/*`, authorized `/admin/*`. Missing, refused, partial, stale and unknown are never numeric zero; Call settlement, recorded transfer and bank payout are separate states.

Priority and page anatomy follow [Arc full-page generation §§Brief, Plan, States](https://uiarc.dev/r/skills/arc-pro/full-page-generation.md), the free Arc composition/component/copy rules, and the buyer showcase's impact × effort ordering. Each detail below names present readbacks, documented Arc IDs, ergonomics and relevant states. Shared shell, exact-money, authority and focus contracts remain AE-owned per the doctrine below.

## Method and hard boundaries

For each surface: name the user's job, choose one primary action, then match each region to an Arc item by its documented job. The page owns one heading and one container; loading mirrors final geometry, resolved empty has one next step, failures remain distinct from empty, permissions remain explicit, and success follows the authoritative readback. See [Arc composition §§Plan the page, States](https://uiarc.dev/r/skills/arc/composition.md), [Arc components §§How to decide, Wiring rules](https://uiarc.dev/r/skills/arc/components.md), [Arc copy §§Rules, Patterns](https://uiarc.dev/r/skills/arc/copy.md), [Arc Pro full-page generation §§Brief, Plan](https://uiarc.dev/r/skills/arc-pro/full-page-generation.md), and [Arc Pro refactor §§Inventory, Parity](https://uiarc.dev/r/skills/arc-pro/refactor-to-arc.md). Motion must carry a state change, not decorate operational truth ([motion guidance](https://uiarc.dev/r/skills/arc-pro/motion-recommendations.md)); verify 320, 390, 768, 1024 and 1440px, keyboard and reduced motion ([responsive](https://uiarc.dev/r/skills/arc-pro/responsive-optimization.md), [accessibility](https://uiarc.dev/r/skills/arc-pro/accessibility-audit.md)).

**Binding doctrine:** install or resync `src/components/arc/**` only from `@uiarc/<id>` or `@uiarc-pro/<id>`; keep AE DTOs, exact-money formatting, access decisions, hooks and server calls in `src/components/ae/<domain>/<feature>/` container, hook, contracts and view-model. No Pro source imitation, no private Arc CSS coupling. AE's visible `:focus-visible` edge override **wins over Arc's no-outline advice**, including portal content. Preserve Clerk/org frame, native navigation links, cursor semantics, per-record evidence and source failures. Every proposal is contingent on public props and behavior parity, not resemblance alone. [Elevation doctrine §§1, 4, 5](arc-elevation-plan-2026-10-06.md#1-doctrine-and-stop-rules), [restore matrix](arc-elevation-plan-2026-10-06.md#3-restore-matrix-every-vendored-entry).

**Priority:** P0 blocks completing a core task or misleading money/security truth; P1 improves a frequent journey; P2 is a specialist enhancement with real data. A ranked design is not an instruction to install all listed items. `KEEP` is a deliberate Arc-fit decision.

## Priority: impact × effort efficiency

Scores match the buyer showcase: impact 1–5 measures journey reach and decision/money clarity; effort 1–5 measures implementation cost, including schema/semantics, not cosmetic effort. Priority index = impact × (6 − effort), higher first. This ranks return on implementation effort, not delivery time; ties favor money-risk, then downstream journey reach. `P0/P1/P2` tags in the details are urgency/condition, not score bands. ★ marks a showcase standpiece; it does not imply that the underlying data is complete.

### Advanced chart eligibility, not a shopping list

- **`funnel-chart`: YES, narrow.** The existing two-stage quote-conversion chart gates complete snapshots and checks converted ≤ created for each day; it says Call creation, **not** payment/delivery. A larger provider onboarding → inspect → publish → purchase funnel needs a cohort/event join and common denominator before design. [Existing chart](../../src/components/ae/admin/metrics/components/MarketplaceSignalCharts.tsx#L12-L43).
- **`line-chart` / `bar-chart`: CONDITIONAL.** Arc's `line-chart` contract maps a missing series value to zero and the `bar-chart` requires a numeric value for each bar ([line](https://uiarc.dev/components/line-chart/markdown), [bar](https://uiarc.dev/components/bar-chart/markdown)). Use a bar only when every date in the selected range is observed. Do not send sparse days through either chart as zero. Current AE chart leaves incomplete days out of its trend line and identifies the number of recorded snapshots; use its day table for the actual dates, and retain this composition unless a replacement proves honest gap semantics. [Snapshot mapping](../../src/components/ae/admin/metrics/marketplace-dashboard.ts#L7-L35), [render behavior](../../src/components/arc/blocks/metrics-dashboard/metrics-dashboard.tsx#L109-L155).
- **`sankey-flow`: NOT YET.** Arc requires branch links between 3 to 5 stages ([documented contract](https://uiarc.dev/components/sankey-flow/markdown)); current aggregate daily fields give no per-entity transition edges, and a purchased-credit vs promotional donut is not an acquisition-to-payment journey. Add only after source-attributable transitions, consistent cohort and conservation accounting are available. Never manufacture links from independent totals. [Current fields](../../src/lib/operator/admin-console/metrics.contracts.ts#L11-L35).
- **`realtime-stream`: NOT YET.** It requires an append-only timed point feed for a genuinely live measure ([documented contract](https://uiarc.dev/components/realtime-stream/markdown)); the current Marketplace report is completed-day snapshots and Treasury uses dated observation/reconciliation that can be stale. A looping animation would claim live monitoring that the backend does not provide. Prefer a timestamped static trend and explicit stale state. [Readbacks](../../src/components/ae/admin/metrics/MarketplaceActivity.tsx#L30-L50), [staleness](../../src/components/ae/admin/treasury/AdminTreasuryPage.tsx#L35-L40).
- **`race-bar-chart`: NOT YET.** It needs complete per-item frames; missing item IDs become zero and autoplay is inappropriate for a glanceable admin dashboard ([documented contract](https://uiarc.dev/components/race-bar-chart/markdown)). Available `transactingTools` and `transactingProviders` are daily totals, not a time-varying ranking by stable Tool or Provider. If period/item frames become authoritative, restrict to an explicitly requested recap, autoplay off, with a table and complete-day checks. [Current contract](../../src/lib/operator/admin-console/metrics.contracts.ts#L25-L35).
- **`data-grid`: NO on current records.** Client-side editing, fill, delete and currency-number coercion conflict with read-only paginated audit/purchase lists, exact decimal units, privileged mutations and incomplete loaded sets. Use `sortable-data-table` with a loaded-only sorting disclosure; consider Pro `data-grid` only for a future genuinely editable, complete, authorized spreadsheet with independent validation. [Arc decision rule](https://uiarc.dev/components/data-grid/markdown), [loaded-only disclosure](../../src/components/ae/admin/activity/PurchaseActivity.tsx#L76-L79).

## Design acceptance gates for any implementation slice

1. **Contract:** inspect exact Arc id's `when to use`, `when not to use`, public props and install tier first. No source edits in `arc/`; source-to-props projection and mutation/pending/permission logic live at the AE edge. Do not use a source demo's records, numbers, OAuth, forecasts, payment states or controls. [Elevation plan §1](arc-elevation-plan-2026-10-06.md#1-doctrine-and-stop-rules).
2. **Truth:** differentiate read not loaded, source unavailable, resolved empty, partially scanned, not applicable, refused, unknown outcome, settled Call, transfer recorded and bank payout not observed. Counts require coverage and denominator; money stays exact and currency-labeled. Do not compute provider totals from truncated lists. [Earnings readback](../../src/modules/capability-supply/internal/supply-funnel/earnings-readback.ts#L1-L40), [metrics coverage](../../src/lib/operator/admin-console/metrics.contracts.ts#L37-L61).
3. **Interaction:** one primary action per page/step; native links navigate, mutation callbacks return authoritative pending/confirmed/refused; sensitive actions retain reverification, approval, idempotency and return-focus. Keep row filters and cursor state when entering a record and returning. [Arc components §§Actions, States](https://uiarc.dev/r/skills/arc/components.md).
4. **Accessibility and motion:** AE edge CSS retains visible focus even where Arc removes rings. Status is labeled, stale data announces staleness, charts include textual values/table, loading region is `aria-busy`, errors show retry, touch targets are 44px. Test 320/390/768/1024/1440 and both themes; no autoplay or moving particles when reduced motion is requested. [Doctrine §1.4](arc-elevation-plan-2026-10-06.md#1-doctrine-and-stop-rules), [Arc accessibility §§3–6](https://uiarc.dev/r/skills/arc-pro/accessibility-audit.md).
5. **Stop conditions:** if the Arc public API cannot express current authorization, paging, exact money, focus or server-derived state, **KEEP** the AE component. Before any shell adoption specifically, prove Clerk org switch, admin gate, mobile route and focus parity; otherwise leave the current shell. [Elevation plan §§4–6](arc-elevation-plan-2026-10-06.md#4-hand-roll-pattern-map-and-keep-ledger).
