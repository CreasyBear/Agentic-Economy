# E1-16 — Combobox

**Vendor state:** `src/components/arc/combobox/combobox.tsx` is **PATCHED**; `combobox.module.css` is registry-pristine. Arc item: Free `@uiarc/combobox`.

- **Diff:** Hide exiting popover content from assistive technology and keyboard interaction (`aria-hidden` and `inert`); hide, remove from tab order, and disable the exiting clear action; stop Escape propagation after the combobox handles it; begin ArrowUp navigation at the last enabled option when nothing is active; use a `Map` for option refs so every valid string key remains addressable, and guard indexed lookup under strict TypeScript settings.
- **Reason:** Keep animated exit content out of keyboard/screen-reader navigation; allow Escape to close the combobox before its enclosing Market Drawer; make the ArrowUp boundary consistent with listbox navigation; preserve lookup correctness for arbitrary option values and strict indexed access. The corrections preserve the public Arc API.
- **Upstream report:** The registry Combobox does not stop Escape from reaching a containing dialog, leaves exiting options/clear controls exposed during AnimatePresence, and ArrowUp from no active option lands at the wrong enabled option. Please address these keyboard/accessibility boundary cases in the upstream implementation. A plain object also does not safely address all valid string option values, and the indexed value is possibly undefined under `noUncheckedIndexedAccess`.

- **Kept AE controls:** The Market Drawer filter trigger and Advanced filter disclosure remain AE-native buttons because Arc Button has no documented flexible label/count layout. Nested in the public Radix `DrawerTrigger asChild` and Base UI `CollapsibleTrigger render` slots, native buttons preserve injected ref, click, ARIA and keyboard behavior. AE token CSS keeps their targets at least 44px with visible focus; the Advanced trigger also respects reduced motion. The existing Arc ChipGroup remains the payer facet control; a named, focusable AE wrapper marks it as FilterToolbar’s return target because ChipGroup exposes no ref or native data attributes. Payer choices sit in FilterToolbar children, and active minimum payer filters are summarized there, so removing the final chip restores focus without a misleading empty state.
