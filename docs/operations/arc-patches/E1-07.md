# E1-07 Arc patch and keep record

## `alert` minimal semantic patch

- **Registry/install:** Free `@uiarc/alert`; installed in `/tmp/arc-scratch/E1-07` with `npx shadcn@latest add @uiarc/alert --overwrite --yes`. Rehydrated the two owned targets from registry `files[].content`, SHA-256 checked, and copied only those targets; the generated foundation outputs were not copied and no dependency was added. Upstream hashes: `alert.tsx` `9274031ede5420e54a3a65825e19062c12443731d4171143054f9104f8fc946c`; `alert.module.css` `938cddc734989a721d38e92ed62c40df3a911cc3c6af6d9da313daaaf57965a6`.
- **Diff:** `alert.tsx` is PATCHED: root role is `props.role ?? (tone === "danger" ? "alert" : "status")`; string/number details remain in `<motion.p>`, while rich non-string children render in `<motion.div>`. `alert.module.css` remains byte-identical to the upstream hash above.
- **Reason:** The registry source hard-coded tone-derived role despite `AlertProps` inheriting `HTMLAttributes<HTMLDivElement>`, so caller overrides were ignored. It also placed every details node in a paragraph, invalid for rich block markup. The patch honors the declared caller role and preserves valid rich-child structure without changing tone defaults or plain-text presentation.
- **Upstream report:** The Free alert API documents `children: ReactNode`, says danger uses `role="alert"` and other tones use `role="status"`, and lists forwarded `HTMLAttributes<HTMLDivElement>` props: https://uiarc.dev/components/alert/markdown. The original role and paragraph behavior are present in registry source https://uiarc.dev/r/alert.json (upstream TSX SHA-256 above).
