# E1-15 — chip-group

## Patched Arc item

**Item:** Free `@uiarc/chip-group`.

**Diff:** In `src/components/arc/chip-group/chip-group.tsx`, before collapsing an expanded group that will remove the focused `Show less` button, move focus to the first remaining visible chip. During exit, mark the overflow button `aria-hidden`, set `tabIndex={-1}`, and disable it. The two changes are marked with `// arc-patch:`. At the AE edge, `OperatorScopesComposition.css` raises provider-filter chips to a 44px minimum on coarse pointers.

**Reason:** The upstream focus loss leaves keyboard users without a logical focus target; the outgoing control must not remain interactive while removed from the visible/accessibility model. Visible focus styling stays at the AE edge (`.arc-market :focus-visible`).

**Upstream report text:** “When the expanded `Show less` overflow button is focused and activation collapses the group, it is removed without handing focus to a surviving control. During its exit animation it also remains enabled. Please move focus to a surviving chip before collapse when the overflow control will disappear, and make exiting overflow controls inert to keyboard and pointer interaction.”

**Install:** Used isolated `npx shadcn@latest add @uiarc/chip-group --overwrite --yes`; the registry declares `chip-group.tsx` and `chip-group.module.css`, and all required npm packages already exist. Rehydrated both scratch files from registry `files[].content` and verified their SHA-256 values before copying: TSX `6daed55a7cd2122cc67fa4ee0243c3266fb1b002ed5609c00836e349bc781812`, CSS `cc8c6c63756b0dee42c97c55ede87074996628f237bc31ef32e3d64f8f72b928`.
