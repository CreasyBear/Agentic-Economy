# Mercator → Aecon capability parity register

Status: design baseline, 2026-10-05; **not a claim of deployed Plan support**. Source of truth for implementation is the [accepted; building Plan Quotes RFC](../designs/2026-10-05-plan-quotes-rfc.md#12-w0w6-delivery-and-evidence). This extends the **capability names and evidence** in [ADR 0006's coverage table](../adr/0006-mercator-capability-foundations.md#capability-coverage), which has no row IDs; MP IDs provide stable tracking rather than a duplicate foundation decision. Its F1–F5 slices remain separate: notably F2 (conventional async provider completion), F4 (selected artifacts) and literal payment-rail parity are **not silently delivered** by Plan Quotes. Joel accepted RFC D1–D5. [Mercator contracts](https://mercator.sh/openapi.json) and [documentation](https://mercator.sh/docs) describe a public interface, not independently verified private execution. `PRESENT` means an equivalent *bounded* AE capability exists in source, not a fresh hosted proof; `PARTIAL` means the single-Tool or narrower capability exists; `ABSENT` means no current AE equivalent; `BEYOND` means AE's current boundary is stronger than the public Mercator contract (without inferring its private internals). Wave is the **earliest RFC wave that checks or extends this row**, not a claim the wave has shipped. Acceptance is a future, observable CLI/MCP/HTTP proof; an existing command is cited in [AE CLI manifest](../../tools/ae/commands/manifest.ts#L642-L691). No paid production job is required.
Build plan: [Plan Quotes implementation plan](plan-quotes-build-plan.md).
