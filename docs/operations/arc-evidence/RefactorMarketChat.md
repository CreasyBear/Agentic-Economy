## 4. Keep hand-rolled / do not misclassify

- **Bounded Call output preview — keep.** `CallOutputPreview` limits initial rows, depth and long text before offering full JSON; Arc JsonViewer does not promise those display caps. Use the viewer only for already-full receipt/request JSON disclosures unless an equivalent bounded view is proven. Keep exact output copy and authorized projection unchanged.
- **17 native `details` disclosures — keep.** They are ordinary independent, low-state native disclosure controls, not a hand-built overlay or accordion. The available Arc `accordion` is one-open and expects a grouped list; converting disparate receipt and provenance leaves would change simultaneous-open state and add composition/state work without a demonstrated accessibility gain. Existing summaries are descriptive and inherit visible-focus policy.
- **`SpendingLimitInputs` — keep.** The Arc `money-input` API rounds the interaction contract to numeric minor units. AE requires strings through edit and formats sandbox-only values without editing; it cannot be substituted without changing exact-money/user-draft semantics.
- **`OptionCard` — keep as an AE-specific projection, not a duplicate Arc product block.** Product listing is a storefront; it cannot represent quoteable vs merely selectable candidates, readiness and source attribution, and transcript-scoped review/compare actions. It already borrows Arc market styling and the controller owns its choices.
- **RJSF widget glue — keep, not another control implementation.** `shared/tool-input-form/AeToolInputWidgets.tsx:17–20,21–89,94–136` adapts schema-generated IDs/names, required/read-only/disabled, validation, blur/focus, examples, and empty values to existing Arc Checkbox/Input/Textarea. Replacing the glue with static Arc form controls would discard runtime schema behavior.
- **Market catalogue/search/filters are mostly already Arc, not handroll findings.** `DirectoryExplorerFilters.tsx:3–9,269–295,358–370`, `AeX402Directory.tsx:10–22,514–570`, `DirectoryToolList.tsx:5–6,40`, and `DirectoryProviderList.tsx:2–6,25–32` use Arc FilterToolbar, ChipGroup, Combobox, Drawer, Tabs, Select, SegmentedControl, ProductListing, and SortableDataTable. Their AE callbacks/URL state remain edge behavior; do not replace them with sample block logic. `DirectoryToolPlayground.tsx:5,98–99` already uses the local `ai-elements` code block, correcting an apparent `<pre>`-only reuse gap.
- **Boundary warning (outside edit scope):** current `src/components/arc/market/ProductListing.tsx:10–13` imports AE route context and Market domain DTOs into the vendored Arc layer. This is the inverted boundary, not a reason to alter licensed block source in this lane. Move domain/router binding to the scoped Market adapter in a dedicated edge-boundary change; existing audit `docs/operations/arc-audit-2026-10-06.md:100` records it as R32. No vendored edits or mass reinstall.

## 5. Highest payoff first

1. Use Free Arc `json-viewer` only for full structured Call receipt/request disclosures behind an AE adapter; retain the bounded output preview, exact copy, and access boundary. Gains interactive keyboard inspection, but limited JSX deletion.
2. Reuse the existing Shiki `ai-elements/code-block` at market sample and chat fence edges; unify code semantics, keyboard copy, and language handling without installing a duplicate renderer.
3. Migrate the four raw text controls to existing Arc Input/Textarea; gains consistent labels/error visuals and removes duplicated styling while preserving native values and validation.
4. Align the Call feedback reason `<select>` to Arc Select and evaluate RadioGroup only with proven pending-disable parity; modest but direct keyboard/consistency gain.
5. Address ProductListing's inverted AE dependency in a separate edge-adapter task; high architecture/maintainability payoff, but never edit the vendored Arc source in this inventory lane.

**Effort:** JSON-viewer adapter M; reusable code-block edge M; text controls S; Select S / RadioGroup M; ProductListing boundary M. No surface was runtime- or viewport-verified in this read-only assignment.
