## 4. Keep hand-rolled / reuse-vs-handroll decisions (with explicit missing capability)

1. **Keep `AeAppShell`, `AeOperatorPage`, `WorkspaceMenu`, `AeOwnerMobileNavigation` and their `useAppShellState`/entitlement hooks** (`layout/AeAppShell.tsx:29-93`; `layout/AeOperatorPage.tsx:93-194`; `layout/app-shell/WorkspaceMenu.tsx:30-104`; `layout/AeOwnerMobileNavigation.tsx:13-42`). Arc Pro `sidebar-rail` is a **different frame/navigation IA** with sample data and its own mobile sheet; it does not preserve persistent root-frame chrome, TanStack native links, Clerk org/session changes, admin entitlement, signed-in bottom nav, route-focused main, or document/chats scroll policies out of the box. Its local copy is test-only. Arc `workspace-sidebar` explicitly has **no mobile sheet**, assumes favorites/projects and workspace switcher, while Arc `glass-tabbar`/`liquid-tab-bar` expose `role=tab`/`aria-selected` (not page links with `aria-current`), so replacing AE mobile navigation loses correct route semantics. Preserve the genuine Arc public Drawer already in header. Avoid a net-increase of adapter/code/bundle merely to use a shell block.
2. **Keep `ThemeToggle` and Clerk `UserButton`/`OrganizationSwitcher`** (`layout/ThemeToggle.tsx:33-61`; `layout/app-shell/AeAppHeader.tsx:123-129`). Arc `theme-switch` excludes `system`; Arc `user-menu` includes it but cannot replace Clerk's authenticated account/org switch and user profile route, so layering it would duplicate account controls. Current Radix three-way radio menu is a declared internal UI primitive, not a hand-rolled popover.
3. **Keep `AeOperatorBreadcrumbs`** (`layout/AeOperatorBreadcrumbs.tsx:127-220`): Arc `breadcrumb` currently documents rendering `next/link` for `href`, unlike this TanStack app, and its API does not specify AE's intermediate-crumb overflow/dropdown nor router typed params; swapping adds dependency/router friction for no meaningful deletion. Keep Radix dropdown and real links; don't fake a compatible link API in Arc source.
4. **Keep `AdminActionSheet` state machine and Arc Drawer** (`admin/actions/AdminActionSheet.tsx:12-87`). Arc `confirm-morph` says use Dialog when consequences need explanation; it is one-step confirmation/optional undo, not reason → evidence → MFA/proof → audit preview → separate owner approval → uncertain receipt recovery. Arc `roles-permissions` is a permission **matrix**, not identity grant/revoke. Arc `hold-to-confirm` protects taps but cannot encode two-person authorization or pending money truth. Small controls may migrate, not the AE command model.
5. **Keep treasury exact-money state, metrics view-model, current shadcn Dialog unless focused UI evidence shows an Arc win** (`admin/treasury/TreasuryActions.tsx:17-85`; `TreasuryMetrics.tsx:74-98,157-193`; `treasury-view-model.ts`). Arc `money-input` accepts JS-number minor units and Arc `metric-card` requires a number, whereas AE's six-decimal exact USDC and unavailable states cannot pass through either without precision/status loss. `billing-overview`/`usage-billing` are customer billing/projected-spend pages, not company float/reconciliation. The existing shadcn dialog is not custom modal implementation; Arc Dialog replacing it would mostly swap primitives, not delete domain UI. Move `exposureMeter` math out of TSX (audit R34), not into Arc internals.
6. **Keep dynamic audit filter editor/event picker, but reuse Arc for chips** (`admin/audit/components/AuditFilterChips.tsx:68-126`). Arc `FilterToolbar` Add supports enumerated choices, **not** free-text actor/target/correlation IDs and date boundaries; `date-range-picker` expects viewer-local whole days/draft Apply, potentially changing server filter date/time contracts. Do not conflate filter UI with query semantics. The already-Arc activity filter is distinct: `admin/activity/AdminActivityPage.tsx:69-77`.
7. **Keep source-partial empty states, role restrictions, approval list and route recovery behavior** (`admin/exceptions/components/ExceptionFeedTable.tsx:50-80`; `admin/audit/PendingApprovalsActions.tsx:17-60`; `layout/AeRouteError.tsx:22-140`). Arc `empty-state` is for genuinely empty results (not pending/incomplete reads), `timeline` is chronological display rather than actionable approvals with proposer inequality/expiry, and Arc `confirm-morph` cannot do owner proof. Arc visual primitives may display statuses, but authorization and refusal truth stay with AE.
8. **Honesty corrections:** `AeRecordTable` is *not* a hand-rolled table visual; it already renders Arc `SortableDataTable` (`operator/AeOperatorDataTable.tsx:297-325`). Admin dashboards and headers already use Arc blocks (`admin/metrics/AdminMetricsPage.tsx:41-44`; `admin/treasury/TreasuryMetrics.tsx:98-104`; `layout/AePageHeader.tsx:43-60`). `src/components/ae/admin/metrics/components/MetricsControls.tsx:14-18` is unmounted per prior audit R23; do not count it as a live pattern or replace it with another Arc control. No vendored Arc edits and no new dependencies are justified for those false positives.
