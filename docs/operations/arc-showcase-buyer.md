# Arc showcase: buyer journeys

**Status:** page plans only, not an implementation or permission to invent product data. **Catalog:** Arc MCP `list_components` returned 236 live IDs (128 Free, 108 Pro) on 2026-10-06; `search_components` covered discovery, detail, comparison, chat, receipts, money, analytics, setup and landing. `get_component` supplied the use and **when not to use** checks below. Free IDs use `@uiarc/<id>`, Pro IDs use `@uiarc-pro/<id>`. No item is installed by this document.

## Brief and integration contract

Audience: a person choosing a Tool, deciding whether to trust and pay for a Call, then following its result and connecting an Agent. Jobs: discover → inspect/compare → ask/approve → inspect receipt → fund/control spend → review history → connect. Primary action: exactly one per page, specified below. Data: only existing public directory/admitted Tool projections, current owner-scoped Call and money reads, agent-access records and completed usage reports; never sample ratings, purchase counts or projected charges. Surfaces: public Market and Tool pages plus authenticated chat/account pages. This applies `~/.claude/skills/arc-pro/full-page-generation.md` §§1–2 **plan-only**: each page has a five-part brief, region map and complete state treatments, without installation/build. `~/.claude/skills/arc/components.md` §§How to decide/App blocks, `composition.md` §§Plan the page/States, `copy.md` §§Rules/Patterns, `design.md` §§Color/Spacing and `checklist.md` §§States/Accessibility set the choice and review bar. `arc-pro/refactor-to-arc.md` §§Inventory/Map/Parity, `motion-recommendations.md` §§Decide/Assign tokens, `responsive-optimization.md` §§Measure/Fix, and `accessibility-audit.md` §§Structure/Feedback/Visual and touch inform migration checks, not claims of completed validation.

The binding local doctrine is `docs/operations/arc-elevation-plan-2026-10-06.md:5-11`: reinstall upstream-pristine vendor files via registry, keep AE data and lifecycle in `src/components/ae/<domain>/<feature>/` containers/hooks/contracts/pure view-models, never transplant Pro code, and **override Arc's no-outline preference** with visible `:focus-visible` treatment in AE edge CSS (including portals). Verify documented props and declared dependencies before choosing a Pro block. Existing AE-adapted files under `src/components/arc/market` are not evidence that pristine upstream supports their bespoke props. Exact AUD amounts remain exact money types, not chart floats. Source claims distinguish Coinbase Bazaar activity from AE Calls and directory Hosts from verified Providers (`src/modules/market/directory-card.view-model.ts:233-272`, `src/routes/providers.$providerHost.tsx:23-42`).

**Shared layout/states:** one `h1`, one primary action, one page container, 16px inside groups, 24px between regions, 24–32px page gutters and one informative motion detail per view. App shell and route authority stay AE-owned; don't replace Clerk/org/navigation with `sidebar-rail` just for spectacle. In the tables, **limited** covers disabled, unavailable, partial, permissions and long-content conditions; absence of data is not zero. Every loading region uses final-size `skeleton` and `aria-busy`, errors an adjacent `alert` with an appropriate retry, success is visible in place, empty offers one next action. All controls need visible edge-owned keyboard focus, named actions, 44px targets, status text not color alone, 320/390/768/1024/1440px reflow, reduced-motion final state. No decorative loop, fabricated throughput or autoplay marquee.

## Priority: impact × effort efficiency

Scores: impact 1–5 measures journey reach and decision/money clarity; effort 1–5 measures implementation cost including schema/semantics, not cosmetic effort. Priority index = impact × (6 − effort), higher first. The index is a prioritization signal, not an estimate of delivery time; tied scores are ordered by money-risk and downstream journey reach. **★ = showcase standpiece**, not a promise that all conditional data exists.

## Cross-journey decisions and acceptance for later implementation

1. **Keep authority at the edge:** directory listing ≠ admitted callable Tool, Host ≠ verified Provider, source USDC listing ≠ AUD Quote, issued key ≠ authenticated Agent, pending Call ≠ paid/delivered, usage report ≠ invoice. All six distinctions appear in source projections cited above and must survive any Arc cutover.
2. **Pristine capability gate:** before each proposed Pro/Free substitution, `get_component` → documented props and *when not to use* → `get_install_command` → dependency/licence check → isolated registry overwrite → AE edge adapter → consumer parity. **KEEP** existing AE composition if pristine product/checkout/chart props cannot express its state. No Pro source reconstruction, copied demo rows, AE imports in vendor, or exact money through JavaScript floats.
3. **Motion inventory:** `arc-pro/motion-recommendations.md` §§1–5 requires inventory/remove/assign tokens/reverse rapidly/reduced-motion for each migrated screen. Prefer selected/filter/status transition; never animate a payment into certainty. Stable keys and tabular numbers prevent layout jumps.
4. **Accessibility/responsive proof for implementation, not claimed now:** `arc-pro/accessibility-audit.md` §§1–6 and `responsive-optimization.md` §§1–4 require focus order and **visible edge focus** in both themes, announced async/refused states, keyboard-return from overlays, 44px controls, no hover-only actions and no page-wide horizontal scroll at 320/390/768/1024/1440. Arc's contrary no-focus-ring checklist is overridden by repository WCAG doctrine; untouched vendor files are not the place for the exception.
5. **Success measurement:** walk public Market → admitted Tool → Agent connection → fresh Quote → approval → same-ref receipt → credit/history without losing query, Tool ref, Call ref or truth labels. A showcase is not finished by a pretty block or screenshot; verify actual paths and financial/status provenance before claiming it works.
