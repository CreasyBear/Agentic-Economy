# Ideal app: two-sided capability market

**Status:** target analysis. No application changes authorised.  
**Date:** 2026-09-21  
**Authority:** [PRODUCT.md](../../PRODUCT.md) journeys 1–6; [CONTEXT.md](../../CONTEXT.md); [DESIGN.md](../../DESIGN.md)  
**Current-state maps:** [platform-design-package.md](../operations/platform-design-package.md)  
**Earlier sketch:** [2026-09-21-platform-experience-audit.md](./2026-09-21-platform-experience-audit.md) §2 — this file supersedes that sketch as the ideal. The audit remains evidence of the 21 September walk.

Design the platform around the decisions people need to make and the outcomes they need to reach. Derive navigation, routes, and screens from those journeys. Do not start from `/owner/*` path names.

This is the target. Current source is evidence, not the dest law. Grades in the distance section follow the package (`CHARTER` / `IMPLEMENTED` / `PARTIAL` / `SEEN` / `OPEN` / `DOCS`).

---

## Thesis

A Customer's Agent finds a suitable outside Tool, buys one bounded contribution within granted authority, and continues in the existing harness; a Provider exposes that Tool and gets paid without becoming a distribution expert.

Five words a user should be able to say: **“My agent bought this Tool.”**

If half the product must go, the half that survives is: Market → inspect → existing Agent Quote/Call → Call receipt → Provider publish. Everything else is a prerequisite, a recovery, or a later compounding loop.

---

## What this is most like — and where it diverges

| Familiar thing | What we take | What we refuse |
| --- | --- | --- |
| Airbnb listing grammar | Cards, filters, inspectable listing, host/publish in a mode not a fourth buyer tab | Human **Reserve**. A Tool is not a stay. The Agent Quotes and Calls. |
| Locus | Connect once, prepaid credit, spending policy, usage as Call history | A second catalog behind login. Market is one URL. |
| Nevermined catalog | Browse before account; list-your-service as a door; listed price is not checkout | “Top up on the listing” as the primary commit. Credit is a dest, not the listing action. |
| Perplexity ask | Natural-language need on the market; thread as a page | Owning the user's project, Sessions-as-the-product, or a chat that can purchase. |
| OpenRouter `/models` | Guest catalog; scannable card (author, context, two listed prices); Compare as a durable control; pin | Replacing the need-ask with “Search models…”; modality dests; token volume as trust; assuming every row will Call. Stress test: [2026-09-21-openrouter-stress-test.md](./2026-09-21-openrouter-stress-test.md). |

Controversial decision (keep it): **the human never checks out a Tool.** The listing's job is suitability and a truthful next step into the Agent the Customer already authorised. Chat discovers and compares. Quote and Call belong to that Agent. The receipt is how a person explains what happened.

## 1. Jobs the ideal app serves

Jobs already live in [platform-job-map.md](../operations/platform-job-map.md). The ideal app does not add screens for jobs that are not progress. It makes these succeed:

| Actor | Job | Ideal success (person can say) |
| --- | --- | --- |
| Customer | J-B01 Find despite vocabulary | “These three fit what I asked; I did not guess a registry name.” |
| Customer | J-B02 Compare without exhaustion | “I picked this one because of X, and I can show the others I dropped.” |
| Customer | J-B03 Buy and continue | “My Agent called it; I am back in my own work.” |
| Customer | J-B04 Record no-fit | “Nothing assessed fits; I can wait 30 days or stop matching.” |
| Customer | J-B05 Grant authority | “This Agent may spend this much on these Tools. Credit did not grant that.” |
| Customer | J-B06 Fund | “I have this available, this reserved. That is not permission.” |
| Customer | J-B07 Explain | “This Call, this Agent, this Quote, this Charge, this delivery, this resolution.” |
| Customer | J-B08 Recover | “Same Call. Cancel or reconcile. Not a second purchase.” |
| Agent | J-A01, J-A02 | Search → quote → call → result; at most one safe next action. |
| Provider | J-P01 Publish | “This version is live at this URL, at this price.” |
| Provider | J-P02 Reach demand | “Buyers already on this market can find it.” |
| Provider | **J-P03 Get paid** (add to job map) | “This is earned; this is paid; this is held, and why.” |
| Returning | J-R01, J-R02 | Same chain, less re-entry; policy and credit still visible. |
| Support | J-S01, J-S02 | Same receipt, same `callRef`, one next action. |

**Not jobs:** browse an endless directory; use a dashboard; share a login; post a public RFP; become the Customer's project manager.

## 2. Ideal journeys (including after payment)

### Buyer

```text
Need → Discover → Compare → Evaluate → Commit → Receive → Manage or resolve → Return
```

| Stage | Decision | Ideal behaviour |
| --- | --- | --- |
| Need | Do I need an outside Tool? | Describe the contribution on Market or in a thin ask. AE does not take the project. |
| Discover | Which Tools enter the set? | Shortlist with provenance. Indexed ≠ callable. Empty is “no supported fit in what was assessed,” not “nothing exists.” |
| Compare | Which version stays? | Same attributes, exclusions, and reasons survive inspect, refresh, and share. Cap stays small (≤4). |
| Evaluate | Proceed toward Quote? | Listing states fit, indicative price, terms, readiness, and the exact unmet prerequisite. Listed price is never dressed as a Quote. |
| Commit | Accept this Call? | The **existing** authorised Agent Quotes, then Calls. Expiry and drift fail before money or Provider effect. No chat principal. No extra human approval inside an already-authorised routine Call. |
| Receive | Use it, wait, or treat as failed? | Bounded output or honest pending. Delivery, payment, and purchase resolution remain separate facts. |
| Manage | Cancel, reconcile, or accept? | Same `callRef`. Help opens with that ref. Suggested next action is never a fresh Call after possible dispatch. |
| Return | Same Tool, switch, or new need? | Prior Call and saved Tool are recall, not a score. Fresh Quote. No project memory. |

Journey 5 sits on Discover when the shortlist is empty: record the bounded phrase, show the 30-day window, allow withdraw. A match never buys.

Journey 6 is Return done well — not a personalised homepage.

### Provider

```text
Assess → Set up → Publish → Receive demand → Fulfil → Get paid → Improve
```

| Stage | Decision | Ideal behaviour |
| --- | --- | --- |
| Assess | Is this market worth it? | `/for-providers` states pass/fail before a banking form. |
| Set up | Connect this source? | Start from the capability. Identity and payout appear when publish or earnings require them. Drafts survive OAuth. |
| Publish | Make this version callable? | Preview the public listing. Submit ≠ live. Withdraw is a confirmed destructive act. |
| Receive demand | Accept the Call? | Upstream runtime. Provider sees attributed Calls, not a second marketplace. |
| Fulfil | Complete or fail? | AE records observations. Disputes stay on the Call. |
| Get paid | What is earned vs paid? | Earnings, obligation, available payout, completed payout. A Stripe return is not “ready.” |
| Improve | Revise price or withdraw? | Correct the Publication. Demand signals are later; do not invent a Provider inbox for this release. |

### Agent (not a third side)

```text
Connect → Search / compare → Quote → Call → Continue in harness
```

Connect once. Never send `accountRef`. After possible dispatch, only `status` / `cancel` / `reconcile`.

## 3. Objects people must understand

Small vocabulary. [CONTEXT.md](../../CONTEXT.md) wins. Ideal user-facing machines (internal enums stay hidden):

```text
Tool (indexed | inspectable | callable)
  └── Tool version  →  Quote (open → expired / refused / accepted)
                         └── Call
                               ├── delivery: pending | delivered | failed | uncertain
                               ├── payment: none | reserved | charged | refunded
                               └── purchase resolution: open | delivered | failed | adjusted | refunded

Spending policy  ≠  Prepaid credit (available | reserved)
Agent            ≠  Credential
Publication      ≠  Listing  ≠  Source  ≠  Provider connection
Charge           ≠  Provider obligation  ≠  Payout
Service request  (active 30d | withdrawn | expired)   — never a tender
Service comparison (considered / excluded / reasons) — durable enough to survive inspect
```

Every consequential screen answers:

1. What has happened?
2. What is happening now?
3. Who needs to act?
4. What can I do next?
5. When should I expect an update?

Forbidden copy: “Success” for a submitted request; “Available credit” as if reserved did not exist; “Payout setup verified” for a Connect return; directory card language that implies the endpoint will Call.

## 4. Ideal destinations

Working contexts stay separate. One person may buy and supply; the switch is explicit.

| Context | Primary dests | Not dests |
| --- | --- | --- |
| Public discovery | **Market** | For agents / For providers (marketing doors) |
| Buyer working | **Market · Agents · Calls** | Credit (rail or account). Overview. Second Market. |
| Provider working | **Supply** (mode or menu) | Fourth header tab beside Market |
| Shared account | Profile, security, team, workspace | Header peers |
| Operations | Discovery, catalog health, audit | Buyer chrome |

### Target chrome (provisional until signed-in AE + Airbnb walks)

```text
Public:     Market · For agents · For providers · Sign in
Signed-in:  Market · Agents · Calls · [Account] · List tools
```

**List tools** is a menu/mode entry, not a peer tab. That matches SEEN Airbnb “Become a host” and Nevermined “List your service.” AE’s current **My tools** header slot is the thing to demote, not a new dest to invent.

### Route rules (unchanged law)

- Path = dest or resource (`/tools/…`, `/calls/…`, `/t/…`).
- Query = shareable view (filters, compare set, activity agent).
- Page when the task must resume or be linked; dialog when closing returns to the same dest.
- Refresh, Back, and post-login resume keep the task.
- Secrets stay out of URLs.
- Server enforces access. `/owner` is organisation scope, not permission.

### Dest law (not the current path list)

One dest, one URL, one name. Path names today are evidence of accretion, not the law.

```text
Market     one catalog, guest and signed-in
Agents     who may spend
Calls      what happened
Credit     prepaid (rail / account — not a header peer)
Supply     publish mode, not a fourth buyer tab
Account    profile, security, team, workspace — menu, not chrome
```

Resources hang off those dests (`/tools/…`, `/calls/…`, authorize, funding return, add-source). Doors (`/for-agents`, `/for-providers`, `/about`) are not dests.

**The current tree is adhoc.** It grew by prefix (`/owner*` = “signed-in dump”), by feature folder (`/agent-access`, `/activity`, `/fund`, `/t`), and by rail (`Overview`, second Market). Labels then papered over the folders (Calls lives at `/activity`; My tools is supply). That is why the site feels like slop pages: the URLs do not say the dest.

**Brownfield paths are a strangler map, not the target.** Reuse a path only while it still names the dest. Fold or demote when it does not. Do not treat “the file exists” as “the tree is right.”

**Fold:** `/owner/market` → Market. `/owner/` Overview → Market.  
**Demote:** My tools header peer → Supply menu/mode.  
**Rename-when-we-touch:** `/activity` is Calls; `/agent-access` is Agents; `/owner/credit` is Credit (buyer), not a Provider page.  
**Do not add:** `/trips`, `/messages`, `/saved` as chrome, `/wishlist`, demand CRM, chat checkout, a connections hub, a Get-paid dest.

**J-B04:** not a header dest. When scheduled, eligibility and withdraw live on Market (query or a page-not-dest). Until then the Agent/API path remains the implementation, and the empty Market state must not pretend a human recorded a gap.

## 5. Ideal screens

Spec chain: **user and context → job → information → decision → actions → resulting state → recovery.**

Wireframe every state: normal, empty, loading, invalid, unavailable, interrupted, completed. Discover grammar ([DESIGN.md](../../DESIGN.md)): listing cards for choice, tables for comparison and records.

### Market — `DEST-PUBLIC-MARKET` / `DEST-BUYER-MARKET`

Need on the page. Collections and filters as views, not sibling dests. Cards: contribution, Provider, **callable vs indexed**, provider-listed price, save, compare.

| Element | Purpose |
| --- | --- |
| Ask + retained constraints | J-B01 |
| Shortlist / no-fit / assessment unavailable | Honest empty |
| Compare (query-persisted, ≤4) | J-B02 — not memory |
| Primary: open listing | Advance |
| Empty: record gap (when JI-08) | J-B04 |

Disabled Compare says why (“Select two Tools”). Opening a listing does not destroy the compare set.

### Tool listing — `RES-TOOL`

| Element | Purpose |
| --- | --- |
| Title, Provider, contribution | What this is |
| Callable vs indexed | Feasibility |
| Indicative / provider-listed price | Not a Quote |
| Terms, effects, data use | Commitment |
| Exact unmet prerequisite | Authority, credit, or admission |
| **Continue with your Agent** or **Connect an Agent** | J-B03 / J-B05 — `resumeTool` + inputs. Must be as obvious as OpenRouter’s “Create API Key” + snippet. |
| Copy Tool ref | Take this into the caller |
| Back to Market | Reconsider |

There is no Reserve. There is no Top up as the listing's primary action. Top-up lives on Credit when the prerequisite is money. A human playground, if it ever exists, is a sandbox Action execution — not a Call and not Chat-as-market.

### Ask thread — `RES-ASK-THREAD`

Thin discovery around the same catalog. Cards match Market facts. Quote/Call tools are absent for the human session. Continuation: “Use this with your Agent.” Shared threads cannot buy.

### Agents — `DEST-BUYER-AGENTS`

Who is connected, what they may spend, on which Tools. Connect ≠ grant. Resume selected Tool. Authorize is a page (resume/link), not a toast.

### Credit — `DEST-BUYER-CREDIT`

Available **and** reserved. Top-up quote (credit, fee, GST, total) before Stripe. Monthly ceiling is **authority**, presented as such — not a funding line.

### Calls — `DEST-BUYER-CALLS` + `RES-CALL`

List by Call identity. Receipt:

```text
What happened
What is happening now
Delivery | payment | purchase status     (three facts)
Who must act
The one safe next action
Get help with this Call  →  /support?callRef=
```

Purpose, when we have it, is a recorded field — not a blank “why.”

### Supply — `DEST-PROVIDER-SUPPLY`

Source first. Preview public listing. Publish when requirements are met. Earnings ≠ payout. Withdraw is destructive and confirmed. ABN and payout only when the next step actually needs them, and only if we persist what we ask.

## 6. Friction: remove vs keep

Optimise for **confident completion**, not minimum clicks.

| Remove (hostility) | Keep (commitment) |
| --- | --- |
| Sign-in wall on browse | Sign-in for Agents, Calls, Credit, publish |
| Compare that dies on inspect | Small compare, persisted in the URL |
| Unexplained disabled Compare | Named rule on the control |
| Directory card as “ready to call” | Indexed browse (x402 clarification) |
| Chat that appears to buy | Deliberate Quote/Call in the Agent |
| ABN we do not save | Identity when publish/earnings need it |
| Payout before a first draft | Stripe hosted when money will move |
| Generic “Something went wrong” | Problem + what remains saved + next step |
| Receipt without a help link | Cancel / reconcile on the same Call |
| Credit that hides reserved | Ceiling as authority, not as a top-up |

## 7. Ergonomics as acceptance

Not polish. A dest is not done because a component exists.

- Keyboard to every decision; visible focus; no `tabIndex={-1}` on money-changing modes.
- Labels on every control. Status not by colour alone.
- Contrast via semantic tokens; `FieldError` must meet AA ([DS-09](../operations/design-system-maturity-register.md)).
- Touch ~44×44 CSS px (`--ae-touch`). WCAG 24×24 is the floor.
- Colocated skeletons **wired** to the route. Credit, listing, Market, Chat, Calls must not snap.
- Validation says what is missing and how to proceed. Money playbooks: what happened, financial impact, next step.
- Test with keyboard open, large text, slow link, long names, awkward prices, interrupted login.

Weakest dests today (do not “fix” by restyling): Market card focus, Shared account Clerk island, Calls chips/export. Owners stay DS / W.

## 10. What we will not build

Cut these even if they look like “ideal marketplace” completeness:

- Human checkout / Reserve / listing Top-up as commit
- Chat purchasing Agent or synthetic grant
- Search / Keys / Trips rename
- Messages, Wishlists-as-chrome, Overview dashboard
- Demand CRM or Provider match inbox (journey 5–6 later)
- Second visual kit or route taxonomy rewrite
- New analytics, form, or search service
- Project memory, tender board, general agent runtime

Reuse: Clerk, TanStack Router, installed Base UI / `Ae*`, Stripe hosted, existing MCP/CLI actions, Convex retrieval, PostHog as already wired.

## Design integrity (interview skipped)

Reviewed against the written charter and the eight current-state registers. No additional user interview.

1. **Thesis:** my Agent bought this Tool; the Provider got it found and paid.
2. **Integrity:** strong if listing, chat, and chrome obey the no-human-checkout / no-chat-principal / supply-as-mode choices. Weak if we add dests to look like Airbnb signed-in chrome we have not seen.
3. **Top risks:** treating component tests as journey completion; dressing indexed rows as callable; expanding J5–J6 into the current buyer gate.
4. **Cuts:** Reserve, chat checkout, Overview, rail Market, header My tools, demand CRM.
5. **Constraints that improved the design:** Agent-mediated purchase (forced a listing that inspects, not books); one installed stack (forced dest reuse); x402 browse-before-admission (forced callable vs indexed); no signed-in reference walk (forced provisional chrome, not dest law).
6. **Next:** do not implement from this file. Walk signed-in AE header and one listing. Then schedule existing owners in the package sequence (inspect → authorised Agent → callable vs price → compare memory → store asked facts).
