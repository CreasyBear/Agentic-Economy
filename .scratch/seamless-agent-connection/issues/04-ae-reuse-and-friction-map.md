# Map AE's reusable connection primitives and current friction

Type: research
Status: resolved
Blocked by:

## Question

What is the current end-to-end AE agent-connection journey across `/for-agents`, owner developer settings, CLI installation, MCP registration, OAuth/device authorization, agent-directory readback, credential lifecycle, and recovery; which existing components and maintained dependencies can be composed into the feature, and where does the current application force users to interpret documentation or coordinate subsystems?

Produce a route/component/dependency map with direct file-and-line evidence. Identify reusable public interfaces and behavior seams, not implementation tasks. Flag any proposed new infrastructure that would violate the no-handrolling constraint.

## Answer

### Executive finding

AE already owns the difficult connection machinery. It has a distributable CLI, a standard OAuth authorization server with device and authorization-code flows, Clerk-backed one-time credential issuance, an official MCP SDK server, a canonical agent identity and directory, owner-side rotation/revocation, and Invocation recovery. The maturity gap is at the joins: setup is documented three times, MCP registration has two incompatible paths, CLI diagnostics cannot prove that the selected harness loaded the connection, and owner/agent recovery requires humans to reconcile local CLI state with server-side credential state.

The current journey is therefore not one connection. It is a sequence of independently sound subsystems joined by prose:

`/for-agents` -> global CLI install -> manual harness choice -> `add-mcp` -> harness restart -> public MCP visibility -> CLI call challenge -> `ae connect` -> owner browser consent -> CLI token polling/storage -> optional second MCP file/import -> `/agent-access` readback -> browser-only revocation -> manual agent reconnect.

### Public interfaces already suitable for composition

These are the stable boundaries to compose. They should not be copied into new feature-local models.

- **CLI distribution contract:** `AE_CLI_VERSION`, `AE_CLI_ARCHIVE_FILENAME`, `aeCliArchiveUrl`, `aeCliInstallCommand`, `aeCliEaccesFallbackCommand`, `AeMcpHarness`, `aeMcpInstallCommand`, and `aeMcpListCommand` in `src/lib/cli-distribution.ts:5-33`.
- **CLI machine interface:** `ae <command> --json`; commands and accepted flags are centralized in `tools/ae/cli.ts:38-89`, and every caught failure has a redacted structured envelope plus optional `suggestion`/`nextCommand` in `tools/ae/cli.ts:525-596`.
- **MCP boundary:** `POST|DELETE /mcp` via `handleMcpRouteRequest`; admitted tools come from `listMcpActions()` and use the official SDK transport (`src/routes/mcp.ts:6-20`; `src/lib/server/mcp-api.ts:269-347,375-398,506-510`).
- **OAuth boundary:** `/.well-known/oauth-protected-resource`, `/.well-known/oauth-authorization-server`, `/oauth/register`, `/oauth/device_authorization`, `/oauth/authorize`, `/oauth/token`, with constants in `src/modules/agent-access/oauth-state.ts:24-56` and route adapters in `src/routes/oauth.register.ts:9-26`, `src/routes/oauth.device_authorization.ts:9-26`, `src/routes/oauth.authorize.ts:10-37`, `src/routes/oauth.token.ts:10-27`.
- **Consent boundary:** `AeAgentAccessAuthorizeForm` takes a locator plus parsed `AgentConsentDetails` and posts the final decision to `/oauth/authorize` (`src/components/ae/agent-access/AeAgentAccessAuthorizeForm.tsx:139-183,253-307`).
- **Authenticated self boundary:** `GET /api/v1/account` / `agentAccountSelfAction`, explicitly shared by HTTP, MCP, and CLI (`src/modules/agent-access/account.actions.ts:21-35,240-298`).
- **Canonical owner readback:** `readAgentDirectoryServer` -> `loadAgentDirectoryReadback` -> `AgentDirectoryProjection` (`src/lib/server/agent-access-console.functions.ts:10-21`; `src/modules/agent-access/agent-access-console.ts:62-113`).
- **Owner console boundary:** `AeAgentOperatorConsoleProps` already accepts directory, lifecycle callbacks, approvals, deep-link selection, loading and unavailable state (`src/components/ae/console/AeAgentOperatorConsole.tsx:33-73`).
- **Lifecycle boundary:** owner mutations operate on canonical `principalRef`, `credentialRef`, and expected revision; status is recomputed by `agentDirectory:listOwnedPage`, not trusted from the client (`src/routes/_operator/agent-access.tsx:165-239`; `convex/agentDirectory.ts:80-193`).
- **Invocation recovery boundary:** CLI commands and MCP actions return to the original Invocation; official-client behavior proves reconnect/readback without invoking twice (`src/components/ae/agents/AeAgentDoorPage.tsx:198-210`; `tests/unit/server/mcp-api-official-client.test.ts:204-251`).

### Duplicated or hostile joins, ordered by blast radius

1. **MCP registration has two truths.** The public setup uses `add-mcp` against a named harness; `ae connect --mcp` writes a generic bearer-bearing file and requires manual import. Until one existing path owns the journey, “connected” is ambiguous (`src/lib/cli-distribution.ts:23-33`; `tools/ae/commands/connect.ts:75-89,291-316`).
2. **No observable harness-ready state.** Doctor proves the remote endpoint and tool registry, while `add-mcp list` proves a file entry; only the user/agent can presently assert that the active harness exposes `ae_registry_operations_search`. These are three different checks expressed as one setup claim (`src/content/brand-copy.ts:58-59`; `tools/ae/commands/doctor.ts:513-543`).
3. **The setup contract is copied three times.** `AGENT_SETUP_INSTRUCTION`, the six quickstart rows, and `AeAssistantInstallFunnel` each enumerate commands. The funnel itself is rendered both publicly and at the bottom of the owner Agents page (`src/content/brand-copy.ts:52-60`; `src/components/ae/agents/AeAgentDoorPage.tsx:79-89,111-119`; `src/routes/_operator/agent-access.tsx:356`).
4. **A slow consent cannot resume.** A valid 10-minute device grant outlives the CLI’s one-minute wait, but no pending grant handle is saved. The instructed rerun creates a new grant (`src/modules/agent-access/oauth-state.ts:24-27`; `tools/ae/commands/connect.ts:64-72,229-267,267-273`).
5. **Machine readiness can be falsely green.** `ae doctor --json` returns process status 0 when its result is degraded, including remote server failure (`tools/ae/commands/doctor.ts:72-89,116-121`). Consumers must parse every check instead of trusting the conventional exit seam.
6. **Credential validation bypasses the canonical who-am-I.** Connect synthesizes a fake Invocation identifier although `GET /api/v1/account` exists specifically to project authenticated identity on every transport (`tools/ae/commands/connect.ts:19,132-163`; `src/modules/agent-access/account.actions.ts:240-298`).
7. **Local and server lifecycle drift.** Owner revocation correctly invalidates the server key, but `ae revoke` only opens the browser and never cleans local config; the generic MCP file may retain the same stale secret. The next agent request fails later rather than reading a joined state (`tools/ae/commands/revoke.ts:5-24`; `tools/ae/lib/config.ts:225-243,271-290`).
8. **The owner cannot start from owner context.** `/owner/settings/developers` redirects out to public instructions; `/agent-access` empty state also sends the owner to `/for-agents`. The agent must initiate the grant before the owner can see anything (`src/routes/_operator/owner.settings.developers.tsx:3-6`; `src/components/ae/console/AeAgentOperatorConsole.tsx:248-257`; `tests/unit/ui/agent-access-owner-console.test.tsx:91-124`).
9. **Seven-day expiry has no refresh lane.** Metadata deliberately advertises no refresh endpoint and owner recovery says “start a new access request.” That makes reconnection a normal journey, but it currently arrives as an exception path (`src/modules/agent-access/agent-access.ts:22-24`; `tests/unit/routes/oauth-metadata.test.ts:34-46`; `src/components/ae/console/AeAgentOperatorConsole.tsx:580-590`).
10. **The default request starts broad.** CLI asks for bounded-mandate scope by default, then consent allows the owner to narrow to browse or ask-each. This is secure because the owner chooses, but it makes the familiar least-authority connection look like a downgrade from a broad request (`src/modules/agent-access/contract.ts:8-15`; `src/components/ae/agent-access/AeAgentAccessAuthorizeForm.tsx:27-39`).

### Explicit no-handrolling boundaries

The following proposed infrastructure would violate the constraint because maintained packages or canonical AE primitives already own it:

- Do **not** build a custom MCP server/client, JSON-RPC parser, session manager, schema converter, tool registry, or SSE transport. Use `@modelcontextprotocol/sdk@1.30.0` and the existing action registry/`/mcp` adapter (`package.json:84`; `src/lib/server/mcp-api.ts:6-15,269-347,506-510`).
- Do **not** write separate Codex, Claude Code, and Cursor config mutators. The pinned `add-mcp@2.3.0` command is already the maintained harness-specific mutation/readback boundary (`src/lib/cli-distribution.ts:7,23-33`).
- Do **not** invent an API-key paste flow, proprietary device code, refresh scheme, OAuth discovery document, Bearer challenge, client registration, or PKCE implementation. Compose the existing OAuth endpoints and state machine (`src/modules/agent-access/oauth-state.ts:24-56,71-170`; `src/lib/server/agent-access-oauth-api.ts:180-275,674-720`).
- Do **not** create or persist credentials outside Clerk-backed issuance and AE’s origin-bound CLI store. Reuse `issueAgentAccessKey`, `authenticateAgentAccess`, `storeConnection`, and `resolveAgentAccessCredential` (`src/modules/agent-access/agent-access.ts:253-343`; `src/lib/server/agent-access-auth.ts:128-231`; `tools/ae/lib/config.ts:245-312`).
- Do **not** make OAuth grant rows, local config files, application names, or provider key ids into a second Agent identity. `principalRef` plus Account membership is canonical (`src/modules/agent-access/agent-access-console.ts:85-113`; `convex/agentDirectory.ts:39-78,80-193`).
- Do **not** add a second owner connection table or lifecycle status model. Reuse `AgentDirectoryProjection`, `AeAgentOperatorConsole`, and the existing revoke/disconnect/rename mutations (`src/components/ae/console/AeAgentOperatorConsole.tsx:33-73`; `src/routes/_operator/agent-access.tsx:165-239,318-344`).
- Do **not** create a new command-copy, clipboard feedback, confirmation, table, sheet, empty-state, status-badge, toast, radio, select, routing, validation, retry, or test framework. The manifest and primitives above already cover them.
- Do **not** fold credential recovery into Invocation recovery or retry an uncertain Invocation as part of reconnection. The stable Invocation `status`/`wait`/`recover` and MCP status/reconcile actions already own effect recovery (`src/components/ae/agents/AeAgentDoorPage.tsx:198-210`; `tests/unit/server/mcp-api-official-client.test.ts:204-251`).

### Constraint for the parent plan

The evidence supports a single-feature plan around composing and truthfully reporting the existing connection seams. It does **not** support replacing OAuth, MCP, the CLI, the Agent Principal model, the owner directory, or Invocation recovery. The plan should choose one familiar reference journey first, agree the black-box seams above before tests, and reduce the number of human interpretation points without adding complexity to the market core loop.
